# Коннекторы к приложениям

Почему так - ADR 0028, карта - раздел «Коннекторы» в `docs/architecture.md`.

- **Вход коннектора не попадает в хранилище провайдера.** Токены - только в `Vault`
  (`safeStorage`), провайдер видит шлюз с ключом своего процесса. Ни `claude mcp add`, ни
  запись в `~/.claude.json` для коннекторов - иначе вход снова уедет вместе с аккаунтом
  Claude.
- **Без шифрования секрет не пишется** (`Vault.set` отказывает). Открытым текстом на диск -
  никогда, даже «временно». То же для ключей подключений панели открытых моделей: свой файл
  `Vault` (`open-models.vault`), окну ключ не возвращается.
- **Имя сервера - тип и подпись** (`gmail-work`): по нему хук владельца `block-outbound.sh`
  узнаёт отправку (`*gmail*send*`, `*slack*send*`). Тип в начале имени не убирать.
- **Отправка людям - ступень `outbound`**, по умолчанию выключена (`isToolEnabled`), включает
  только человек на виде Connectors. Новый свой инструмент, который что-то отправляет,
  письмо, сообщение, приглашение, ответ организатору, - `outbound`, а не `write`. В
  календаре писать без гостей и с `sendUpdates=none`.
- **Вызов инструмента не повторяется** (`RemoteMcpSource.callTool`): оборвавшийся вызов мог
  выполниться, повтор создал бы второй черновик. Повторять можно только чтение списка.
- **Порт возврата 5319** (`CONNECTOR_REDIRECT_URL`) вписан в Slack app человека и в
  регистрацию Notion, Notion сверяет его строго. Не менять; занят - `callback-busy`.
- **Шлюз** слушает только `127.0.0.1`, проверяет `Host` и ключ процесса разговора
  (`GatewayLaunches`: свой случайный ключ на каждый процесс, хранится хешем, гаснет с
  процессом). Конфиг для CLI - права 600. Ответ - потоком событий с отметками «жив»: долгий
  вызов не рвётся тайм-аутом клиента. Набор серверов поменялся - `serversChanged`
  (перезапуск свободных процессов), поменялось внутри сервера - `serverChanged`
  (`mcp_reconnect`).
- **Браузер открывает только кнопка человека** (`SignInDesk`). Фоновый источник
  (`McpAuthProvider` без `interactive`) при истёкшем входе ставит «нужен вход», а не
  открывает вкладку посреди работы.
- **Коннекторы - вид середины окна** (`features/connectors/ConnectorsView`, зона 6), а не
  раздел настроек: им нужно место. Подключённые - плитками (`Tile` из `packages/ui`) сеткой
  с переносом (заголовок - имя типа, под ним подпись подключения), под ними - каталог нового
  двумя группами: приложения со своими типами и свои способы добавить (адрес, команда, ИИ,
  перенос); сверху шапка вида (`PageHeader`, разделы - `Section`, ADR 0030); подробности,
  выбор проектов и формы - окном по центру (`Modal`, открытое окно держит
  `connectors.store.ts`). Иконка полосы видов середины и поиск везде ведут на этот вид
  (`showMainView`); строки в меню Claude Code у него нет - иконки хватает. Всё, что идёт долго (вход, работа ИИ), живёт в главном
  процессе: уход на другой вид снимает страницу, но не работу.
- **Свой коннектор - тип** (ADR 0034): имя с заглавной, «несколько раз» и образец того, чем он
  работает (`StoredType`, секреты образца - под `typeSecretsKey`). Подключение держит копию
  образца, вход у каждого свой (`DEFINITION_SECRETS` - общее, остальное - нет). Имя сервера
  ставится при создании и с переименованием типа не меняется. Тип «несколько раз» - в
  каталоге рядом с Gmail, удаляется вместе с подключениями; «один раз» уходит со своим
  подключением. Прежний реестр переносит `assignCustomTypes`, импорт группирует так же.
- **Встроенные с официальным MCP** - Notion, Slack, Jira & Confluence, Todoist
  (`REMOTE_MCP_URL`, ADR 0036): адрес держит IDE. Todoist входит личным токеном API
  (способ входа всегда «токен»), остальные - OAuth в браузере. Jira & Confluence - только
  облако Atlassian.
- **Playwright - встроенный** (ADR 0035): команду `npx -y @playwright/mcp@<версия>` собирает
  `playwrightCommand` из настроек подключения (профиль, без окна, версия). Работает движком
  своей команды (`runsCommand`): копия на процесс разговора, входа нет. Своя команда,
  которую узнаёт `playwrightOptionsOf`, переносится в Playwright (`adoptPlaywright`, импорт -
  `asPlaywright`); флаги сверх известных - остаётся своей.
- **Описание коннектора** - слова человека для себя и для модели: шлюз отдаёт его в
  пояснении сервера (`instructionsFor`), смена - `serverChanged` (`mcp_reconnect`). Окно
  сохраняет его само через секунду тишины, при уходе из поля и при закрытии окна, а не на
  каждую букву: каждое сохранение переподключает сервер у живых разговоров.
- **Инструкции по проектам** (ADR 0053): у коннектора `inProjects` - по пути проекта слова
  модели и у Browser профиль Chrome проекта. Шлюз отдаёт их в пояснении сервера только
  процессу этого проекта (`instructionsFor` с `projectPath`), смена - `serverChanged`, как у
  описания. Окно коннекторов общее на IDE: проект для инструкций выбирается явно (с открытого),
  а не подставляется молча. Пустое не хранится (`withInProject`); забытые папки переносят и
  забывают их вместе с доступностью.
- **Доступность по проектам** (ADR 0029, 0033): «во всех» - все, без исключений, выбор по
  одному - только у «только в отмеченных». Конфиг `--mcp-config` пишется при подъёме
  процесса (`GatewayHost.open`), проект шлюз узнаёт по ключу процесса, а не по вычислимому
  заголовку. Это фильтр видимости, а не песочница: процесс с Bash прочтёт чужой конфиг в
  userData. Смена доступности - перезапуск только там, где она поменялась. Конфиг не
  записался - разговор идёт без коннекторов и говорит об этом строкой CONNECTORS.
- **MCP-команда - своя копия на процесс разговора** (`LiveConnector.sourceFor`), в папке
  его проекта, всегда, как в Claude Code: два разговора не делят браузер Playwright.
  Общего процесса и переключателя для него нет - параллельной работе нужен второй
  коннектор (ADR 0029). Выключенный коннектор свою команду не запускает, удалённый - не
  поднимает заново.
- **В реестре ключей нет и в аргументах:** аргументы команды и путь адреса с ключом
  хранятся маской, полные - в хранилище (`commandForStore`, `publicUrl`); старые записи
  переносит `moveSecretsToVault`.
- **Коннектор от ИИ - данные, а не код.** Описание проверяет `specSchema` везде, где оно
  входит (ответ ИИ, добавление, реестр с диска); запрос не уходит за `baseUrl`, ключ
  подставляет шлюз, перенаправления запрещены. ИИ предлагает и другое (ADR 0050): перенос
  сервера человека из Claude Code (ключ переезжает внутри IDE) или официальный MCP по адресу
  (https без ключа в адресе); MCP-команду - нет, это чужой код на машине. Файлов человека ИИ
  не читает - рядом WebFetch; что уже настроено, он узнаёт списком переноса с маской ключей.
- **Работа ИИ - разговор в очереди** (ADR 0050): `main/connectors/ai/` держит работы
  (параллельно, на диске, ход до 10 минут), `main/claude/connector-chat/` ведёт процесс -
  поток JSON в обе стороны с оградой `fenceArgs` (`--json-schema`, белый список
  `--tools WebFetch WebSearch`, `--restricted`, `--safe-mode`, `dontAsk`, без MCP) в своей
  пустой папке; запрет лишних вместо белого списка пропустил бы то, чего нет в запрете. Окно не ждёт работу: форма
  закрывается, работа - в очереди на виде, её окно показывает ленту и пишет ИИ посреди хода.
  Готовое, которому от человека ничего не нужно (`proposalNeed`: ни ключа, ни адреса не с сайта
  документации), главный процесс добавляет сам (`ai-adopt.ts`, ADR 0086) - без входа в браузере,
  его начинает только кнопка человека; работа уходит из очереди, открытое окно работы становится
  окном коннектора (`connectors:aiJobAdded`).
- **Клиент Google - свой у человека, опубликованный на его домене** (ADR 0031): иначе
  войти могут только тестовые пользователи. Промпт настройки (`connectors.google.agentPrompt`)
  сначала создаёт клиент, потом спрашивает домен; без домена - тестовый режим с названными
  адресами, выдуманных ссылок в Branding нет, DNS - только добавление записей и с вопросом.
  Политика из промпта говорит правду о данных: поменялись инструменты Google - поправить её.
  Отдаётся промпт приложению ИИ ссылкой (`agent-links.ts`): схему и путь собирает главный
  процесс, из окна - только текст; ссылка кладёт промпт в поле ввода, отправляет человек.
- **Slack app - свой на рабочее пространство** (ADR 0032): MCP Slack пускает только внутренние
  и опубликованные в Marketplace приложения. Создаётся по ссылке с описанием
  (`slack-manifest.ts`): адрес возврата, разрешения - те, что Slack MCP объявляет сейчас (вход
  просит их все), и бот, без которого Slack не ставит приложение. MCP описанием не включить -
  это шаг человека. Забыл - Slack отвечает 400 «App is not enabled for Slack MCP server
  access», и карточка говорит это своей причиной `slack-mcp-off` со ссылкой на страницу
  приложения из ответа (`service-answer.ts`); другой ответ сервиса - его словами, а не «не ответил».
- **Перенос из Claude Code сохраняет имена** серверов: на них завязаны правила и хуки
  человека; новое имя видно в списке. Одинаковые серверы с именами «начало-подпись»
  (playwright-1, playwright-2) встают одним своим типом. Конфиг Claude Code не трогается.
  `.mcp.json` - только у доверенной папки, отклонённые в Claude Code серверы не предлагаются, неодобренные
  помечены, и серверы проекта по умолчанию не отмечены. `${VAR}` раскрывается из оболочки,
  проба входа решает OAuth только по 401.
- **У Codex имя сервера IDE может получить хвост `-ide`** (`codexServerNames`): флаг
  `-c mcp_servers.<имя>` не заменяет одноимённый сервер из `~/.codex/config.toml` человека, а
  сливается с ним, и адрес шлюза рядом с его командой Codex отвергает («url is not supported
  for stdio») - разговор не открывается вовсе. Занятое имя уходит с хвостом (тип в начале
  остаётся), сервер человека выключается, как остальные. Проверено вживую на Codex 0.163.
- **Browser** (ADR 0040): `upload` - ступень `outbound`, а файлы для загрузки и адреса `file:` -
  только из папки разговора (`SourceLaunch.workDir`: проект, у сценария - worktree) по
  настоящему пути (`realPathInside`): страница может уговорить модель отправить ключ с диска.
  Сессия браузера - на разговор, а не на процесс: процесс называют разговором сразу после
  выдачи ключа (`McpLaunch.own`), конец процесса ждёт следующий (`SessionLaunches`), закрытая
  вкладка разговора - `McpLaunch.end`; другие типы ключуют своё по процессу, как раньше.
  Работа разговора встала (ни хода, ни фоновых агентов; сценарий - на каждом `result`) -
  `McpLaunch.idle` (ADR 0065): отладчик, рамка и курсор уходят с вкладок сессии, а вкладки
  остаются (`tab-rest.ts`), капсула Computer уходит сразу. Вызов Browser идёт через
  `BrowserAgent.during`: под идущим вызовом вкладки не отдыхают. Рамку помнит `framed`, а не
  `attached`: отладчик снимают и без IDE. В
  тестах манифесты host - только в `AGENTIC_WORKSTATION_BROWSER_HOSTS_DIR` или папку профиля
  своего Chromium, никогда в папки настоящих браузеров. Человек смотрит на руку агента (ADR
  0049): действие на странице - только рукой (`moveTo`/`reach`), `evaluate` - для чтения;
  пояснение сервера - `BROWSER_GUIDE` (там и правило вкладок: своя новая, вкладка человека -
  только по его слову или по делу), скрипт, который сам нажал, получает замечание. Профиль
  Chrome копии расширения IDE находит по её ключу в файлах профиля (ADR 0052,
  `chrome-profiles.ts`) и отвечает им в welcome до «профиль поднялся»: первая сводка сессий
  после welcome решает судьбу вкладок агента. Welcome ждёт поиска не дольше 2 с, опоздавшее имя
  досылается запросом `profile.chrome`. На macOS папку Chrome читает только IDE с «Полным
  доступом к диску» (и host тоже не может): без него поиск - `denied`, окно просит доступ. Имя, данное человеком в окне расширения, главнее.
  Профиль вызова - `profile-pick.ts`: названный моделью, группы сессии, проекта, единственный.
  Названный профиль закрыт - IDE открывает окно браузера в нём (`--profile-directory`, папка из
  Local State, только с нашим расширением) и ждёт его до 20 с (`reachProfile`). Расширение само
  переподключается будильником раз в минуту: таймер повтора умирает со сном воркера, а профиль,
  где человек всё время работает, воркер не перезапускает.
  К элементу - колесом (`aimOf`/`revealByHand`, ADR 0051), а не `DOM.scrollIntoViewIfNeeded`
  напрямую. Клик проверяет попадание прямо перед каждым нажатием (ADR 0119, `page-click.ts`,
  `page-hit.ts`): по ref - только сам элемент или потомок (один повторный подход, потом отказ), по
  x,y в действующий элемент - только с `expect` (имя совпадает целиком: вхождение пустило бы
  «Don't Save» на «Save»), ответ - `clicked`; подпись поля под точкой - попадание в поле (`labelFor`),
  другая кнопка внутри ref - «закрыт». `getNodeForLocation` - без
  `ignorePointerEventsNone` (с ним попадание - курсор агента) и в координатах документа (точка
  окна плюс прокрутка). Новое действие, которое нажимает, - через `click`, а не мимо проверки.
  Перевод строки в наборе (ADR 0095) - только Shift+Enter (`page-typing.ts`, `charEvents`),
  голого Enter внутри текста нет ни в одном пути; многострочный текст с `submit` - отказ
  (`typed-lines.ts`), в однострочное поле - тоже. `type` в редактор без `submit` отвечает текстом
  поля по строкам и картинкой поля: текст собирается по блокам (`field-read.ts`), не `innerText` -
  Lexical держит строку абзацем `<p>`, и `innerText` показал бы пустую строку, которой не уйдёт.
- **Computer Use** (ADR 0057, 0058): компьютер человека настоящими мышью и клавиатурой по снимкам,
  мак и Windows. Ввод через koffi - CoreGraphics на маке (`main/computer/cg-events.ts`), SendInput
  и SetCursorPos на Windows (`win-input.ts`: точки - DIP, курсор - пиксели экрана; окно от
  администратора ввод молча выбросит - рука отказывает заранее), снимки - `desktopCapturer`;
  координаты модели - пиксели её последнего снимка. Перевод строки в `type` - Shift+Return и между
  вставками (ADR 0095), многострочный текст с `submit` - отказ. Текст на Windows - вставкой из буфера
  (`win-clipboard.ts`), а не знаками: занятое приложение путает знаки Юникода. Буфер человека
  вернуть всегда (`finally` руки), свой текст - с пометками «не в историю, не в облако». Чужую
  память в главном процессе - только копией (`RtlMoveMemory` в свой буфер): `koffi.view` Electron
  запрещает, и процесс падает. Модификатор - только своей клавишей с
  отпусканием в `finally`: флаг на событии без клавиши macOS запоминает зажатым. Вмешательство
  человека - по месту курсора (рука помнит, куда ставила), а не по счётчикам простоя: наши события
  их тоже сбрасывают. Мышь одна - компьютер держит один разговор (`ComputerDesk`), пауза и стоп -
  в капсуле. Строка капсулы (ADR 0060) - `intent` вызова (поле у каждого инструмента через `schema`),
  без него - действие словами окна (набираемый текст не показывать), между шагами - последняя
  законченная фраза модели из ленты (её приносит `ide-features`). Stop в капсуле прерывает и ход
  разговора панели (`ComputerRuntime.stopped`, ставит `ide-features`), а не только шаг. Клики
  сквозь капсулу - только пока рука бьёт в точку под ней (`covers`): иначе Stop посреди действия
  проваливался в приложение под капсулой. Перед каждым нажатием рука спрашивает, что под точкой
  (ADR 0119, `InputDriver.elementAt`): на маке - системный поиск доступности (`ax-element.ts`),
  только синхронно в главном потоке - из фонового потока koffi Electron падает; атрибуты
  доступности Chromium и Electron чужим приложениям не ставим. На Windows - UI Automation
  (`uia-native.ts`, места методов COM сверены с IDL Wine), окна самой IDE не спрашиваем. Действующий
  элемент без `expect` и промах `expect` - отказ `mismatch` со свежим снимком; не определённый
  элемент и действующий без имени с `expect` - отказ, без него - клик с пометкой. Курсор «рука» над её кнопками macOS не покажет: окно
  фонового приложения, не ключевое, курсор не ставит (CSS, `NSCursor set` и `SetsCursorInBackground`
  проверены на macOS 27), а ключевая капсула забрала бы клавиатуру у приложения, где печатает ИИ.
  Страницы сайтов - Browser, то,
  куда расширение не пускают (chrome://, сам Chrome, окна системы), - Computer: так говорят оба
  пояснения и ошибки Browser. Пояснения обоих заполнены почти до 2048 знаков вместе с описанием
  человека (держит тест; у Browser и у Computer на Windows запас - единицы знаков): новое правило туда - только за счёт сжатия старого. Проверять живьём - копия
  окна с временным документом, не приложения человека; TextEdit сам сохраняет новый документ в
  iCloud - убрать за собой.
- **Сама IDE - встроенный `workstation`** (ADR 0090): заводится вместе с уведомлениями
  (`ensureBuiltIns`), не удаляется. Инструменты - `kinds/workstation/` поверх `WorkstationPorts`
  (порты встают в `ide-features.ts` и снимаются на выходе; без них - «IDE поднимается или закрывается»). Ступень `read` - только у
  того, что ничего не меняет: шлюз разрешает её CLI без вопроса (`WORKSTATION_READ_TOOLS`).
  Права даёт и повышает только человек: ответить на вопрос разрешения вкладки инструмента нет,
  разрешение прогона агент может только отклонить, новая вкладка - в режиме новых вкладок
  человека, новое задание агента - тоже в нём (ADR 0121, `task-drafts.ts`), и свободнее его агент
  заданию режим не ставит; сценарию - только `default`/`plan` (режим, уже поставленный человеком,
  правка не трогает). Сужение по проектам - граница
  (`workstation-scope.ts`): чужой проект, очередь, прогон, задание, доска трекера и разговор
  разговору не видны. Трекер (`kinds/workstation/tracker-*.ts`, ADR 0101) правит доску теми же
  правками `TrackerOp`, что окно: удаление проекта трекера - только архив (стереть навсегда агент
  не может), срок и сценарий карточки проверяются до записи, пачка `tracker_add_cards` - до первой
  карточки. Раскладку работы (ADR 0111: шаги - задачи одной группы, продолжение - проверка после
  выполненной задачи, новый поток и проект трекера - только с согласия человека) говорят и
  пояснение сервера, и описания `tracker_*`: меняешь смысл - правь оба, пояснение держи в 2048
  знаках (тест `connector-view.test.ts`).
  Проект в аргументах - путём или именем из известных IDE, без него - проект разговора, а снаружи
  проекта нет: списки - по всем проектам, действие без проекта - отказ словами.
- **Вход снаружи** (`connectors/outside/`, ADR 0090): второй `ConnectorGateway` только с сервером
  `workstation` на постоянном порту 127.0.0.1 (4461 у собранной, 4462 у dev,
  `AGENTIC_WORKSTATION_OUTSIDE_PORT` у копии окна и проверок), выключен по умолчанию. Ключ - в
  `Vault`, без шифрования вход не включается; сравнение - хешами за постоянное время; Host - только
  127.0.0.1 и localhost. Текст настройки с ключом кладёт в буфер главный процесс
  (`connectors:copyOutside`), окну ключ не уходит. Новый ключ сразу отрезает старых клиентов.
  Перенос из Claude Code сервер на этом порту не предлагает (`isOwnOutside`). Копия окна агента -
  порт 4472 (`agent-window.sh`).
- Проверять вход вживую - в копии окна (`/dev`): у неё свой userData и свои коннекторы,
  коннекторы dev человека не трогать.

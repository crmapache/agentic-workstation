# Трекер задач и облако IDE

Почему так - ADR 0101 (трекер) и 0102 (облако), карта - разделы «Трекер задач» и «Облако IDE»
в `docs/architecture.md`.

- **Правка доски - только `TrackerOp` через `TrackerService.apply`** - и из окна, и из MCP.
  Своих путей записи в книгу мимо правок нет: проверки (`tracker-guards.ts`, `tracker-fields.ts`)
  идут до первой записи, отказ не оставляет полуправки.
- **Поле пишется только `TrackerBook.write`**: оно ставит отметку часов и метку «не
  отправлено». Поле с тем же значением новой отметки не получает - иначе пустая правка перебила
  бы настоящую правку другой машины. Пачка тихих записей (`silent`) заканчивается `commit()`.
- **Порядок - дробная строка `rank`**, перенос - одно поле одной записи. Соседей не переписывать:
  перенос на другой машине тогда не спорит с этим. Равные места решает id (`byRank`); место для
  вставки - `slotBefore`: он разводит двух соседей с одним местом, иначе новое встало бы после
  обоих.
- **Встречные правки сводятся после забора, а не правками окна:** двойники пространств
  (`mergeTwinSpaces`, и из уже удалённого двойника), сироты под удалённым предком
  (`healOrphans`: правка новее удаления возвращает предков), продолжение продолжения и цикл
  (`TrackerTree.rootOf`: корень цикла - карточка с меньшим id). Продолжение хранит группу своей
  задачи - корню после разрыва цикла есть где встать.
- **Окно шлёт только тронутые поля** (карточка, проект, поток, группа): иначе «Save» вернул бы
  отметку очереди, правку ИИ или другой машины, сделанную, пока окно было открыто.
- **Срок архива - только после сверки с облаком** (`allowPurge`): по устаревшей копии машина
  удалила бы проект, который уже вернули на другой.
- **Удаление - поле `deleted`, а не стирание**: старая копия другой машины не воскресит запись,
  а «Undo» - это `undelete`. Каскад (`descendants`) - тоже отметки.
- **Продолжение держится за задачу (`parent`), а не за группу**: перенос задачи - одно поле,
  продолжения едут сами. Задачу нельзя сделать продолжением своей же цепочки.
- **Что только этой машины - не в записи**: привязка «путь проекта → пространство» и связь
  «карточка → элемент очереди» лежат в книге отдельно и в облако не уходят.
- **Отправка в очередь проверяет все карточки до первого `start`** и ставит их по одной, по
  порядку доски. Карточка, стоящая в очереди (`isInQueue`), второй раз не уходит. Сделанный
  элемент отмечает карточку один раз (`settled`): снятую руками галочку очередь назад не ставит.
- **Облако не читает записи.** Сервер хранит id, версию и шифр; всё, что о записи знает сервер,
  - её id и размер. Новое поле записи - внутри шифра, а не рядом с ним. Запись принимается только
    на ту версию, что лежит на сервере (`baseRev`); спор - забрать, слить, записать снова.
- **Ключ аккаунта окно не видит**: показывает его системное окно главного процесса
  (`cloud-dialogs.ts`, «Copy» - в буфер на минуту), в окно IDE идёт только короткий id аккаунта.
  Смена аккаунта и новый аккаунт - только после «да» в системном окне, прежний ключ хранится
  рядом. Ключ - в `cloud.vault` (safeStorage); без связки ключей облако не включается; ключ
  пропал, а книга уже жила в аккаунте, - `keyLost`, нового тихо не заводить.
- **Остановка синхронизации ждёт конца её захода** (`CloudSync.stop`): ответ старого аккаунта,
  пришедший после смены ключа, не пишет в книгу. Облако с версией ниже курсора (поднято из
  бэкапа) - всё своё заново (`restart`); спор о версии, которую забор уже прошёл, - `rebase`.
- **Подпись облака - своя метка `aw-cloud/v1` и хост облака в тексте**: подпись к магазину или к
  другому облаку не подходит; клиент не идёт по переадресациям, http - только к своей машине.
  Сервер читает тело последним (после маршрута, длины и подписи по заголовкам), аккаунт заводит
  только первой принятой записью, считает адрес по последней записи X-Forwarded-For. Протокол (`packages/cloud-protocol`) и сервер (`apps/cloud`) - Node без сборки:
  импорты с `.ts`, только стираемый синтаксис TypeScript (как у магазина).
- **Новый путь данных наружу** (что ещё уходит в облако) - сначала политика на сайте
  (`apps/site/privacy/index.html`).
- **Проверять вживую** - копией окна (`/dev`): без `AGENTIC_WORKSTATION_CLOUD_URL` облако в ней
  выключено (подставная связка ключей). Боевое облако проверяется сквозным тестом с
  `AGENTIC_WORKSTATION_CLOUD_LIVE`. «Show account key» в копии не нажимать: системное окно
  всплывёт у человека на экране.

# Трекер задач и облако IDE

Почему так - ADR 0101 (трекер) и 0102 (облако), карта - разделы «Трекер задач» и «Облако IDE»
в `docs/architecture.md`.

- **Правка доски - только `TrackerOp` через `TrackerService.apply`** - и из окна, и из MCP.
  Своих путей записи в книгу мимо правок нет: проверки (`tracker-guards.ts`, `tracker-fields.ts`)
  идут до первой записи, отказ не оставляет полуправки.
- **Поле пишется только `TrackerBook.write`**: оно ставит отметку часов и метку «не
  отправлено». Поле с тем же значением новой отметки не получает - иначе пустая правка перебила
  бы настоящую правку другой машины. Пачка тихих записей (`silent`) заканчивается `commit()`.
- **Порядок - дробная строка `rank`**, перенос - одно поле одной записи. Соседей не переписывать:
  перенос на другой машине тогда не спорит с этим. Равные места решает id (`byRank`).
- **Удаление - поле `deleted`, а не стирание**: старая копия другой машины не воскресит запись,
  а «Undo» - это `undelete`. Каскад (`descendants`) - тоже отметки.
- **Продолжение держится за задачу (`parent`), а не за группу**: перенос задачи - одно поле,
  продолжения едут сами. Задачу нельзя сделать продолжением своей же цепочки.
- **Что только этой машины - не в записи**: привязка «путь проекта → пространство» и связь
  «карточка → элемент очереди» лежат в книге отдельно и в облако не уходят.
- **Отправка в очередь проверяет все карточки до первого `start`** и ставит их по одной, по
  порядку доски. Карточка, стоящая в очереди (`isInQueue`), второй раз не уходит. Сделанный
  элемент отмечает карточку один раз (`settled`): снятую руками галочку очередь назад не ставит.
- **Облако не читает записи.** Сервер хранит id, версию и шифр; всё, что о записи знает сервер,
  - её id и размер. Новое поле записи - внутри шифра, а не рядом с ним. Запись принимается только
  на ту версию, что лежит на сервере (`baseRev`); спор - забрать, слить, записать снова.
- **Ключ аккаунта окно не видит**: копирует его главный процесс, в окно идёт только короткий id
  аккаунта. Ключ - в `cloud.vault` (safeStorage); без связки ключей облако не включается.
- **Подпись облака - своя метка `aw-cloud/v1`**: подпись к магазину расширений облаку не
  подходит. Протокол (`packages/cloud-protocol`) и сервер (`apps/cloud`) - Node без сборки:
  импорты с `.ts`, только стираемый синтаксис TypeScript (как у магазина).
- **Новый путь данных наружу** (что ещё уходит в облако) - сначала политика на сайте
  (`apps/site/privacy/index.html`).
- **Проверять вживую** - копией окна (`/dev`) с `AGENTIC_WORKSTATION_CLOUD_URL` на свой
  сервер: иначе копия заведёт аккаунт в боевом облаке. Две машины - два профиля копии с одним
  ключом аккаунта.

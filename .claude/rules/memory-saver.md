# Новые службы и экономия памяти

При добавлении или изменении ресурсоёмкой службы IDE проверяй, нужна ли она при
работе только через AI-агентов. Это касается и отдельных процессов, и worker-ов,
и служб внутри процесса: LSP, автодополнения, диагностики, индексов и крупных кешей.

- Службу, нужную только для расширенных функций редактора, сразу подключать к
  общему Memory Saver (`main/memory-saver/`, ADR 0098). Это часть готовности новой
  функции, а не задача на потом.
- Включение реально освобождает память: процесс завершается, worker уничтожается,
  служба освобождает кеши, подписки и таймеры. Скрыть подсказки недостаточно.
- Запуск запрещён до чтения сохранённого режима и всё время, пока он включён,
  включая открытие файлов, смену проекта и правки агентов. Выключение восстанавливает
  обычную работу без перезапуска и без изменения прежних пользовательских настроек.
- Управлять только ресурсами, которыми владеет IDE. Сохранять редактирование,
  подсветку, сравнение файлов, Git, терминалы и агентов. Если служба общая с ними,
  сначала разделить зависимости. Не искать процессы по имени и не трогать сборки,
  тесты, dev-серверы и другие приложения.
- Добавить состояние новой службы в общий статус режима: успех только после
  освобождения ресурсов, частичный отказ виден на кнопке. Проверить жизненный цикл
  тестами и в запущенной IDE: память до/после, отсутствие повторного запуска,
  восстановление, быстрые переключения и ошибки.

Устройство режима и исходные замеры: `docs/adr/0098-memory-saver-editor-lifecycle.md`.

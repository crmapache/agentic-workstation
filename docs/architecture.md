Пути выше - от `apps/desktop/src/renderer/src`. Раскладку собирает
`workbench/Workbench/Workbench.tsx`, и только она знает про все зоны сразу. Она же
мерит место, которое делят панели и середина; сколько кому достаётся, считает
`state/layout.utils.ts`. У панелей есть минимум, но нет потолка: растут они только в
место середины, до самой полосы иконок, а в узком окне ужимаются, не уезжая за край
([ADR 0021](adr/0021-main-area-auto-collapse.md)). Разговор не уже 250, окно - от 422: левой
панели, которой нет места рядом с разговором, не видно, середину, которой не хватает места,
заменяет разговор ([ADR 0055](adr/0055-narrow-window-conversation-first.md)). Виды
боковых панелей и середины держит `workbench/ViewStack`: открытый однажды вид остаётся
смонтированным и прячется, поэтому переключение не теряет прокрутку и состояние. Какой
вид выбран в каждой области, что развёрнуто и открыт ли терминал - своё у каждого проекта и
меняется вместе с активным, ширины панелей и доля терминала - одни на окно
([ADR 0107](adr/0107-layout-per-project.md)).

**Меню проекта и меню ветки - всплывающие панели, как в WebStorm.** Панель - `Popover`
из дизайн-системы на Popover API браузера: верхний слой, закрытие по клику мимо и по
Esc, привязка к кнопке через CSS anchor positioning - без библиотек и своего кода
позиционирования. Внутри - `Menu` с поиском, секциями и навигацией стрелками.
Содержимое монтируется только открытым, поэтому каждый раз свежее. Вопросы с вводом
(имя ветки, адрес репозитория, подтверждение push) - `Dialog` на нативном
`<dialog>`, он живёт снаружи панели: панель закрывается при выборе пункта.
Меню правой кнопки (вкладки файлов и разговоров, код) и выбор файла по ссылке в ленте -
те же `Popover` и `Menu` у якоря из кода (`useAnchoredPopover`): вкладки, точки нажатия,
ссылки. Меню правой кнопки открывается после отпускания кнопки (`openWhenReleased`): на
macOS contextmenu приходит при нажатии, и отпускание закрыло бы панель как клик мимо.

**Проекты.** Меню проекта: новый проект (системный диалог «где и как назвать», пустая
папка), открыть, клонировать (адрес и папка, клон сразу открывается вкладкой);
открытые проекты с путём и недавние - закрытые раньше, до 20 штук. Недавний
открывается только из списка недавних: произвольный путь окно так не откроет. Первым
всегда стоит дом - проект для общих запросов со своей папкой `~/.agentic-workstation/home`
(у копии с профилем - внутри профиля): закреплённая вкладка с домиком, не закрывается и не
двигается ([ADR 0059](adr/0059-home-project.md)).

**Поиск везде** - как Search Everywhere в WebStorm: двойной Shift, ⌘⇧O (файлы), ⌘⇧A
(действия), ⌘⇧F (текст); кнопки в шапке нет, слой поиска - `workbench/SearchLayer`.
Панель сверху по центру окна, вкладки All, Files, Actions, Text; фокус всё время в
поле, стрелки двигают выделение (`ListBox`).
Список файлов проекта главный процесс отдаёт один раз на открытие (`git ls-files`, у
папки без git - обход без тяжёлых папок), имена сравниваются в окне. Текст ищет
главный процесс (`git grep`) после паузы в наборе. Действия IDE собирает
`workbench/actions/`. Найденный файл выбирается, дерево раскрывается до него
([ADR 0007](adr/0007-search-everywhere.md)).

**Настройки IDE и размер текста** ([ADR 0024](adr/0024-ide-text-size.md)). Settings… (⌘, в
меню программы, шестерёнка внизу левой полосы иконок, действие поиска) - широкое окно
`features/settings` во всю высоту поверх IDE, которая под ним не темнеет: слева меню разделов
(вертикальные `Tabs` в колонке `Modal aside`), справа раздел строками настроек в карточке.
Разделы: вид (размер текста), Chat (сворачивание вставки в поле любого провайдера и возврат к чату после Computer Use, ADR 0130), звуки, AI (служебная работа) и Git (кто пишет сообщение Commit and push: провайдер, модель, усилие и запасные); Chat и Git - общие настройки IDE (`shared/ide-prefs.ts`, `main/ide-prefs/`, ADR 0099). Новый раздел - пункт в `SETTINGS_SECTIONS` и свой вид. Размер текста всей IDE - 60-200% с шагом 5: один
множитель `--font-scale` на корне документа, от него токены считают все кегли и высоты, в
которых стоит строка текста (шапка, вкладки, строки дерева и меню, контролы). Иконки,
отступы и ширины панелей не меняются. Хранит размер окно (`state/text-size.store.ts`, в
localStorage) и ставит его до первой отрисовки. ⌘+, ⌘- и ⌘0 в меню двигают тот же размер
(событие `window:command`), масштаба страницы в меню нет. Monaco получает кегль числом на
ходу (`followTextSize`), «светофор» macOS встаёт по середине выросшей шапки - окно шлёт её
высоту главному процессу (`window:setTitleBarHeight`).

**Зов разговора: звуки и точки на вкладках проектов** ([ADR 0046](adr/0046-calls-ide-level.md)).
Сервис разговоров отдаёт каждый повод позвать человека (`ConversationCall`: конец работы,
вопрос, план, лимит, доплата, поломка). Конец работы - не конец хода: пока идёт фон, который
разбудит агента (агенты, фоновая команда, наблюдатель Monitor, будильник), «готово» молчит, а
вкладка горит «работает» ([ADR 0117](adr/0117-done-means-no-background.md), `awaitsBackground`). Звуки - настройка IDE: `main/sounds/`
(`SoundsService`, файл `sounds.json`, при первом запуске громкости переезжают из `claude.json`),
каналы `sounds:get` / `sounds:set`, событие `sounds:changed`, в окне - `state/sounds.*` и раздел
Sounds в настройках IDE; файлы звуков и проигрывание - `lib/sound-player.ts`. Выключенный повод
главный процесс до окна не доносит (телефону Remote Control - все). Окно играет звук
(`claude-code/sounds.hooks.ts`), зажигает вкладку разговора и ставит точку на вкладку его
проекта: `workbench/views/project-calls.ts` собирает позвавшие разговоры по проектам,
`features/projects/ProjectTab` рисует их маячками справа (`ClosableTab.trailing`): ядро тоном
повода, дышащий ореол и волна от ядра, до трёх и «+N», с чатами в подсказке. Позвавший разговор
открытого проекта зажигает и иконку своего провайдера в зоне 3, пока его панели не видно
(`workbench/views/provider-calls.ts`, `IconButton call` - тот же `CallLight`, что у вкладки):
работа в другом провайдере не проходит мимо. Источник у света и точки один: открыли
разговор - гаснут все. Все звуки разом выключает `SoundPrefs.muteAll` - кнопка в строке состояния
рядом с телефоном Remote Control (`features/settings/MuteSoundsButton`), строка в разделе Sounds и действие поиска:
молчат зов разговоров, уведомления и баннеры ОС (`silent` в `tasks-setup` и `scenarios-setup`),
а свет вкладок, точки и настройка по поводам остаются.

**Знак работы на вкладках проектов** ([ADR 0071](adr/0071-project-tab-work-mark.md),
[0073](adr/0073-home-tab-work-spinner.md)). Что в проекте работает само, без человека, -
янтарный `Spinner` слева от имени (`ClosableTab.leading` в ряду fill: подпись остаётся по
центру), у дома - тот же спиннер на месте знака дома, по центру квадрата. Работа - разговор,
чья вкладка горит «работает» (`worksOnItsOwn` в `StatusDot.utils.ts`: ход или фон, который
разбудит агента, без вопроса и разрешения), идущий прогон сценария и задания без вопроса
(`isRunWorking` в `shared/scenario-runs.ts`, `isTaskRunWorking` в `shared/tasks.ts`,
`workbench/views/project-work.ts`). Знак горит и у открытого проекта; что работает - строками в
подсказке. Ждёт человека - это точки зова справа, не знак работы. Идут одни сценарии и задания, а
чат молчит, - вместо дуги кольцо из шагов с бегущим огоньком (`Spinner variant="steps"`,
ADR 0097), так же и в списке проектов телефона: IDE шлёт ему, сколько прогонов сценариев и заданий
работает само (`QueuesSummary.working`, `TasksSummary`; порт заданий моста заполняется после их
подъёма, в `ide-features.ts`), а он сверяет с ходом разговоров (`projectWorksInBackground`).

**Git** - в главном процессе через `git` (`main/git/`): текущая ветка, локальные и
удалённые ветки, переключение (удалённая ветка без локальной создаёт отслеживающую),
новая ветка, переход на тег или коммит, Update Project (`pull --ff-only`: разошедшиеся
ветки не сливаются без окна конфликтов), Push с подтверждением (ветка без upstream
публикуется). Force push нет. Имена веток и ревизии проверяются до вызова git - опция
вместо имени в него не попадёт. Ответ git при отказе показывается как есть. Commit -
пока нет: список изменений для него уже есть (вид Changes, ниже), не хватает коммита
из этого вида. Ветка перечитывается при
возврате в окно - её часто меняют в терминале. Справа от ветки - её PR (`gh pr view`,
номер и значок состояния, нажатие открывает браузер); нет PR, gh или входа в него -
кнопки нет. Записывающие команды (pull, push, переключение, новая ветка, checkout) идут
по очереди на проект, чтения не ждут.

**Редактор** (зона 6, [ADR 0018](adr/0018-editor-tabs-autosave-highlighting.md)). Над
кодом - вкладки открытых файлов проекта (`features/editor/EditorTabs`, `ClosableTab`
с иконкой типа): в порядке открытия, переносятся рядами, больше 30 не бывает - новый
файл закрывает самый первый из открытых. Закрыл активную - открывается та, что была
активна до неё. Вкладки и порядок выбора живут в `state/selection.store.ts` (их видят
дерево, строка состояния и панель Claude Code), переходы - чистые функции
`state/editor-tabs.utils.ts`; вкладки переживают перезапуск. ⌘W вне панели Claude Code
закрывает вкладку файла (меню приложения, `editor:command`).
Редактор - Monaco по частям одним ленивым куском (`CodeEditor`, `monaco-setup.ts`): один
редактор файла на окно и рядом разница (ADR 0020), оба живут, неактивный спрятан; модель
на открытый файл (`documents.ts`), выделение для Claude Code говорит тот, что на виду. Подсветка - те же
грамматики shiki, что у блоков кода в ленте (`lib/highlighter.ts`, построчно со стеком
правил), язык - по имени и расширению файла (`lib/syntax-languages.utils.ts`, .env и
tsconfig - тоже). Комментарии, скобки и отступы - готовые конфигурации языков Monaco.
Тема собирается из ролей `--color-*` при старте редактора (`monaco-theme.ts`).
Прокрутка файла - миникарта 80 px вместо вертикальной полосы, код в ней блоками
([ADR 0062](adr/0062-minimap-scrollbar.md)); у разницы полосы прежние. ⌘ + наведение делает
переменную или импорт ссылкой, ⌘ + клик (и ⌘B, F12) ведёт к определению: в том же файле - к
имени, в другом - вкладкой ([ADR 0061](adr/0061-go-to-definition.md)). Ищет главный процесс
(`main/definitions/`, канал `editor:definition`): компилятор TypeScript в своём служебном
процессе, который поднимается первым вопросом и завершается после пяти минут простоя.
Кнопка Memory Saver рядом с mute останавливает этот процесс вместе с компилятором
и кешами во всех проектах и окнах ([ADR 0098](adr/0098-memory-saver-editor-lifecycle.md)).
Режим читается до регистрации IPC, новые запросы блокируются у владельца процесса,
а остановка считается успешной только после exit. Переключения исполняются по
очереди, ошибки видны на кнопке; после сбоя остановки она повторяет тот же выбор, а не
меняет режим. Выключение возвращает запуск по запросу; настройки
редактора не меняются. Общий EditorWorker Monaco, подсветка, файловые наблюдатели,
Git, терминалы и агенты продолжают работать.
Файлы пишутся сами, как в WebStorm: через секунду после паузы в наборе, при уходе из
редактора и из окна, при закрытии вкладки и перед выходом из IDE (главный процесс ждёт
ответа окна, `editor:savedAll`, и идущих записей). Чтение и запись - `fs:readFile`,
`fs:writeFile` (`main/fs/text-file.ts`, `main/fs/text-write.ts`): запись безопасная
(временный файл и переименование) и идёт только поверх своей версии файла, иначе -
конфликт, и файл не трогается. Изменения на диске (Claude Code, терминал) приходят
событием `fs:changed` со списком файлов: файл без своих правок перечитывается сам,
удалённый закрывается, при своих правках над кодом встаёт вопрос «взять с диска /
оставить моё», и до ответа автосохранение молчит. Несохранённое с вопросом не теряется
молча: закрыть вкладку, проект, окно, выйти и обновиться - только после вопроса
(`state/discard-guard.store.ts`). Файл по ссылке за проект и файл вне проекта, открытый
ссылкой из ленты (ключ вкладки - абсолютный путь), пишутся только по ⌘S. Не
текст, нечитаемый и файл больше 20 МБ показываются словами вместо кода. Картинка (PNG, JPEG,
GIF, WebP, AVIF, BMP, ICO; SVG - кодом) открывается своим видом `ImageView` без Monaco
([ADR 0070](adr/0070-images-in-editor-tab.md)): вписана в место, масштаб кнопками, щипком и ⌘ +
колесом к точке под курсором, сведения о размере; читает её `fs:readImage`, как просмотр
Markdown, и перечитывает при правке на диске.

**Просмотр Markdown** ([ADR 0019](adr/0019-markdown-preview.md)). У файла Markdown в правом
верхнем углу - плавающая панель трёх видов, как в WebStorm (`MarkdownLayoutSwitch`): только
код, код и просмотр рядом (ручка делит ширину), только просмотр; вид -
`markdown-layout.store.ts`.
Просмотр (`MarkdownPreview`) берёт текст из модели редактора: marked в HTML с меткой
строки перед каждым блоком (`markdown-html.utils.ts`), HTML разбирается браузером в
отдельный документ без окна и собирается элементами React по списку тегов GitHub
(`markdown-dom.utils.ts`) - innerHTML нет. Картинки проекта читает главный процесс
(`fs:readImage`, `main/fs/image-file.ts`), с сайтов - тоже он и только по нажатию
человека (`preview:readWebImage`, `web-images.store.ts`): окно в сеть не ходит. Ссылки:
сайт - в браузер, `#раздел` - к заголовку, путь - общим действием «открыть файл» точным
путём, картинка - крупно. Код и просмотр прокручиваются вместе по меткам строк
(`markdown-scroll.hooks.ts`).

**Изменения и разница файла** ([ADR 0020](adr/0020-changes-view-and-diff.md)). Вид
Changes левой панели (`features/git/ChangesView`), как окно Commit в WebStorm: что
поменялось с последнего коммита - группы Changes (изменён, добавлен, удалён, переименован
в индексе, конфликт) и Unversioned Files (новые, каждый файл отдельно), имя цветом статуса
и буква справа. Список строит главный процесс (`main/git/git-changes-output.ts`) тем же
сервисом, что статусы дерева: после первого вопроса окна (`git:getChanges`) он
перечитывается вместе со статусом и приходит событием `git:changes`, если стал другим.
Тем же сервисом считается, сколько строк добавлено и удалено с последнего коммита
(`git:getLineStats`, событие `git:lineStats`): шапка показывает «+N −M» справа от ветки, и
нажатие открывает Changes, повторное - прячет, как иконка вида (`LineStats`). Файлы, которые знает git, считает `git diff HEAD --numstat`
(`main/git/git-line-stats.ts`), новые - главный процесс с диска, как git: двоичные и
крупнее 8 МБ строк не дают, неизменённые не перечитываются (`file-line-counter.ts`).
Нажатие по файлу открывает вкладку разницы - одну на проект, другой файл встаёт на её место
(`openDiffTab`); ключ такой вкладки - путь с нулевым символом впереди (`diffTabKey`,
`tabTarget`), наружу уходит только путь. Разница - редактор разницы Monaco
(`features/editor/DiffEditor`): слева файл из HEAD (`git:readHeadFile`, перечитывается
при изменениях в .git), справа - документ файла с автосохранением, у удалённого - пусто.
Две колонки или одна, свёрнутое неизменённое (`diff-view.store.ts`), F7 и Shift+F7 - по
правкам, стрелки - по файлам списка, F4 - сам файл на строке курсора, стрелка у правки
возвращает кусок из коммита и ставит курсор справа к нему (`diff-revert.ts`): ⌘Z отменяет
возврат, нажат он справа, слева или вне кода (список изменений, дерево - тогда отмена идёт в
файл середины, `editor-sync.hooks.ts`). История отмены переживает уход разницы к другому
файлу: модели файлов - со схемой file, их историю Monaco хранит и после закрытия. Новая пара
сторон показывается, когда Monaco её сравнил (`diff-reveal.ts`), - уже свёрнутой, без
мелькания целого файла.

**Дерево файлов** (зона 5). Папка читается при раскрытии, по одному уровню. Иконка
строки - `FileIcon` из дизайн-системы: набор Catppuccin в тонах нашей палитры, выбор по
имени, расширению и папке над файлом, как в VS Code
([ADR 0016](adr/0016-file-type-icons.md)). Имя красится статусом git, как в WebStorm:
изменён - синий, добавлен - зелёный, не в git - лососевый, игнорируется - бурый,
конфликт - красный; папка с изменениями внутри - синяя. Над деревом - шапка вида боковой
панели (`PageHeader size="sm"`): найти открытый файл и свернуть всё. Меню правой кнопки и
клавиши, как в WebStorm ([ADR 0043](adr/0043-file-tree-actions.md)): создать, вырезать,
копировать, вставить, полный путь, переименовать и перенести с правкой ссылок, в корзину.
Действия - `files:*` (`main/fs/file-ops*.ts`); ссылки ищет `main/fs/references/` по списку
файлов проекта и синонимам tsconfig. Перед переносом окно дописывает несохранённое
(`state/editor-documents.ts`) и переводит вкладки, раскрытое и буфер дерева на новые места.
За диском открытых проектов следит главный процесс (`main/fs/project-watcher.ts`,
fs.watch с recursive - FSEvents): пачкой говорит окну, какие папки перечитать и что
поменялся `.git` (`fs:changed` - дерево и ветка в шапке), и перечитывает статус git
(`main/git/git-status-service.ts`), рассылая его окну, если он стал другим
(`git:status`). Статус читается без записи в индекс (`GIT_OPTIONAL_LOCKS=0`), иначе
слежение будило бы само себя ([ADR 0017](adr/0017-disk-watch-and-git-status.md)).

**Локальная история** ([ADR 0045](adr/0045-local-history.md)), как Local History в
WebStorm: каждая правка файла открытого проекта хранится 30 дней. Ведёт её главный процесс
(`main/history/`): база `local-history/history.db` в профиле, ключ содержимого - ключ
объекта git, поэтому закоммиченное отдаёт git, а история хранит только новое. События -
из того же слежения за диском, причины - из объявлений пишущих: сохранение редактора
(`fs:writeFile`), правка ссылок при переносе из дерева, возврат версии, инструменты правки
агента в ленте разговора (`observeFeed`); точный дифф правки агента из потока CLI
(`claude/changes/agent-edits-tap.ts`) даёт «до», если снимок опоздал. Перенос, в том числе
`git mv` в терминале, ведёт историю за файлом; перенос из дерева и возврат версии идут
работами очереди истории проекта. Окно - вкладка истории в середине (`features/editor/LocalHistoryView`,
`history:*`): версии по дням, разница с файлом сейчас или изменение события, «Restore».

**Процессор и память IDE** - в строке состояния, все процессы вместе (главный, окно,
GPU, служебные), те же цифры, что в «Мониторинге системы». Меряет главный процесс
(`main/usage/`): процессор - Electron, память - физический след из macOS через koffi,
потому что RSS у Electron завышает её в разы. Окно спрашивает раз в секунду, пока его
видно; свёрнутое или закрытое другими окнами не спрашивает
([ADR 0008](adr/0008-resource-usage.md)).

**Панели провайдеров** (зона 7, [ADR 0083](adr/0083-provider-panels-shared-core.md)) - у
каждого провайдера своя иконка в полосе и своя панель: Claude Code, Codex, Antigravity, Kimi
Code, открытые модели. Общее только
в коде. Главный процесс: ядро `main/agents/` (разговор, очередь, лента, учёт ходов, команды
`!`, базовый сервис панели `AgentPanel`) и драйверы - `main/claude/` и `main/codex/` (Codex
через `codex app-server`, построчный JSON-RPC; модели, вход и лимиты - процессом-каталогом,
который гаснет после простоя). Обе панели поднимает `main/provider-panels.ts`, каналы
`agent:*` несут провайдера и находят панель в реестре. Что провайдер умеет (режимы, усилие,
форк, откат, вход, поиск) - `shared/panel-capabilities.ts`; окно (`features/agent-panel`,
обёртки `ClaudeCodePanel` и `CodexPanel`) показывает только объявленное. Интерфейсное
состояние у каждой панели своё (стор панели на провайдера), слова - тоже: имя провайдера
подставляется в общие строки, свои строки Codex - `locales/en.codex.json` поверх общих.
Список провайдеров - один (`PROVIDER_IDS`, порядок иконок), всё, что от него зависит, -
таблицы `Record<ProviderId, ...>` (ADR 0093). Каждой сессии модели, панельной и без вкладки,
IDE называет пояс человека и просит писать время в нём, UTC - только по делу
(`agents/conversation/local-time-briefing.ts`, [ADR 0132](adr/0132-person-local-time-for-models.md)):
сессии без вкладки получают строку обёрткой исполнителей в `runProviders`, панели - каждая своим
способом передать указания.

**Агенты ACP** (Google Antigravity и Kimi Code, [ADR 0092](adr/0092-acp-providers-antigravity-kimi.md)) -
одно ядро клиента ACP в `main/acp/`: процесс агента и JSON-RPC 2.0 (`client/`), лента из
`session/update` (`feed/`, вид вызова по `kind` ACP), разговор и вопросы (`conversation/`:
разрешения, план, формы `elicitation/create`, модели и режимы через
`session/set_config_option`), процесс-каталог для истории и повтора старых разговоров
(`catalog/`), вход силами CLI агента (`acp-account.ts`, `acp-sign-in.ts`) и сервис панели
`AcpPanel`. Своё агента - описание `AcpAgent` в `main/antigravity/` и `main/kimi/`: поиск CLI,
своя папка IDE (`--gemini-dir`, `KIMI_CODE_HOME`), режимы, линза вызовов (артефакты
Antigravity, коннекторы, вопросы). Записи живого протокола - `main/acp/__fixtures__/`.
Чего ACP у агента не даёт, драйвер берёт сам ([ADR 0136](adr/0136-kimi-past-acp-failure-usage-title.md)):
у Kimi сбой хода - из журнала сессии (`turnFailure`), лимиты подписки (`usage`, кольца под полем
через `acp-usage.ts`) и имя разговора (`title`, `conversation/acp-title.ts`) - с его сервера его
же токеном, только на чтение. Antigravity работает только в своём чате: работа без человека - по правилу провайдера
(`worksUnattended`, [ADR 0094](adr/0094-background-work-per-provider.md)).

**Claude Code** (зона 7, [ADR 0009](adr/0009-claude-code-gui.md)) - своя реализация, а
не панель amazing-claude-code. Главный процесс (`main/claude/`) находит CLI в PATH
терминала человека (macOS не даёт приложению из Finder его PATH; на Windows - PATH из реестра,
папки установщиков и `claude.exe` за обёрткой npm, [ADR 0125](adr/0125-windows-cli-search.md)),
запускает `claude -p` в режиме потока JSON по процессу на разговор и собирает поток в ленту: реплики,
размышления, вызовы с результатами, итоги ходов. Вопросы CLI (разрешение, выбор,
план) приходят управляющими запросами и ждут ответа человека без таймеров. Модель,
усилие и режим меняются живому процессу, без перезапуска. Процесс поднимается на первое
сообщение и гасится после получаса простоя; разговор продолжается с `--resume`.
Папкам проектов IDE доверяет всегда: вопроса о доверии нет, CLI сразу читает настройки,
хуки и CLAUDE.md проекта ([ADR 0126](adr/0126-always-trust-project-folders.md)).
Сообщение, которое не смогло уйти, ждёт в очереди и уходит само. Выход из IDE ждёт,
пока процессы CLI закроются.

В поле ввода - картинки (вставка, перетаскивание, выбор; уменьшаются до 1568 по
длинной стороне), упоминания файлов по `@` (тот же нечёткий поиск, что в «Поиске
везде», `lib/file-match.utils.ts`; файл раскрывает сам CLI) и команды `!` - их
выполняет панель в папке проекта, а вывод уходит модели перед следующим сообщением
метками `<bash-input>`/`<bash-stdout>`. Своё сообщение можно откатить (разговор, код
или оба - служебные запросы CLI `rewind_conversation` и `rewind_files`) или форкнуть
(`--fork-session --resume-session-at`); форк, который ещё не родился, показывает
историю источника и шов. Под итогом хода - изменённые файлы: откат и возврат по
копиям, которые CLI сделал для сообщения, начавшего ход, и только если файл с конца
хода не трогали. Экраны настроек панели (кнопка в шапке): плагины (`claude plugin`,
живые процессы перечитывают их сами) и аккаунты - отдельные
хранилища входа CLI (`CLAUDE_SECURESTORAGE_CONFIG_DIR`), вход через Терминал,
аккаунты amazing-claude-code подхватываются без повторного входа. MCP у Claude в IDE -
только коннекторы IDE (`--strict-mcp-config`, ADR 0029): их настраивают на виде Connectors в
середине окна (своя иконка полосы видов, строки в меню панели нет). CLI экранов идёт в
папке проекта, ключи из адресов и аргументов в окно не
уходят, каждое действие отвечает и списком после себя. Лимиты подписки (пять часов,
неделя, неделя модели, доплата) - на карточке каждого аккаунта и кольцами в ряд под полем
ввода: `main/claude/usage/`, ответ CLI на `get_usage` у живого разговора после хода,
иначе своим процессом CLI в постоянной папке конфига аккаунта. Рядом с кольцами - «tok»,
токены за сегодня по всем проектам машины (`usage/today-tokens.ts`): из транскриптов CLI
вместе с субагентами, изменённых с полуночи, с дочитыванием только нового; на диске он ничего
не хранит. Любое кольцо и токены можно спрятать (Settings → Usage meters, `hiddenMeters` в
настройках панели: хранится спрятанное, новое окно лимита видно сразу). За индикатором модели,
усилия и режима - до трёх кнопок пресетов (Settings → Quick presets, `presets` и `presetCount`
в настройках панели, возможность `presets` у Claude Code, Codex, Kimi и Antigravity): кнопка
ставит свои модель, усилие и режим, горит по модели и усилию разговора (`presets.utils.ts`,
[ADR 0096](adr/0096-setup-presets-under-composer.md)); те же кнопки телефон показывает в новом
разговоре. Статистики в панели нет - она своя у IDE, видом середины окна (ниже и
[ADR 0042](adr/0042-statistics-ide-level.md)).
Поиск по разговорам - `main/claude/search/` (своё подключение в `main/index.ts`, каналы
`claudeSearch:*`): индекс слов человека и модели по проекту в памяти и копией в userData
(`claude-search/`), транскрипты дочитываются с места остановки, свой BM25; резка слов -
одна на обе стороны (`shared/claude-search-words.ts`). Вопрос модели - отдельный
`claude -p` над разговорами текстом. В окне - `SearchWindow` поверх панели, капсула и
подсветка в ленте (`SearchCapsule`, `search-feed.hooks.ts`).
Сценариев в панели нет - они свои у IDE, видом середины окна (ниже и
[ADR 0039](adr/0039-scenario-queues-ide-level.md)).
Вкладки разговоров привязаны к папке проекта и хранятся в `claude.json`; прошлые
разговоры и их ленты читаются из транскриптов CLI (`~/.claude/projects`). Окно
(`features/agent-panel`) держит состояние и ленты в кэше React Query: изменения ленты
приходят пачками событием `agent:feed`, по id элементов. Разметка ответа - лексер
`marked` и свой рендер без `innerHTML`, подсветка кода - shiki с ролями
`--color-syntax-*`, плавное появление текста - `smooth-stream-text`. Поверх marked -
свои расширения (`markdown-lexer.ts`): заборы кода по правилу ACC (закрывает только
голый забор той же длины, так блок держит блок) и формулы `$…$`, `$$…$$`, `\(…\)`,
`\[…\]` со строгими границами; KaTeX и его стили грузятся при первой формуле
(`formulas.ts`).
Пути в тексте ленты - ссылки (`paths.utils.ts`, `PathLink`, `LinkedText`): узкое правило
формы плюс список файлов проекта, с `строка:колонка` и диапазонами. Куда ведёт путь,
решает главный процесс (`fs:locatePath`, `main/fs/path-locator.ts`): файл проекта
выбирается с местом (`selection.store`), папка показывается в дереве, голое имя
ищется по файлам проекта (несколько - выбор). Текст вне проекта открывается вкладкой
редактора по абсолютному пути (ADR 0027): чтение и запись - те же `fs:readFile` и
`fs:writeFile` с `absolutePath`, пишется только по ⌘S, за диском следит
`main/fs/outside-watchers.ts` (`fs:watchOutside`, правки - тем же `fs:changed`). Картинка
вне проекта - такой же вкладкой (`fs:readImage` с `absolutePath`, ADR 0070). Папка и остальное
вне проекта (PDF, архив, картинка больше 20 МБ) - системой (`fs:openOutside`; исполняемое
только показывается в Finder), сетевые пути - нет.

**Коннекторы к приложениям** ([ADR 0028](adr/0028-connectors-gateway.md),
[ADR 0029](adr/0029-claude-connectors-only.md)) - Gmail, Google Calendar, Notion, Slack, Jira &
Confluence и Todoist ([ADR 0036](adr/0036-atlassian-and-todoist.md)), Playwright
([ADR 0035](adr/0035-playwright-built-in.md)), любой
MCP-сервер по адресу или командой, перенос серверов из Claude Code и коннектор от ИИ; их

([ADR 0050](adr/0050-ai-connector-jobs.md)) - разговор с ИИ в очереди на виде: очередь -
`main/connectors/ai/` (работы на диске, `connectors-ai-jobs.json`), разговор ведёт провайдер
(`main/claude/connector-chat/`, поток JSON в обе стороны и ответ по схеме), ИИ предлагает
перенести сервер человека из Claude Code, официальный MCP по адресу или описание REST API
(`kinds/http/`, описание проверяет схема, исполняет шлюз). Готовое без ключа и без чужого
адреса IDE добавляет сама (`ai/ai-adopt.ts`, [ADR 0086](adr/0086-ai-connector-adds-itself.md)),
с ключом - ждёт человека. У каждого
коннектора доступность по проектам: каждый процесс разговора получает свой файл
`--mcp-config` со своим ключом (`gateway/launches.ts`), и по ключу шлюз знает проект и сам
процесс - выключенному в проекте коннектору он отказывает. MCP-команда запускается своей
копией на каждый процесс разговора, как в Claude Code. Главный процесс (`main/connectors/`) хранит реестр
(`connectors.json`, права 600, ключей в нём нет) и секреты (`connectors-vault.bin`,
`safeStorage`), сам ведёт вход в браузере (возврат на `localhost:5319`) и поднимает локальный
MCP-шлюз на `127.0.0.1` с портом от системы: каждый коннектор - сервер `/mcp/<тип-подпись>`. Gmail и Calendar -
свои инструменты поверх API Google (`kinds/google/`), Notion, Slack и свой адрес - прокси к их
MCP через SDK (`kinds/remote-mcp.ts`). Процессы разговоров получают серверы файлом
`--mcp-config` (`claude/connectors-bridge.ts`): новый или удалённый коннектор - перезапуск
свободных процессов, вход, выключенный инструмент или новое описание - `mcp_reconnect`.
Codex получает те же серверы флагами `-c` (`codex/conversation/codex-connectors.ts`), а
одобрение вызова спрашивает формой MCP - карточкой разрешения у строки вызова
(`codex-mcp-approval.ts`, [ADR 0131](adr/0131-codex-mcp-tool-approval.md)); что без вопроса,
решает один набор шлюза (`GatewayLaunch.allowed`) для обоих.
Описание коннектора пишет человек для себя и для модели: шлюз отдаёт его в пояснении сервера
(`instructions`) вместе с тем, чей это коннектор и что запрещено. Ступени доступа -

виде. Окно - вид Connectors в середине окна (`features/connectors/ConnectorsView`, четвёртая иконка

очередь работ ИИ (окно работы - `features/connectors/AiJobModal`: лента, предложение, поле), под ними каталог
нового двумя группами - приложения (и свои типы «несколько раз», [ADR 0034](adr/0034-custom-connector-types.md))
и свои способы добавить, подробности коннектора (свой тип, описание,
вход, проекты - все или отмеченные, [ADR 0033](adr/0033-all-projects-no-exceptions.md),
инструменты) и формы - окном по центру (`Modal`); событие
`connectors:state`, лента работы ИИ - `connectors:aiJobPatch`. Клиент Google настраивает в браузере приложение ИИ: меню «Set up with AI»
открывает новый разговор в Claude или Codex с промптом в поле ввода
(`connectors/agent-apps.ts`, [ADR 0031](adr/0031-google-client-own-domain.md)).

по `finish`, Stop, закрытой вкладке разговора), `TabControl` (отладчик, рамка, конец сессии,

команд CDP: снимок из дерева доступности со ссылками `e12` (`ax-snapshot.ts`), с документами
iframe под их строкой и ссылками `f2e7` (`page-frames.ts`: фреймы других процессов - своими
сессиями, их расширение подключает само), клики и ввод `Input.*` (точка во фрейме другого
процесса - со сдвигом его iframe, `page-nodes.ts`) рукой человека: путь мыши, удержание
кнопки, набор по клавише, колесо толчками ([ADR 0044](adr/0044-human-hand-in-browser.md),
`human-motion.ts`, `page-pointer.ts`), курсор агента тем же путём и рамка в странице; курсор
остаётся на месте и после перехода страницы. Клик (`page-click.ts`) прямо перед каждым
нажатием спрашивает, что под мышью (`page-hit.ts`: `DOM.getNodeForLocation` в координатах
документа со спуском во фреймы других процессов, роль и имя - `getPartialAXTree`): по `ref` -
только сам элемент или его потомок, иначе один повторный подход и отказ; по `x,y` в кнопку,
ссылку, пункт меню или поле - только с `expect`; ответ называет нажатое (`clicked`,
[ADR 0119](adr/0119-click-checks-target-at-press.md), правила - `click-check.ts`). Список, дата и цвет - тоже рукой, а `evaluate` -
только для чтения: пояснение сервера говорит модели, что человек смотрит на курсор, а скрипт,
который сам нажал или ввёл, получает замечание ([ADR 0049](adr/0049-browser-acts-only-by-hand.md),
`page-scripted.ts`). К элементу ниже экрана страница едет колесом под мышью, а не прыгает
([ADR 0051](adr/0051-scroll-to-element-by-wheel.md), `page-reveal.ts`). Перевод строки в наборе -
Shift+Enter, многострочный текст с `submit` - отказ, а `type` в редактор отвечает текстом поля по
строкам и его картинкой: сообщение людям модель сверяет до Enter
([ADR 0095](adr/0095-line-breaks-shift-enter-check-before-send.md), `page-typing.ts`,
`field-read.ts`). Инструменты - `connectors/kinds/browser/`, мост
ставит и убирает `BrowserRuntime` вместе с коннектором (манифесты host во все браузеры
семейства Chromium, копия расширения в видимой `~/Agentic Workstation/Chrome Extension` для
«Load unpacked»). Протокол, имена host, id расширения и ссылка на вкладку - пакет
`packages/browser-protocol`. На виде Connectors у Browser - шаги установки и профили Chrome на
связи (`connectors:state`).

**Computer Use** ([ADR 0057](adr/0057-computer-use.md), [0058](adr/0058-computer-use-windows.md)) -
встроенный коннектор (сервер `computer`, мак и Windows): ИИ работает на компьютере настоящими
мышью и клавиатурой по снимкам экрана - другие приложения и то, куда Chrome не пускает расширение.
Снимки - `desktopCapturer`, ввод через koffi: на маке CoreGraphics (`main/computer/cg-events.ts`),
на Windows SendInput и SetCursorPos (`win-input.ts`, перед действием - отказ у окна
администратора); раскладка клавиш - по системе; координаты модели - пиксели её последнего
снимка (`computer-geometry.ts`). Текст на Windows вставляется через буфер обмена
(`win-clipboard.ts`): буфер человека запоминается со всеми форматами и возвращается, текст
кладётся отложенно - окно IDE отдаёт его, когда приложение просит, и так узнаёт, что вставка
принята; не принята - знаками. Перевод строки - Shift+Return и между вставками, голого Return
внутри текста нет ([ADR 0095](adr/0095-line-breaks-shift-enter-check-before-send.md)). Рука
(`computer-hand.ts`) ведёт курсор путём руки браузера
(ADR 0044), модификаторы жмёт своими клавишами и всегда отпускает, а курсор не на своём месте -
мышь взял человек, действие обрывается. Перед каждым нажатием рука спрашивает, что под точкой
(`InputDriver.elementAt`: системный поиск доступности macOS - `ax-element.ts`, UI Automation на
Windows - `uia-element.ts`, `uia-native.ts`; разбор - `screen-element.ts`): кнопка, пункт меню,
ссылка или поле - только с `expect`, не совпало - отказ со свежим снимком, ответ называет
нажатое ([ADR 0119](adr/0119-click-checks-target-at-press.md)). Ещё раньше, до движения мыши, агент сверяет экран со
снимком модели ([ADR 0129](adr/0129-computer-use-looks-before-it-acts.md), `computer-seen.ts`): снимка нет, после него
была пауза или перерыв, человек трогал мышь или клавиатуру, окна в точке действия (у клавиш - перед
клавиатурой) поменялись - действие не идёт, ответ - свежий снимок. Окна и время ввода даёт свидетель
экрана (`screen-scene.ts`; `cg-scene.ts` - оконный сервер мака, `win-scene.ts` - `EnumWindows` и
`GetLastInputInfo`). Работа разговора, бравшего компьютер, встала, а человек после последнего снимка
ИИ не трогал ввод - IDE выходит вперёд с его чатом: проект, вкладка, панель провайдера
([ADR 0130](adr/0130-return-to-chat-after-computer-use.md), `computer-chats.ts`, `return-to-chat.ts`,
`window/raise-window.ts`, событие `computer:returned`). Стол (`computer-desk.ts`) - один разговор за раз, вызовы
по одному, пауза и остановка; работа разговора встала - компьютер свободен сразу
([ADR 0065](adr/0065-agent-marks-only-while-working.md)). Пока разговор держит компьютер, внизу по центру экрана капсула -
окно-панель без фокуса поверх всех, закрытое от захвата экрана (`computer-capsule.ts`, страница
`capsule.html` и `features/computer`, каналы `computer:*`); накладные окна не получают событий
окна IDE (`window/overlay-windows.ts`), общее у них - `overlay-window.ts`. Пока ИИ держит мышь,
системная стрелка спрятана, а вместо неё стрелка ИИ стального синего - маленькое окно, которое
едет за рукой (`computer-pointer.ts`, `computer-pointer-window.ts`, страница `pointer.html`;
[ADR 0079](adr/0079-computer-use-pointer.md)); двинул мышь человек - сразу его стрелка. На виде Connectors - разрешения macOS «Универсальный
доступ» и «Запись экрана», главный процесс перечитывает их при возврате в IDE.

**Сама IDE для ИИ** ([ADR 0090](adr/0090-ide-controls-itself-mcp.md)) - встроенный коннектор
`workstation` (плитка «Agentic Workstation»): разговор управляет IDE без мыши. Инструменты -

снаружи (`connectors/outside/`) - второй шлюз с одним этим сервером на постоянном порту 127.0.0.1
(собранная IDE 4461, dev 4462), с ключом из хранилища; включается в окне коннектора, там же
копируется настройка для Claude Code, Codex, Antigravity CLI, Kimi Code или любого клиента MCP.

**Трекер задач** ([ADR 0101](adr/0101-task-tracker.md)) - вид середины окна `features/tracker`,
главный процесс - `main/tracker/`. У каждого проекта IDE своя доска: проекты трекера вкладками
(перетаскиваются общим `lib/tab-drag.hooks.ts`, правой кнопкой - переименовать, сдвинуть, в

это помнит `tracker.store.ts`), в потоке группы колонками, в группе задачи сверху вниз, у задачи
продолжения справа, в её ряду и от её верха: продолжение всегда на уровне своей задачи,
высокая карточка раздвигает свой ряд ([ADR 0120](adr/0120-tracker-follow-ups-in-task-row.md)).
Карточка - заголовок, подзаголовок, описание, срок (дата и, если нужно, время) с повтором,
приоритет P1-P4, отметка «сделано» (гаснет на месте) и сценарий с полями (`{{card}}` и другие
подстановки раскрываются при отправке). Перетаскивание доски - свой хук

(`tracker-rank.ts`) и отметкой часов у каждого поля (`tracker-clock.ts`, слияние -
`tracker-records.ts`); книга - `userData/tracker.json` (`tracker-book.ts`); правки -
`TrackerOp` (`tracker-ops.ts`, карточки - `tracker-card-ops.ts`), доска - `tracker-view.ts`.
Пространство - доска проекта на всех машинах: на этой машине привязка «путь → пространство»,
новое узнаётся по origin в git, дому или имени папки, двойники после первой встречи сливаются
(`tracker-spaces.ts`). Группа или карточка уходит в очередь сценариев (`tracker-runs.ts`):
всё проверяется до первого запуска, ставится по порядку доски, новая очередь - с именем группы;
карточка без сценария встаёт пометкой (`placeholder`), мимо которой очередь проходит
([ADR 0105](adr/0105-queue-placeholders-for-plain-cards.md)); элемент сделан - карточка
отмечается выполненной один раз (полем `doneByRun`). Карточка, чей сценарий стоит в очереди, идёт
или её выполнил, закрыта на правку, кроме описания и «сделано» (`TrackerCard.lock`, отказ
`locked` в `tracker-guards.ts`, [ADR 0110](adr/0110-tracker-card-locked-while-scenario-works.md)).
Повтор, как в Todoist
([ADR 0103](adr/0103-tracker-repeat-and-auto-run.md)): поле `repeat`, счёт -

**Облако IDE** ([ADR 0102](adr/0102-cloud-e2e-sync.md)) - сервер `apps/cloud`
(agentic-workstation-cloud.mzpizote.com), протокол `packages/cloud-protocol`, в IDE -
`main/cloud/`. Доска синхронизируется записями, зашифрованными ключом аккаунта: сервер хранит
id, версию и шифр и ничего не читает. Ключ аккаунта создаётся сам при первом запуске и лежит в
`cloud.vault` (safeStorage); из него выводятся ключ подписи Ed25519 (личность на сервере) и ключ
AES-256-GCM (шифр записей, id - в доп. данных). Окно ключа не видит: «Show account key» показывает его
системным окном главного процесса (`cloud-dialogs.ts`, «Copy» - в буфер на минуту), «Use another
key» подключает второй компьютер после «да» в системном окне; пропавший ключ - `keyLost`, а не
новый аккаунт. Встречные правки двух машин сводятся после забора (`tracker-heal.ts`,
`mergeTwinSpaces`). Синхронизация
(`cloud-sync.ts`): забрать новое, записать своё (принимается только на ту версию, что на
сервере; иначе - забрать, слить по полю, записать снова), ждать перемен долгим забором; своя
правка прерывает ожидание. Значок облака - в шапке трекера.

**Календарь звонков** ([ADR 0114](adr/0114-call-calendar.md)) - вид середины окна
`features/calendar`, главный процесс - `main/calendar/`, общий на IDE, не проектный. Источники
задаёт человек: Google Calendar (вход коннектора, `connectors/calendar-access.ts`, без модели), ICS-

источники параллельно и сам (15 минут, открытие вида, пробуждение), ИИ-источники - по кнопке,
строго по одному. Чтение ИИ - разовый прогон провайдера со схемой ответа и допуском шлюза
(`GatewayHost.openGranted`, `LaunchGrant`): один коннектор, инструменты поимённо, профиль Chrome и
сайт закреплены (`profile-pick`, `pinnedSiteAllows`); с галочкой кликов ИИ открывает каждую

и дубли - `shared/calendar-overlaps.ts` на оба процесса; новые накладки впереди - карточкой в

панели вида (панель во всю высоту, ширину тянут ручкой), «видел» (`seen` в `calendar.json`) гасит

звонке и утренний синк ИИ-источников; их ведут часы календаря `calendar-clock.ts` (раз в полминуты:
`calendar-reminders.ts`, `calendar-morning.ts`; кнопка `syncCalendar` в карточке). Виды сетки - день,
неделя (`WeekGrid`) и месяц (`MonthGrid`).

**Сценарии** ([ADR 0039](adr/0039-scenario-queues-ide-level.md)) - вид середины окна
`features/scenarios`, главный процесс - `main/scenarios/`. Сценарий - JSON формата ACC на полках
проекта (`.claude/scenarios`) и личной (`~/.claude/scenarios`). Запуск ставит сценарий в очередь:
новую (в папке проекта или в своём git worktree - `main/git/git-worktree*.ts`, вне проекта, ветка
`scenarios/<slug>`; локальные файлы Claude Code и пути из `.worktreelink` в нём - ссылками на проект,
ADR 0066) или существующую. Очередей сколько угодно; очереди в своих worktree идут параллельно, а
очереди без worktree одного проекта делят его папку и работают в ней по одной
([ADR 0128](adr/0128-queues-wait-for-project-folder.md)): папку держит та, чья работа в ней идёт
(или стоит недоделанной), остальные ждут своей очереди в порядке прихода (`turn` у очереди, снимок
занятых папок `folders` в `scenarios:queues`, правила `queues/queue-folder.ts`, отпустил папку -
шаг ждущим в `QueueRunner`); «запустить рядом сразу» - только выбор человека. Внутри очереди - по
одному сценарию, и следующий стартует только после сделанного: упавший или остановленный держит
очередь, а Resume продолжает его прогон с места ([ADR 0082](adr/0082-queue-goes-on-only-after-done.md));
последний несделанный, за которым никто не ждёт (оборван перезапуском IDE, остановлен), продолжается
кнопкой на своей строке - правило `carryOnItemOf` в `shared/scenario-queues.ts` одно с `reopenItem`;
решения очереди - чистые правила `queues/queue-rules.ts` (остановка после текущего или выбранного,
несделанный элемент, отказ старта, перезапуск IDE посреди прогона),
исполнение - `QueueRunner`, хранение - `QueueBook` (`scenario-queues.json`). Рабочие часы очереди
([ADR 0074](adr/0074-queue-working-hours.md)): вне окна она спит - идущий прогон на паузе,
следующий не стартует, - в начале окна просыпается сама (правила `queues/queue-nap.ts`,
исполнитель `QueueHoursKeeper` внутри шага очереди, окно - `shared/queue-hours.ts`). Очереди идут
новыми сверху, а открытая очередь без дела две недели закрывается сама: дело - любая запись в книгу,
кроме тихих (сон по часам, место у папки, имя от ИИ), идущий прогон и ожидание папки держат её
открытой
([ADR 0115](adr/0115-idle-queues-close-themselves.md)). Элемент помнит, на чём идёт (`runsOn`:
модель и усилие головы и карточек, как их поднимет провайдер, - `scenarios/runs-on.ts`, тот же
расчёт у движка): ждущий - по сценарию на полке, стартовавший - по снимку прогона
(`queue-runs-on.ts`); строка очереди показывает это чипами. Имя очереди даёт
дешёвая модель провайдера, человек может переименовать. Прогон ведёт движок с «головой» из ACC
(`engine/`) через провайдера (`main/providers/`: `ScenarioProvider`, сейчас Claude Code -
процессы `claude -p` с коннекторами IDE по исходному проекту). Что окно знает о провайдерах -
`providers:list` (имя, на месте ли, модели: у Claude Code - каталог аккаунта и свои модели
человека), перемены - событием `providers:changed` (`providers/provider-registry.ts`); редактор
сценария берёт модели оттуда, а не из панели Claude. Расписание поднимает новую очередь. Окно: вкладки Queues (очереди только этого проекта полосами, ADR 0072; открывается первой),
Schedule, History, Library (полки, редактор, написание с ИИ); прогон - окно по центру с таймлайном, вопросом человеку и журналом шага
лентой провайдера (`state/conversation-log.context.ts`); число ждущих человека - на иконке вида.
Сессии сценариев скрыты из истории и поиска панели; разговор головы можно продолжить чатом.

**Задания по расписанию** ([ADR 0069](adr/0069-scheduled-tasks-and-inbox.md)) - вид середины окна
`features/tasks`, главный процесс - `main/tasks/`. Задание - промпт, папка проекта, ритм (вручную,
разово, каждый час, день, дни недели, раз в месяц - день больше длины месяца значит последний),
модель и режим разрешений; хранится в `userData/tasks.json` вместе с прогонами (по 30 на задание).
Часы - `shared/task-clock.ts` (одни для главного процесса и окна: форма говорит «Next run»), тик -
20 с и сразу после пробуждения машины (`powerMonitor`), у всех заданий IDE, а не только у открытых
проектов. Срок, проспанный дольше 5 минут, наверстывается одним прогоном (`catchUp`) или
отмечается пропуском. Ближайший срок повторяющегося задания человек может пропустить кнопкой в
строке (`skipAt`, `task-due.ts`): часы доходят до него, пишут пропуск «You skipped this run» и
берут следующий; правка ритма или выключение пропуск снимают. Прогон - свой разговор CLI без вкладки: `ScenarioSession` поверх
`providers/claude/claude-sessions.ts` (общий с сценариями подъём процесса: аккаунт панели,
коннекторы проекта), брифинг говорит модели, что за столом никого и куда звать
(`task-briefing.ts`); идущие прогоны, потолок 3 часа работы без ожидания человека - `task-desk.ts`,
`task-run.ts`. Разговоры прогонов скрыты из истории и поиска панели (`setHiddenConversations`
теперь держит несколько источников), «Open in chat» открывает законченный прогон вкладкой. Окно:
задания и прогоны только открытого проекта - задание принадлежит проекту, как очередь (ADR
0080); правка - `TaskModal` (новое встаёт в открытый проект; при правке поле Project переносит
задание в другой известный IDE проект, пока ни один его прогон не идёт и поручение не спит, а
прошлые прогоны остаются там, где шли, - ADR 0081), прогон -
`TaskRunModal` (отчёт,
лента разговора через `conversation-log.context`, вопрос - карточкой уведомления через
`state/inbox-card.context.ts`, «сказать заданию»); открытый прогон - `state/task-run.store.ts`.
Идущий прогон - знак работы на вкладке проекта (`project-work.ts`, ADR 0071); если в проекте
идут только сценарии и задания, а чат молчит, знак - кольцо из шагов (`Spinner variant="steps"`).
Новое задание начинается с вкладки «With AI»: человек говорит своими словами, ИИ пишет вид, имя,
текст прогона, ритм и пределы поручения и открывает форму - сохраняет человек
(`tasks:author`, `main/tasks/task-author*.ts`, на Claude - `providers/claude/claude-task-author.ts`).
Один разовый `claude -p` по схеме, без инструментов и чтения проекта, модель новой вкладки не ниже
Sonnet; ему названы проект, включённые в нём коннекторы и сейчас. Модель, усилие и разрешения ИИ
не выбирает, отправку людям без кнопки (free) поручению - тоже.

**Поручения «до результата»** ([ADR 0080](adr/0080-goals-until-done.md)) - второй вид задания
(`Task.kind: goal`), главный процесс - `main/goals/`, связка с заданиями - `tasks/task-goals.ts`.
Одна жизнь вместо прогона на срок: модель работает выбранной моделью и усилием, а когда остаётся

**Уведомления** ([ADR 0069](adr/0069-scheduled-tasks-and-inbox.md)) - вид середины окна
`features/inbox`, главный процесс - `main/inbox/`, лента в `userData/inbox.json`. Приходят: вопросы,

notify, list_notifications, cancel_notification): он заводится на загрузке реестра
(`ensureBuiltIns`), в каталоге его нет, удалить нельзя, а шлюз отдаёт CLI правило «разрешено без
вопроса» (`McpLaunch.allowed` → `--allowedTools`). Кнопки: ответ (reply - слова в разговор,
приславший уведомление: прогон продолжается `--resume`, вкладка панели - сообщением), открыть
(адрес или файл через `openOutside`), закрыть, разрешить, план, ответ на вопросы, показать прогон,

окна (`InboxToasts` в `NotificationArea`: от кого - строкой над заголовком, суть - первыми строками
тела; у вопроса с одним ответом - его варианты; значок у крестика ведёт на вид уведомлений, а если
ответить в углу нечем - кнопка в ряду; крестик только убирает её из угла, «Got it» у правого края
закрывает уведомление прочитанным, у ждущих ответа его нет), звуком из
Settings → Sounds (`state/inbox.utils.ts`) и баннером ОС, когда окно не в фокусе (нажатие ведёт к
уведомлению, `inbox:reveal`). «Remind me» - напоминание себе без ИИ. На виде карточки свёрнуты до
шапки (`Card collapse`, у свёрнутой в шапке и тема), кроме ждущих ответа - те раскрыты
(`expandedByDefault`); выбор человека помнит `inbox.store` до выхода из IDE, переход из баннера или
карточки в углу раскрывает своё уведомление.

на ценах API (`pricing.ts`), имена и семьи моделей - `shared/claude-models.ts`, общий с панелью
Claude Code.

Период - вкладки «день, 7 и 30 дней, всё время» и последний день периода в фильтрах вида
(`statistics.store.ts`, null - сегодня): стрелки листают на длину периода, дата открывает
`DatePicker`. Сутки и неделя - по часам, длиннее - по дням (`HOURLY_PERIOD_MAX_MS`); столбцы во
всю ширину шага, у недели - линии суток и полосы выходных ([ADR 0063](adr/0063-statistics-bars-and-date-paging.md)).
График времени - стопкой: снизу присутствие, сверху агенты вне минут присутствия, по шагам из
отрезков `agentTime` ([ADR 0075](adr/0075-time-chart-presence-below.md)).

**Remote Control** ([ADR 0041](adr/0041-remote-control-ide-level.md)) - телефон смотрит и ведёт
IDE через свой релей. Три части: протокол `packages/remote-protocol` (общий для IDE и телефона:
конверт релея, метки шифрования `aw/v1`, адрес пары, сообщения v1, белый список команд, правила
ленты, право на адрес), релей `apps/relay` (Node и ws, адрес занимает только тот, кто подписал
вызов релея ключом, из которого адрес выведен; маршрут по адресу из 42-байтного заголовка, тела
не читает, короткий ящик для отсутствующего, `/healthz`, `/v1/info`, `/privacy`, статика
телефонного клиента) и главный процесс `main/remote/`. В нём провод и шифрование (`wire/`: P-256, HKDF,
AES-GCM, окно повторов), линия до релея с отступом и сердцебиением кадром себе (`link/`), ключи
через `safeStorage` (`store/`, `remote.json`), пара по одноразовому QR, рукопожатия и пределы
частоты при получении (`agent/`) и мост к IDE (`bridge/`): инвентарь (проекты ключом - хешем пути,
разговоры провайдеров, очереди коротко), подписки (лента - снимок и заплатки с номером в журнале
разговора, состояние разговора, прогон, очереди; спящему телефону - ничего, проснувшись, он
догоняет) и команды через публичные методы `ClaudeService` и его панели, `ScenarioService`,
поиска по разговорам, аккаунтов и коннекторов (узкие порты `bridge-ports.ts`; по областям -
`conversation-commands.ts`, `conversation-tools.ts`, `scenario-commands.ts`, `shelf-commands.ts`,
`machine-commands.ts`; очередь на телефон с отменой при отзыве, итог по id без повторного
выполнения). Режим разговора телефон меняет на любой, что даёт меню MODE окна, а погашенное окном
гасится и у него тем же правилом `modeAvailability` (`bridge/mode-gate.ts`,
[ADR 0076](adr/0076-phone-permission-modes.md)). Папки машины в тексте для
телефона - метки `{project}`, `{worktree}`, `~` (`bridge/redact.ts`). Снимок ленты, страница выше
и журнал шага меряются строками, которые рисует телефон: шаг субагента, чей вызов есть в ленте
IDE, элементом не едет - только числом шагов на строке вызова (`bridge/feed-window.ts`), а живая
заплатка несёт новый шаг новым числом по памяти «чей шаг какой» (`bridge/feed-steps.ts`); иначе
долгий субагент вытеснял бы из окна сами строки. Пуши телефону не на связи
(`push/`): поводы из состояния IDE и звонков разговора (`attention.ts`), когда и кого будить,
пауза в минуту на повод (`push-desk.ts`); уведомление запечатано ключом пары
(`wire/push-seal.ts`), подписка браузера лежит у пары в `remote.json`, кадр FRAME_PUSH релею -
`agent/push-out.ts`. Релей отдаёт payload службе пушей (`web-push`, белый список хостов, пределы)
и подписок не хранит. Связь включается в
окне Remote Control (`features/remote`: кнопка в строке состояния, действие поиска везде), по
умолчанию выключена; адрес релея - константа `wss://agentic-workstation-relay.mzpizote.com`.
Телефонный клиент `apps/phone` - PWA на Vite и React, её раздаёт тот же релей (образ собирает
её в папку статики). Ядро без React (`src/remote/`): адрес на релее, одна линия до него на все
спаренные IDE, рукопожатия и печать на WebCrypto (ключи пары и ключ подписи адреса -
неизвлекаемые `CryptoKey` в IndexedDB), окно повторов, подписки с догонкой по номеру (одна
каждого вида), команды из белого списка (фото и файлы - частями; файл IDE пишет в каталог вставок
и ставит в текст ссылкой «@путь», `bridge/attached-files.ts`, ADR 0077) с повтором тем же id после
resync, страница
ленты выше (`src/remote/earlier-pages.ts`). Уведомления: подписка браузера и передача её
каждой IDE (`src/push/push-setup.ts`, `src/remote/push-sync.ts`), сервис-воркер (`src/sw/`,
отдельная сборка классическим скриптом) открывает пуш ключами пары из IndexedDB и ведёт на экран
разговора, очереди или прогона. Пара - камерой самой страницы (`features/pairing/QrCamera`,
getUserMedia и jsQR, ADR 0067) или адресом из QR, который открыла камера системы. Экраны
(`src/features/`) читают зеркало IDE в кэше React Query (`src/state/mirror.ts`), интерфейсное -
в Zustand; общее экранов - `src/shell/`
(экран с полосой связи и уведомлениями над низом, карточка решения над полем `Dock`, ожидание
IDE `LinkWait`); токены и примитивы - `packages/ui` (размер `touch` у кнопок, полей и строк).
Экран, который по итогу команды ведёт дальше (сохранить, запустить, открыть), ведёт только через
`navigateFromHere` (`src/lib/router.store.ts`): ответ идёт через релей сотни миллисекунд, и если
человек за это время ушёл с экрана, переход не делается.
Экран разговора над полем показывает контекст и лимиты аккаунта, на котором идёт разговор
(`ConversationWire.usage` - окна выбранного аккаунта панели его провайдера; нажатие - когда окна
сбросятся). Окно IDE освежает лимиты только своей открытой панели, поэтому мост сам просит их у
провайдеров разговоров, открытых на телефонах, - сразу при подписке и раз в две минуты
(`bridge/usage-refresh.ts`). Таблица ответа - своей шириной и листается вбок. В списке разговоров
проекта времени нет: «с какого момента в состоянии» читалось как длительность работы. Пустых
вкладок «New chat» в нём тоже нет: IDE помечает их `blank` (`bridge/conversation-wire.ts`
`isBlank`), телефон их не показывает и не считает (`startedConversations`), а провайдер без
начатых разговоров пропадает целиком - новый разговор начинают кнопкой. Новый разговор с
телефона по умолчанию «как в IDE»: модель, усилие и режим, которых телефон не выбрал, вкладка
берёт, как новая вкладка окна этого провайдера (его Settings → New chats, иначе выбранная вкладка
проекта); режим «как в окне» проверяется тем же `ModeGate` по вышедшей вкладке. Над моделью -
пресеты провайдера, те же кнопки, что под полем окна (`ProviderCaps.presets`, ADR 0096): плашки
делят ряд поровну, нажатие ставит модель, усилие и режим разом, «по умолчанию» пресета уходит
null, а не «как в IDE»; режим, в котором проект разговор не начнёт, пресет не ставит. Идущие субагенты,
фоновые команды, наблюдатели Monitor и будильники агента - капсулами под шапкой разговора, как чипы потоков панели
(`features/conversation/TaskCapsules`, из строк ленты): нажатие - лист задачи с «остановить» во
всю ширину; в строке вызова в ленте кнопки остановки нет.
Сквозная проверка в мобильном Chromium - `pnpm --filter @agentic-workstation/phone e2e`: свой
релей за прокси с задержкой 80-150 мс в одну сторону (`e2e/latency-proxy.ts`,
`AGENTIC_WORKSTATION_PHONE_LATENCY_MS`), иначе гонки «ответ пришёл на другой экран» не видны.
Боевой релей - `AGENTIC_WORKSTATION_PHONE_LIVE_RELAY` (страница - выложенная сборка), а с
`AGENTIC_WORKSTATION_PHONE_LIVE_PAGE=local` - своя сборка через настоящую сеть до выкладки.

## Голосовой режим

Живой разговор с агентом голосом - из панели IDE или с телефона (ADR 0104). Вся логика голоса -
в главном процессе (`main/voice/`): только он знает ключ Deepgram (`voice.vault`) и ходит в
Deepgram. Окно и телефон - конечные точки звонка (`call/voice-endpoint.ts`): пишут микрофон
кадрами PCM16 16 кГц по 80 мс и играют ответ PCM16 24 кГц. Звук в браузере - общий пакет
`packages/voice-audio` (ворклет микрофона, проигрыватель ответа с эпохами и отчётом о
проигранном).

- **Deepgram** (`main/voice/deepgram/`): Flux STT `/v2/listen` (`flux-general-multi`,
  переподключение с буфером микрофона до 5 с) и Flux TTS `/v2/speak` (ответ - один ход, фразы
  уходят по мере появления, перебивание - `Interrupt` с местом в сессии).
- **Звонок** (`main/voice/call/`): уши (`call-ears.ts` - ходы Flux в реплики, двухшаговое
  перебивание), рот (`call-mouth.ts` - ответ агента по фразам в синтез, эпохи, что услышано),
  мозг (`call-brain.ts` - реплики в разговор панели, вопросы агента вслух), звонок
  (`voice-call.ts` - состояния, пауза, потеря связи, тишина). Разговор - обычный в проекте Home у
  провайдера из настроек, через тот же порт панелей, что у телефона.
- **Голосовые правила агенту** - скрытой пометкой к каждой реплике голосом
  (`agents/conversation/voice-note.ts`), как заметка редактора: у всех провайдеров, без
  перезапуска, повтор журнала её вынимает.
- **Окно**: `features/voice` (звук звонка на всё окно, звонок в строке состояния), в панели -
  кнопка звонка, полоса над полем и микрофон у голосовых сообщений; Settings → Voice.
- **Телефон**: звук - телом внутри SEALED (`remote-protocol/src/audio-frame.ts`: первый байт
  `0x01`/`0x02`, у JSON - `{`), кнопки и отчёт о проигранном - словом `voice`; в IDE -
  `main/remote/voice/phone-voice.ts`, ответ кадрами по 200 мс без очереди. На телефоне строка
  «Voice call» у машины, звук - в корне страницы (`features/voice-call`), экран звонка - экран
  его разговора с полосой звонка сверху. Пуш `done` - когда агент доделал после звонка.
- **Язык** (ADR 0106, `main/voice/speech/text-language.ts`): голос ответа - по языку текста
  ответа, а не реплики; язык реплики для пометки модели - по её словам, ярлык Flux решает только
  неуверенную латиницу. Цитата в кавычках язык не меняет.
- **«Прочитать вслух»** у ответа модели (ADR 0106, `main/voice/reading/`): синтез в главном
  процессе кусками - окну событием `voice:reading` (кнопка в `features/agent-panel`, звук -
  `features/voice`, состояние - `state/read-aloud.store.ts`), телефону кадрами вида `reading`
  (`main/remote/voice/phone-reading.ts`, `features/read-aloud` телефона). Звук - на диске месяц
  (`voice-samples.ts`, тем же ключом, что образцы); ответ, сказанный звонком целиком, ложится
  туда же. Во время звонка чтения нет.

Живая проверка на настоящем Deepgram - `AGENTIC_WORKSTATION_VOICE_E2E=1` и `DEEPGRAM_API_KEY`
(`main/voice/voice-live.e2e.test.ts`); звонок в копии окна - микрофон из WAV через
`AGENTIC_WORKSTATION_AGENT_ARGS` (`agent-window.sh`), телефон - `e2e/voice.browser.test.ts`.

### Walkthrough - голосовой показ на экране

Агент показывает и объясняет на экране человека, как на созвоне ([ADR 0134](adr/0134-walkthrough-voice-show-on-screen.md),
[ADR 0135](adr/0135-walkthrough-highlight-ask-and-pens.md)): говорит звонком, смотрит и действует
Computer Use (везде, Chrome тоже; Browser - только прочитать страницу), куда смотреть -
подсвечивает, затемняя всё остальное, и говорит о каждой подсветке. Человек отвечает голосом и
своими пометками.

- **Коннектор** `walkthrough` (`connectors/kinds/walkthrough/`): один на IDE, добавляется только
  поверх включённых Computer Use и Browser (`walkthroughMissing`, отказ `walkthrough-needs`);
  шлюз отдаёт его процессу, только если оба видны в проекте (`gateway-host.ts`), и целиком без
  вопроса. Правила показа - пояснение сервера (`walkthrough-guide.ts`, в пределе 2048 знаков).
  Инструменты: `highlight` (область и обязательная фраза `say`), `clear`, `ask` (вопрос,
  `critical`), `wait_for_user`, `user_marks`, `finish`; вне показа отказывают словами.
- **Начало** - кнопка Walkthrough в шапке панели рядом с микрофоном
  (`features/agent-panel/WalkthroughAction`, видна там, где показ готов - `isWalkthroughReady`):
  `voice:startWalkthrough` поднимает звонок режима `walkthrough` в выбранном разговоре панели (нет
  его - новый в проекте, в режиме новых вкладок), IDE сама спрашивает «что показать?», у правого
  края экрана встаёт панель инструментов. Реплики уходят с пометкой показа (`voiceNote` с
  `walkthrough`, с `drawn` - сколько пометок нарисовано), и звонок сразу отзывается коротким
  «хорошо, секунду» (`call-show.ts`), пока модель думает.
- **Такт с голосом** (`main/walkthrough/walkthrough-desk.ts`): фраза подсветки встаёт в голос
  сразу за словами модели до вызова (`VoiceCall.say` - своим ходом синтеза), подсветка появляется,
  когда те прозвучали (`VoiceCall.speechSoFar` - лента показала идущий инструмент, потом
  `CallMouth.drained`), и держится, пока звучит её фраза (`CallMouth.spokenOf`); потом следующая.
  Перебили - очередь до этого места не рисуется. Действие Computer Use ждёт слов и очереди внутри
  вызова (`ComputerPort.beforeAct`), потом - пока человек держит инструмент или мышь, и стирает
  метки. Точки - пиксели последнего снимка разговора (`ComputerAgent.aim`): снимок не годится -
  отказ со свежим снимком; уехавшее окно стирает подсветку само.
- **Сцена и окна** (`walkthrough-stage.ts`): подсветки модели, пометки человека и инструмент в руке
  - на одном дисплее. Окно меток (`walkthrough-window.ts`, `walkthrough.html`,
    `features/walkthrough/WalkthroughMarks`): прозрачное во весь дисплей, ступенью ниже капсулы,
    закрыто от захвата; затемнение `--color-backdrop` с вырезами и каймой, вырез переезжает плавно
    (переход по `d`); с инструментом в руке ловит мышь и рисует пометку. Панель
    (`walkthrough-panel.ts`, `walkthrough-panel.html`, `features/walkthrough/WalkthroughPanel`):
    обвести, подчеркнуть, стрелка, стереть. Каналы `walkthrough:view`, `walkthrough:marks`,
    `walkthrough:panel`, `walkthrough:panelChanged`, `walkthrough:pick`, `walkthrough:erase`,
    `walkthrough:stroke`.
- **Ожидание человека** (`walkthrough-listen.ts`): `ask` задаёт вопрос своим ходом голоса и ждёт;
  тишина (пока человек не говорит) на обычный вопрос - «да», на важный - повтор и конец звонка.
  `wait_for_user` отдаёт мышь (`ComputerAgent.handOver`) и ждёт шага (`walkthrough-wait.ts`). Пока
  ждут, звонок слушает (`VoiceCall.listen`): «да» - ответ, а не поддакивание; реплику забирает
  ожидание, а не чат.
- **Пометки человека модели** - `user_marks` (`walkthrough-user-marks.ts`): свежий снимок дисплея,
  пометки словами в его пикселях (`ComputerAgent.pixelsOf`) и крупные планы.
- **Конец** - по любой причине (finish, трубка, тишина, сбой): метки и панель уходят, IDE выходит
  вперёд с этим чатом (`WalkthroughDesk.backToChat`, ставит `computer-chats.ts`). Пока показ
  идёт, возврат к чату после Computer Use (ADR 0130) молчит.

## Части кода и кто кого импортирует

Правило держит линтер (`boundaries/dependencies` в `eslint.config.mjs`), нарушение -
ошибка, а не предупреждение.

| Часть               | Где                             | Может импортировать                                                                     |
| ------------------- | ------------------------------- | --------------------------------------------------------------------------------------- |
| `ui`                | `packages/ui/src`               | только себя                                                                             |
| `shared`            | `apps/desktop/src/shared`       | только себя. Ни Electron, ни Node, ни React                                             |
| `main`              | `apps/desktop/src/main`         | `main`, `shared`, протоколы (тесты - и `relay`, `store`, `cloud`)                       |
| `preload`           | `apps/desktop/src/preload`      | `preload`, `shared`                                                                     |
| `lib`               | `renderer/src/lib`              | `lib`, `shared`                                                                         |
| `state`             | `renderer/src/state`            | `state`, `lib`, `shared`                                                                |
| `feature`           | `renderer/src/features/<имя>`   | свою фичу, `state`, `lib`, `shared`, `ui`, `locales`, `voice-audio`. Соседнюю - никогда |
| `workbench`         | `renderer/src/workbench`        | всё, кроме `app`                                                                        |
| `app`               | `renderer/src/app`              | всё в окне                                                                              |
| `browser-protocol`  | `packages/browser-protocol/src` | только себя. Ни Node, ни Electron: едет и в расширение                                  |
| `browser-extension` | `apps/browser-extension/src`    | себя и `browser-protocol`                                                               |
| `native-host`       | `apps/desktop/src/native-host`  | себя и `browser-protocol`. Чистый Node, без Electron                                    |
| `remote-protocol`   | `packages/remote-protocol/src`  | только себя. Ни Node, ни DOM: едет и в телефон                                          |
| `relay`             | `apps/relay/src`                | только себя (тесты - и `remote-protocol`). Свой сервер на Node                          |
| `phone`             | `apps/phone/src`                | себя, `ui`, `remote-protocol`, `voice-audio`. К IDE - только протокол                   |
| `voice-audio`       | `packages/voice-audio/src`      | только себя. Web Audio: микрофон и ответ звонка окна и телефона                         |
| `phone-e2e`         | `apps/phone/e2e`                | `phone`, `main`, `shared`, `relay`, `remote-protocol`: настоящая IDE в тесте            |
| `site`              | `apps/site/src`                 | себя и `ui` (только стили). Статическая страница, к IDE - ничего                        |
| `store-protocol`    | `packages/store-protocol/src`   | только себя. Node без Electron: едет в главный процесс и в сервер магазина              |
| `store`             | `apps/store/src`                | себя и `store-protocol`. Свой сервер магазина расширений на Node                        |
| `cloud-protocol`    | `packages/cloud-protocol/src`   | только себя. Node без Electron: едет в главный процесс и в сервер облака                |
| `cloud`             | `apps/cloud/src`                | себя и `cloud-protocol`. Свой сервер облака IDE на Node, хранит только шифр             |

Отсюда два следствия, которые чаще всего забывают:

1. **Фичи не знают друг о друге.** Что-то нужно двум фичам - это данные в `state/`
   (как выбранный файл: его читают дерево, редактор и строка состояния) или
   композиция в `workbench/`.
2. **Окно не трогает Node и Electron.** Всё через `lib/ipc.ts`.

## Дизайн-система

`packages/ui` - отдельный пакет: токены, база и примитивы (список - в его
[README](../packages/ui/README.md)). Стиль - плоское тёмное стекло: на чёрной раме окна
только шапка, всё под ней - графитовые листы с зазором между ними (вкладки, полосы
иконок, панели, редактор, строка состояния), оранжевый акцент
([ADR 0006](adr/0006-design-system-flat-glass.md)). Сырые значения в стилях запрещает
stylelint: цвет, шрифт, отступ, радиус, слой - только токеном, и токен должен
существовать. Кегль выбирается по роли текста - одна роль, одна ступень во всей IDE и в
панели Claude Code; все кегли растут от одного множителя размера текста
([ADR 0024](adr/0024-ide-text-size.md)).

**Витрина** - все токены и компоненты на одном экране (`features/showcase`). Открывается
действием поиска везде «Show or Hide Design System» (⌘⇧A) и ложится поверх панелей. Есть только в dev и в копии окна
агента: в релизной сборке флаг ложен на этапе сборки, и код витрины в бандл не попадает.

## Обновления

Установленная IDE раз в четыре часа смотрит манифест последнего релиза и, если есть
версия новее, показывает уведомление. По кнопке качает zip, сверяет размер и
контрольную сумму, проверяет, что новая версия подписана тем же сертификатом, что и
установленная, подменяет себя и перезапускается. Почему не electron-updater и что
проверено - [ADR 0004](adr/0004-self-update.md). Как выпустить релиз -
[releasing.md](releasing.md), подпись - [code-signing.md](code-signing.md). На Windows -
установщик целиком: IDE пускает его, только если его sha512 подписан ключом выпуска (Ed25519)
([ADR 0048](adr/0048-windows.md)). Запускает его сторож после выхода IDE, с окном, а не тихо: на
время установки снимает регистрацию host браузера, пишет каждый шаг в `update.log`, а если новая
версия не встала - открывает старую ([ADR 0124](adr/0124-windows-update-visible-installer.md)).

## Платформы

Мак - основная, Windows x64 - тот же код ([ADR 0048](adr/0048-windows.md)). Развилки - в
`main/platform.ts` (главный процесс: рамка окна, меню, оболочка и терминал PowerShell, поиск
CLI в PATH из реестра и папках установщиков ([ADR 0125](adr/0125-windows-cli-search.md)),
гашение дерева процессов, память, мост браузера через именованный канал и реестр,
обновление) и `lib/platform.ts` (окно: платформа приходит мостом preload). Клавиши записаны
маковскими: `lib/keys.ts` превращает Ctrl в ⌘ для проверок и рисует подписи Windows. Пути: от
корня проекта - всегда «/» (`toWindowRelative` в главном процессе), абсолютные - путь системы,
разбор в окне - `lib/path.utils.ts`. Окна консоли у дочерних процессов Windows прячет
`main/windows/console-hide.ts` одним местом. Установщик Windows собирается на Mac (`pnpm dist:win`).

## Сайт продукта

`apps/site` - страница https://agentic-workstation.mzpizote.com: что за IDE, ссылки на установщики
и шаги установки для мака и Windows ([ADR 0068](adr/0068-product-site.md)). Статика из Vite:
`index.html`, стили SCSS на токенах `packages/ui` и своих крупных `site-tokens.css`, немного
TypeScript (главная кнопка под систему посетителя, копирование команды, номер версии). Ссылки на
скачивание постоянные (`/releases/latest/download/<имя>`), так что выпуск IDE сайт не трогает;
номер версии страница берёт с `/release.json` - ответа API GitHub в кеше nginx. Снимки окна -
настоящая IDE на демо-проекте, как их переснять - `apps/site/README.md`. Выкладка -
`apps/site/scripts/site-deploy.sh`.

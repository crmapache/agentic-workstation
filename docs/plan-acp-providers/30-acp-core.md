# Этап 3. Ядро клиента ACP

Решение - ADR 0092. Ядро клиента ACP - `main/acp/`, общее для любого агента ACP. Драйверы
(`main/antigravity/`, `main/kimi/`) дают только своё: поиск CLI, папку и окружение, отображение
режимов, вход и квоту, уточнение вида вызова, артефакты. Образец устройства - драйвер OpenCode
(`main/opencode/`): разговор, сессия, лента, вопросы, каталог, сервис панели.

## Части

- **`acp/protocol/`** - типы ACP v1, которые нужны IDE (подмножество схемы
  `@agentclientprotocol/sdk` 2.8.0: `initialize`, `session/*`, `session/update`, разрешение,
  `elicitation/create`). Своё у агентов - только в драйвере (`_meta`, незаявленные поля).
- **`acp/client/acp-process.ts`** - процесс агента и JSON-RPC 2.0 построчно: запросы с id и
  сроком, уведомления, запросы агента (обработчик от сессии; незнакомый - `-32601`), очередь до
  рукопожатия, хвост stderr для ошибки, остановка без сирот: закрыть stdin, через 3 с сигнал
  группе (`main/process/process-group.ts`). **`acp-connection.ts`** - методы протокола словами
  IDE.
- **`acp/feed/`** - сборщик ленты `AcpFeedBuilder` (по образцу `OpenCodeFeedBuilder`):
  - ответ и размышление - кусками; без id сообщения у ACP куски одного вида подряд - один
    элемент, вызов или смена вида начинают новый; id - номер хода и счёт;
  - вызов: `tool_call` создаёт, `tool_call_update` дополняет (поля, которых нет в обновлении, не
    стираются); `kind` ACP → `ToolAction`, драйвер уточняет (имя инструмента у `agy` в
    незаявленном `name`, у Kimi - в `title`; MCP - по имени сервера коннектора); id вызова - его
    устойчивая часть (у Kimi после двоеточия);
  - дифф `{path, oldText, newText}` → карточка правки строками (`agents/changes/line-diff`); у
    `agy` в вопросе - кусок, в конце - файл целиком: конечный побеждает; новый файл (`oldText`
    null) - запись;
  - вывод команды - текст содержимого или `rawOutput.output`; статус `failed` после отказа
    остаётся отказом;
  - `plan` → список задач над полем; `compaction_update` → карточка сжатия; `notice` →
    отметка; `usage_update` → кольцо контекста; `session_info_update` → имя вкладки (ранг llm);
  - `session/load` повторяет историю теми же обновлениями: тот же сборщик с префиксом id
    страницы, `user_message_chunk` - сообщение человека, ход - до следующего сообщения.
- **`acp/conversation/`** - разговор ядра:
  - `AcpSession` (`AgentSession`): `begin` - `session/resume` (разговор есть) или
    `session/new` (`cwd`, серверы коннекторов, `systemPrompt`, если объявлен); `send` -
    `session/prompt` (текст с рамками, заметкой редактора и выводом `!`, картинки - блоками
    `image`); конец хода - ответ `prompt` (`stopReason`, у `agy` ещё `usage`); Stop -
    `session/cancel`; **сообщение посреди хода ждёт конца хода внутри сессии** и уходит
    следующим ходом (у `agy` второй промпт вытесняет первый);
  - вопросы `acp-requests.ts`: разрешение → карточка с вариантами агента (`allow_once` →
    allow, `allow_always` → allowAlways, `reject_*` → deny); `ExitPlanMode` Kimi (варианты
    `plan_*`) → карточка плана (одобрить → `plan_approve`, доработать → `plan_revise`, отказ →
    `plan_reject_and_exit`); `elicitation/create` форма → вопрос с вариантами (`oneOf`), поле
    `<id>_other` - свой ответ; снятый вопрос (ход кончился) - карточка уходит;
  - модели, усилие, режим - `session/set_config_option` (`model`, `thought_level`, `mode`)
    перед ходом, если поменялись; запасные `set_mode`; режимы IDE ↔ агента - у драйвера;
  - `acp-driver.ts` (`AgentDriver`), `acp-conversation.ts` (своё ACP у разговора).
- **`acp/catalog/`** - процесс-каталог на панель: `session/list` (фильтр по папке - сами),
  повтор разговора для ленты (`session/load`, сбор обновлений, `session/close`), имя;
  гаснет после простоя. Kimi держит замок писателя - каталог закрывает сессию до того, как её
  продолжит разговор.
- **`acp/acp-panel.ts`** - сервис панели `AcpPanel extends AgentPanel` по описанию агента:
  состояние, модели из `configOptions`, возможности из `initialize` и описания, доверие к папке
  (`FolderTrust`), коннекторы через шлюз (`AcpConnectorsBridge`), вход и квота - у драйвера.
- **`acp/acp-agent.ts`** - описание агента ACP (`AcpAgent`): провайдер, поиск CLI, аргументы и
  окружение запуска, режимы IDE ↔ агента, уточнение вызова, артефакты, вход, квота, как
  отдать указания IDE.

## Переводчик для сценариев и заданий

`main/providers/acp/` - процесс сессии движка поверх `AcpProcess`, как у Codex и OpenCode
(ADR 0085): сообщения Claude, которые читает движок (`system/init`, `assistant`, `result` с
расходом, `control_request can_use_tool`, отмена). Работает только у провайдера, которому
правило фоновой работы это разрешает (ADR 0094): сейчас - Kimi.

## Проверка

Тесты на поддельном агенте (скрипт, который отвечает строками записи
`__fixtures__/*.ndjson`), разбор записей `agy-session` и `kimi-session` в ленту, вопросы,
отмена, повтор истории. Живые - по переменной окружения: `agy` - только `initialize` и
`session/new` (без ходов: условия Google), Kimi - ход на локальной модели.

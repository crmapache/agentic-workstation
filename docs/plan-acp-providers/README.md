# Провайдеры на ACP: Google Antigravity и Kimi Code

Рабочий план агента. Составлен заранее, 2026-11-19, работа ещё не начата: в это время шла
соседняя работа (ветка `feat/plugins`). Нужен, чтобы после смены чата или сжатия контекста
продолжить с того же места и с теми же решениями. Галочка ставится, только когда пункт сделан
и проверен, а в журнал внизу пишется, чем проверен.

Прошлый план провайдеров (Codex и OpenCode) закрыт и лежит в `docs/plan-providers/`. Его
устройство здесь не переделывается: общее ядро панелей и драйверы (ADR 0083), вся IDE на любом
провайдере через переводчики (ADR 0085). Новое - четвёртый и пятый провайдер, общий для них
клиент ACP и правило фоновой работы по провайдеру.

## Как читать после сброса контекста

1. Этот файл целиком: факты, решения, этапы, журнал внизу.
2. Файл текущего этапа (`30-acp-core.md`, `40-antigravity.md`, `50-kimi.md`, `60-ide.md`), если
   он уже заведён: подробный дизайн этапа пишется в его начале, как в прошлом плане.
3. В рабочей копии: `git log --oneline main..HEAD` и `git status`.
4. Последние записи журнала.
5. Только потом код.

## Правила работы

- Проектные правила целиком: `CLAUDE.md`, `.claude/rules/*`, границы частей, 200 строк на
  `.tsx` и 300 на `.ts`, токены дизайн-системы, i18n, один контракт IPC, ADR на решения.
- Каждый шаг: `pnpm check` зелёный; тронут интерфейс - осмотр окна `/dev`; логика - тесты.
  Живые пробы CLI - малыми прогонами (самая дешёвая модель Gemini у Antigravity, локальная
  модель или ключ платформы у Kimi до подписки), во временной папке-проекте внутри домашней.
- **Живые пробы Antigravity на подписке - только руками человека в окне копии** или одиночными
  ходами, которые агент запускает как проверку протокола; никаких пачек ходов, циклов и
  автоматических повторов на личном входе Google (условия Google, раздел «Antigravity»).
  Тесты, которые гоняют много ходов, - на поддельном агенте ACP.
- Перед коммитом этапа - проектные ревьюеры на дифф этапа (`ide-electron-boundaries`,
  `react-architecture`, `react-design-system`, `logic-tracer`, `edge-case-hunter`,
  `regression-hunter`), находки проверяет `finding-verifier`, подтверждённые исправляются.
- **Не трогать настройки человека:** `~/.gemini/` (и `antigravity-cli` внутри), `~/.kimi-code/`,
  их MCP, плагины и вход. У IDE для обоих свои папки (как у Codex и OpenCode). Пробы, которые
  всё же создают разговор в папке человека, убирают его за собой средствами самого CLI
  (`session/delete` у Kimi) или удалением ровно своих файлов.
- Обновить `agy` и `kimi` до свежих версий - с согласия владельца в начале работы (это его
  инструменты и в терминале тоже).
- Всё запущенное для проверки гасить в том же заходе.

## Antigravity: что известно (2026-11-19)

Замер на этом Mac (`agy` 1.5.3, `~/.local/bin/agy`): `initialize` и `session/new` по ACP во
временной папке, без хода модели; пробный разговор удалён, скрипты проб - `~/aw-acp-probe/`

[сторон.] - чужие разборы и issue.

### Продукт и путь встраивания

- С 19.05.2026 Antigravity - четыре части: приложение Antigravity 2.0, старая IDE (форк VS
  Code), CLI `agy` и Python SDK; приложение и CLI работают на одном агенте [офиц.]
  (https://antigravity.google/docs/features/).
- **`agy acp` - официальный путь встраивания** [офиц.]: ACP v1 по stdio с 1.5.0 (04.11.2026),
  документация зовёт любые ACP-клиенты («Other ACP clients: run agy acp with the project directory
  as cwd») - https://antigravity.google/docs/cli/acp/. Код CLI закрыт (Go), релизы почти каждый
  день: свежая версия 1.5.12 (19.11.2026), на этом Mac - 1.5.3.
- **Gemini CLI - не вариант**: с 18.06.2026 он не обслуживает подписки Google AI Pro и Ultra,
  только платные ключи API и корпоративные лицензии; замена - Antigravity CLI [офиц.]
  (https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/).
- Python SDK - только ключ Gemini API или Google Cloud, подпиской не входит [офиц.]. Language
  server приложения и `agy --hub` - внутренние каналы, официально ими пользоваться нельзя.

### Условия Google (главное для плана)

- **Additional Terms, раздел 6** [офиц.] (https://antigravity.google/terms?hl=en): «Using third
  party software, tools, or services to access the Service (e.g. using OpenClaw with Antigravity
  OAuth) is a breach» - вплоть до закрытия доступа к Antigravity и Gemini CLI.
- **FAQ** [офиц.] (https://antigravity.google/docs/faq.md): `agy -p` - для своих скриптов и CI;
  «Wrapping agy inside third-party coding agents or applications, or automating account
  rotation, is not supported under consumer plans»; сторонним агентам - ключ Gemini Enterprise
  или AI Studio.
- **Толкование мейнтейнера** (12.11.2026) [мейнтейнер]
  (https://github.com/google-antigravity/antigravity-cli/issues/1493):
  - **можно:** любой интерактивный ACP-клиент, в том числе свой интерфейс, если он запускает
    неизменённый `agy acp`, а сессией прямо управляет человек; подтверждать каждый вызов
    вручную не обязательно;
  - **нельзя при личном входе (`oauth-personal`):** `agy acp` или `-p` как фоновый исполнитель
    внутри стороннего агента, оркестратора или очереди задач; промпты, которые сочиняет другой
    агент; подмена системной инструкции Antigravity; автоматическая смена аккаунтов.
- Форум Google (09.11.2026): личное приложение на неизменённом `agy acp` с AI Pro - можно, без
  фоновой автоматизации и без нескольких пользователей
  (https://discuss.ai.google.dev/t/personal-app-using-the-official-agy-acp-binary-with-google-ai-pro-permitted/198889).
- Баны: февраль 2026 - массово за OpenClaw с OAuth Antigravity; 16.11.2026 - `403
TOS_VIOLATION` у OpenCode с плагином `opencode-antigravity-auth`; осень 2026 - тот же ответ
  бывает и на официальном `agy`, похоже на ложные срабатывания [сторон.].

**Вывод для IDE:** панель Antigravity (человек пишет в чат сам, с компьютера или телефона) -
можно. Сценарии, задания, цели, служебная работа IDE, коннектор от ИИ, управление разговорами
Antigravity из MCP `workstation` другими агентами и смена аккаунта при лимите - **на личном
входе Google нельзя**; можно только при входе ключом Gemini API или Enterprise (оплата по API,
не подпиской). Системные указания - только дописывать (`systemPrompt.append`), не заменять.

### Протокол `agy acp`

- `initialize` (замер 1.5.3): `loadSession`; `sessionCapabilities` - `resume`, `close`, `load`,
  `list`, `additionalDirectories`, **`fork` нет**; картинки и вложенный контекст в сообщении;
  `_meta.antigravity` - `tier` и `systemPrompt.append`; вход - `oauth-personal`,
  `oauth-business`, `gemini-api-key`, `agent-platform` (и `terminal-login` по документации),
  `agy acp --login`, `logout`. Без входа - ошибка `-32000` «Authentication required».
- **MCP:** `mcpCapabilities` не объявлены, но HTTP MCP в `session/new` работает - открытый баг
  #1604 [сторон.]; по документации серверы клиента по HTTP требуют `--process-per-session`
  [офиц.]. Свои серверы `agy` - `~/.gemini/config/mcp_config.json` и проектный
  `<папка>/.agents/mcp_config.json`, удалённые - только Streamable HTTP (`serverUrl`).
- `session/new` (замер, вход с бесплатной квотой): Gemini 3.8 Flash (High, Medium, Low), Claude
  Sonnet 4.6 и Opus 4.6 (Thinking), GPT-OSS 120B; по документации на AI Pro (не пробном) и Ultra
  есть Claude Sonnet 5.5 и Opus 5.5, а Claude 4.6 и GPT-OSS сняты 18.11.2026. `configOptions` -
  `model`, `thought_level` (на 1.5.3 - low, medium, high; по документации - до Extra и Max),
  `mode`.
- **Режимы:** `default`, `accept-edits`, `plan`; `auto` (проверка команд вне песочницы) - с
  1.5.4. Флаги процесса `--dangerously-skip-permissions` и `--sandbox`. По одному замеру `plan`
  всё равно выполнял команды shell [сторон.] - проверить.
- Разрешения - `session/request_permission` с `allow_once` и `reject_once`. Шлёт `usage_update`
  (только заполненность контекста, с 1.5.8), `tool_call`, `current_mode_update`,
  `config_option_update`, `available_commands_update` (команды `goal`, `compact`, `schedule`,
  `browser`, `plan` и другие).
- **Сообщение посреди хода не работает** - второй промпт вытесняет первый [сторон.]: только
  очередь. В 1.5.3 `session/load` отвечал успехом на несуществующий id [сторон.].
- `session/list` фильтр по `cwd` не применил (замер) - фильтровать самим.
- **Форк и откат** - в TUI есть `/fork` и `/rewind`, через ACP не нашли.
- **Квота:** официального API нет. Строка состояния получает `quota` по корзинам
  (`remaining_fraction`, `reset_in_seconds`), `plan_tier` и `cost` [офиц.]
  (https://antigravity.google/docs/cli/statusline/); команды `/usage` (`/quota`) и `/credits`.
  Корзины на 5 часов и неделю общие у `agy`, `-p`, `acp`, приложения и расширений [мейнтейнер].
- **Вход:** токены - в Keychain (на Windows - Credential Manager) [офиц.]. `_meta.antigravity.tier`
  сейчас - «Antigravity Starter Quota» (`free-tier`): **в `agy` на этом Mac вошёл не аккаунт с
  подпиской.**
- **Хранилище** (формат не документирован): `~/.gemini/antigravity-cli/conversations/<uuid>.db` -
  SQLite, шаги и метаданные модели - protobuf в blob (`steps`, `gen_metadata`); индекс
  `conversation_summaries.db`; расшифровка `brain/<id>/.system_generated/logs/transcript.jsonl`
  (без токенов и модели); артефакты - `brain/<id>/`. `--gemini-dir` переносит всё состояние в
  другую папку; у `agy acp` ещё `--app-data-dir`, `--cli_dir_name`, `--disable-telemetry`.
- Windows поддерживается (`irm https://antigravity.google/cli/install.ps1 | iex`).

## Предлагаемые решения (утверждает владелец)

1. **Оба провайдера - через ACP, одним ядром клиента ACP.** Драйверы Antigravity и Kimi тонкие:
   поиск CLI, вход и аккаунты, квота, коннекторы, свои режимы и команды. Тот же клиент подойдёт
   следующим агентам с ACP. ADR.
2. **Сначала - реестр провайдеров одной записью.** Сейчас список провайдеров разбросан по
   десяткам мест развилками «если codex, иначе если opencode» (около 70 файлов упоминают
   Codex). Четвёртый и пятый провайдер добавляются в одну запись, а не в 30 развилок. ADR.
3. **Antigravity - официальный неизменённый `agy acp`**, вход делает сам `agy`, токенов IDE не
   касается. Не приложение Antigravity, не Gemini CLI, не внутренние каналы.
4. **Фоновая работа - правилом провайдера** (ADR). У записи провайдера - когда ему можно
   работать без человека: сценарии, задания, цели, служебная работа, коннектор от ИИ, разговоры
   по просьбе других агентов через MCP `workstation`, смена аккаунта при лимите.
   - Claude, Codex, открытые модели - как сейчас.
   - **Antigravity - только ручной чат в своей панели** (решение владельца 2026-11-19): в выборах
     фоновой работы провайдер виден, но недоступен с объяснением; `workstation` не шлёт
     сообщения в разговоры Antigravity; смены аккаунта при лимите нет никогда. Вход ключом
     Gemini API (с ним фон был бы разрешён) в этом плане не делаем.
   - **Kimi - всё, как у Claude и Codex, и на подписке** (решение владельца 2026-11-19):

## Риски

- **Условия Google размыты.** FAQ говорит «не поддерживается для приложений», разрешение для
  интерактивных клиентов - в комментарии мейнтейнера и на форуме. Ложные `TOS_VIOLATION` бывают
  и на официальном `agy`. Держим строго: неизменённый `agy`, вход его силами, без фона на личном
  входе, без смены аккаунтов, системный промпт только дописываем. Письменного подтверждения не
  просим (ответ владельца).
- **ACP у `agy` беднее, чем у Kimi:** нет форка, отката, сообщения посреди хода, HTTP для MCP
  официально. Чего нет - не показываем; мост для MCP - общий.
- **История Antigravity в protobuf.** Лента и история - только через ACP (`session/load`);

# Часть 3. Расширение Chrome - браузер для ИИ

Требования - раздел «Браузерное расширение» в [PLAN.md](../../PLAN.md), решения владельца - в
[README.md](README.md): управление через отладчик Chrome только на время работы; ИИ видит все
вкладки профиля.

## Что просил владелец, по пунктам

1. Когда ИИ работает во вкладке - виден виртуальный курсор, как он двигается; работа идёт в
   группе вкладок, где расширение открывает новые вкладки, а в конце группа очищается и
   закрывается.
2. Человек спокойно работает в других вкладках или сворачивает браузер.
3. По правой кнопке на странице - «скопировать ID вкладки», чтобы дать ИИ ссылку: в каком
   профиле и какой вкладке работать.
4. ИИ может открывать пустые вкладки и работать в них.
5. Стиль проекта.

## Как это устроено (решения и почему)

```
ИИ-провайдер (claude -p)
   │ MCP по HTTP, ключ процесса
   ▼
Шлюз коннекторов IDE (main/connectors/gateway) ── встроенный тип «browser», свои инструменты
   │
   ▼
main/browser/ BrowserHub ── unix-сокет ~/.agentic-workstation/browser/<профиль IDE>.sock (права 600)
   ▲
   │ JSON-строки
native host (node-скрипт, исполняется самим Electron с ELECTRON_RUN_AS_NODE=1)
   ▲
   │ native messaging (stdin/stdout, кадр с длиной)
Расширение Chrome (MV3) в каждом профиле ── chrome.debugger (CDP) во вкладках агента
```

- **Связь - native messaging, а не порт на localhost.** Так сделаны Claude in Chrome и Codex
  (у владельца стоят оба, проверено по их манифестам). Chrome сам запускает host и пускает к
  нему только наше расширение (`allowed_origins`), порт не открыт никому, пары и ключей не надо.
  Порт расширение всё равно не нашло бы: шлюз берёт его у системы.
- **Host - JS, исполняемый бинарником самой IDE** (`ELECTRON_RUN_AS_NODE=1`): Chrome запускается
  из launchd без PATH, а node у человека может не быть. Обёртка `sh` указывает на путь к
  бинарнику IDE (установленной или dev). Host держит связь с сокетом IDE и переподключается, если
  IDE перезапустилась; IDE нет - отвечает расширению «IDE не запущена».
- **Dev и установленная IDE живут одновременно**, поэтому имя host и сокет - свои у каждого
  профиля IDE: `com.agentic_workstation.browser` и `com.agentic_workstation.browser_dev`.
  Расширение пробует оба и держит связь с каждым, который ответил.
- **Манифест host** IDE пишет сама при старте в папки `NativeMessagingHosts` всех найденных
  браузеров семейства Chromium (Chrome, Chrome Beta/Canary, Chromium, Brave, Edge, Arc,
  Vivaldi) - дёшево, и человек может перейти в другой браузер.
- **Постоянный id расширения** - поле `key` в манифесте (открытый ключ, закрытый не нужен для
  распакованного). Id нужен для `allowed_origins`.
- **Установка сегодня - «Load unpacked»** в режиме разработчика: IDE кладёт собранное
  расширение в `~/.agentic-workstation/chrome-extension/` (путь без пробелов, не меняется между
  версиями). Публикация в Chrome Web Store - аккаунт и проверка Google, не ночная задача, в
  «Вопросы на утро». При обновлении IDE папка перезаписывается, расширение видит новую версию от
  host и перезагружает себя (`chrome.runtime.reload`).
- **Управление - CDP через `chrome.debugger`**, решение владельца. Клики и ввод - `Input.*`
  (сайты не отличают от настоящих), снимок страницы - дерево доступности
  (`Accessibility.getFullAXTree`) с короткими ссылками на элементы (как Playwright MCP), картинка
  - `Page.captureScreenshot`. Подключаемся к вкладке, когда агент её взял, отключаемся по
    `finish`, после минуты простоя и когда сессия агента кончилась - плашка Chrome видна только во
    время работы.
- **Доступ - все вкладки профиля** (решение владельца): инструмент списка вкладок отдаёт все
  вкладки всех окон профиля. Взять чужую вкладку можно по ссылке или по номеру из списка.
- **В IDE это встроенный коннектор «Browser»** (как Gmail: инструменты исполняет сам шлюз, ADR
  0028, 0035). Отсюда бесплатно: доступность по проектам, ступени доступа, любой провайдер,
  сессии сценариев тоже получают браузер. Имя сервера - `browser-chrome` (тип в начале имени,
  правило коннекторов).
- **Сессия браузера - на разговор**, а не на весь коннектор и не на процесс: два разговора не
  делят вкладки и группу, а смена процесса одного разговора (перезапуск ради коннекторов,
  другой аккаунт, сон) вкладки не закрывает. Процесс называют разговором сразу после выдачи
  ключа шлюза (`McpLaunch.own`), конец процесса ждёт следующий 10 минут, закрытая вкладка
  разговора заканчивает сессию сразу (`McpLaunch.end`).

## Поведение

- **Группа вкладок на сессию агента:** первая вкладка, которую агент открыл, создаёт группу
  оранжевого цвета с именем «AW · <имя разговора>» в окне, где человек был последним, вкладки
  открываются **неактивными** - фокус и текущая вкладка человека не трогаются. Вкладки, которые
  агент взял по ссылке, остаются на своих местах (не переносятся в группу, чтобы не ломать
  раскладку человека), на них видна рамка и курсор.
- **Конец работы:** `finish` закрывает вкладки, открытые агентом, и группу; взятые по ссылке
  отпускаются (отладчик отключён, курсор и рамка убраны). Так же - когда процесс разговора
  кончился (шлюз отпускает запуск). Закрыл группу человек - сессия это видит и не открывает её
  заново молча: следующий вызов создаёт новую.
- **Виртуальный курсор:** в странице - свой элемент в закрытом shadow DOM поверх всего,
  `pointer-events: none`, стрелка акцентного оранжевого цвета с подписью «Agentic Workstation»;
  перед кликом плавно едет к точке, на клик - короткий круг. Тонкая рамка по краю страницы, пока
  агент её держит. Цвета и шрифт - значения токенов дизайн-системы, вписанные при сборке.
- **Фон и свёрнутый браузер:** CDP шлёт ввод и снимает дерево в фоновой вкладке. Картинка
  фоновой вкладки - **проверить вживую** (Chrome держит отрисовку вкладки, пока её снимает
  DevTools, но это надо увидеть). Не вышло - запасной путь: вкладки агента в отдельном
  неактивном окне, и картинка - только когда она возможна, иначе внятный ответ «вкладка скрыта,
  вот дерево». Итог - в журнал и ADR.
- **«Скопировать ID вкладки»:** пункт контекстного меню страницы и значка расширения - «Copy tab
  reference for AI». В буфер уходит строка вида `chrome-tab:<профиль>/<id вкладки> «Заголовок»`.
  Профиль - короткий постоянный id установки расширения в этом профиле Chrome плюс имя профиля,
  которое человек видит в окне расширения. Инструменты принимают такую строку целиком.
  Запись в буфер из фонового скрипта - через offscreen-документ.
- **Окно расширения (значок):** связь с IDE (есть / IDE не запущена / host не установлен), имя
  этого профиля (можно поменять), активные сессии агентов с кнопкой «Stop» (закрыть группу и
  отключиться). Стиль - токены и плоское стекло проекта.

## Инструменты (сервер `browser-chrome`)

Чтение (`read`): `profiles`, `tabs` (все вкладки: ссылка, заголовок, адрес, активна ли, группа),
`snapshot` (дерево доступности текстом со ссылками `e12`), `screenshot` (PNG, видимая часть или
вся страница), `console` (последние сообщения консоли).

Действия (`write`): `open` (новая вкладка в группе, адрес или пустая), `take` (взять вкладку по
ссылке), `navigate`, `back`, `forward`, `reload`, `click` (по ссылке элемента или координатам,
двойной, правая), `type` (в элемент, с Enter по желанию), `fill` (несколько полей сразу),
`press` (клавиши и сочетания), `hover`, `scroll`, `select` (выбор в списке), `upload` (файл с
диска в поле файла), `wait` (текст появился или пропал, время), `evaluate` (выражение JS в
странице), `close_tab`, `finish`.

Отправки людям (`outbound`) у браузера нет как отдельного инструмента: клик по «Отправить» не
отличить от любого клика. Записано в «Вопросы на утро»: при желании - подтверждение в окне
расширения на формах с отправкой.

## Код

- `apps/browser-extension/` - новый пакет: MV3, TypeScript, сборка Vite (фоновый скрипт,
  контент-скрипт курсора, окно значка, offscreen). Границы в `eslint.config.mjs` (`ELEMENTS`) -
  своя часть, импортирует только себя и `shared`-подобный протокол (решить при создании, может,
  протокол - в своём пакете `packages/browser-protocol`).
- `apps/desktop/src/native-host/host.ts` - отдельный вход сборки (electron-vite), без Electron,
  только Node.
- `apps/desktop/src/main/browser/` - `browser-hub.ts` (сокет, профили, запросы с тайм-аутом),
  `browser-sessions.ts` (сессия на запуск: группа, вкладки, подключения отладчика),
  `native-host-install.ts` (манифесты в браузеры, обёртка, копия расширения),
  `ax-snapshot.ts` (дерево в текст со ссылками - чистая функция, тесты).
- `apps/desktop/src/main/connectors/kinds/browser/` - инструменты на `NativeTool`.
- `shared/connectors.ts` - тип `browser`, вид Connectors: плитка, окно подробностей с шагами
  установки (кнопки «Show extension folder», «Open Chrome extensions»), список подключённых
  профилей вживую.
- Сборка установленной IDE: собранное расширение и host - в ресурсы приложения
  (`electron-builder.yml`, `extraResources`), после правки сборки - `update:e2e`.

## Риски

- Картинка фоновой вкладки (см. «Поведение»).
- Сервис-воркер MV3 засыпает: держится живым, пока открыт порт native messaging (Chrome 105+);
  проверить, что не засыпает посреди долгой работы.
- Сайты с несколькими процессами фреймов: дерево доступности - по всем фреймам через
  `Target.setAutoAttach` с `flatten`; если не успею - только главный фрейм, записать.
- Chrome ограничивает ответ host → расширение 1 МБ: картинки идут в обратную сторону
  (расширение → host, до 64 МБ), это нормально.

## Заметки после ревью (2026-11-11)

- **Безопасность.** `upload` - ступень `outbound` (выключена, пока не включит человек) и только
  файлы папки разговора по настоящему пути; `file:` в `open` и `navigate` - так же. Причина:
  страница может уговорить модель «приложить» ключ из `~/.ssh`, а «Load unpacked» даёт
  расширению доступ к `file:` по умолчанию.
- **Мост.** Удаление коннектора убирает мост и у выключенного; на старте без коннектора
  остатки подчищаются. Длинный домашний путь не роняет старт IDE: сокет уходит во временную
  папку, не влез и туда - код `socket-path` в окне.
- **Связь.** id запросов - со случайного места у каждой связи, host отбрасывает ответы на
  чужие запросы; сборщики кадров и строк линейные (20 МБ - десятки миллисекунд вместо секунды).
- **Сессия на разговор** с ожиданием нового процесса; Stop и «Отмена» на плашке Chrome - одно;
  `finish` закрывает только свои вкладки, оставшиеся в группе; отключённый профиль - вкладки без
  связи до сверки, а не забыты; расширение само закрывает вкладки IDE, которая упала или не
  вернулась, и группы агента, восстановленные после перезапуска Chrome.
- **Ссылка на вкладку** несёт метку запуска Chrome; без метки сверяется заголовок.
- **Страница.** «Покинуть сайт?» на вкладке человека - не уходить и спросить; дата, время, цвет и
  ползунок - значение напрямую; устаревшие ссылки снимка - «новый снимок»; ожидание переживает
  переход; картинка - не больше 2000 пикселей; дерево доступности прореживается в расширении.
- **Вид.** Слой курсора - в верхнем слое документа (popover), кнопки и поле окна расширения -
  как `Button` и `field-frame`, пояснение имени профиля - в подписи поля, Chrome 125+.
- Не проверено вживую: окно IDE (вид Connectors) глазами - копию окна агенту этой задачи
  запускать было нельзя; восстановление групп после перезапуска настоящего Chrome - только тест
  чистых функций (`agent-state.utils.test.ts`).

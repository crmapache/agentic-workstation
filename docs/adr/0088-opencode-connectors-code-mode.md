# 0088. Коннекторы у OpenCode - через Code Mode, а не описаниями в каждом запросе

- **Статус:** Принято
- **Дата:** 2026-11-18

## Контекст

Панель открытых моделей (ADR 0084) отдавала OpenCode коннекторы проекта прямыми
инструментами (`codemode: false`): описание каждого инструмента каждого сервера шло в каждый
запрос к модели. У облачной модели это деньги, у локальной - окно и время. Qwen3.8 27B на
Ollama с окном 64K в проекте agentic-workstation получала первый запрос в 56 тысяч токенов:
окно занято почти целиком до первого слова человека, первый ответ - около четырёх минут.
Больше половины запроса - коннекторы, и три четверти их веса - один Todoist (46 инструментов
с длинными схемами).

## Варианты

1. **Прямые инструменты, как было.** Просто, каждый вызов виден в ленте и в вопросе
   разрешения своим именем. Минус - вес описаний в каждом запросе: локальной модели не
   остаётся места на работу.
2. **Свой поиск в шлюзе IDE**: вместо серверов один служебный сервер с `search_tools` и
   `call_tool`. Обычные вызовы инструментов, проще для маленьких моделей, всё в наших руках.
   Минус - OpenCode спрашивает разрешение на обёртку, а не на настоящий инструмент: «разрешить
   в этом разговоре» разрешило бы все коннекторы разом, правила прогонов
   (`mcp__<сервер>__<инструмент>`) перестали бы совпадать, и всё это пришлось бы строить
   заново поверх OpenCode.
3. **Подгружать настоящие инструменты по поиску** (список инструментов сервера растёт,
   `notifications/tools/list_changed`). Настоящие имена. Минус - список инструментов стоит в
   начале запроса, и каждая подгрузка сбрасывает кеш начала у Ollama: модель перечитывает весь
   запрос заново (десятки тысяч токенов, минута и больше); шлюзу понадобились бы сессии.
4. **Code Mode самого OpenCode.** В запросе - короткий неполный каталог, остальное модель
   находит `search(...)` и зовёт кодом внутри одного инструмента `execute`. Найденное ложится
   в разговор, а не в список инструментов, - кеш начала живёт. Разрешение OpenCode спрашивает
   на каждый настоящий вызов изнутри кода тем же действием `<сервер>_<инструмент>`, что и на
   прямой: правила режима, «для этого разговора» и прогонов работают без изменений. Минус -
   модель пишет код, а ленте IDE надо показывать вызовы изнутри `execute`.

## Решение

Вариант 4: `codemode: true` у серверов шлюза в конфиге OpenCode. Главная причина - запрос
худеет вдвое, а модель разрешений OpenCode остаётся прежней: вызов коннектора спрашивается и
разрешается им самим. Что код сделал, IDE берёт из `metadata.toolCalls` хода и итога вызова и
показывает каждый вызов коннектора своей строкой ленты; код, который только ищет
инструменты, в ленте не виден, как ToolSearch у Claude.

## Факты и замеры

MacBook Pro M5 Pro, 48 ГБ, Ollama 0.40.16 (окно 65 536, `OLLAMA_KV_CACHE_TYPE=q8_0`),
OpenCode 2.3.2, модель `qwen3.8:latest` (27.8B, nvfp4, движок MLX). Размер запроса - по строке
`cache miss total=` в `~/Library/Logs/ollama.log`.

- Панель IDE, проект agentic-workstation, восемь коннекторов, прямые инструменты: первый
  запрос 55 948 токенов, первый ответ 3 мин 50 с, пик памяти Ollama 28.8 GiB.
- `opencode run` во временной папке без файлов указаний: без коннекторов - 22 642 токена; те
  же восемь серверов шлюза с `codemode: true` - 24 655. Коннекторы стоят около 2 тысяч
  токенов вместо 33.
- Вес описаний по серверам (`tools/list` шлюза): Todoist - 46 инструментов, 154 тыс. знаков;
  Shotter - 9 и 15 тыс.; Browser - 22 и 13 тыс.; остальные пять вместе - около 21 тыс.
- Qwen3.8 в Code Mode с первого раза нашла инструмент Todoist поиском и вызвала его с верными
  параметрами (`find-tasks-by-date`, «задачи на сегодня»), дважды: через `opencode run` и через
  `opencode serve` с правилами «спрашивать».
- Живая проба `opencode serve` (как его ведёт IDE): `execute` сам разрешения не спрашивает;
  вызов изнутри спрашивает `permission.asked` с `action` `<сервер>_<инструмент>`,
  `metadata.input` - вход вызова, источник - id всего `execute`; ход идёт
  `session.tool.progress` с `metadata.toolCalls` `{tool: "<сервер>.<инструмент>", status,
input}`, итог несёт их же. Отдельных событий у вызовов изнутри нет.

Повторить: `OPENCODE_CONFIG_CONTENT` с `mcp.servers` (адреса и заголовки - из файла
`--mcp-config` разговора Claude в IDE) и `codemode` true или false, затем
`opencode run "Reply with the single word: ok"` во временной папке со своими `XDG_*_HOME` и
посмотреть `cache miss total=` в журнале Ollama.

## Последствия

- `opencode-launch.ts` включает Code Mode у всех серверов шлюза - в панели, прогонах сценариев
  и заданий и разовых вопросах.
- `feed/code-mode.ts`: вызовы коннекторов изнутри кода - по тексту кода до хода и по
  `metadata.toolCalls` по ходу и в итоге; первая строка - сам `execute`, у каждого следующего
  вызова своя строка `<id>#<n>` со своим входом и исходом, как у `patch` на несколько файлов.
  Журнал разговора разбирается тем же путём.
- Карточка разрешения (`holdPermission`) строит вызов коннектора из `action` и
  `metadata.input`, если сервер известен процессу: источник вопроса в Code Mode - весь код.
  Заодно вопрос прогона о прямом вызове коннектора стал `mcp__<сервер>__<инструмент>`, а не
  безымянным действием.
- Журнал прогона пишет вызовы изнутри кода (`<сервер>_<инструмент> <вход>`), а не сам код;
  статистика считает их вызовами MCP своего сервера.
- Пересмотреть, если OpenCode поменяет форму `toolCalls` или вопроса разрешения (тогда
  сначала новая живая проба), или если модели в панели начнут путаться в коде - тогда вариант
  2 со своим учётом разрешений.

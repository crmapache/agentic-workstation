# 0038. Новое имя - Agentic Workstation, чисто, до первого релиза

- **Статус:** Принято
- **Дата:** 2026-11-10

## Контекст

Продукт переименован: «Amazing IDE» → «Agentic Workstation». Папка проекта и
репозиторий кода уже называются `agentic-workstation`. От имени зависят вещи, которые
ADR 0004 закрепил навсегда: `appId`, сертификат подписи, имена файлов релиза и
репозиторий релизов. Установленная копия проверяет новую версию правилом подписи
(идентификатор + отпечаток сертификата) и ищет её в репозитории, вшитом в сборку.

Сейчас ни одного релиза не было, установленных копий нет. Переименовать начисто можно
только до первого релиза: после него любая смена `appId` или сертификата требует
переходной версии.

## Варианты

1. **Чисто до первого релиза.** Новые `appId`, сертификат, имена артефактов,
   репозиторий релизов, переменные окружения, папка состояния, ключи окна.
   - Плюсы: старого имени не остаётся ни в подписи, ни в настройках macOS, ни в коде;
     переходного кода нет.
   - Минусы: установленные копии обновиться не смогли бы, но их нет. Dev-профиль
     разработчика и ключ шифрования коннекторов переносятся один раз руками.
2. **Сменить только видимое имя.** `appId` и сертификат прежние.
   - Плюсы: старые копии понимали бы новый релиз.
   - Минусы: `amazingide` навсегда в идентификаторе и в подписи. Смена `productName`
     всё равно переносит папку состояния и ключ safeStorage, так что перенос данных
     нужен и здесь.
3. **Переходный релиз.** Версия N под старым именем переносит данные и ключ, учит
   подмену бандла новому имени; версия N+1 уже новая.
   - Плюсы: установленные копии переходят сами.
   - Минусы: код и сценарий `update:e2e` для нуля пользователей.

## Решение

Вариант 1. Установленных копий нет, поэтому переходная версия никого не спасает, а
оставленный старый `appId` или сертификат несли бы старое имя во всех будущих подписях.
Новые значения: `appId` `io.github.crmapache.agenticworkstation`, сертификат
`Agentic Workstation Code Signing`, артефакты `agentic-workstation-mac-arm64.*`,
репозиторий релизов `crmapache/agentic-workstation-releases`, переменные
`AGENTIC_WORKSTATION_*`, пакеты `@agentic-workstation/*`, ключи окна
`agentic-workstation.*`.

## Факты и замеры

Проверено 2026-11-10 на Mac разработчика:

- релизов и тегов в `crmapache/amazing-ide-releases` - 0
  (`gh api repos/crmapache/amazing-ide-releases/releases --jq length`);
- установленных копий нет:
  `mdfind 'kMDItemCFBundleIdentifier == "io.github.crmapache.amazingide"'` - пусто;
- данные есть только в dev-профиле `~/Library/Application Support/Amazing IDE Dev`;
  папка установленной версии `Amazing IDE` пустая.

## Последствия

- Сертификат `Agentic Workstation Code Signing` теперь единственный и навсегда, с
  теми же правилами, что были у старого в ADR 0004. Старый `Amazing IDE Code Signing`
  и его `.p12` остаются в связке ключей и в корне, но ничего не подписывают.
- ADR 0004 в части имён (`appId`, сертификат, артефакты, репозиторий) заменён этой
  записью, устройство самообновления прежнее.
- Перенос dev-профиля - один раз руками: папку `Amazing IDE Dev` переименовать в
  `Agentic Workstation Dev`, ключ из записи связки `Amazing IDE Safe Storage`
  скопировать в `Agentic Workstation Safe Storage` до первого запуска, ключи
  `amazing-ide.*` окна переписать в `agentic-workstation.*`. Кода миграции в
  приложении нет: переносить больше некому.
- Пересматривать не нужно. Следующее переименование после первого релиза - только
  через вариант 3.

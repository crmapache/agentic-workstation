# 0048. Windows-версия: тот же код, сборка на Mac, своя подпись обновлений

- **Статус:** Принято
- **Дата:** 2026-11-11

## Контекст

IDE писалась под macOS (ADR 0001: «сначала macOS, потом Windows и Linux»): маковская шапка со
«светофором», клавиши через ⌘, пути только через «/», терминал zsh, поиск Claude через оболочку
входа, замер памяти через libSystem, самообновление подменой `.app` с проверкой подписи кода.
Владелец попросил Windows-версию и выпуск обеих систем одним скиллом, как в callmate: там
Windows собирается прямо на Mac, без второго компьютера. Сертификата подписи кода для Windows у
проекта нет, как нет и Developer ID у мака.

## Варианты

1. **Остаться на маке.** Ноль работы, но просьба не закрыта.
2. **Отдельная ветка кода под Windows.** Свободно, но две IDE расходились бы с первого дня.
3. **Тот же код с развилками по платформе, сборка Windows на Mac.** Развилки - в нескольких
   местах (`main/platform.ts`, `lib/platform.ts`), остальной код о Windows не знает. Сборка NSIS на
   Apple Silicon - без Wine, свежим набором NSIS у electron-builder, как в callmate. Минус - своей
   Windows у владельца нет, и проверяется она не каждый день руками.

Для обновления на Windows:

- **Как на маке - проверка подписи кода.** Нужен сертификат Authenticode: самоподписанный
  SmartScreen не убирает, а проверять его подпись из Node без Windows API - отдельная работа.
- **Только sha512 из манифеста.** Просто, но сумму подменит тот, кто подменит релиз.
- **Своя подпись Ed25519.** Закрытый ключ - на машине выпуска, открытый - вшит в IDE; подпись
  над sha512 установщика едет в манифесте. Подменённый релиз без ключа не пройдёт. Node умеет
  это сам.

## Решение

Вариант 3 и своя подпись обновлений.

- **Сборка:** `pnpm dist:win` - установщик NSIS x64 на одного человека, без прав
  администратора, в `%LOCALAPPDATA%\Programs`. Портативного exe нет: он распаковывает себя на
  каждом запуске. Бинарники терминала у каждой платформы свои (`mac.files`, `win.files`).
- **Окно:** кнопки окна Windows справа (`titleBarOverlay`), страница оставляет под них место
  по `env(titlebar-area-*)`; полосы меню нет, меню только держит сочетания клавиш. Крестик окна -
  выход тем же путём, что ⌘Q: окно закрывается, когда редактор сохранён и всё погашено, а
  отменённый выход (файл в конфликте) окно оставляет.
- **Клавиши:** записаны маковскими. На Windows `withMacKeys` превращает Ctrl в ⌘ для проверок,
  `shortcutLabel` рисует «Ctrl+Shift+T». ⌥⌘ на Windows - один Alt: Ctrl+Alt там AltGr. «Открыть
  панель» - Ctrl+Shift+Space: Ctrl+Esc забирает «Пуск». В терминале Ctrl+C с выделением копирует,
  Ctrl+V вставляет, как в Windows Terminal.
- **Пути:** путь от корня проекта в окне - всегда через «/» (`toWindowRelative`), абсолютный -
  путь системы; `lib/path.utils.ts` понимает диск, обе черты и сетевые пути.
- **Процессы:** у каждого дочернего процесса окно консоли скрыто одним местом
  (`windows/console-hide.ts`), программа со своим окном (браузер) - с пометкой `SHOWS_WINDOW`.
  Групп процессов как на маке нет: остановка гасит дерево `taskkill /T /F` сразу, пока корень
  жив, - после его выхода номер мог достаться чужому процессу, а потомков /T уже не найдёт.
- **Claude Code:** только `claude.exe` родного установщика - обёртку npm (`claude.cmd`) без
  оболочки не запустить, а через cmd.exe слова человека ломались бы на кавычках. Окружение -
  процесса, без оболочки входа; PATH одним ключом. Вход в аккаунты и `/design-login` - окном
  PowerShell (`.cmd` рядом со `.ps1`). Команды «!» и терминал - PowerShell.
- **Браузер для ИИ:** сокет - именованный канал, манифест host - через ключи реестра браузеров.
  Канал лежит в общем пространстве имён машины, поэтому IDE и host до первого кадра доказывают
  друг другу, что знают ключ моста из папки host (HMAC над числом другой стороны,
  `bridge-auth.ts`). На маке сокет закрыт правами файла, и проверки нет.
- **Файлы вне проекта:** на Windows системе отдаются только документы и медиа из белого списка,
  остальное показывается в Проводнике: запускаемого там слишком много для чёрного списка.
  Сетевой путь решается после нормализации, абсолютный путь - только с диском.
- **Память в строке состояния:** `privateBytes` из Electron, как в «Диспетчере задач».
- **Обновление:** установщик целиком. Ключ выпуска подписывает строку из назначения, сборки,
  версии, sha512 и размера: старый подписанный установщик под новым номером не пройдёт. IDE
  проверяет подпись до загрузки и sha512 с размером после, поднимает сторожа, который ждёт её
  полного выхода (до минуты) и запускает установщик тихо (`/S --updated --force-run`), и выходит;
  установщик ставит и открывает новую версию. Ключ - `agentic-workstation-update-signing.pem`
  (docs/code-signing.md).
- **Выпуск:** скилл `/build` вместо `/release` - мак и Windows одним релизом; `/reinstall` - на
  этом Mac, как в callmate.

## Факты и замеры

- Сборка Windows на этом Mac (Apple Silicon, electron-builder 26.15.3, набор NSIS 1.2.1):
  `pnpm dist:win` проходит без Wine, установщик - 118 МБ. Модули koffi под Windows в сборку не
  едут - на Windows koffi не грузится.
- Юнит-тесты на развилки: пути Windows (`lib/path.utils.test.ts`), клавиши (`lib/keys.test.ts`),
  подпись установщика (`updates/win-update.test.ts`), скрипты входа PowerShell
  (`accounts/design-login.test.ts`).
- **На настоящей Windows ещё не запускалось:** виндовый ноут для проверок сломался, другой
  Windows нет. Проверено по коду тремя ревью и тестами развилок на маке; что без Windows не
  проверить (кнопки окна поверх шапки, ConPTY в собранном приложении, Chrome и run-host.cmd по
  ключу реестра, вход claude.exe в своё хранилище, перезапуск после обновления) - первым делом
  при первой установке.

## Последствия

- Новое платформенное - развилкой в `main/platform.ts` или `lib/platform.ts`, а не
  `process.platform` по месту.
- Новое сочетание клавиш - маковской записью; подпись - через `shortcutLabel`/`shortcutKeys`,
  проверка - на `withMacKeys(event)`. Сочетание, которое Windows забирает себе, - своё на Windows.
- Путь в окно - `toWindowRelative` для пути от корня; разбор пути в окне - только через
  `lib/path.utils.ts`.
- Новый дочерний процесс с окном (браузер, программа человека) - с пометкой `SHOWS_WINDOW`.
- Что не сделано и почему: подписи кода Windows нет (SmartScreen предупреждает при первой
  установке); claude из npm не находится; Linux не собирается. Пересмотреть, когда появится
  сертификат Authenticode: тогда установщик подписывается им, а Ed25519 остаётся вторым ключом.

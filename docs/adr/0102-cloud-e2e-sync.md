# 0102. Облако IDE: свой сервис, записи шифром ключа аккаунта, версия на запись и долгий забор

- **Статус:** Принято
- **Дата:** 2026-11-20

## Контекст

Доски трекера (ADR 0101) должны жить в облаке: Windows-ноут владельца уже пропадал вместе с
данными, а на втором компьютере нужна та же доска. До этого IDE ничего не хранила вне машины:
политика сайта обещает, что код, разговоры и настройки - только на компьютере, релей Remote
Control (ADR 0041) ничего не хранит и ничего не читает, магазин расширений (ADR 0091) хранит
только публичное. Аккаунтов у IDE нет: личность в магазине - ключ установки.

## Варианты

**Где хранить.**

- **Папка iCloud Drive.** Плюсы: без сервера. Минусы: на Windows нужен iCloud для Windows,
  одновременная правка с двух машин даёт файлы-конфликты, слияние по полю не сделать.
- **Свой сервис открытым текстом.** Плюсы: данные видно в базе, их можно читать напрямую
  (телефон без IDE, облачные агенты). Минусы: доски человека лежат читаемыми на сервере, это
  меняет обещание политики.
- **Свой сервис, записи шифром ключа аккаунта (выбрано владельцем).** Плюсы: сервер хранит
  только id, версию и шифр - читать нечего; ключ подписи и ключ шифра выводятся из одного
  ключа аккаунта, поэтому регистрации нет. Минусы: потерян ключ - доски не вернуть никому;
  телефон без IDE доску не увидит без ключа.

**Как сливать правки двух машин.**

- **Последняя запись побеждает на сервере по времени.** Минусы: правка заголовка на одной
  машине и перенос карточки на другой - одна из них теряется.
- **Сервер принимает запись только на ту версию, что у него лежит (`baseRev`); спор - IDE
  забирает свежую, сливает по полю (ADR 0101) и пишет снова (выбрано).** Сервер шифр не
  читает и сливать не может - сливают машины, сервер только не даёт затереть невиданное.

**Как узнавать о переменах.** Опрос раз в N секунд - либо задержка, либо лишние запросы.
WebSocket - ещё один долгоживущий канал и своя переподключалка. Выбрано: долгий забор
(`GET /v1/pull?since&wait=25`) - сервер держит запрос до первой записи аккаунта или 25 секунд,
своя правка IDE прерывает ожидание и уходит сразу.

## Решение

Сервис `apps/cloud` (Node, `node:http`, SQLite в томе `/data`) на сервере владельца
(agentic-workstation-cloud.mzpizote.com, Coolify `aw-cloud`), протокол
`packages/cloud-protocol`, в IDE - `main/cloud/`. Ключ аккаунта - 32 случайных байта,
создаётся сам при первом запуске и лежит в `cloud.vault` (safeStorage); человек видит его
строкой Crockford base32 с контрольной суммой. Из него HKDF выводит ключ Ed25519 (подпись
запросов меткой `aw-cloud/v1`, адрес аккаунта на сервере) и ключ AES-256-GCM (шифр записи, id
записи - в доп. данных, чтобы сервер не подменил одну другой). Главная причина - выбор
владельца: доски в облаке, но читает их только он.

## Факты и замеры

- Протокол: 8 тестов (ключ туда и обратно, опечатка ловится контрольной суммой, одни ключи на
  любой машине, шифр не открывается чужим ключом, под чужим id и после порчи, подпись сходится).
- Сервер: 15 тестов на настоящем HTTP (подпись, повтор разового числа, спор версии, страницы,
  долгий забор с ранним ответом и истечением, чужой аккаунт, предел тела и аккаунта, уход
  клиента освобождает место ожидания) - `pnpm --filter @agentic-workstation/cloud test`.
- IDE: синхронизация на подделке облака (5 тестов: доска появляется на второй машине по
  origin, двойники пространств сливаются, правки разных полей сходятся, запись, обогнанная
  другой машиной, сливается и уходит снова, чужой ключ не открывает записи) и сквозной тест
  `CloudService` на настоящем сервере (3 теста: второй компьютер с тем же ключом видит доску и
  правки обоих, отказ на чужой текст вместо ключа, без сервера - offline и выключение).
- Боевое облако 2026-11-21: тот же сквозной тест против agentic-workstation-cloud.mzpizote.com
  прошёл (`AGENTIC_WORKSTATION_CLOUD_LIVE=https://agentic-workstation-cloud.mzpizote.com pnpm
--filter @agentic-workstation/desktop exec vitest run src/main/cloud/cloud-service.integration.test.ts`);
  копия окна (`/dev`) на боевом облаке - «Synced» через пару секунд; без подписи сервер отвечает
  `unsigned`; снимок базы для ежечасного бэкапа (`src/backup.ts`) снимается.
- Замера нагрузки нет: доска - сотни записей по сотне байт, запрос - миллисекунды.

## Последствия

- Политика сайта говорит про облако трекера (раздел «Task tracker and cloud sync»): новый путь
  данных наружу - сначала туда.
- Копии IDE для проверок ходят в облако по `AGENTIC_WORKSTATION_CLOUD_URL`; без него копия
  заводит пустой аккаунт в боевом облаке.
- Удалённые записи остаются отметками навсегда: без них старая копия воскресила бы удалённое.
  Сжатие отметок - когда их станет заметно много.
- Пересмотреть, если понадобится доска на телефоне без IDE (ключ аккаунта на телефон через
  пару Remote Control), общий доступ другим людям или восстановление без ключа.

# 0039. Сценарии на уровне IDE: очереди, worktree на очередь, провайдер - исполнитель

- **Статус:** Принято
- **Дата:** 2026-11-10

## Контекст

ADR 0014 убрал сценарии из панели Claude Code до переезда на уровень IDE, ADR 0015 дал им место

- вид середины окна. Владелец описал, каким должен быть переезд (PLAN.md): сценарии - IDE, а
  не провайдера; провайдер выбирается при запуске; несколько линий работы («веток») идут
  параллельно, у каждой своя очередь; линия может работать в отдельном git worktree; имя линии
  даёт ИИ; кроме паузы - «остановить после текущего» и «остановить после выбранного»; страница со
  всеми очередями. В ACC и в архиве IDE очередь была одна на проект и шла в папке проекта.

У владельца уже есть сценарии формата ACC на полках `.claude/scenarios` (roas-radar,
claude-code-ide). Движок прогона с «головой» из архива проверен тестами на подделке CLI и
повторяет ACC; переписывать его ради нового места незачем.

## Варианты

**Очередь - на проект, как в ACC; worktree - на каждый прогон.**

- Плюсы: модель ACC без изменений, меньше нового кода.
- Минусы: параллельной работы нет вовсе - пункт владельца не выполнен; прогон в своём
  worktree не видит результата предыдущего в той же линии.

**Очередь-ветка: именованная линия со своей очередью и своей папкой (проект или worktree на
всю очередь); очередей сколько угодно, параллельно.**

- Плюсы: закрывает все пункты владельца одной сущностью; следующий сценарий очереди видит
  работу предыдущего; две несвязанные работы не мешают друг другу, если хотя бы одна в worktree.
- Минусы: новая модель данных и свой исполнитель очередей; две очереди без worktree в одной
  папке могут мешать друг другу (окно запуска предупреждает).

**Провайдер - через полную абстракцию ClaudeService.**

- Плюсы: второй провайдер встал бы без оговорок.
- Минусы: переделка всей панели Claude Code за одну ночь, риск сломать то, что работает.

**Провайдер - узкий интерфейс исполнителя сценариев (`main/providers/`), движок говорит на
потоке stream-json Claude Code как на внутреннем формате.**

- Плюсы: панель не тронута; новое (сценарии, дальше статистика и удалённый доступ) говорит со
  словом «провайдер»; второй провайдер приносит переводчик своего потока.
- Минусы: формат движка завязан на Claude Code - перевод потока второго провайдера ляжет на него.

## Решение

Очередь-ветка с worktree на всю очередь (решение владельца) и узкий слой провайдеров. Очереди
живут в главном процессе, в `userData/scenario-queues.json` профиля IDE; решения очереди -
чистые правила (`queues/queue-rules.ts`), исполнение - `QueueRunner`. Worktree - вне проекта
(`~/.agentic-workstation/worktrees/<проект>-<хеш>/<slug>`, ветка `scenarios/<slug>` от текущего
HEAD), остаётся после очереди, пока человек не удалит; закрытая очередь без коммитов и правок
убирает его сама. Формат и полки сценариев - как в ACC.

## Факты и замеры

- Тесты: правила очереди (14), движок архива (64 вместе с хранилищами и автором), worktree на
  настоящем git (17), сквозной тест сервиса на подделке CLI, включая очередь в worktree (4).
- Живьём 2026-11-10 в копии окна (`/dev`), настоящий `claude -p` на haiku, временный репозиторий:
  запуск в новую очередь с именем от ИИ, очередь в worktree параллельно с очередью в папке
  проекта (файлы разошлись по папкам), остановка после выбранного, выход IDE посреди прогона и
  продолжение с места, вопрос человеку с числом на иконке вида, пауза, удаление worktree.
- Имя очереди: `claude -p --json-schema … --tools '' --model haiku` отвечает `{title}` за
  доли цента.
- Замера скорости нет: время прогона - время модели.

## Последствия

- `main/scenarios/` (движок, столы прогонов, очереди, расписание, полки), `main/providers/`,
  `main/git/git-worktree*.ts`, IPC-область `shared/ipc/scenarios.contract.ts`, вид
  `features/scenarios`. Расписание поднимает новую очередь со своим worktree и провайдером.
- Сессии сценариев получают коннекторы IDE по исходному проекту (ADR 0029) и не видны в истории
  и поиске панели (`claude/history/hidden-conversations.ts`). Разговор головы можно продолжить
  чатом - роль главного потока снимается (`claude/history/released-heads.ts`).
- Журнал шага рисуется лентой провайдера через контекст `state/conversation-log.context.ts`:
  фича сценариев не знает о панели Claude Code.
- Пересмотреть, если появится второй провайдер с другим потоком (тогда - переводчик или свой
  движок) или если очереди понадобится общая между dev и установленной IDE.

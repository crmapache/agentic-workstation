# 0125. Поиск CLI на Windows: PATH из реестра, папки установщиков, программа за обёрткой npm

- **Статус:** Принято
- **Дата:** 2026-11-25

## Контекст

Тестировщик на Windows (релиз 0.1.50): «клода сразу не нашла, пришлось путь искать». IDE искала
Claude Code только как `claude.exe` и только в PATH своего процесса (ADR 0048: «только
`claude.exe` родного установщика», «окружение - процесса, без оболочки входа», «claude из npm не
находится»). Этого мало по трём причинам.

- **npm.** Глобальная установка кладёт в PATH обёртку `%APPDATA%\npm\claude.cmd`, а `claude.exe`
  в PATH нет. Путь руками на `claude.cmd` (его показывает `where claude`) тоже отвергался: Node
  без оболочки `.cmd` не запускает (EINVAL), проверка `--version` молчала, и выходило «not-claude».
- **PATH процесса устарел.** Его наследуют от того, кто запустил IDE: установщика из браузера,
  открытого до установки CLI, или прошлой IDE после самообновления. Что winget или npm дописали в
  PATH позже, IDE не видит, хотя новый терминал видит.
- **Codex и OpenCode** искались так же (`codex.exe`, `opencode.exe`), а экран «не найден» сам велит
  ставить их через `npm install -g`. То есть на Windows они не находились никогда.

Родной установщик Claude (`%USERPROFILE%\.local\bin\claude.exe`) находился и раньше: эта папка
была в списке запасных.

## Варианты

**Где искать.**

- **PATH процесса (как было).** Плюсы: ничего не стоит. Минусы: см. выше, устаревает.
- **Спросить `where.exe`.** Минусы: он смотрит тот же PATH процесса, ничего не добавляет.
- **PATH из реестра и папки установщиков (выбрано).** PATH системы и человека из реестра - тот,
  что получит новое окно терминала. Плюс папки, куда CLI кладут установщики, даже если их нет в
  PATH: родной установщик Claude, ярлыки winget (на человека и на машину), npm, pnpm, Yarn,
  nvm-windows, Scoop, Chocolatey, Bun, Volta. Минусы: чтение реестра стоит запуска PowerShell.

**Как читать реестр.**

- **`reg.exe query`.** Плюсы: быстро. Минусы: пишет в трубу в кодовой странице OEM, путь с
  кириллицей в имени человека приходит кашей.
- **koffi и RegGetValueW.** Минусы: koffi на Windows не грузится (ADR 0048).
- **PowerShell, `[Environment]::GetEnvironmentVariable` с выводом в UTF-8 (выбрано).** .NET сам
  раскрывает `%ПЕРЕМЕННЫЕ%` в значениях REG_EXPAND_SZ. Минусы: старт до секунды, поэтому один раз
  за запуск IDE (как оболочка входа на маке) и заново только по кнопке «искать заново».

**Как запускать Claude из npm.**

- **Не поддерживать (как было).** Минусы: у всех, кто ставил через npm, панель пустая.
- **Обёртку `claude.cmd` через cmd.exe, как Kimi (`launchTarget`).** Минусы: в аргументах Claude
  текст, кавычки и JSON, а батник режет строку на переводе строки (опыт ACC); ADR 0048 это
  запретил не зря.
- **Прочитать обёртку и запускать её программу (выбрано).** Пакет npm несёт ту же родную
  программу, что и установщик (`bin/claude.exe`), обёртка только передаёт ей аргументы. Строку
  запуска пишет генератор npm (`"%dp0%\…"`) или pnpm и Yarn (`"%~dp0\…"`), её путь берётся от
  папки обёртки. Claude по-прежнему запускается только самой программой, без cmd.exe.

**Codex и OpenCode.** У Codex из npm за обёрткой не программа, а скрипт `codex.js`: его запускает
cmd.exe (`launchTarget`), как Kimi. Аргументы у Codex и OpenCode задаёт IDE (`app-server -c …`,
`serve --stdio`), слов человека в них нет. Обёртку над программой (OpenCode из npm) заменяет сама
программа, как у Claude.

## Решение

Один поиск на всех провайдеров - `main/process/cli-search.ts` (чистые функции) и
`binary-locator.ts` (машина): папки PATH, на Windows ещё папки установщиков, в каждой сперва
`.exe`, потом `.cmd` (порядок PATHEXT), обёртка менеджера пакетов заменяется её программой. Claude
и программы расширений берут только программу; Codex, OpenCode и агенты ACP - и обёртку над
скриптом, через cmd.exe. На Windows окружение CLI получает PATH из реестра
(`windows/registry-path.ts`, `shell-env.ts`), кнопка «искать заново» читает его снова. Путь руками
на `claude.cmd` принимается и превращается в её `claude.exe`. Главная причина: IDE должна находить
CLI там же, где его находит новый терминал человека, и не запускать Claude через cmd.exe.

Заменяет в [ADR 0048](0048-windows.md): «Claude Code: только `claude.exe` родного установщика»,
«Окружение - процесса, без оболочки входа» и «claude из npm не находится». Остальное в 0048
действует.

## Факты и замеры

- **Документация Claude Code** (code.claude.com/docs/en/setup и troubleshoot-install, 2026-11-25):
  родной установщик кладёт `%USERPROFILE%\.local\bin\claude.exe` и PATH сам не меняет; пакет npm
  ставит ту же родную программу через платформенную необязательную зависимость; winget -
  `Anthropic.ClaudeCode`.
- **`npm view <пакет>@latest bin`** (2026-11-25): `@anthropic-ai/claude-code` 2.1.332 -
  `bin/claude.exe`; `opencode-ai` 1.19.6 - `bin/opencode.exe`; `@openai/codex` 0.172.0 -
  `bin/codex.js`. Без postinstall на месте `bin/claude.exe` лежит заглушка в 500 байт.
- **Манифест winget** `Anthropic.ClaudeCode` 2.1.330 (microsoft/winget-pkgs): `InstallerType:
portable`, команда `claude` - ярлык в `WinGet\Links`.
- **Формат обёртки npm** сверен с генератором, который идёт с npm
  (`node_modules/npm/node_modules/cmd-shim/lib/index.js`): над программой - одна строка
  `"%dp0%\<путь>" %*`, над скриптом - `IF EXIST "%dp0%\node.exe"` и путь скрипта.
- **Тесты на маке** (платформа подменяется в зависимостях поиска, как в `acp-locator.test.ts`):
  `process/cli-search.test.ts` (родной установщик вне PATH, winget, npm, pnpm, Yarn, свой prefix
  npm в кавычках, Scoop, обёртка над скриптом, обёртка без программы, порядок, Codex и OpenCode
  из npm, разбор обёрток), `windows/registry-path.test.ts`, `claude/cli/cli-path.test.ts`,
  `acp/acp-locator.test.ts`. Соседние наборы: 59 файлов, 258 тестов прошли, 10 пропущены.
  Повтор: `pnpm --filter @agentic-workstation/desktop exec vitest run src/main/process
src/main/windows src/main/claude/cli src/main/acp src/main/codex src/main/opencode
src/main/extensions/host src/main/agents/panel src/main/providers`.
- **На настоящей Windows не проверено:** сколько занимает чтение PATH из реестра и не мелькает
  ли окно (потолок 5 с); раскрытие переменных в PATH человека; запуск `codex.cmd` через cmd.exe с
  настоящими аргументами коннекторов; winget без права на символьные ссылки (тогда он дописывает в
  PATH папку пакета, её видно только через реестр); каким способом Claude стоит у тестировщика.
  Первым делом при живой проверке - `where.exe claude` у него и панель после «искать заново».

## Последствия

- Новый CLI провайдера ищется через `findCommand` или `candidatesIn` и `launchableOf`, а не
  своим обходом PATH. Новая папка установщика на Windows - строкой в `WINDOWS_CLI_DIRS`.
- Claude на Windows запускается только программой: всё, что получает `cli.binary`, может звать
  его без оболочки. Процесс провайдера, который может оказаться обёрткой `.cmd`, запускается через
  `launchTarget`.
- «Искать заново» теперь и на маке перечитывает оболочку входа (до секунды на нажатие).
- Пересмотреть, если пакет npm Claude Code снова станет скриптом (тогда npm-установка опять не
  найдётся, а cmd.exe для Claude по-прежнему нельзя) или если PowerShell на машинах людей окажется
  медленным или запрещённым: тогда `reg.exe` с определением кодовой страницы.

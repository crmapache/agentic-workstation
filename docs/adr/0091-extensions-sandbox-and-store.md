# 0091. Расширения IDE: песочница QuickJS, права, интерфейс деревом, общий магазин

- **Статус:** Принято
- **Дата:** 2026-11-19

## Контекст

Владелец просит раздел плагинов: каждый человек с ИИ пишет свой плагин и меняет почти любое
поведение IDE. Ручки должны чётко ограничивать вмешательство и при этом быть как можно шире.
Следом - общий магазин на сервере: плагин публикуется, его видят и ставят все, у него оценки и
отзывы, и всё это внутри IDE.

Что мешало взять готовое. «Плагины» в IDE уже есть - плагины Claude Code (экран панели, каналы
`plugins:*`), поэтому новое называется Extensions. Главный процесс держит всё состояние (ADR
0003), окно не трогает Node (ADR 0002), дизайн-система строгая (ADR 0006): чужой HTML её бы
сломал. Разговоры идут у трёх провайдеров (ADR 0083, 0085), а не только у Claude.

## Варианты

**Где исполнять код расширения.**

- **В окне или главном процессе как есть (как VS Code).** Плюсы: всё доступно, ноль кода
  песочницы. Минусы: расширение может всё, что может IDE, - читать ключи, ломать окно, вешать
  главный процесс; «ограничить ручками» нечем.
- **`node:vm` в главном процессе.** Плюсы: без зависимостей. Минусы: не граница безопасности
  (выход через `constructor.constructor` известен), вечный цикл вешает весь процесс.
- **Скрытое окно Chromium с `sandbox: true`.** Плюсы: настоящая песочница. Минусы: процесс на
  расширение (десятки МБ), сеть и таймеры надо отрезать от браузера, проверять только в Electron.
- **QuickJS в WebAssembly в отдельном потоке (выбрано).** Плюсы: у кода нет ничего, кроме того,
  что дали (ни Node, ни DOM, ни сети); у каждого расширения свой модуль WASM со своей памятью и
  потолком; срок на каждый заход в код; поток не держит окно; проверяется в vitest без Electron.
  Минусы: интерпретатор медленнее V8 в десятки раз (для логики расширений хватает), пакеты npm
  в песочницу не ставятся - только свои модули папки.

**Как расширению рисовать интерфейс.**

- **Свой HTML в iframe-песочнице.** Плюсы: что угодно. Минусы: свой стиль мимо дизайн-системы,
  поверхность для XSS и фишинга внутри IDE.
- **Декларативное дерево из примитивов дизайн-системы (выбрано).** Плюсы: всё нарисованное
  выглядит своим, раскладку не сломать, проверка дерева - схемой. Минусы: только то, что есть в
  словаре узлов; новый узел - правка IDE.

**Личность в магазине.**

- **Вход через GitHub.** Плюсы: настоящее имя, меньше накрутки. Минусы: своё OAuth-приложение
  владельца, сеть до GitHub у каждого, вход - отдельный шаг человека.
- **Ключ Ed25519 этой IDE в хранилище ключей (выбрано).** Плюсы: ни паролей, ни аккаунтов,
  подпись каждого запроса, владелец расширения - ключ, который его первым опубликовал. Минусы:
  потерял ключ (новая машина) - новые версии старого расширения не опубликовать; ключей можно
  наделать сколько угодно, поэтому отзыв - только у того, кто ставил, и не у своего.

## Решение

Расширение - папка `~/.agentic-workstation/extensions/<id>/` (у копии с профилем - внутри
профиля) с `extension.json` и ES-модулем. Главный процесс (`main/extensions/`) находит папки,
следит за ними и перезапускает расширение на каждое сохранение его файлов. Код исполняется в
QuickJS (`quickjs-emscripten`, вариант `wasmfile-release-sync`) в одном потоке-воркере: свой
модуль WASM на расширение с памятью WebAssembly до 64 МБ, срок 1 с на каждый синхронный заход,
модули - только относительными путями из своей папки по настоящему пути. Наружу - глобальный
`ide` (прелюдия на JS внутри песочницы) и один мост `host(method, payload)` JSON-ом.

Ручки делятся на две ступени. Без прав: команды (поиск действий, клавиши, которые IDE не
занимает), свои виды с иконками в полосах середины и левой панели, до трёх пунктов строки
состояния, уведомления, вопросы человеку (prompt, confirm, pick), тема (токены `--color-*`,
`--palette-*`, `--font-family-*` без `url(`), своё хранилище, настройки из манифеста (секреты -
в хранилище ключей), таймеры, журнал. С правами, которые выдаёт человек: `files.read`,
`files.write` (только открытые проекты, по настоящему пути, удаление - в корзину), `agent.observe`
(конец хода любого разговора), `agent.intercept` (переписать сообщение до модели, отклонить
вопрос разрешения - разрешить нельзя), `ide.control` (все инструменты workstation, ADR 0090),
`ai.tools` (инструменты для ИИ во встроенном коннекторе `extensions`), `network` (только хосты
манифеста, и перенаправления тоже), `shell` (только программы манифеста, без оболочки),
`clipboard`. Просит шире выданного - стоит «ждёт одобрения». Хуки разговоров - в ядре панелей
(`ConversationOutbox`, `ConversationRuntime.hold`, `settleTurn`), одинаково для Claude, Codex и
OpenCode, со сроком: перед отправкой 3 с, охрана 2 с.

Интерфейс расширения - дерево узлов (`shared/extension-ui.ts`), его проверяет схема и рисует окно
примитивами дизайн-системы (`features/extensions/ExtensionSurface`). Новое расширение пишет ИИ:
IDE кладёт заготовку с руководством (`AGENTS.md`, `CLAUDE.md`, `ide.d.ts`), открывает папку
проектом и начинает разговор выбранного провайдера; проверяет себя ИИ инструментами
`list_extensions`, `extension_logs`, `reload_extension`, `run_extension_command`.

Магазин - свой сервер `apps/store` (Node, SQLite в томе) и пакет протокола
`packages/store-protocol`. Пакет расширения - JSON с манифестом и текстовыми файлами (без архива,
пути проверяются), отпечаток - sha256 канонического JSON; IDE сверяет его после скачивания и
разбирает манифест своим разбором. Запись подписывается ключом IDE (время, разовое число,
отпечаток тела). Своё расширение с тем же id магазин не затирает; обновление, которое просит
шире, ждёт одобрения; новая установка получает права, которые человек видел у кнопки «Install
and allow».

## Факты и замеры

- Проба QuickJS (Node 24, M5 Pro, `/tmp/qjs-probe`): модуль WASM поднимается за 3 мс, контекст -
  за 1 мс; пять модулей со своей памятью - +16 МБ RSS. Счёт памяти QuickJS без
  `malloc_usable_size` не видит строк (лимит 4 МБ, а набрано 2 ГБ), поэтому потолок - память
  WebAssembly: при 64 МБ та же нагрузка - «out of memory» внутри песочницы, процесс жив.
- Вечный цикл обрывается по сроку: в проверке срок 100 мс, ответ - меньше 2 с с поломкой
  `timeout`; задание 1 с в IDE.
- Проверки: песочница (10: модуль и колбэки, асинхронный мост, нет Node и `Function` наружу,
  журнал, срок, память, импорт за папку и по ссылке, сбой модуля, таймеры, deactivate), манифест и
  права (6), дерево и тема (4), сервис целиком на настоящей песочнице (8: без прав, одобрение и
  отказ без права, выход за проект, три хука, инструменты ИИ, срок, настройки и секреты,
  выключение и удаление), хуки (2), инструменты workstation (3), заготовка (2), сводка хода (2),
  клавиши (2), значения полей вида (2), сервер магазина на настоящем HTTP (6: публикация и
  каталог, подпись и повтор, владелец и версия, отзыв только после установки, имя и модерация,
  путь наружу в пакете), магазин внутри IDE с настоящим сервером (3: автор публикует - другая IDE
  ставит, запускает, оценивает, получает обновление, которое ждёт одобрения; своя папка не
  затирается; без сети - offline).
- Повторить: `pnpm --filter @agentic-workstation/desktop exec vitest run src/main/extensions`,
  `pnpm --filter @agentic-workstation/store test`.

## Последствия

- Новая ручка - метод в `main/extensions/host/*-methods.ts` с правом, функция в прелюдии
  (`engine/prelude-api.ts`) и строка в `authoring/templates/ide.d.ts.txt` и `AGENTS.md.txt`: без них
  ИИ о ручке не узнает. Новый узел интерфейса - тип в `shared/extension-ui.ts`, схема в
  `host/ui-tree.ts`, компонент в `ExtensionSurface/parts`.
- Право расширения действует, только пока его и просит манифест, и выдал человек
  (`effectiveGrant`); выданное раньше, но больше не просимое, не действует.
- Хук не держит разговор дольше своего срока и не может расширить права разговора.
- Расширения не попадают на телефон Remote Control: их виды и команды - только в окне.
- Магазин выкладывается скриптом `apps/store/scripts/store-deploy.sh` после того, как владелец
  заведёт приложение Coolify; пока сервера нет, вкладка Store говорит «магазин не отвечает».
- Отпечаток пакета IDE сверяет с тем, что сообщил сам магазин: это защита от порчи в пути, а не
  от взломанного сервера. Следующий шаг, если магазин станет большим: автор подписывает отпечаток
  своим ключом, IDE запоминает ключ автора при первой установке и не ставит обновление, подписанное
  другим. Песочница и права при этом остаются главной границей: даже подменённый пакет может только
  то, что человек выдал этому расширению.
- Пересмотреть, если расширениям понадобятся пакеты npm (сборка в один модуль при публикации),
  настоящий вход в магазин (GitHub) или свой HTML (iframe-песочница рядом с деревом).

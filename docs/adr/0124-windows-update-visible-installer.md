# 0124. Обновление на Windows: установщик с окном, журнал сторожа, host браузера снят на установку

- **Статус:** Принято
- **Дата:** 2026-11-25

Дополняет [0048](0048-windows.md): заменяет в нём только то, как сторож запускает установщик
(было тихо, `/S --updated --force-run`).

## Контекст

Тестировщик на Windows: IDE видит обновление, качает его, закрывается, и на этом всё. После
ручного запуска та же старая версия предлагает то же обновление. На настоящей Windows путь
обновления из ADR 0048 до этого не запускался ни разу.

Разбор по коду однозначной причины не дал. Опубликованный установщик 0.1.51 проверен: внутри
версия 0.1.51, подпись ключа выпуска сходится. Зато нашлись три слабых места:

- **Следа нет.** У собранной IDE на Windows нет консоли, и `console.warn` уходит в никуда.
  Сторож ничего не пишет, журнал NSIS в сборке electron-builder выключен.
- **Тихий установщик (`/S`) уходит молча на любом сбое.** Шаблон electron-builder
  (`allowOnlyOneInstallerInstance.nsh`) гасит процессы из папки установки. Если за два круга
  (около 8 с) они не погасли, срабатывает `/SD IDCANCEL` и `Quit` без единого окна.
- **Такой процесс у нас есть: native host коннектора Browser.** Это exe IDE из папки установки
  (`run-host.cmd`). Он живёт и без IDE, ждёт её, а Chrome по зову расширения поднимает его снова
  через 1, 2, 4 с после каждого убийства (`host-link.ts`). Второй кандидат - exe IDE, запущенный
  от администратора: его не погасить ни сторожу, ни установщику.

Кроме того, даже удачная тихая установка - это десятки секунд без единого окна. Человек решает,
что ничего не происходит, и открывает IDE руками посреди установки.

## Варианты

**Как ставить:**

1. **Оставить `/S` и добавить только журнал.** Плюс - минимум правок. Минус - сбой по-прежнему
   не виден человеку, гонка с host остаётся, и остаются десятки секунд пустоты.
2. **Перейти на electron-updater.** Плюс - проверенный путь. Минус - другой формат релиза и
   другая проверка подписи, от которых ADR 0004 и 0048 отказались осознанно. Установленные копии
   ждут наш манифест, а гонку с host он не решает.
3. **Установщик без `/S`, сторож с журналом.** Плюс - прогресс виден, сбой показывает окно NSIS
   с Retry, каждый шаг остаётся в `update.log`. Минус - на экране окно установщика, то же, что
   при первой установке.

**Как не дать Chrome поднять host посреди установки:**

- **Положиться на цикл NSIS и растущую паузу расширения.** Это гонка: исход зависит от
  скорости машины.
- **Метка «идёт обновление», которую проверяет `run-host.cmd`.** Обёртку переписывает только
  IDE с включённым коннектором. Забытая метка ломает Browser до следующего запуска.
- **Снять регистрацию host в реестре на время установки.** Без ключа `NativeMessagingHosts`
  Chrome host не запускает вовсе. Ключи возвращаются после установщика при любом исходе. Новая
  версия на старте с включённым коннектором регистрирует host заново и сама.

## Решение

Вариант 3 и снятие регистрации host. Главная причина: сбой обновления больше не бывает
невидимым ни для человека, ни для разбора.

Сторож (`main/updates/win-install-watch.ts`, PowerShell 5.1) делает по порядку:

1. Ждёт выхода IDE до минуты. Не дождался (выход отменили) - убирает установщик и уходит.
2. Снимает регистрацию host этой IDE во всех браузерах, запомнив значения.
3. Гасит всё, что живёт из папки установки, и пишет, что это было. Процесс IDE с невидимым
   путём (запущен от администратора) тоже уходит в журнал.
4. Запускает установщик с `--updated --force-run` без `/S` из временной папки. Ждёт выхода
   только его самого и пишет код выхода.
5. При любом исходе возвращает регистрацию host. Код не 0 - открывает установленную версию,
   как подмена на маке.

Всё пишется в `update.log` в папке журналов IDE, туда же, куда пишет маковский скрипт подмены.
Шаги самой IDE (загрузка, запуск сторожа, отказ) - туда же.

## Факты и замеры

- **Шаблоны electron-builder 26.15.3** (`app-builder-lib/templates/nsis`):
  - `--updated` и `--force-run` проверяются по командной строке и от тихого режима не зависят
    (`nsisScriptGenerator.js`, `flags`).
  - С `--updated` окна «приложение запущено, закрыть?» нет: установщик сразу гасит процессы
    (`allowOnlyOneInstallerInstance.nsh:108-119`).
  - Не погасли - окно «cannot be closed» с Retry и Cancel. Retry - новый круг, Cancel - выход,
    и старая версия цела (строки 153-157). Тупика нет.
  - Без `/S` и с `runAfterFinish` новая версия запускается сама, с аргументом `--updated`
    (`installSection.nsh:91-97`, `common.nsh`, `StartApp`).
  - Старый деинсталлятор установщик всегда зовёт с `/S` (`installUtil.nsh:224`). Если он не
    справился, окно показывает уже установщик.
- **Регистрация host на старте есть.** `BrowserDesk.sync` на старте IDE с включённым
  коннектором зовёт `installBridge`, а тот пишет ключи всех браузеров. У выключенного
  коннектора ключи возвращает сам сторож.
- **Прогон скрипта.** Скрипт сторожа прогнан в PowerShell 7.7 (macOS arm64) с подменёнными
  командлетами. Сценарии:
  - успех;
  - сбой установщика (код 2): регистрация вернулась, открыта старая версия;
  - IDE не вышла: установщик убран, реестр не тронут;
  - установщика нет;
  - нет доступа к процессу IDE: вместо ожидания опрос;
  - процесс, который не гасится, и процесс с невидимым путём.

  Скрипт передавался одним многострочным аргументом `-Command`, коды выхода 0 и 1, ошибок
  разбора нет. Windows PowerShell 5.1, настоящий реестр и окно установщика не проверены:
  Windows нет.

- Юнит-тесты - `updates/win-install-watch.test.ts` (текст и порядок шагов сторожа, аргументы
  установщика, снятие и возврат регистрации host), `updates/update-log.test.ts`. Повтор:
  `pnpm --filter @agentic-workstation/desktop exec vitest run src/main/updates/`. Обвязка с
  подменёнными командлетами для PowerShell была разовой и в репозиторий не легла.

## Последствия

- **Обновление выполняет сторож той версии, что уже стоит.** Исправление действует только на
  обновления с этой версии. Копии, где обновление не проходит, один раз ставят новую версию
  руками, по постоянной ссылке на установщик.
- **При жалобе на обновление Windows первым делом просить журнал:**
  `%APPDATA%\Agentic Workstation\logs\update.log`.
- **Пока идёт установка, расширение в Chrome видит «host не найден».** После установки оно
  подключается само: его будильник срабатывает раз в минуту.
- **Сторож трогает в реестре только ключи host этой IDE:** канал installed, у отдельного профиля
  dev.
- **Пересмотреть после первой проверки на настоящей Windows.** Если окно установщика не выходит
  на передний план или Windows PowerShell 5.1 ведёт себя иначе, чем 7.7, - менять запуск, а не
  возвращать `/S`.

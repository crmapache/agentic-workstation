# 0028. Коннекторы к приложениям держит IDE, провайдеры получают их через локальный MCP-шлюз

- **Статус:** Принято, дополнено [0029](0029-claude-connectors-only.md)
- **Дата:** 2026-10-25

## Контекст

Владелец работает с почтой, Notion, Slack и календарём через агентов, и сейчас это ломается
в трёх местах.

1. **Вход в MCP-сервер живёт вместе со входом в Claude.** CLI кладёт токены MCP
   (`mcpOAuth`) в ту же запись Keychain, что и вход в аккаунт (`claudeAiOauth`). Аккаунт
   панели - своё хранилище входа (`CLAUDE_SECURESTORAGE_CONFIG_DIR`, ADR 0009), и у
   нового аккаунта входов в MCP нет. Проверено 2026-10-18: в обычной записи живые токены
   Slack и Notion, в девяти записях аккаунтов - ни одного.
2. **Коннекторы claude.ai** (Gmail, Calendar, Drive) живут на сервере Anthropic и
   привязаны к аккаунту claude.ai. У ChatGPT-коннекторов Codex то же самое.
3. **Один сервис - один вход.** Две почты Google (рабочая и своя) или два Notion в одном
   конфиге не уживаются: у сервера одно имя и один токен.

Нужно: коннекторы не зависят ни от провайдера (Claude Code, Codex, следующие), ни от его
аккаунта; одного типа их может быть сколько угодно; смена аккаунта Claude ничего не трогает.

Что известно о сервисах (проверено 2026-10-25):

- **Notion** - официальный MCP `https://mcp.notion.com/mcp`, OAuth 2.1 с динамической
  регистрацией клиента (RFC 7591). Своё приложение не нужно. Адрес возврата сверяется
  строго, со всем портом.
- **Slack** - официальный MCP `https://mcp.slack.com/mcp`, адреса входа отдаёт сам
  (`/.well-known/oauth-protected-resource`), но динамической регистрации нет: нужен свой
  Slack app (client id и secret), внутренний для рабочего пространства или из каталога, с
  включённым MCP. Приложение действует в одном рабочем пространстве.
- **Google** - свои MCP для Gmail и Calendar (`gmailmcp.googleapis.com`) пока в Developer
  Preview: нужен членский доступ в программу и Web-клиент с заранее известными адресами
  возврата. Обычные Gmail API и Calendar API открыты, вход - OAuth «приложения на
  компьютере» с возвратом на любой порт 127.0.0.1. Свой клиент Google создаётся вручную в
  Cloud Console: API для этого нет.
- **Claude Code** принимает серверы при запуске (`--mcp-config`) и держит при этом свои.
  **Codex** - через `-c mcp_servers.<имя>...` (версия 0.163).

## Варианты

1. **Копировать конфиги в каждый CLI** (так делает мост `sync-claude-harness.py` для
   Codex). Просто, ничего не нужно держать запущенным. Но входы всё равно делает каждый
   CLI сам и кладёт в своё хранилище, то есть пункт 1 контекста остаётся, а два экземпляра
   одного сервиса так и не уживаются.
2. **IDE ведёт входы и запускает для каждого коннектора свой процесс MCP-сервера** (stdio)
   и прописывает его в CLI командой. Токены у IDE, но процесс сервера на каждый разговор и
   каждый коннектор: десяток разговоров на пять коннекторов - полсотни процессов. И у
   Notion или Slack нет stdio-сервера, их всё равно пришлось бы проксировать.
3. **IDE ведёт входы и поднимает один локальный HTTP-шлюз MCP.** Каждый коннектор -
   отдельный сервер на шлюзе (`/mcp/<имя>`), CLI получает их адресами. Шлюз сам ходит в
   Notion и Slack (прокси к их MCP) и сам реализует Gmail и Calendar поверх API Google.
   Сложнее: свой HTTP-сервер в главном процессе, свой OAuth, свой формат инструментов.
   Зато токены не покидают IDE, процесс один, и правила доступа (что можно, что нельзя)
   держатся в одном месте для любого провайдера.

## Решение

Третий вариант. Только он закрывает все три пункта: вход делает IDE и хранит его у себя,
провайдер видит просто локальный сервер без входа, и экземпляров одного типа сколько
угодно - у каждого своё имя на шлюзе и свой токен в хранилище IDE.

Как устроено:

- **Имя сервера** - тип и подпись: `gmail-work`, `calendar-personal`, `notion-reclick`,
  `slack-work`, `mcp-<подпись>` у своего адреса. Имя всегда несёт сервис, поэтому модель
  не путает экземпляры, а хук владельца `block-outbound.sh`, который ловит отправку по
  имени инструмента (`*gmail*send*`, `*slack*send*`), узнаёт и наши.
- **Шлюз** - `127.0.0.1`, порт выбирает система на каждый запуск, каждый запрос - с ключом
  этого запуска (`Authorization: Bearer`) и с проверкой заголовка Host (защита от DNS
  rebinding). Без ключа шлюз не отвечает, даже если порт кто-то нашёл.
- **Подключение к Claude Code** - файл `--mcp-config` в userData (права 600), все
  коннекторы сразу. Набор серверов поменялся (добавили, удалили) - процессы разговоров
  перезапускаются, как только свободны (как после `claude mcp add`). Внутри сервера
  поменялось (вход, выключили инструмент) - живым процессам `mcp_reconnect` по этому
  серверу. Выключенный или не вошедший коннектор отвечает пустым списком инструментов и
  пояснением для модели.
- **Хранилище** - реестр без секретов (`connectors.json`) и хранилище секретов, зашифрованное
  `safeStorage` Electron (ключ в Keychain самой IDE). Нет шифрования - секрет не пишется.
- **Вход** - код в браузере и возврат на `http://localhost:5319/callback` (порт в
  `~/.claude/ports.md`). Порт один на все входы: Notion сверяет адрес строго, у Slack app
  адрес вписывается в настройки руками. Notion, Slack и свой MCP - через OAuth из
  `@modelcontextprotocol/sdk` (поиск адресов, регистрация, PKCE, обновление). Google -
  свой маленький поток «приложения на компьютере» с PKCE.
- **Доступ к инструментам** - три ступени: чтение, запись, отправка людям (письмо,
  сообщение, ответ на приглашение, комментарий). Отправка по умолчанию выключена у
  каждого инструмента, включить её может только человек в IDE (вид Connectors): ни модель, ни
  провайдер до этого переключателя не дотягиваются. Ступень у своих инструментов задана
  в коде, у чужих (Notion, Slack, свой MCP) - по пометкам MCP и имени.
- **Google** - свой клиент OAuth владельца («приложение на компьютере»), один на все
  экземпляры Gmail и Calendar: IDE берёт файл клиента, скачанный из Cloud Console.
  Gmail - `gmail.modify`, Calendar - события и список календарей. Отправки письма нет
  среди включённых по умолчанию, приглашения в календарь гостям не уходят
  (`sendUpdates=none`).
- **Slack** - client id и secret своего Slack app у каждого экземпляра: приложение
  действует в одном рабочем пространстве.

Не вошло сейчас и ждёт своей записи: коннектор, который пишет агент по документации
сервиса (описание инструментов, вход подставляет шлюз), шлюз для процессов вне IDE
(терминал, плагин JetBrains), выбор коннекторов по проекту, stdio-серверы через шлюз.

## Факты и замеры

- Записи Keychain посмотрены `security find-generic-password -s "Claude Code-credentials[-<хеш>]" -w`
  с разбором ключей JSON без вывода значений.
- Notion, Slack, Google: страницы `developers.notion.com/guides/mcp/build-mcp-client`,
  `docs.slack.dev/ai/slack-mcp-server`, `developers.google.com/workspace/guides/configure-mcp-servers`.
- Флаги CLI: `claude --help` (2.1.293) и `codex mcp --help` (0.163.0).
- Проверено вживую 2026-10-25 в копии окна (`/dev`): свой MCP DeepWiki добавлен из
  настроек, настоящий `claude -p --mcp-config <файл шлюза>` (2.1.293) увидел сервер
  `mcp-deepwiki`, его пояснение и вызвал инструмент через шлюз; выключенный в настройках
  инструмент пропал из списка, прямой вызов получил отказ. Notion: поиск адресов и
  регистрация клиента SDK с возвратом на `localhost:5319` проходят до экрана согласия.
  Slack: адреса входа находятся сами (`/.well-known`), права берутся из его метаданных.
  Вход Google, Notion и Slack до конца - только руками владельца (свой клиент Google,
  свой Slack app).
- Замера скорости шлюза нет: запрос к локальному порту - доли миллисекунды рядом с сетью
  до Google или Notion.

## Последствия

- Смена аккаунта Claude и смена провайдера коннекторов не касаются.
- Коннекторы работают, пока открыта IDE: шлюз живёт в её главном процессе. Агент в
  терминале и плагин JetBrains их пока не видят.
- У dev и установленной IDE коннекторы разные: у каждой своя папка userData.
- Новый тип коннектора - модуль в `main/connectors/kinds/`: описание типа, инструменты или
  адрес MCP, ступени доступа.
- Пересмотреть, если Google откроет свои MCP для всех (тогда Gmail и Calendar станут
  прокси, как Notion) или если CLI научатся хранить входы MCP отдельно от аккаунта.

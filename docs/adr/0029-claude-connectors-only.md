# 0029. У Claude в IDE MCP - только коннекторы IDE: по проектам, с командами, импортом и коннектором от ИИ

- **Статус:** Частично заменено [0033](0033-all-projects-no-exceptions.md) (исключения у «во всех»)
- **Дата:** 2026-10-25

## Контекст

После ADR 0028 у Claude Code в IDE было два источника MCP: коннекторы IDE и всё, что CLI
сам читает из конфига человека, плагинов и claude.ai (экран MCP панели). Второй источник
и был болью: входы в нём живут с аккаунтом Claude и слетают при его смене, плагины
приносят серверы, которые вечно просят вход. Владелец попросил:

- в Claude внутри IDE MCP-экран убрать, MCP - только коннекторы;
- выбирать коннекторы для каждого проекта отдельно;
- создавать коннектор с помощью ИИ сразу при добавлении.

Оригинальный плагин amazing-claude-code и терминальный Claude это не затрагивает: речь
только о Claude внутри IDE.

## Варианты

**MCP у Claude в IDE.**

1. Оставить экран MCP рядом с коннекторами. Ничего не теряется, но остаются оба мира:
   серверы с входом Claude слетают на смене аккаунта, а у человека два места настройки.
2. Строгий список: процесс получает `--strict-mcp-config` и только файл шлюза IDE. Один
   источник, входы не зависят от аккаунта. Минус - свои серверы человека (chatkepr,
   Playwright, Graphite) пропали бы. Это закрывается двумя вещами ниже: коннектор
   «MCP-команда» и перенос серверов из конфига Claude Code.

**Выбор по проектам.**

1. Писать серверы в конфиг Claude Code проекта (область local в `~/.claude.json`). Родной
   механизм CLI, но IDE начала бы править чужой конфиг, а ключи лежали бы там открыто.
2. Доступность у самого коннектора (везде, кроме…; или только в…) и свой файл
   `--mcp-config` с собственным ключом у каждого процесса разговора: по ключу шлюз знает
   проект и отказывает выключенному в нём. Ключ проекта, вычисленный из пути, не годился:
   любой процесс с общим ключом шлюза назвался бы любым проектом. Всё остаётся у IDE;
   выключение действует сразу, даже на процесс, поднятый раньше.

**Процесс MCP-команды.**

1. Один процесс на коннектор, общий для всех разговоров. Экономно, и сервер с одним
   профилем (браузер с постоянным входом) не спорит сам с собой. Но два разговора
   уводили бы друг у друга страницу Playwright, а у Claude Code каждый процесс CLI
   поднимал свою копию - схема «один инстанс на поток» держалась на этом.
2. Своя копия на каждый процесс разговора и общий процесс переключателем у коннектора.
   Гибко, но переключатель говорит об устройстве процессов, а не о задаче человека, и
   владелец его отверг: для параллельной работы он заводит разные коннекторы
   (playwright-1 и playwright-2), а не режим одного.
3. Своя копия на каждый процесс разговора, в папке его проекта, всегда - как у Claude
   Code. Внутри разговора (и его субагентов) сервер один. Копия поднимается только на
   первый вызов и гаснет с процессом разговора; список инструментов для плитки - разовым
   процессом. Сервер с одним профилем (браузер с постоянным входом) в двух разговорах
   разом спорит сам с собой - так же, как в Claude Code.

**Коннектор от ИИ.**

1. ИИ пишет код MCP-сервера, IDE его запускает. Гибко, но это чужой код с доступом к
   машине и к ключу; проверить его человек не сможет.
2. ИИ пишет описание: базовый адрес, способ входа и инструменты как HTTP-запросы. Шлюз
   исполняет описание сам: подставляет ключ, не выпускает запрос за базовый адрес,
   ступень доступа берёт строже из двух (от ИИ и по имени инструмента). Покрывает сервисы
   с личным ключом (большинство: Todoist, Linear, GitHub, intervals.icu), а сервисам
   только с OAuth честно отвечает «не выйдет».

## Решение

- **Строгий список.** Процесс разговора запускается с `--strict-mcp-config`; MCP у него -
  только коннекторы IDE. Экран MCP панели удалён, вместо него - вид Connectors в середине
  окна (четвёртая иконка полосы видов, рядом с файлом, сценариями и статистикой; своей строки
  в меню панели у него нет - иконки хватает): подключённые - плитками сеткой, каталог нового -
  отдельной сеткой под ними, подробности и формы - окном по центру (ADR 0030). Проекты
  выбираются у самого коннектора: во всех (лишние выключаются) или только в отмеченных.
- **Коннектор «MCP-команда»** (stdio) - третий вариант: своя копия на процесс разговора,
  всегда, как у Claude Code. Её поднимает шлюз с окружением оболочки входа (PATH до
  npx и node); строка команды раскрывает `~` и `$NAME`, как терминал. Переменные с ключами
  и аргументы с ключом - в хранилище IDE, в реестре - маска. Выключенный коннектор команду
  не запускает.
- **Перенос из Claude Code**: серверы из `~/.claude.json` (общие и свои для открытых
  проектов) и `.mcp.json` открытых проектов - только доверенных папок, без отклонённых в
  Claude Code; неодобренные помечены, а серверы `.mcp.json` по умолчанию не отмечены: их
  принёс репозиторий, а не человек. Имена те же (на них опираются правила и хуки
  человека: `mcp__chatkepr__…`), а если IDE имя меняет - это видно в списке. `${VAR}`
  раскрывается из оболочки, как у Claude Code; переменной нет - сервер не переносится.
  Ключи из env, заголовков, адреса и аргументов - в хранилище, свой для проекта сервер
  виден только в нём и запускается в его папке. Сервер по адресу без заголовков
  проверяется пробой своим протоколом: 401 - OAuth, пустил - без входа, не ответил -
  не переносится (вход не узнать). Конфиг Claude Code не меняется.
- **Доступность по проектам** - второй вариант. Перезапуск при смене - только у
  процессов тех проектов, где видимость поменялась. Это фильтр видимости, а не песочница:
  конфиги всех процессов лежат в userData одного пользователя, и процесс с Bash прочтёт
  чужой. Конфиг не записался - разговор идёт без коннекторов и говорит об этом в ленте.
- **Коннектор от ИИ** - второй вариант. Описание пишет `claude -p` с ответом по
  JSON-схеме (`--json-schema`). Инструменты - белым списком (`--tools WebFetch WebSearch`),
  без настроек, хуков, CLAUDE.md и MCP человека (`--restricted`, `--safe-mode`,
  `--strict-mcp-config`), остальное - отказ без вопроса (`--permission-mode dontAsk`), в
  пустой своей папке: модель читает чужие страницы, и запрет списком пропустил бы всё, чего
  в нём нет. Работа идёт в главном процессе, уход с вида Connectors её не прерывает. Описание
  проверяет одна схема (zod) при генерации, при добавлении и при чтении реестра; негодный
  инструмент выбрасывается и называется, а не губит всё описание. Ключ человек вводит
  после, ИИ его не видит; хост, куда уйдёт ключ, показан крупно, а не тот, что у
  документации, - с предупреждением.

## Факты и замеры

- `claude --help` (2.1.293): есть `--strict-mcp-config` и `--json-schema`; ответ
  `--output-format json` несёт готовый объект в `structured_output` (проверено 2026-10-25
  вызовом с маленькой схемой на haiku).
- Конфиг человека на 2026-10-25: chatkepr, Graphite, playwright-1 и -2, notion-web - команды;
  snakein - адрес с Bearer. Все переносятся одним нажатием.
- `claude -p --safe-mode --restricted --strict-mcp-config --permission-mode dontAsk --tools
WebFetch WebSearch --allowedTools WebFetch WebSearch` (2026-10-25, haiku): модель видит
  только StructuredOutput, WebFetch и WebSearch и читает страницу без отказов.
- Описание Open-Meteo строится за 80-120 секунд (два прогона 2026-10-25); у сервисов с
  большой документацией дольше, потолок - 10 минут.

## Последствия

- Смена аккаунта Claude и плагины Claude Code больше не влияют на MCP в IDE.
- Новый свой сервер - только коннектором (адрес, команда, перенос или ИИ).
- Терминальный Claude и amazing-claude-code живут со своим конфигом как раньше.
- Коннектор от ИИ - только запросы HTTP с ключом; потоковых ответов, загрузки файлов и
  OAuth у него нет. Пересмотреть, если таких сервисов станет много.

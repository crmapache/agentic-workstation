# 0036. Jira & Confluence и Todoist - встроенные, через официальные MCP

- **Статус:** Принято
- **Дата:** 2026-11-10

## Контекст

Владелец попросил заранее встроить коннекторы к сервисам, которыми пользуется каждый день:
Todoist, Jira, Confluence, почта и Teams Microsoft. По Todoist сказал: если у их MCP вход
слетает, делать по личному токену, MCP не обязателен. По Jira и Confluence: делать облако,
собственные серверы компаний (Data Center) пока не трогать. Microsoft (Outlook, Teams, свой
Exchange) отложен: там вход упирается в разрешения компании.

## Варианты

**Todoist.**

1. Официальный MCP (`ai.todoist.net/mcp`) со входом OAuth. Свои инструменты Doist, вход в
   браузере. Сторонние сайты писали, что вход живёт сутки.
2. Свои инструменты поверх Todoist API v1 по личному токену, как Gmail. Токен не истекает,
   но инструменты, их описания и поддержку пришлось бы вести самим.
3. Официальный MCP по личному токену в заголовке `Authorization`. Инструменты Doist и токен,
   который не истекает.

**Jira и Confluence.**

1. Официальный Atlassian Rovo MCP (`mcp.atlassian.com/v1/mcp`): один сервер на Jira и
   Confluence, вход OAuth в браузере. Только облако Atlassian.
2. Свои инструменты поверх REST API с личным токеном - работают и на Data Center. Заметная
   работа; владелец отложил её.

## Решение

Todoist - третий вариант: официальный сервер пускает по личному токену, а токен не
протухает. Так закрыт и вопрос входа, и поддержки инструментов. Jira и Confluence - первый
вариант, один коннектор «Jira & Confluence» с входом в браузере, как у Notion. Оба - встроенные
типы с официальным адресом в IDE (`REMOTE_MCP_URL`) и именем сервера «тип-подпись».

## Факты и замеры

- 2026-11-10: `POST https://ai.todoist.net/mcp` (initialize, tools/list) с личным токеном API в
  `Authorization: Bearer` - 200, сервер todoist-mcp-server 14.0.4, 49 инструментов. Через
  источник IDE (`RemoteMcpSource`): 23 чтения, 23 записи, 3 отправки людям (add-comments,
  update-comments, manage-assignments).
- Сервер авторизации Todoist (`todoist.com/.well-known/oauth-authorization-server`) заявляет
  `refresh_token` и саморегистрацию клиента - слух о входе на сутки не подтверждается, но
  токен проще и не зависит от этого.
- `mcp.atlassian.com/.well-known/oauth-authorization-server`: саморегистрация клиента и
  `refresh_token`; `/v1/mcp` без входа отвечает 401 с `WWW-Authenticate: Bearer`. Вход через
  браузер с аккаунтом Atlassian вживую не проверен: нужен человек.
- Atlassian Rovo MCP - только облако; поддержки Data Center в планах Atlassian нет
  (developer.atlassian.com/cloud/rovo-mcp, сообщество Atlassian).

## Последствия

- Типы `atlassian` и `todoist`. У Todoist способ входа всегда «токен»: работает замена ключа
  на карточке, как у своего MCP.
- Назначение задачи человеку (assign) теперь - отправка людям: ему приходит уведомление.
- Пересмотреть Todoist, если официальный сервер перестанет принимать личный токен: тогда
  OAuth по тому же адресу (он заявлен) или свои инструменты. Jira и Confluence на своём
  сервере компании - отдельной записью, когда понадобятся.

# 0087. Окно модели Ollama - то, с которым её держит сервер, а не её предел

- **Статус:** Принято
- **Дата:** 2026-11-18

## Контекст

Панель открытых моделей ([ADR 0084](0084-open-models-engine-opencode.md)) отдаёт OpenCode
окно контекста каждой модели (`limit.context` в конфиге процесса). По нему OpenCode решает,
когда сжать разговор. Для Ollama IDE брала окно из `model_info` ответа `/api/show`, а это
предел, на котором модель учили: у Qwen3.8 - 262 144 токена. Держит же сервер модель со своим
окном: своё `num_ctx` модели (PARAMETER в Modelfile), иначе своё по умолчанию
(OLLAMA_CONTEXT_LENGTH, ползунок приложения или по памяти видеокарты), и не больше предела
модели. На Mac с 48 ГБ по умолчанию это 32 768.

OpenCode при этом считает, что места в восемь раз больше, и разговор не сжимается вовремя.
Ollama молча отрезает начало, и модель посреди работы теряет указания и инструменты. Владелец
собрался пробовать Qwen локально, так что ошибка стала видна прямо сейчас.

Через вход в формате OpenAI, которым ходит OpenCode, окно запросом не задать: `num_ctx` там
сервер пропускает. Своё окно по умолчанию сервер тоже не называет. Видно его только у
загруженной модели, в `/api/ps`.

## Варианты

1. **IDE сама задаёт окно.** Перед ходом модель загружается родным `/api/generate` с
   `options.num_ctx`. Окно было бы ровно таким, какое выбрала IDE. Минусы: оно идёт поверх
   настройки человека в Ollama, IDE пришлось бы подбирать его под память, а первый запрос
   OpenCode без `num_ctx` всё равно перезагрузил бы модель с окном сервера.
2. **Модель-копия с `num_ctx`** (`/api/create`). Окно держалось бы и через вход OpenAI.
   Минусы: в списке моделей человека появляются чужие модели, и их надо поддерживать при
   каждом обновлении исходной.
3. **Своё прокси, которое переводит запросы OpenAI в родной `/api/chat`.** Даёт полный
   контроль над окном. Минусы: перевод потока, инструментов и рассуждений пришлось бы делать
   своим, ради одного числа.
4. **Читать окно у сервера.** Окно загруженной модели берётся из `/api/ps`, своё `num_ctx` -
   из `/api/show`. По загруженным моделям IDE узнаёт окно сервера по умолчанию: модель
   загружена с окном меньше предела - значит, ровно оно, упёрлась в предел - значит, «не
   меньше». Пока окно - догадка, модель разговора загружается перед запуском процесса
   OpenCode. Плюсы: настройку человека IDE уважает, а загрузка та же, что сделал бы первый
   запрос. Минусы: пока модель грузится, сообщение ещё не в ленте. Это случается один раз
   после старта Ollama: дальше окно сервера известно.

## Решение

Вариант 4. Окно задаёт человек в Ollama, а IDE честно передаёт OpenCode то, что сервер
реально держит. Проба Ollama (`connection-probe.ts`) читает `/api/ps` и `num_ctx` модели,
окно считает `ollama-window.ts`, а окно сервера `ModelConnections` помнит между пробами (пробы
одного подключения идут друг за другом). Сервер не ответил - окно забывается: поднятый заново
мог взять другое. Перед запуском процесса OpenCode (разговор, прогон, разовый вопрос)
`OpenModelsService.launchOn` зовёт `ModelConnections.prepare`. Если окно модели - догадка,
модель загружается (`/api/generate` без промпта), и проба повторяется.

## Факты и замеры

Проверено на Ollama 0.40.16, MacBook Pro M5 Pro с 48 ГБ, на своём сервере с отдельной
папкой моделей и qwen3:0.6b (предел 40 960):

- в журнале сервера `vram-based default context total_vram="37.4 GiB" default_num_ctx=32768`;
  наружу это число сервер не отдаёт (`/api/status` и `/api/show` его не знают);
- `/v1/chat/completions` с `num_ctx` и с `options.num_ctx` - окно 32 768, сервер их пропустил;
  родной `/api/chat` с `options.num_ctx: 12288` - 12 288;
- OLLAMA_CONTEXT_LENGTH=65536 - окно 40 960, то есть упирается в предел модели;
- модель-копия с `num_ctx 16384` - 16 384 и через вход OpenAI;
- `/api/generate` без промпта загружает модель (`done_reason: "load"`) с тем же окном, что
  первый запрос OpenAI.

Повтор: `AGENTIC_WORKSTATION_OLLAMA_LIVE=http://127.0.0.1:11999
AGENTIC_WORKSTATION_OLLAMA_MODEL=qwen3:0.6b npx vitest run ollama-window.live` на своём
`OLLAMA_HOST=127.0.0.1:11999 OLLAMA_MODELS=<папка> ollama serve`. Логику держат
`ollama-window.test.ts` и `connections.test.ts`.

## Последствия

- В меню у модели Ollama окно, которое держит сервер, а не предел. Пока сервер ни одной
  модели не загружал, окна у неё нет. Предупреждение о маленьком окне теперь честное: при
  окне 4 096 оно горит.
- Человек перезапустил Ollama с другим окном - IDE узнаёт об этом сразу, если застала сервер
  выключенным (окно забыто). Иначе узнаёт по первой пробе после того, как модель загрузится:
  при запуске процесса или по проверке на экране подключений. После неё живые процессы
  перезапустятся, как освободятся. До этого ход идёт с прежним окном.
- Если Ollama урежет окно большой модели, чтобы та влезла в память, окно сервера окажется
  меньше настоящего. OpenCode тогда сожмёт разговор раньше нужного, но ничего не потеряет.
- LM Studio тоже грузит модель со своим окном, а IDE отдаёт её предел. Это та же ошибка, она
  ждёт своего решения: проверить её здесь было не на чем.
- Пересмотреть, если Ollama начнёт принимать `num_ctx` через вход OpenAI или называть своё
  окно по умолчанию.

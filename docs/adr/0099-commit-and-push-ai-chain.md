# 0099. Commit and push в шапке: сообщение пишет цепочка ИИ с запасными

- **Статус:** Принято
- **Дата:** 2026-11-20

## Контекст

Владелец коммитит и пушит по многу раз в день, и каждый раз это одно и то же: всё, что
изменилось, одним коммитом с понятным сообщением, затем push текущей ветки. Он попросил кнопку
рядом со счётом строк в шапке (`+1,548 −57`), которая делает это сама и сама пишет сообщение, а
в настройках - модель, усилие и запасных провайдеров со своими моделями и усилиями.

## Варианты

**Что коммитить.**

- _Только то, что лежит в индексе._ Плюсы: уважает частичный stage. Минусы: кнопка «закоммить и
  запушь» без stage ничего не делает, а stage в IDE - отдельная работа, которую владелец не просил.
- _Всё, как `git add -A`._ Плюсы: ровно то, что просили; `.gitignore` работает как обычно.
  Минусы: частичный stage растворяется в общем коммите - для этого есть меню ветки и терминал.

**Когда трогать индекс.** Сообщение пишет модель, она может не ответить. Если добавить всё в
индекс до вопроса, отказ оставит человеку изменённый индекс. Дифф для модели собирается во
временном индексе (`GIT_INDEX_FILE`, копия настоящего - без перехеширования проекта), настоящий
трогается только после того, как сообщение написано.

**Кто пишет сообщение.**

- _Провайдер служебной работы (Settings → AI)._ Минусы: одна модель без усилия и без запасных, а
  владелец назвал именно цепочку.
- _Своя цепочка в настройках IDE._ Основной и до трёх запасных - провайдер, модель, усилие.
  Плюсы: лимит одного провайдера не останавливает коммит.

## Решение

Кнопка `CommitPushButton` в шапке сразу за счётом строк (только на ветке, только когда есть
изменения). Главный процесс (`main/git/commit-push/`): ветка → дифф во временном индексе → цепочка
`IdePrefs.commitAi` по порядку, пока кто-то не вернёт тему и тело по схеме → `git add -A` и
`git commit` в очереди записывающих команд проекта → `push` тем же путём, что Push из меню ветки
(ветка без upstream публикуется, force нет). Итог - в углу окна: сообщение и кто его написал,
«коммит лёг, push отказал» с ответом git или шаг, на котором встало.

Цепочка - в новых общих настройках IDE (`shared/ide-prefs.ts`, `main/ide-prefs/`, файл
`ide-prefs.json`, каналы `idePrefs:*`), раздел Settings → Git. Туда же переехало сворачивание
вставки из настроек панели Claude Code: оно касается поля любого провайдера (Settings → Chat).

## Факты и замеры

Поведение держит `main/git/commit-push/commit-push.integration.test.ts` на настоящем git с
bare-репозиторием: нечего коммитить, никто не ответил (индекс человека цел, коммита нет), отказ
первого и ответ запасного (уходят и новые файлы), два нажатия подряд, не на ветке.

```sh
pnpm --filter @agentic-workstation/desktop exec vitest run commit-push ide-prefs
```

## Последствия

- Пустая модель у Claude Code - Haiku: тема коммита не требует большего, а ждать её человек будет
  с окном перед глазами. У остальных - модель провайдера по умолчанию.
- Antigravity в цепочке не выбрать: без человека ему работать нельзя (ADR 0094).
- Хуки `pre-commit` человека выполняются, у коммита свой потолок времени - 10 минут.
- Стиль сообщения - по последним темам репозитория (префиксы, язык, длина), а не наш.
- Второе нажатие, пока идёт первое, получает тот же итог, а не второй коммит из пустоты.
- Пересмотреть, если понадобится коммит части изменений или выбор ветки/удалённого репозитория.

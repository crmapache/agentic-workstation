# 0079. Стрелка ИИ Computer Use - своя синяя вместо системной, пока ИИ держит мышь

- **Статус:** Принято
- **Дата:** 2026-11-17

## Контекст

У Browser (ADR 0040) своя стрелка: оранжевая, со свечением, внутри страницы Chrome. Computer Use
(ADR 0057) двигает настоящую системную стрелку, обычную чёрную, и по ней не видно, что мышь
сейчас у ИИ, а тем более у какого из двух коннекторов. Владелец попросил, чтобы стрелки
различались цветом: у Browser - как была, у Computer Use - синяя.

Ограничения, которые нельзя обойти:

- Системная стрелка всегда рисуется поверх всех окон. Своя стрелка рядом с ней - это две стрелки
  на экране.
- macOS прячет стрелку (`CGDisplayHideCursor`) только у приложения на переднем плане. ИИ
  работает в чужих окнах, и над ними система возвращает стрелку сразу.
- Windows не даёт программе спрятать стрелку над чужим окном вовсе.
- Модель не должна видеть знак ИИ на снимке: она приняла бы его за часть приложения, а подпись
  к снимку говорит «стрелка не нарисована».

## Варианты

1. **Свечение вокруг системной стрелки.** Синий ореол и круг нажатия под настоящей стрелкой.
   Ничего системного не трогает, работает везде. Но стрелка остаётся чёрной, и с оранжевой
   стрелкой Browser она не сравнивается: знак ИИ получается другой формы.
2. **Своя синяя стрелка, системная спрятана.** На маке - закрытое свойство соединения с оконным
   сервером `SetsCursorInBackground`, после него `CGDisplayHideCursor` действует из фона (им же
   пользуются утилиты вроде Cursorcerer). На Windows - все системные курсоры на время работы
   подменяются пустыми (`SetSystemCursor`), потом схема человека перечитывается из реестра
   (`SPI_SETCURSORS`). Стрелка одна, той же формы, что у Browser. Минусы: на маке закрытый
   вызов, Apple может его убрать; на Windows падение IDE посреди работы оставило бы курсоры
   пустыми.
3. **Своя стрелка рядом с системной.** Проще второго, но две стрелки на экране.

## Решение

Вариант 2, выбор владельца. Главная причина - одна стрелка того же силуэта, что у Browser,
отличается только цветом. Пока стол держит компьютер (ADR 0057) и не на паузе, системная
стрелка спрятана, а маленькое прозрачное окно со стрелкой стального синего (`--color-computer-cursor`)
едет туда, куда рука ставит курсор. Человек двинул мышь (курсор ушёл не рукой) - сразу его
системная стрелка, синяя возвращается со следующим шагом руки. Пауза, Stop и конец работы -
тоже системная. Система не дала спрятать стрелку - синей нет вовсе.

## Факты и замеры

Мак владельца (macOS 27, Darwin 27.2), 17 ноября 2026, отдельный процесс Node с koffi, снимок
`screencapture -C` 40×40 вокруг стрелки:

- Без закрытого свойства `CGDisplayHideCursor` из фона не действует: снимок со стрелкой совпал с
  исходным побайтно.
- Со свойством стрелка пропадает и остаётся спрятанной, пока процесс шлёт события движения
  (20 шагов по 3 точки), и возвращается после `CGDisplayShowCursor`.
- Процесс убит (`SIGKILL`) со спрятанной стрелкой - через полсекунды она снова на экране: скрытие
  держит соединение процесса с оконным сервером.
- `CGCursorIsVisible` врёт (до скрытия ответил false) - проверять скрытие им нельзя.

Копия окна (`/dev`) с настоящим Claude Code и коннектором Computer Use, наблюдатель по оконному
серверу (`CGWindowListCopyWindowInfo`) раз в 150 мс и снимок 40×40 вокруг мыши раз в 600 мс:

- Задача «кликни README.md в дереве, подвигай мышь»: файл открылся - клик прошёл сквозь окно
  стрелки, лежащее ровно под острием. Окно стрелки 80×80 на всех замерах стояло центром ровно
  в точке мыши, слой 1001 (капсула - 1000), `sharingState` 0. Системной стрелки на снимках не было,
  после конца хода она вернулась, окно стрелки ушло.
- Модель ждёт 10 секунд перед снимком, сторонний процесс ведёт мышь, как человек (15 шагов по
  10 точек): через 250 мс окна стрелки нет, системная стрелка на снимке есть.
- Страница окна стрелки по CDP: синий наконечник со свечением, острие в середине, после клика -
  гаснущий круг.

Windows живьём не проверен: машины с Windows нет. Подмену и возврат держат модульные проверки
на подставных вызовах (`win-cursor.test.ts`).

Повторить: `pnpm --filter @agentic-workstation/desktop exec vitest run src/main/computer`; живьём -
копия окна (`/dev`), коннектор Computer Use, задача в панели.

## Последствия

- `main/computer/`: `computer-pointer.ts` (когда стрелка ИИ на экране, слежение за мышью человека,
  ввод `withPointer`, о котором рука не знает), `computer-pointer-window.ts` (окно 80×80, острие в
  середине, `setPosition` на каждом шаге руки, клики насквозь), `cg-cursor.ts` и `win-cursor.ts`
  (системная стрелка), `overlay-window.ts` (общее у капсулы и стрелки). Страница - третий вход
  рендерера (`pointer.html`, `features/computer/ComputerPointer`), событие `computer:pointerPressed`.
- Силуэт стрелки - один на IDE и расширение: примитив `AgentPointer` в `packages/ui`, его
  `AgentPointer.constants` берёт и расширение Chrome (граница линтера пускает его в `ui`).
- На Windows метка `computer-cursor-hidden` в папке состояния: следующий запуск IDE по ней
  возвращает курсоры, если прошлый упал с пустыми. Выход процесса возвращает их тоже.
- Окно стрелки закрыто от захвата экрана, как капсула. Значит, на записи экрана человека, пока
  ИИ держит мышь, стрелки не видно вовсе: системная спрятана, синяя в запись не попадает.
- Пересмотреть, если Apple уберёт `SetsCursorInBackground` (синяя тогда просто не появится, в
  журнале - предупреждение) или если пустые курсоры на Windows хоть раз останутся у человека.

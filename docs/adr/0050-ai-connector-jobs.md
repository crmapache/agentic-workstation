# 0050. Коннектор от ИИ - очередь разговоров на виде, а не окно с ожиданием

- **Статус:** Принято
- **Дата:** 2026-11-12

## Контекст

Коннектор от ИИ ([ADR 0029](0029-claude-connectors-only.md)) был одним вопросом к `claude -p` с
ответом по схеме. Пока ИИ работал (минуты), окно по центру показывало крутилку и Stop и
закрывало всю IDE затемнением. Работа одна на IDE, что ИИ делает - не видно, поправить его по
ходу нельзя: только остановить и начать заново. Владелец назвал это неприемлемым и попросил
очередь на странице коннекторов, большое окно с ходом работы и переписку с ИИ.

Вторая жалоба в тот же день: коннектор к своему продукту (Callmate) не вышел. ИИ искал
«Callmate» в сети, нашёл чужую компанию с тем же именем и ответил «не выйдет». При этом
Callmate у владельца уже подключён в Claude Code как MCP-сервер по адресу с ключом. ИИ видел
только сеть и умел предложить только описание REST API с личным ключом.

## Варианты

**Как идёт работа.**

1. Оставить разовый вопрос, только не держать окно: плитка в очереди и итог. Не блокирует,
   но хода не видно и написать ИИ нельзя - половина просьбы.
2. Разговор на процессе CLI в режиме потока JSON в обе стороны, как у панели Claude Code:
   лента та же, слова человека доходят посреди хода, ответ каждого хода - по той же схеме.
   Процесс между ходами засыпает и продолжается по id разговора.

**Что ИИ может предложить.**

1. Только описание REST API (как было). Свои продукты человека, сервисы с официальным MCP и
   сервисы только с OAuth остаются без коннектора.
2. Три вида: сервер, который у человека уже настроен в Claude Code (перенос с его входом),
   официальный MCP-сервер по адресу, описание REST API. Плюс ответ без предложения - вопрос
   человеку или честное «не выйдет».
3. Ещё и MCP-команду (`npx пакет`). Это чужой код на машине по совету модели, которая читала
   чужие страницы, - то, от чего ADR 0029 отказался. Не берём.

**Как ИИ узнаёт, что у человека уже есть.** Дать ему читать файлы нельзя: рядом WebFetch, и
страница могла бы уговорить его отправить ключ с диска наружу. Даём список серверов из
конфига Claude Code тем же переносом (`import-candidates.ts`): имена, адреса и команды уже с
маской ключей. Ключи переезжают при переносе внутри IDE, модель их не видит.

## Решение

Работа ИИ над коннектором - разговор (вариант 2), предложений - три вида (вариант 2).

- **Очередь в главном процессе** (`main/connectors/ai/ai-connector-desk.ts`): работ сколько
  угодно, идут параллельно. Состояние работы - `AiJob` в `ConnectorsState.aiJobs`, лента
  разговора - отдельно: снимок запросом `connectors:aiJobFeed`, дальше патчи
  `connectors:aiJobPatch`, как у панели. Работы пишутся на диск (`connectors-ai-jobs.json`):
  готовое и начатое переживает перезапуск IDE, шедший ход встаёт остановленным, следующее слово
  человека продолжает разговор с `--resume`.
- **Разговор ведёт провайдер** (`main/claude/connector-chat/`): модуль коннекторов получает
  `OpenAiChat` и про Claude Code не знает. Процесс - `-p --input-format stream-json
--output-format stream-json --include-partial-messages` и ограда разового вопроса
  (`fenceArgs`: схема, `--tools WebFetch WebSearch`, `--safe-mode --restricted
--strict-mcp-config`, `dontAsk`). Правила для ИИ - системным промптом из файла
  (`--append-system-prompt-file`), первое сообщение - просьба человека как он её написал.
  Через три минуты после хода процесс засыпает. Продолжение по id - только если CLI успел
  заговорить: иначе разговора на диске нет.
- **Ход** ограничен 10 минутами (как вопрос раньше); не ответил на остановку за 30 секунд -
  процесс гасится.
- **Порядок проверок у ИИ:** серверы человека из Claude Code, встроенные коннекторы IDE,
  официальный MCP, REST API. Имя неоднозначно или сервис не найден - вопрос человеку, а не
  отказ.
- **Окно:** форма просьбы закрывается сразу; очередь - раздел над подключёнными коннекторами;
  работа открывается большим окном (`Modal lg tall`): слева живая лента той же ленты, что
  панель (`ConversationLog`, ответ по схеме показан словами ИИ), справа предложение с
  проверкой и ключом, внизу поле. Добавленный коннектор убирает работу из очереди.

## Факты и замеры

CLI 2.1.293, haiku, папка `~/tmp-aw-probe` (2026-11-12):

- Два сообщения в один процесс с `--json-schema` и потоком JSON: два хода, у каждого `result`
  с `structured_output`.
- Сообщение, отправленное через 6 секунд после первого, пока шёл WebSearch: ответ один и уже
  с учётом второго (просьба отвечать по-русски выполнена). С `--replay-user-messages` CLI
  отдаёт такое сообщение эхом в момент, когда взял его в ход (через 35 секунд, после
  результата поиска).
- Новый процесс с `--resume <id>` и теми же флагами помнит прошлый ход (слово из него
  названо верно); пустого итога-рукопожатия на этой версии не было, проверка
  `isStartupResult` осталась.
- `--append-system-prompt-file` принят, правило из файла выполнено.
- Конфиг владельца: `callmate` - `type: http`, `https://callmate.mzpizote.com/api/mcp`,
  заголовок `Authorization`. Перенос берёт его вместе с заголовком.

Повтор пробы - в пустой папке, поток сообщений на stdin:

```
( echo '{"type":"user","message":{"role":"user","content":"Say hi"}}'; sleep 25 ) |
  claude -p --input-format stream-json --output-format stream-json --verbose \
  --json-schema '{"type":"object","properties":{"message":{"type":"string"}},"required":["message"]}' \
  --safe-mode --restricted --strict-mcp-config --permission-mode dontAsk \
  --tools WebFetch WebSearch --allowedTools WebFetch WebSearch --model haiku
```

Живая проверка в копии окна (скилл `/dev`, 2026-11-12):

- Просьба владельца дословно («Callmate», «токен посмотри где то уже был»): ИИ за 6,5 с
  предложил перенести `callmate` из Claude Code; перенос - коннектор «Connected», 56
  инструментов, ключ не вводили.
- Linear: официальный MCP `mcp.linear.app` за 16 с, форма своего MCP с адресом и входом в
  браузере. Вопрос посреди хода («ответь одним предложением») ИИ взял в тот же ход.
- Процесс копии погашен и поднят заново с тем же профилем: работа на месте («Ready»), лента
  прочитана с диска, следующее слово продолжило разговор (`--resume`), предложение
  обновилось.

## Последствия

- Коннектор от ИИ больше не блокирует IDE и не живёт в одном экземпляре; новый вид
  предложения - запись в `AiProposal`, разбор в `ai-answer.ts` и часть окна.
- Предложение проверяется теми же правилами, что добавление: описание - `specSchema`, адрес
  MCP - https без ключа, сервер Claude Code - по списку, который ИИ видел. Не прошло - ход
  кончается `invalid` с пояснением, разговор продолжается.
- `applyFeedPatch` - в `renderer/src/state`, прокрутка журнала у конца - в `lib`: их делят
  панель, сценарии и коннекторы.
- Пересмотреть, если CLI начнёт требовать что-то вместо `--append-system-prompt-file` или
  потеряет `structured_output` в потоковом режиме: тогда первым делом повторить пробы выше.

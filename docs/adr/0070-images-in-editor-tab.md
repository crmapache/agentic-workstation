# 0070. Картинка открывается вкладкой редактора: сама картинка, а не «не текст»

- **Статус:** Принято
- **Дата:** 2026-11-16

## Контекст

Картинка проекта (скриншот, иконка, макет) открывалась из дерева вкладкой, а вкладка писала
«Not a text file»: редактор умел только текст. Ссылку из ленты на картинку вне проекта
(скриншот, который агент снял в `/tmp`) ADR 0027 отдавал системе, и она уходила в Preview. Владелец
попросил показывать картинки в самом редакторе.

Читать картинки главный процесс уже умел: просмотр Markdown берёт их через `fs:readImage` data
URL-ом, с версией файла и ответом unchanged (ADR 0019). Только внутри проекта и до 20 МБ.

## Варианты

**Своя схема протокола (`aw-file://…`), картинка - обычным адресом в `<img>`.**

- Плюсы: байты не идут через IPC и base64, большой файл не держится строкой в памяти окна.
- Минусы: новый обработчик схемы, который сам решает, какой путь окну можно, - вторая дорога к
  диску рядом с проверенной `fs:readImage`; кэш Chromium по адресу надо сбрасывать на каждую
  правку файла. Ради картинок до 20 МБ это лишнее.

**Тот же `fs:readImage`, вкладка - свой вид без Monaco.**

- Плюсы: одна проверка пути и типа на просмотр и вкладку, версия и unchanged уже есть - правка
  файла на диске перечитывает картинку без лишних байтов. Вид лёгкий, Monaco не нужен.
- Минусы: картинка едет base64, примерно на треть тяжелее файла; потолок 20 МБ остаётся.

**Оставить «не текст» и открывать картинку системой.**

- Плюсы: ничего не менять.
- Минусы: ровно то, на что жалуется владелец.

## Решение

Вкладка файла с картинкой (PNG, JPEG, GIF, WebP, AVIF, BMP, ICO) показывает её своим видом
`ImageView` через тот же `fs:readImage`. Главная причина - одна проверенная дорога к диску на
просмотр и вкладку и готовая сверка версии. SVG остаётся кодом: это текст, его правят. Картинка
вне проекта по ссылке из ленты открывается такой же вкладкой, а не Preview.

Детали, которые легко потерять:

- что картинка, решает расширение: `opensAsImage` в `shared/preview-images.ts`, одно правило на
  окно и главный процесс. Вкладка выбирает вид по нему, `fs:locatePath` по нему же отвечает
  `opensInTab` у файла вне проекта (бывшее `editable`). Картинка больше 20 МБ вне проекта
  по-прежнему уходит системе;
- `fs:readImage` принимает, как `fs:readFile`, ровно один путь: от корня (только внутри проекта)
  или абсолютный (`outsidePath`, только картинка по расширению настоящего файла, потолок тот же).
  Ответ несёт размер файла - для строки сведений;
- код и картинка - две вкладки вида file, и у каждой свой живой вид: `EditorArea` держит
  последнюю вкладку кода в Monaco и последнюю картинку в `ImageView` (`useRecentTab` с отбором),
  переход между ними не пересоздаёт Monaco;
- вкладка сверяет картинку при каждом показе и по возврату в окно (`live` в `useImageFile`),
  видимую картинку вне проекта слушает `fs:watchOutside` (`outside-watch.ts`, источник `image`).
  Удалили показанную картинку - вкладка закрывается сама, как текст без правок;
- масштаб: вписать (большая уменьшается, маленькая остаётся своего размера), ступени кнопками,
  щипок и колесо с ⌘ - к точке под курсором, двойной щелчок - свой размер и обратно. С 200% и
  крупнее пиксели рисуются квадратами;
- побочно закрыт пункт ADR 0027: картинки Markdown вне проекта из его же папки теперь
  показываются - путь абсолютный, и запрос уходит абсолютным.

## Факты и замеры

Замеров скорости нет: чтение то же, что у просмотра Markdown. Проверено тестами: чтение вне
проекта, размер, отказ сетевому и относительному пути, `fitsImageTab`
(`main/fs/image-file.test.ts`), решение «вкладкой» для картинки вне проекта
(`path-locator.test.ts`), правило расширений (`shared/preview-images.test.ts`), расчёт масштаба
(`ImageView.utils.test.ts`). Вживую в копии IDE (`/dev`): вписывание, маленькая иконка 100%,
битый файл, ступени, щипок, переключение с кодом.

## Последствия

- Ключ вкладки file бывает картинкой: то, что ждёт за вкладкой документ редактора, проверяет
  `opensAsImage`. Документа у картинки нет - нет и автосохранения, вопроса о несохранённом и
  локальной истории по открытию.
- Ссылка на картинку в просмотре Markdown по-прежнему открывает её крупно поверх окна, не уводя
  из документа; вкладкой её открывает дерево и лента.
- Пересмотреть, если понадобятся картинки больше 20 МБ или разница картинок в Changes: тогда -
  своя схема протокола с той же проверкой пути, что у `fs:readImage`.

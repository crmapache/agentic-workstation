# 0037. Терминал под панелью Claude Code: node-pty в главном процессе, xterm.js в окне

- **Статус:** Принято
- **Дата:** 2026-11-10

## Контекст

Владелец попросил терминал, как окно Terminal в WebStorm: кнопка внизу правой полосы
иконок (зона 3), по ней снизу правой колонки открывается терминал на половину её высоты и
сдвигает панель Claude Code вверх; граница тянется мышью, терминал не ниже 250 пикселей.
Внутри - вкладки оболочек проекта («Local», «Local (2)»), «+» и «спрятать».

Настоящий терминал - это псевдотерминал (pty): оболочка должна получить управляющий
терминал, иначе нет управления задачами - Ctrl+C не доходит до запущенной команды, `vim`
и `htop` не понимают размер окна. В Node и Electron псевдотерминала нет. Окно IDE в
песочнице и Node не видит (ADR 0003), значит, оболочки живут в главном процессе.

Правило главного процесса - нативное делать через koffi, без новых аддонов (ADR 0008).

## Варианты

**node-pty (Microsoft, на нём терминал VS Code) + xterm.js в окне.**

- Плюсы: проверенная пара - то же, что в VS Code. node-pty на Node-API и везёт готовые
  бинарники для macOS (`prebuilds/darwin-arm64`): под каждую версию Electron не
  пересобирается, node-gyp не нужен. Пауза оболочки (`pause`/`resume`), размер окна,
  выход процесса - из коробки. xterm.js рисует всё, что умеют программы терминала.
- Минусы: второй нативный модуль главного процесса и вспомогательная программа
  `spawn-helper` - обе должны лечь в `app.asar.unpacked`. Берём бету 1.2.0-beta.18: в
  стабильной 1.1.0 у `spawn-helper` в пакете нет права на запуск, и первая же вкладка
  падает с `posix_spawnp failed`. VS Code тоже живёт на бетах node-pty.

**koffi: `openpty` из libSystem и обычный `spawn` с концом pty вместо stdio.**

- Плюсы: без нового аддона, по правилу ADR 0008.
- Минусы: управляющий терминал выдаёт только `ioctl(TIOCSCTTY)` в самом дочернем
  процессе между `fork` и `exec`, а Node туда не пускает. Оболочка без него - без
  управления задачами: Ctrl+C не останавливает команду. Читать конец pty без блокировки
  главного процесса - ещё свой код поверх libuv.

**`script -q /dev/null $SHELL` на трубах.**

- Плюсы: ничего нативного, `script` сам заводит pty.
- Минусы: размер своего pty `script` берёт со своего stdin, а у нас там труба: окно
  терминала навсегда 80×24, `vim` и перенос строк врут.

## Решение

node-pty в главном процессе и xterm.js в окне: только так оболочка получает настоящий
управляющий терминал без своего нативного кода, а готовые бинарники на Node-API не
просят пересборки под Electron. Исключение из правила ADR 0008 - ради управления
задачами, которое через koffi не сделать.

Как устроено:

- `main/terminal/TerminalService` держит оболочки: входная оболочка пользователя (`-l`) в
  корне проекта, окружение IDE без её личных переменных (`terminal-env.ts`: Electron, IDE,
  скрипты pnpm, чужой терминал, из которого запущен dev). Вывод копится и уходит окну раз в
  8 мс (`terminal:output`) с концом счёта знаков.
- Окно подтверждает дорисованное (`terminal:ack`); отстало на 200 тысяч знаков - оболочка
  на паузе, догнало до 20 тысяч - идёт дальше. Иначе `yes` забил бы окно.
- Сессии переживают перезагрузку окна: главный процесс держит хвост вывода (до миллиона
  знаков), окно подключается к нему (`terminal:replay`) и по счёту знаков отбрасывает
  куски, уже вошедшие в хвост.
- Закрытая вкладка, закрытый проект, выход IDE: SIGHUP, через 1,5 с - SIGKILL; выход IDE
  ждёт оболочки, как процессы CLI.
- В окне терминал - `workbench/TerminalDock` под листом провайдера в той же колонке:
  доля высоты в раскладке (`layout.store`, сохраняется), не ниже 250 пикселей, панель над
  ним - тоже не ниже 250; колонке не хватает на оба - пополам. Без панели провайдера
  терминал занимает всю колонку. Спрятанный остаётся смонтированным, оболочки всех
  проектов рисуются дальше.
- Цвет. Программы красят вывод сами, но приглашение zsh по умолчанию на macOS бесцветное,
  а `ls` красит только с `CLICOLOR` - команды тонули в выводе. Оболочка zsh запускается
  через обёртку (`terminal/zsh-integration*`, как у терминала VS Code): ZDOTDIR на время
  запуска смотрит в `userData/terminal-zsh`, каждый файл человека читается из его папки с
  его ZDOTDIR, история остаётся его (`/etc/zshrc` кладёт её в ZDOTDIR), в конце ZDOTDIR
  возвращается. Сверху - одно: приглашение по умолчанию (`%n@%m %1~ %# `) в цвет - машина
  тише, папка и ветка git ярче, знак зелёный после удачной команды и красный после ошибки.
  Своё приглашение человека не трогается; bash и другие оболочки - без обёртки.
  `CLICOLOR=1` - в окружении терминала.
- Как в WebStorm: открытый терминал проекта без вкладок сам открывает «Local», закрытая
  последняя вкладка (или `exit`) прячет терминал, ⌥F12 показывает его с клавиатурой в
  оболочке или прячет, если она уже там. Цвета - роли `--color-ansi-*` из палитры, шрифт -
  кодовый с кеглем `sm`, растёт с размером текста IDE.

## Факты и замеры

MacBook на Apple Silicon, Electron 44.7.2, node-pty 1.2.0-beta.18. Пробник под
`ELECTRON_RUN_AS_NODE=1`: `zsh -l` в pty, `echo $((6*7))` вернул 42, `stty size` после
`resize(100, 30)` - `30 100`, `exit` - код 0. Права в пакетах: в 1.1.0 у
`prebuilds/darwin-arm64/spawn-helper` - `rw-r--r--`, в 1.2.0-beta.18 - `rwxr-xr-x`
(`npm pack node-pty@<версия>` и `tar tvzf`).

Собранное приложение (`pnpm dist:local`, запуск из zip с отдельным профилем): node-pty лежит в
`app.asar.unpacked`, `spawn-helper` исполняемый, оболочка в терминале отвечает (`tty` -
`/dev/ttys003`); бинарников Windows и Linux в бандле нет. Без `npmRebuild: false`
electron-builder пересобирал node-pty через node-gyp и падал на Command Line Tools этой машины
(`tapi error: malformed file` в `libSystem.tbd`).

В копии окна: `seq 1 300000` дорисовался за две секунды без зависания окна; Ctrl+C прерывает
`sleep`; перезагрузка окна возвращает вывод; выход IDE гасит и команду на переднем плане, и
фоновую задачу оболочки.

## Последствия

- В главном процессе два нативных модуля: koffi и node-pty. Бинарники node-pty для
  Windows, Linux и Intel в сборку не едут (`electron-builder.yml`), свои - в
  `app.asar.unpacked`. Пересборки нативных модулей при сборке нет (`npmRebuild: false`): оба
  на Node-API с готовыми бинарниками.
- node-pty грузится на первой вкладке терминала, а не на старте IDE.
- Пересмотреть бету, когда выйдет стабильная node-pty с исполняемым `spawn-helper`.
- Своего рендерера WebGL у терминала нет - xterm.js рисует DOM. Станет тесно на больших
  потоках - подключить `@xterm/addon-webgl` с откатом на DOM, как в VS Code.

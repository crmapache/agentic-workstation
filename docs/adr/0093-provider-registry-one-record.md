# 0093. Провайдер ИИ - одна запись в реестре, а не развилки по id

- **Статус:** Принято
- **Дата:** 2026-11-19

## Контекст

К трём провайдерам (Claude Code, Codex, открытые модели) добавляются Antigravity и Kimi Code
(ADR 0092). Провайдер в коде сейчас - не место, а развилки: `ProviderId` и список в
`shared/providers.ts`, `capabilitiesOf` по `switch`, папка журналов прогонов тернарником,
источники статистики, цены, список провайдеров телефона (`CORE_PROVIDERS`), схема работ
коннектора от ИИ (`z.enum`), обработчики IPC, виды панелей и иконки в окне, ключи кэша. Около 70
файлов упоминают Codex. Пятый провайдер по этой схеме - ещё раз пройти их все, и шестой тоже.

## Варианты

**Дописать новые id в каждую развилку.**

- Плюсы: ничего не переделываем, сразу к делу.
- Минусы: те же 30 правок на каждого провайдера, пропуск одной развилки молча роняет
  провайдера в «по умолчанию» (статистика без цены, телефон без разговоров) - тесты такое не
  ловят, пока не написан тест на этого провайдера.

**Одна запись на провайдера.** В `shared` - описание (id, имя, вид панели, возможности по
умолчанию, вид аккаунтов, правило фоновой работы); в главном процессе - запись драйвера (панель,
исполнитель прогонов, источник статистики, цены, папка журналов); окно строит виды и иконки по
списку.

- Плюсы: новый провайдер - запись и папка драйвера; пропустить место нельзя - тип записи
  требует все поля. Развилки по id остаются только в коде самого провайдера.
- Минусы: переезд существующих трёх без видимых изменений, большой дифф.

## Решение

Список провайдеров - один (`PROVIDER_IDS` в `shared/providers.ts`, из него выводится
`ProviderId`), а всё, что зависит от провайдера, - исчерпывающие таблицы
`Record<ProviderId, ...>` (возможности, виды панелей, слова, команды установки, папки журналов
прогонов) или проход по `PROVIDER_IDS` и реестру панелей (список провайдеров, телефон, MCP
`workstation`). Главная причина - пятый и шестой провайдер, и любой следующий, не скомпилируются,
пока их нет в каждой таблице, а списки берут их сами. Отдельный объект «драйвер провайдера» на
весь главный процесс не заводим: его части поднимаются в разное время (панели, прогоны,
статистика), и таблица на месте даёт ту же проверку без переезда запуска.

## Факты и замеры

`grep -rln "'opencode'" apps packages` (без тестов) - 17 файлов в главном процессе и `shared`;
файлов, где упомянут Codex, - 72 (`find apps/desktop/src -name '*.ts*' | grep -v test | xargs
grep -l codex | wc -l`), замер на `main` 0dbf638.

## Последствия

- `ProviderId` выводится из `PROVIDER_IDS`, а не пишется руками; порядок списка - порядок иконок.
- Где у провайдера чего-то нет (прогонов у Antigravity), в таблице - пустое значение с
  объяснением, а не пропуск: молчаливого «как у Claude» больше нет.
- Свои экраны провайдера (аккаунты Claude, подключения открытых моделей) остаются его кодом;
  реестр знает только, есть ли они.
- Пересмотреть, если запись начнёт обрастать полями, нужными одному провайдеру: значит, это его
  код, а не реестра.

# 0052. Профиль Chrome копии расширения IDE находит по её ключу в файлах профиля

- **Статус:** Принято
- **Дата:** 2026-11-12

Дополняет [0040](0040-browser-extension.md): там профиль - это копия расширения с ключом и
именем, которое человек даёт в её окне. Остальное в 0040 в силе.

## Контекст

У владельца пять профилей Chrome (Max, Work, Improving, Support, Claude Work), расширение стоит в
четырёх. Имя копии по умолчанию - имя браузера, и все четыре пришли к ИИ как «Google Chrome».
Агент работал в Support, когда нужен был Improving, и сказал, что Improving не подключён:
такого имени среди подключённых не было. Переименовывать каждую копию руками - лишний шаг, о
котором узнают только после промаха.

API расширения имени профиля Chrome не отдаёт. `chrome.identity.getProfileUserInfo` даёт почту
аккаунта Google, но вошёл в Google только один профиль из четырёх. Native host профиль тоже не
знает: Chrome один процесс на все профили и передаёт хосту только адрес расширения.

## Варианты

1. **Просить человека назвать каждую копию.** Ничего не строить, но промах уже случился именно
   из-за этого: по умолчанию все копии одинаковые.
2. **Почта аккаунта через `chrome.identity`.** Официальное API, но новое разрешение с
   предупреждением при установке, и у профиля без входа в Google почты нет - у владельца это три
   профиля из четырёх.
3. **Ключ копии в файлах профиля.** Ключ (8 случайных знаков) копия уже хранит в
   `storage.local`, а это файлы LevelDB внутри папки профиля:
   `<папка данных>/<профиль>/Local Extension Settings/<id расширения>/`. IDE ищет ключ в этих
   файлах у каждого профиля и берёт имя из `Local State` (`profile.info_cache`). Ни разрешений,
   ни шагов человека; риск - формат хранения Chrome, он не обещан.

## Решение

Вариант 3. IDE ищет профиль на каждом hello копии (`chrome-profiles.ts`) и отвечает им в welcome
(`chromeProfile`); копия запоминает его и показывает в своём окне вместо имени браузера. Welcome
ждёт поиска не дольше 2 с: на старте IDE те же потоки читают транскрипты и статистику, и поиск
опаздывает (так было на 0.1.4 у владельца - обе копии остались «Google Chrome»). Опоздавшее
имя IDE досылает запросом `profile.chrome`, не нашедшееся ищет ещё раз через 30 с. Имя, которое человек дал сам, главнее: hello говорит, дал ли (`named`). ИИ видит
и имя, и профиль Chrome, а просить профиль может любым из них или ключом. Welcome уходит раньше,
чем агент узнаёт о связи: первая сводка сессий после welcome решает в расширении судьбу вкладок
агента.

## Факты и замеры

Этот Mac, Chrome владельца, только чтение, из терминала: ключи четырёх копий нашлись в своих
профилях - Max (Default, имя по умолчанию, взято имя аккаунта), Work, Improving, Support - за
2-55 мс на поиск, чужой ключ - null за 5 мс.

Из самого приложения (0.1.5) - отказ EPERM на `Local State` и папки профилей: macOS не пускает в
данные Chrome приложение без «Полного доступа к диску». Терминал этот доступ имел, поэтому замер
выше прошёл. Тот же отказ и у native host, хотя его запускает сам Chrome: Chrome не передаёт ему
своё право на свои файлы. Проверено пробой, запущенной через `open` как приложение, и пробой
внутри host - обе `EPERM`. Поэтому владелец даёт IDE полный доступ к диску (его выбор из трёх:
назвать копии в IDE руками, полный доступ, или и то и другое); без него поиск отвечает `denied`,
и окно Browser Use говорит, что дать, и открывает нужную настройку. Ключи лежали в журнале `.log`; в таблицах `.ldb` значения сжаты
snappy, но короткая строка без повторов остаётся в них как есть. Тест -
`chrome-profiles.test.ts`, связь целиком - `browser-hub.integration.test.ts`.

## Последствия

- Профиль у ИИ называется так, как его видит человек в Chrome; одинаковых «Google Chrome» больше
  нет, пока человек сам не дал двум копиям одно имя.
- IDE читает файлы браузеров человека - только читает, и только Local State и хранилище своего
  расширения. На macOS для этого нужен «Полный доступ к диску»: без него копии зовутся именем
  браузера, а окно просит доступ (`namesDenied`).
- Если владелец передумает давать полный доступ - вариант «назвать копию в окне IDE»: поле имени у
  каждого подключённого профиля с подсказкой, какие сайты в нём открыты.
- Если Chrome поменяет хранение `storage.local` (уйдёт от LevelDB или начнёт шифровать), поиск
  вернёт null, и копия будет зваться как раньше - именем браузера. Тогда пересмотреть: вариант 2
  или выбор профиля человеком в окне расширения.

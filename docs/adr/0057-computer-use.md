# 0057. Computer Use - настоящие мышь и клавиатура мака по снимкам экрана, капсула внизу экрана

- **Статус:** Частично заменено [0058](0058-computer-use-windows.md) (Windows), [0060](0060-capsule-activity-line.md) (строка капсулы)
- **Дата:** 2026-11-13

## Контекст

Браузер для ИИ (ADR 0040) работает только внутри страницы: Chrome не пускает расширение в свои
страницы (chrome://settings, магазин расширений), в меню расширений, к закреплению вкладок, к
окнам разрешений, загрузки и печати, к выбору файла. Других приложений мака ИИ в IDE не видит
вовсе. Владелец попросил «общий computer use, чтобы тыкать по всему компьютеру» и выбрал из
двух путей macOS один - настоящие мышь и клавиатуру по снимку экрана, без «Универсального
доступа» как способа читать окна. Страницы сайтов остаются за расширением, а то, что ему
недоступно, ИИ сам делает через Computer. Пока Computer работает, внизу по центру экрана
капсула, как у диктовки, с паузой и остановкой.

Ограничения, которые нельзя обойти:

- События мыши и клавиатуры в чужие приложения macOS пускает только процессу с разрешением
  «Универсальный доступ», снимки экрана - с «Записью экрана». Выдаёт их только человек, в
  Системных настройках; после «Записи экрана» macOS может попросить перезапустить приложение.
- Мышь у машины одна: пока ИИ действует, человек ею пользоваться не может, а два разговора
  сразу её не поделят.
- По системным счётчикам простоя macOS события, посланные программой, от событий человека не
  отличить: посланное событие тоже сбрасывает «секунды с последнего ввода» (проверено опытом,
  см. ниже).
- Флаг модификатора на событии без нажатия и отпускания самой клавиши macOS запоминает как
  зажатый, и следующий набор становится сочетаниями - у человека тоже.

## Варианты

**Чем делать ввод и снимки.**

1. Свой помощник на Swift в бандле: ScreenCaptureKit и CGEvent в отдельном процессе. Точное
   время событий, но ещё одна сборка (нужны Command Line Tools), ещё один подписанный бинарник
   и ещё один протокол.
2. koffi из главного процесса для CGEvent (как `usage/phys-footprint.ts`, ADR 0008) и
   `desktopCapturer` Electron для снимков. Ни сборки, ни бинарника, правило проекта уже велит
   так звать нативное macOS. Время событий - таймеры главного процесса, как у руки браузера
   (ADR 0044), которая шлёт события ещё и через native messaging.

**Как модель называет точки.**

1. Пиксели снимка, уменьшенного до размера, который API Anthropic принимает без своего
   уменьшения (до 1568 по стороне и 1,15 Мп). Так обучен computer use Claude; перевод в точки
   экрана делает IDE.
2. Точки экрана macOS. Модель не знает масштаба Retina и размера дисплея, ошибалась бы.

**Как узнать, что мышь взял человек.**

1. Системные счётчики простоя (`CGEventSourceSecondsSinceLastEventType`). Не работает: наши
   события их тоже сбрасывают.
2. Перехват событий (event tap) с меткой на своих. Точно, но колбэк в цикле событий главного
   процесса и отдельное разрешение на слежение за вводом.
3. Рука помнит, куда сама поставила курсор, и перед каждым шагом сверяет: курсор не там -
   человек. Перед действием - тишина: курсор не двигается, кнопка и модификаторы не зажаты.

## Решение

Встроенный коннектор Computer Use (сервер `computer`, один на IDE) на koffi и `desktopCapturer`,
координаты - пиксели последнего снимка, вмешательство - по месту курсора. Главная причина -
всё уже есть в IDE: koffi и путь руки человека (ADR 0044), шлюз коннекторов и их окно; новый
бинарник ничего не дал бы, кроме сборки и подписи. Один разговор держит компьютер за раз
(минута без вызовов - отпускает), капсула - окно-панель поверх всех без фокуса, закрытое от
захвата экрана, с паузой (идущее действие обрывается, следующий вызов ждёт продолжения) и
остановкой (разговор узнаёт её и больше компьютер не берёт без спроса).

## Факты и замеры

Мак владельца, два дисплея (1920×1080 и 1512×982 при 2x), 13 ноября 2026, копия окна
(`/dev`) с настоящим Claude Code:

- Задача «открыть TextEdit, новый документ, кликнуть, напечатать фразу, описать снимок»:
  модель сама закрыла окно выбора файла через ⌘N, кликнула и напечатала; текст документа по
  AppleScript - ровно «Hello from Computer Use».
- Первый прогон нашёл, что koffi отдаёт 64-битное `uint64_t` обычным числом, а не BigInt;
  второй - что ⌘ флагом без клавиши остаётся «зажатым» (`CGEventSourceFlagsState` - 0x100000
  после сочетания). Теперь модификаторы жмутся своими клавишами и отпускаются в `finally`;
  флаги после прогонов чистые. Чтение CoreGraphics держит тест на настоящем koffi
  (`cg-events.integration.test.ts`).
- Опыт со счётчиками: событие движения в ту же точку, посланное с источником private, HID и
  combined, сбрасывает «секунды с последнего движения» с 71 до 0,14 у HID и combined.
- Человек увёл мышь посреди пути клика (сторонний процесс послал события движения): действие
  оборвалось с текстом «The user moved the mouse…», модель сделала снимок, повторила клик,
  дописала текст.
- Пауза в капсуле посреди снимка: вызов вернул «paused», следующий снимок ждал (16 с) до
  Resume. Stop посреди серии снимков: вызов вернул «Stop», модель прекратила работу.
- Капсула по оконному серверу: 340×44 в точке (790, 964) - низ по центру главного дисплея над
  Dock, слой 1000, `sharingState` 0 - её не видят ни снимки модели, ни Shotter. Центры знака,
  подписи и кнопок совпадают до 0,5 px.

Повторить: `pnpm --filter @agentic-workstation/desktop exec vitest run src/main/computer
src/main/connectors/kinds/computer`; живьём - копия окна (`/dev`), коннектор Computer Use,
задача в панели.

## Последствия

- `main/computer/`: `cg-events.ts` (koffi), `computer-hand.ts` (рука: путь, тишина, обрыв,
  модификаторы), `computer-desk.ts` (один разговор, очередь вызовов, пауза, остановка),
  `computer-screen.ts` и `computer-geometry.ts` (снимки и перевод точек), `computer-agent.ts`,
  `computer-capsule.ts`, `computer-runtime.ts`. Инструменты и пояснение - в
  `connectors/kinds/computer/`. Страница капсулы - второй вход окна (`capsule.html`,
  `app/capsule.tsx`, `features/computer`), её каналы - `computer.contract.ts`.
- Правила стола и руки, без которых модель действовала бы вслепую или мимо человека: у каждого
  вызова свой билет - Stop, конец разговора и выключение коннектора обрывают и идущий, и ждущий
  паузы, и стоящий в очереди вызов, а не будят его работать без капсулы; снимок, сделанный до
  паузы или до смены дисплеев, для действия не годится - модель сначала снимает экран заново;
  набор и сочетания прерываются, если человек зажал кнопку мыши или модификатор (⌘Tab, ⌘Space
  увели бы фокус, и перевод строки стал бы Return в чужом окне); разрешения macOS
  перечитываются на каждом вызове.
- Накладные окна (`window/overlay-windows.ts`) не получают событий окна IDE, не держат IDE
  открытой и не ждут сохранения перед выходом. Скрипт `/dev` (`cdp.mjs`) смотрит на главное
  окно, а не на капсулу.
- Пояснение Browser и его ошибки про chrome:// и закрытые вкладки отправляют модель к Computer,
  пояснение Computer - обратно к Browser для самих страниц.
- Только мак: на Windows коннектора нет в каталоге, а вызовы отвечают «только macOS». Windows
  - свой ввод (SendInput) и снимки, отдельной записью, когда будет на чём проверить.
- Пересмотреть, если понадобится работать с компьютером, не забирая мышь у человека (тогда -
  «Универсальный доступ» как способ читать и нажимать окна), или если таймеров главного
  процесса для пути мыши станет мало.

# 0113. Карточка трекера в чате ИИ: ссылка aw://tracker/card/<id>, чип карточки и инструмент tracker_card

- **Статус:** Принято
- **Дата:** 2026-11-23

## Контекст

Владелец ведёт работу на доске трекера (ADR 0101), а делает её в чатах провайдеров: Claude, Codex,
Kimi, Antigravity, открытые модели. Просьба: в меню карточки - «Implement» с выбором провайдера
сбоку, после выбора карточка встаёт в поле его чата, а отправляет человек сам; и «Copy link» -
ссылка на карточку, которую любой чат IDE понимает без объяснений.

Что было до решения. В поле ввода чипы файлов, кусков кода, цитат и вставок, сущностей IDE среди
них нет. «Send to Chat» из редактора кладёт чип в ту панель, что сейчас видна, выбрать провайдера
нельзя. Найти карточку по id ИИ не мог: `tracker_board` отдаёт доску одного проекта целиком, а
доска проекта - его пространство. Пояснение сервера `workstation` - единственный текст, который
видят все провайдеры, и оно упиралось в 2048 знаков (запас был 11). Отдельной схемы ссылок
(протокола в системе) у IDE нет.

## Варианты

**Что попадает в чат по «Implement».**

- **Только ссылка, карточку ИИ читает сам.** Плюсы: в чате всегда свежая карточка. Минусы:
  каждый «Implement» начинается с поиска инструмента (Claude Code показывает MCP только после
  поиска) и вызова; если коннектор IDE в проекте выключен, ИИ получает непонятную строку.
- **Чип карточки: ссылка и текст карточки (выбрано).** Модели уходит
  `<tracker-card link="aw://tracker/card/<id>">` с заголовком, подзаголовком и описанием внутри,
  человек видит чип с заголовком. Плюсы: работа начинается сразу, у любого провайдера, и с
  выключенным коннектором тоже; ссылка рядом - перечитать и отметить сделанной. Минусы: текст -
  снимок на момент, когда чип положили; правка карточки после этого в чат не доедет.

**Каким текстом ссылка.**

- **Голый id (UUID).** Минусы: строка без смысла, модель не свяжет её с трекером.
- **Своя схема с путём, как у инструмента: `aw://tracker/card/<id>` (выбрано).** Плюсы: путь
  повторяет имя `tracker_card`, и модель, не видевшая пояснения сервера (у Codex и ACP его не
  показывают так, как у Claude), находит инструмент по словам; ссылка короткая. Минусы: схема не
  зарегистрирована в системе - по клику вне IDE ничего не откроется.
- **`agentic-workstation://...` с регистрацией протокола.** Плюсы: открывалась бы из браузера.
  Минусы: длинно в каждом сообщении, а регистрация протокола - отдельная работа для установщиков
  обеих систем без нужды сейчас.

**Где ИИ ищет карточку по ссылке.**

- **Только доска проекта разговора.** Минусы: ссылка из другого проекта не работает, а id карточки
  и так один на все машины.
- **Пространство карточки по цепочке родителей, потом проекты этой машины, привязанные к нему
  (выбрано, `TrackerService.pathsOf`).** Плюсы: ссылка работает в чате любого проекта; ничего не
  заводит. Минусы: проект, закрытый для разговора коннектором, карточку не отдаёт - так и задумано
  (`workstation-scope.ts`).
- **Перебрать `board()` всех известных проектов.** Минусы: `board()` заводит доску проекту, у
  которого её не было, и новое пространство уходит в облако - поиск оставлял бы мусор.

**В какой чат ложится карточка.**

- **В активный, как «Send to Chat» из редактора.** Плюсы: одно правило на все передачи. Минусы:
  карточка - новая работа, а ложилась к чужому разговору со своей историей и контекстом.
- **В новый разговор (выбрано владельцем).** Пустая вкладка с пустым полем и есть новый чат -
  карточка ложится в неё, иначе панель заводит вкладку; две карточки подряд - два разговора.
  Плюсы: у работы чистый контекст, вкладки не множатся пустыми. Минусы: свой путь передачи
  (`ChatHandoff.fresh`, решение - `handoffStep`).

**Выбор провайдера сбоку.** В дизайн-системе не было вложенного меню. Отдельное окно выбора или
вторая страница в той же панели (как выбор модели в настройках чата) - лишний шаг и не то, что
просили. Новый примитив `MenuSubmenu` - вложенная всплывающая панель Popover API, открытая с
`source`: браузер сам держит родительскую открытой и закрывает обе по клику мимо.

## Решение

Чип `card` в поле ввода (`shared/message-draft.ts`, текст для модели - `cardReferenceText`, разбор
из транскрипта - `REPLAY_CARD`), ссылка `aw://tracker/card/<id>` (`shared/tracker-link.ts`) и
инструмент чтения `tracker_card` с местом на доске и путём проекта. «Implement» передаёт чип
названному провайдеру (`ChatHandoff.provider`) в новый разговор (`fresh`) и показывает его панель;
в списке - провайдеры, чьи кнопки стоят на правой полосе, в её порядке. «Copy link» кладёт в буфер ссылку текстом и
чип в text/html: вставка в поле любого чата IDE даёт живой чип с текстом карточки. Главная
причина - работа должна начинаться одним нажатием у любого провайдера, а ссылка - читаться в
любом проекте.

## Факты и замеры

Замера нет: решение о форме данных и словах для модели. Пояснение сервера `workstation` с
описанием человека предельной длины - 2038 знаков из 2048 (строку ссылки оплатило сжатие соседних
строк без потери смысла). Тесты: `tracker-tools.test.ts` (карточка по ссылке, продолжение со своей
задачей, чужой проект, закрытый проект, поиск не заводит доску), `draft.utils.test.ts` (текст для
модели и обратный разбор, подпись и буфер), `chat-handoff.store.test.ts` и `chat-handoff.utils.test.ts` (кусок для провайдера, новый разговор
под карточку) -
`pnpm --filter @agentic-workstation/desktop exec vitest run src/main/connectors src/renderer/src/features/agent-panel src/renderer/src/state`.

## Последствия

- Новый вид чипа проходит те же места, что остальные: подпись и подсказка (`chips.utils.ts`),
  значок (`CHIP_ICONS` - значок трекера), текст модели, буфер, разбор транскрипта. Телефон чипов не
  рисует и показывает тег текстом.
- Значки и имена панелей провайдеров живут в `lib/provider-panels.constants.ts`: их берут и
  правая полоса, и подменю «Implement».
- Запас пояснения сервера `workstation` - 10 знаков: следующая строка снова за счёт сжатия.
- Пересмотреть, если понадобится открывать карточку по ссылке из браузера или почты (тогда -
  регистрация протокола), или если снимок текста в чипе начнёт расходиться с доской на практике.

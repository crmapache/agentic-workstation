# 0078. Окно ленты телефона - в видимых строках, шаги субагента - числом

- **Статус:** Принято
- **Дата:** 2026-11-17

## Контекст

Владелец нажимал «Load earlier messages» в долгом разговоре, и ничего не происходило: на экране
оставались только кнопка и «Working · 34m». ADR 0041 резал снимок ленты для телефона по
элементам ленты IDE (последние 120, в пределах кадра), страницу выше - так же по 60. Но шаги
субагента - тоже элементы ленты, и за полчаса работы субагент набирает их сотни. Телефон рисует
их не строками, а числом шагов на строке вызова, поэтому хвост из одних шагов приходил
невидимым, и каждая страница выше - снова невидимой. Число шагов на строке вызова при этом
было неверным: телефон считал только шаги, дошедшие до него.

## Варианты

**Только на телефоне: прятать шаг, лишь когда загружена строка его вызова (как окно IDE), и
подкачивать страницы, пока не появится видимая строка.**

- Плюсы: протокол и мост не меняются.
- Минусы: по сети по-прежнему идут сотни шагов, которых никто не увидит; строка вызова со своим
  Stop остаётся далеко вверху, а когда подгрузится, видимые шаги схлопнутся, и лента прыгнет.

**В IDE: окно ленты считается в строках, которые рисует телефон; шаги, чей вызов есть в ленте
IDE, не едут вовсе, а их число едет отдельным полем.**

- Плюсы: снимок и страница всегда несут то, что видно; число шагов верное, потому что считано по
  всей ленте IDE; живой шаг - обновлённое число, а не элемент, и строка вызова не всплывает вниз.
- Минусы: мост помнит, какой шаг к какому вызову относится (память живёт и убирается вместе с
  журналом разговора); протокол получает необязательные поля чисел.

## Решение

Второй вариант. Одна функция окна (`bridge/feed-window.ts`) для снимка, страницы выше и журнала
шага прогона: строкой не считается шаг, чей вызов Agent/Task есть в полной ленте IDE; окно -
последние N строк в пределах кадра; число шагов по каждому вызову - полем `steps` у снимка,
страницы и заплатки (в заплатке - число целиком, повтор ничего не ломает). Шаг без видимого
вызова (агент скилла) едет обычной строкой. Страница с «есть ещё выше» не бывает пустой: IDE
дочитывает транскрипт, пока выше не найдётся строка. Главная причина - телефон получает ровно
то, что рисует, а не то, что потом спрячет.

## Факты и замеры

- Модель на настоящих функциях снимка, страницы и фильтра: 50 ответов, сообщение, вызов
  субагента и 400 его шагов. До: шаги по 1.5 КБ - в снимке 120 элементов, видно 0, четыре
  нажатия - по-прежнему 0; шаги по 10 КБ - по 25 в кадре, после 8 нажатий видно 0.
- После: снимок несёт строку вызова с числом 400 и влезает в кадр, новый шаг даёт 401 без нового
  элемента - `bridge/feed-window.test.ts` и случай на настоящем релее в
  `apps/phone/e2e/client-interop.test.ts`.

## Последствия

- Правило ADR 0041 «снимок последних 120 элементов» теперь - «последних строк»: `SNAPSHOT_ROWS`,
  `PAGE_ROWS`.
- Телефон, который старше этих полей, с новой IDE не покажет число шагов; остальное работает.
- Дочитывание транскрипта ради непустой страницы ограничено 20 страницами подряд без строк: каждая
  читает файл транскрипта целиком. Упрёмся - следующее нажатие продолжит выше.

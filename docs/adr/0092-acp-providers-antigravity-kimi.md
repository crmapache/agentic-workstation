# 0092. Antigravity и Kimi Code - через ACP, одним ядром клиента на всех агентов ACP

- **Статус:** Принято
- **Дата:** 2026-11-19

## Контекст

Владелец попросил ещё двух провайдеров рядом с Claude Code, Codex и открытыми моделями: Google
Antigravity (консольный агент `agy`, у владельца подписка Google) и Kimi Code от Moonshot
(`kimi`, подписку купит позже). Устройство провайдеров уже есть (ADR 0083): общее ядро панелей и
драйвер на провайдера, вся IDE работает через драйверы (ADR 0085).

Оба CLI умеют ACP (Agent Client Protocol) - открытый протокол встраивания агента в редактор:
JSON-RPC построчно по stdio, сессии, ход, поток обновлений, вопросы разрешения, режимы, модели,
история. На нём сами разработчики подключают агентов к Zed и JetBrains.

## Варианты

**Свой протокол у каждого.** У `agy` - `agy -p --input-format stream-json --output-format
stream-json` (похоже на поток Claude), у Kimi - KAP (REST и WebSocket через `kimi web`).

- Плюсы: у KAP богаче возможности (форк с хода, откат разговора, история файлов, токены хода).
- Минусы: два новых протокола вместо одного; KAP вышел в день решения, его служебная часть
  меняется без совместимости; поток `agy -p` по условиям Google - для скриптов и CI, а не для
  чужих приложений, и вопросы разрешения он молча отклоняет.

**ACP у обоих, одно ядро клиента.**

- Плюсы: один клиент на двух агентов и на любого следующего с ACP (протокол поддерживают уже
  десятки агентов); официальный путь у обоих: документация Antigravity зовёт «Other ACP clients»,
  документация Kimi советует ACP для встраивания в IDE. Возможности агент объявляет в
  `initialize`, панель показывает только объявленное (ADR 0083).
- Минусы: ACP беднее своих протоколов - нет отката разговора и форка с хода, у `agy` нет форка
  вовсе, а `mcpCapabilities` он не объявляет. Расширения агентов приходят в `_meta` и в
  незаявленных полях, их держит драйвер.

**Для Google - Gemini CLI вместо `agy`.** Он тоже говорит ACP, но с 18.06.2026 не обслуживает
подписки Google AI Pro и Ultra (только платные ключи API), замена ему - Antigravity CLI. Подписку
владельца он не использует - отпадает.

## Решение

ACP у обоих: ядро клиента ACP в главном процессе (`main/acp/`) - процесс, протокол, лента,
вопросы, модели и режимы, история, коннекторы, переводчик для сценариев; драйверы
Antigravity и Kimi - тонкие: поиск CLI, своя папка, вход и квота, отображение режимов, свои
расширения протокола. Главная причина - один выверенный клиент вместо двух протоколов, и тот же
клиент без переделки примет следующего агента с ACP. Для Google - только официальный
неизменённый `agy acp`, вход делает сам `agy`, токенов IDE не касается.

## Факты и замеры

Пробник на Node (`initialize`, `session/new` с MCP по HTTP, 9-11 ходов, отмена, `session/load` в
новом процессе, у Kimi ещё `session/fork`) на `agy` 1.5.12 (Gemini 3.8 Flash, усилие low, вход
Google AI Plus) и `kimi` 2.7.0 (своя папка `KIMI_CODE_HOME`, модель - локальная qwen3.8 через
`KIMI_MODEL_*`, без подписки). Записи - `apps/desktop/src/main/acp/__fixtures__/`.

- **Возможности `initialize`.** `agy`: `loadSession`, сессии `resume`, `close`, `load`, `list`,
  `additionalDirectories`, без `fork` и без `mcpCapabilities`; `_meta.antigravity` - `tier` и
  `systemPrompt.append`. Kimi: `list`, `resume`, `close`, `delete`, `fork`,
  `additionalDirectories`; MCP - `http` и `sse`.
- **MCP по HTTP** в `session/new` работает у обоих, у `agy` - несмотря на необъявленную
  возможность и без `--process-per-session`. Заголовок с ключом `agy` шлёт на POST, а GET без
  него (сервер отвечает 401, на работу не влияет).
- **Вызовы.** `kind` по схеме ACP (`read`, `edit`, `execute`, `other` для MCP). У `agy` в
  вызове есть незаявленные `name` (`edit_file`, `run_command`, `mcp_<сервер>_<инструмент>`) и
  `args`; дифф правки в вопросе разрешения - кусок, в конце вызова - файл целиком; результат
  MCP не приходит. У Kimi `title` - имя инструмента (`Bash`, `mcp__<сервер>__<инструмент>`),
  `rawInput` - во втором обновлении, вопрос разрешения без `kind`, связь - по `toolCallId`.
  **id вызова у Kimi в живом потоке и при `session/load` разные** (`1:call_x` и `2:call_x`) -
  устойчивая часть после двоеточия.
- **Вопросы.** Разрешение: `agy` - `allow` и `deny` (`allow_once`, `reject_once`); Kimi -
  `approve_once`, `approve_always` (на сессию), `reject`. План у Kimi - разрешением
  `ExitPlanMode` с вариантами `plan_approve`, `plan_revise`, `plan_reject_and_exit` и текстом
  плана. Вопрос с вариантами у обоих - `elicitation/create` с формой (`oneOf`, у `agy` ещё
  поле `<id>_other` для своего ответа), если клиент объявил `elicitation.form`.
- **Режим «по умолчанию» у Kimi не спрашивает правки в папке проекта** - только команды и MCP.
- **Расход.** `agy` в ответе на `session/prompt` отдаёт `usage` хода (вход, выход, кэш, мысли);
  Kimi - нет (только `usage_update` с занятым окном). Окно: `agy` - 1 048 576, Kimi с qwen3.8 -
  262 144.
- **Артефакты `agy`** - вызов `write_file` в `brain/<сессия>/` с `rawInput.ArtifactMetadata`
  (`Summary`, `RequestFeedback`, `UserFacing`).
- **Размышления:** `agy` на Flash low их не шлёт; Kimi шлёт очень дробно (1309 кусков за 11
  ходов).
- `session/load` у обоих повторяет историю обновлениями (`user_message_chunk`, вызовы в конечном
  статусе, ответы). `session/list` у `agy` 1.5.3 фильтр по
  `cwd` не применил (на 1.5.12 в своей папке разговор был один - не проверить), поэтому разговоры
  по папке фильтрует IDE.

- **Указания IDE** (замер тем же пробником и живым тестом `acp-live.test.ts`). `agy`:
  `_meta.antigravity.systemPrompt.append` в `session/new` и `resume` дописывает текст к своему
  промпту. Kimi: `--agent-file` перед `acp` молча не действует, полей сессии нет; действует
  профиль `agents/agent.md` в своей папке с `override: true` и `${base_prompt}` первой строкой -
  встроенный профиль `agent` (его берёт каждая сессия ACP) заменяется, промпт Kimi остаётся,
  набор инструментов тот же, в режиме плана тоже действует. Папку делят панель и исполнитель
  сценариев, поэтому текст у Kimi общий для обоих.
- **MCP проекта.** `agy` грузит `.agents/mcp_config.json` папки проекта (сервер-маркер
  запустился; сервер, который не отвечает, повесил ход на 4 минуты), флага выключить это нет.
  Kimi берёт `.mcp.json` проекта и `.kimi-code/mcp.json` только в доверенной папке, а своя папка
  IDE не доверяет ни одной (`KIMI_CODE_TRUST_WORKSPACE` IDE не ставит) - не грузятся, как и
  правила разрешений проекта; `AGENTS.md` проекта Kimi читает. Вопрос доверия папке в IDE
  говорит об этом своими словами для каждого агента.
- **Форк у Kimi.** `session/fork` из чужого процесса, пока разговор открыт, - отказ «This session
  is in use by another Kimi Code CLI instance»; процесс, который держит разговор, форкает сам,
  закрытый форк продолжает другой процесс (`session/resume`, ответ помнит разговор).
- **Ошибки.** На «Internal error» причина - в `data.details` ответа JSON-RPC.
- **Квоты `agy` по ACP нет:** в ответе хода - только расход токенов, в `_meta` - тариф. Сама
  квота - во внутреннем API Google (`retrieveUserQuotaSummary`) с токеном `agy`; ходить туда
  из IDE - доступ к сервису сторонней программой, условия это запрещают. Колец квоты у
  Antigravity нет.
- **Windows** (по установщикам и манифестам winget, живого Windows нет): `agy` -
  `%LOCALAPPDATA%\agy\bin\agy.exe` или ярлык winget; `kimi` -
  `%USERPROFILE%\.kimi-code\bin\kimi.exe`, ярлык winget или `kimi.cmd` от npm (идёт через
  `cmd.exe`). Kimi на Windows без Git Bash сессию не открывает (`KIMI_SHELL_PATH` - свой
  `bash.exe`), IDE ищет его тем же порядком, что Kimi.

Повтор: `node ~/aw-acp-probe/record.mjs <сценарий.json> <выход.ndjson>` (сценарии и пробник -
в истории этой записи, план `docs/plan-acp-providers/README.md`).

## Последствия

- Новый агент с ACP - драйвер: поиск CLI, окружение и папка, вход, квота, отображение режимов и
  расширений. Ядро не обрастает развилками по агенту: что агент умеет, говорит `initialize`.
- Лента ACP держит id вызова по устойчивой части, а не по строке агента.
- Возможностей, которых ACP не даёт (откат разговора, форк с хода, у `agy` форк), панель не
  показывает. Откат кода - силами IDE обратными правками по диффам ленты, как у Codex (общий
  `agents/changes/code-revert.ts`). Форк целиком у Kimi - процессом, который держит разговор.
- Мост stdio↔HTTP для коннекторов не нужен: оба агента берут серверы по HTTP. Появится агент без
  HTTP - мост придёт с ним.
- Свои типы протокола сверяет с официальной схемой тест `protocol-drift.test.ts` (пакет
  `@agentclientprotocol/sdk` - только для разработки, той же версии, что внутри Kimi).
- Пересмотреть, если KAP устоится и даст Kimi то, чего нет в ACP, или если Google даст
  официальный путь богаче ACP.

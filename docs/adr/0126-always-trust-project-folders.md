# 0126. IDE всегда доверяет папкам проектов: вопроса «Trust this folder?» нет

- **Статус:** Принято
- **Дата:** 2026-11-25

## Контекст

С ADR 0009 панель сама спрашивала, доверяешь ли ты папке: с `-p` CLI Claude Code этого не делает
и сразу исполняет хуки проекта. Потом вопрос переехал во все панели (Codex, OpenCode,
Antigravity, Kimi - свой список папок у каждой), в задания и поручения (сбой с кнопкой «Trust
folder and run», ADR 0069, 0080), в сценарии и их черновики (отказ `untrusted`), в экраны
плагинов и `/config`, в импорт коннекторов (`.mcp.json` недоверенной папки не читался, ADR 0029).
Дом IDE доверялся при запуске отдельно (ADR 0059).

Владелец IDE открывает в ней только свои проекты. Вопрос встаёт на первом сообщении в каждой
новой папке и у каждого провайдера по отдельности, сообщение ждёт в очереди до нажатия, а
задание по расписанию в новом проекте падает сбоем, пока его не заметят. Слова владельца:
«больше раздражает», чем защищает.

## Варианты

- **Оставить вопрос.** Плюсы: чужой репозиторий не исполнит хук без согласия. Минусы: вопрос на
  каждую новую папку у каждого из пяти провайдеров, ночные задания и очереди падают на нём;
  человек, который открывает только своё, жмёт «Trust» не читая - защита становится ритуалом.
- **Настройка «спрашивать о доверии», по умолчанию выключена.** Плюсы: защиту можно вернуть.
  Минусы: остаётся весь механизм - пять списков доверия, код отказа в заданиях, сценариях,
  уведомлениях, телефоне и коннекторе IDE, ветки окна - ради режима, которым никто не
  пользуется; каждый новый путь запуска CLI надо помнить проверять.
- **Убрать доверие целиком.** Плюсы: ни вопроса, ни отказа `untrusted` нигде; минус целый слой
  состояния и кода. Минусы: проект, открытый в IDE, исполняет свои хуки и настройки сразу, как в
  терминале с уже нажатым «Trust».

## Решение

Убрать доверие целиком: открыть проект в IDE и значит ему доверять. Разговоры, задания,
поручения, сценарии, экраны плагинов и `/config` поднимают CLI в папке проекта без проверки,
импорт коннекторов читает `.mcp.json` каждого открытого проекта. Главная причина - IDE личная,
в ней открывают только свои проекты, и вопрос не защищал, а мешал работать, особенно заданиям
без человека.

## Факты и замеры

Замера нет: решение о поведении, а не о скорости. Что проверено:

- старый файл панели (`claude.json`, `codex.json` и другие) с полем `trustedProjects` читается
  без ошибки, поле отбрасывается (`claude-state.test.ts`);
- прогон задания из старой записи со сбоем `untrusted` читается со сбоем без кода, кнопка
  `trust` старого уведомления отбрасывается разбором (`task-parse.ts`, `inbox-rules.ts`);
- телефон на неизвестный код показывает общий текст отказа, так что старая IDE с новым
  телефоном не ломается.

## Последствия

- Нет `WorkspaceTrust`, `FolderTrust`, `isTrusted`/`trust` у драйвера и хоста разговора, канала
  `agent:trustProject`, кода `untrusted` у разговора, сценария, задания, экранов плагинов и
  `/config`, кнопки уведомления `trust`. Новый путь запуска CLI доверие не проверяет.
- Серверы `.mcp.json` в импорте коннекторов по-прежнему не отмечены по умолчанию (ADR 0029): их
  принёс репозиторий, а не человек, и подключает их только нажатие.
- Свои правила доверия самих агентов не трогаем: Kimi без `KIMI_CODE_TRUST_WORKSPACE` так же не
  грузит MCP проекта (ADR 0092), MCP у всех агентов - коннекторы IDE.
- Пересмотреть, если IDE станут открывать чужие репозитории (общий компьютер, клонирование
  незнакомого кода из IDE): тогда вернуть вопрос одним местом на уровне проекта, а не у
  каждого провайдера.

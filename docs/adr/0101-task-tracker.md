# 0101. Трекер задач - вид середины окна: доска записями с часами по полям, карточки в очередях сценариев

- **Статус:** Принято
- **Дата:** 2026-11-20

## Контекст

Владелец хочет свой трекер задач вместо Todoist, проще и устроенный так, как ему удобно
(`TASK_TRACKER.md`, схема в Figma): у каждого проекта IDE своя доска; вкладками - проекты
трекера; внутри - потоки (полоса во всю ширину, сворачиваются, это помнится); в потоке - группы
колонками в порядке работы; в группе - задачи сверху вниз, у задачи - продолжения справа.
Всё перетаскивается; выполненная задача гаснет, но остаётся на месте; удалённый проект уходит
в архив и сам удаляется через 30 дней. Доска должна жить в облаке (ADR 0102), ей должен
управлять ИИ через MCP самой IDE (ADR 0090), а к карточке можно привязать сценарий и отправить
всю группу в одну очередь (ADR 0039) - поток «обсудили в чате → карточки → сценарии».

Имя «Tasks» уже занято заданиями по расписанию (ADR 0069), «card» - карточками сценария.

## Варианты

**Хранение доски.**

- **Один JSON-документ доски целиком.** Плюсы: просто. Минусы: две машины, поправившие
  разное, затирают друг друга целиком; порядок списком - перенос на одной машине и вставка
  на другой спорят за весь список.
- **Записи (пространство, проект, поток, группа, карточка) с родителем полем, местом -
  дробной строкой и отметкой часов у каждого поля (выбрано).** Плюсы: перенос - правка одного
  поля одной записи; правка заголовка здесь и перенос там сходятся без потерь; удаление -
  тоже поле, старая копия с другой машины его не воскресит; «Undo» - вернуть поле. Минусы:
  своё слияние и свои часы (гибридные логические), дерево строится на каждый взгляд.

**Продолжения.**

- **Продолжение - дочь предыдущего (цепочка ссылок).** Минусы: удаление середины рвёт
  цепочку, перенос задачи переписывает все звенья.
- **Продолжения держатся за задачу и стоят по месту, как задачи в группе (выбрано).**
  Плюсы: перенос задачи - одно поле, продолжения едут сами; «продолжение продолжения»
  встаёт в ту же цепочку. Минусы: продолжения одного уровня - ветвлений нет (их нет и в схеме).

**Карточка и сценарий.**

- **Текст карточки копируется в поля сценария при привязке.** Минусы: правка карточки потом
  не доходит до прогона.
- **В полях сценария - подстановки `{{card}}`, `{{title}}`, `{{subtitle}}`, `{{description}}`,
  раскрываются при отправке (выбрано).** Первое поле по умолчанию - `{{card}}`.

**Чья доска у папки.** У проекта IDE путь на каждой машине свой. Варианты: (а) только привязка
пути - вторая машина всегда начинает с пустой доски; (б) ключ - origin в git, дом или имя папки
(выбрано). Клоны и worktree одного репозитория делят доску: это тот же проект, а очереди
сценариев в worktree (ADR 0039) видят свои карточки. Две несвязанные папки без git с одним
именем на одной машине получают разные доски: по имени папки доска узнаётся только с другой
машины, а пространство, привязанное здесь к живой папке, второй папке не отдаётся.
Перенесённая папка (старого пути нет) свою доску забирает.

**Удаление проекта трекера.** По заданию проект уходит в архив и сам удаляется через 30 дней.
В окне архива есть ещё «Delete now» - после вопроса, для проекта, который точно не
нужен; ИИ этого не может (`tracker_delete` только архивирует). Срок архива считается только
после первой сверки с облаком: по устаревшей копии машина удалила бы проект, который на другой
машине уже вернули.

**Отправка группы.** По одной карточке через окно Run scenario - медленно и порядок случаен
(старт идёт до первого прогона). Выбрано: главный процесс проверяет все карточки до первого
запуска (сценарий на полке, исправен, обязательные поля, провайдер), затем ставит их по одной
в порядке доски - задача, её продолжения, следующая задача; новая очередь получает имя группы.

## Решение

Вид `tracker` в середине окна (`features/tracker`), доска в главном процессе
(`main/tracker/`) записями с часами по полям в `userData/tracker.json`, правки - одним союзом
`TrackerOp` и для окна, и для MCP; карточка помнит элемент очереди только на этой машине и
отмечается выполненной один раз, когда элемент сделан. Главная причина - слияние по полю:
доска синхронизируется между машинами (ADR 0102), и ни перенос, ни правка не должны теряться.

## Факты и замеры

- Тесты главного процесса: порядок строками (вставка 100 раз в одно место держит порядок,
  длина строки < 30), записи и слияние, правки доски (цепочки, перенос задачи с продолжениями
  в чужую цепочку, запрет «продолжения самой себя», Undo, архив и удаление через 30 дней,
  чужая доска), отправка в очередь (порядок доски, пропуски, проверка до запуска, имя очереди,
  авто-отметка один раз, упавший прогон не отмечает) - `pnpm --filter @agentic-workstation/desktop
exec vitest run src/main/tracker`. Инструменты MCP - 11 тестов (`tracker-tools.test.ts`).
- Живьём 2026-11-20 в копии окна (`/dev`) на временной папке с git-origin и одним сценарием:
  доска по схеме (поток во всю ширину, группы колонками, продолжения справа), перетаскивание
  настоящими событиями мыши - задача выше соседки, задача в конец чужой цепочки, группа перед
  другой группой; линия места и призрак под рукой; сворачивание потока в localStorage;
  быстрое добавление строкой; удаление и Undo; окно карточки (крестики срока - центр в центр
  с полями, 30 px); отправка группы - очередь «Week 1», метка «Fix a task · queued», в
  копии без доверия к папке - «· held».
- Замера скорости нет: доска из сотни карточек строится за единицы миллисекунд, время правки -
  время IPC.

## Последствия

- Перетаскивание вкладок проектов IDE переехало в `lib/tab-drag.*` (`useTabDrag`) - им же
  двигаются вкладки проектов трекера. Доска тянется своим хуком (`Board.hooks.ts`): места
  читаются по data-атрибутам (`data-card`, `data-chain`, `data-group-column`, `data-flow`).
- Связь «карточка → элемент очереди» в облако не уходит: очереди у каждой машины свои.
  Состояние берётся из `queuesView` по id, слушатель - отвод `onQueues` сценариев.
- Доска проекта IDE на машине находится по привязке «путь → пространство»; новое
  пространство узнаётся по origin в git, дому или имени папки (ADR 0102).
- Встречные правки двух машин сводятся после каждого забора (`tracker-heal.ts`,
  `mergeTwinSpaces`): карточка под предком, удалённым на другой машине, возвращает предков, если
  её правка новее удаления, иначе уходит вслед; продолжение продолжения встаёт в цепочку корня,
  цикл встречных переносов рвётся на карточке с меньшим id; два соседа с одним местом
  разводятся при вставке между ними. Окна карточки и заголовков шлют только тронутые поля.
- Пересмотреть, если понадобятся ветвления продолжений, общие доски с другими людьми или
  доска на телефоне без IDE.

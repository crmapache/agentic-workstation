# 0083. Провайдеры ИИ - отдельные панели на общем ядре, Claude Code - первый драйвер

- **Статус:** Принято
- **Дата:** 2026-11-18

## Контекст

Владелец попросил ещё двух провайдеров рядом с Claude Code: OpenAI Codex и открытые модели -
локальные (Ollama, LM Studio) и облачные (OpenRouter). За основу берётся устройство Claude Code
в IDE: оно выверено.

Провайдер Claude большой и растёт с ADR 0009. Вокруг панели на нём стоят сценарии, задания,
цели, статистика, телефон и уведомления, и говорят они не со «словом провайдер», а с форматом
Claude. Движок сценариев читает поток stream-json (ADR 0039 решил так сознательно), задания и
цели берут сессии Claude напрямую, статистика читает только журналы Claude Code, а провайдер в
типах один - `claude`. ADR 0039 сам назвал момент пересмотра: появится второй провайдер с
другим потоком. Он появился.

Где жить провайдерам в окне, решил владелец. У каждого своя иконка в полосе провайдеров и своя
панель со своими вкладками, настройками, аккаунтами и лимитами: Claude, под ним Codex, под ним
открытые модели. Разговоры разных провайдеров не смешиваются.

## Варианты

**Копия провайдера Claude под каждого нового.**

- Плюсы: Claude не трогаем, начать можно сразу.
- Минусы: две, а потом три копии по 50 тысяч строк, которые расходятся с первого дня - то же,
  что ADR 0009 описывает про копию ACC в claude-code-ide. Каждая правка ленты, поля ввода или
  очереди сообщений делается трижды.

**Перевод потока нового провайдера в формат Claude, ядро не трогаем.**

- Плюсы: сценарии, лента и панель работают без правок, как и обещал ADR 0039.
- Минусы: Codex и OpenCode притворяются Claude Code. Аккаунты, лимиты, откат файлов, форк по
  номеру сообщения, быстрый режим - это управляющие запросы CLI Claude, их пришлось бы
  изображать. Лента остаётся в форме инструментов Claude (Bash, Edit, ExitPlanMode), а у Codex
  правка - патч, команда - свой элемент, план - отдельный элемент. Каждая новая возможность
  второго провайдера - ещё один костыль в переводе.

**Общее ядро и драйвер на провайдера, Claude - первый драйвер.**

- Плюсы: вкладки, очередь сообщений, лента, карточки разрешений, вопросов и плана, правки и
  откат, картинки, команды `!`, зов и поиск написаны один раз и уже выверены на Claude. Драйвер
  отвечает только за своё: процесс и протокол, аккаунты, лимиты, модели и усилие, режимы,
  историю, форк и откат, коннекторы, журналы. Чего драйвер не умеет, он не объявляет, и в
  интерфейсе этого нет - без заглушек.
- Минусы: большой переезд Claude, которым пользуются каждый день. Нужен общий формат ленты
  вместо формата Claude и провайдер в каждом вызове IPC.

## Решение

Общее ядро и драйверы. Главная причина - одна реализация чата на три панели: правка ленты или
поля ввода доезжает до всех провайдеров сразу, а у провайдера своими остаются только протокол
и то, чего у других нет. Claude переезжает первым и без видимых изменений, это держат
существующие тесты. Codex и открытые модели встают драйверами на готовое ядро. В окне - три
независимые панели, как решил владелец: общий у них только код.

## Факты и замеры

Замерено на ветке от `main` cc32713:

- Размер провайдера Claude без тестов: главный процесс - 20 410 строк в 18 папках, окно - 514
  файлов и 29 469 строк. Каналов IPC около 79 (`claude:*` 48, `claudePanel:*` 10,
  `claudeSearch:*` 4, `claudeConfig:*` 3, `accounts:*` 10, `plugins:*` 4), провайдера не
  принимает ни один.
- Где провайдер прибит к Claude: `ProviderId` - только `'claude'` (`shared/providers.ts`);
  движок сценариев читает сообщения CLI Claude (`scenarios/engine/scenario-session.ts`);
  `tasks/tasks-setup.ts` берёт сессии, автора заданий и проверки целей Claude напрямую;
  статистика читает только `~/.claude/projects`; провайдер телефона - константа в
  `remote/bridge/conversation-wire.ts`.
- Уже не зависят от провайдера: вкладки, команды `!`, зов, индекс поиска, построчная разница
  правок и большая часть компонентов ленты в окне.
- Codex 0.163.0 на этой машине. Серверный режим `codex app-server` - JSON-RPC построчно через
  stdin и stdout: разговоры, ходы, вопросы разрешения запросами сервера, форк, откат (с 0.160),
  каталог моделей с уровнями усилия, лимиты аккаунта. Типы протокола Codex печатает сам
  (`codex app-server generate-ts`). Справочник - плагин владельца amazing-codex для JetBrains,
  проверенный на Codex 0.152-0.163.
- В бинарнике Codex 0.163 есть ключи настроек MCP по HTTP с токеном из окружения
  (`bearer_token_env_var`, `env_http_headers`): шлюз коннекторов (ADR 0028) может отдать токен
  процессу не аргументом.

Повтор:

```sh
find apps/desktop/src/main/claude -name '*.ts' ! -name '*.test.ts' | xargs cat | wc -l
codex app-server --help
strings /opt/homebrew/lib/node_modules/@openai/codex/node_modules/@openai/codex-darwin-arm64/vendor/aarch64-apple-darwin/bin/codex | grep -c bearer_token_env_var
```

## Последствия

- В главном процессе ядро разговоров отделено от драйверов, код Claude уходит в драйвер. Имена
  папок и интерфейс драйвера - в `docs/architecture.md`, как только переезд появится в коде.
- Лента - общий формат: виды действий (команда, правка, чтение, поиск, веб, коннектор,
  субагент, план, вопрос, список дел), имя инструмента провайдера - только подпись.
- IPC: общий контракт панели провайдера, провайдер - в каждом вызове и событии. Экраны, которые
  есть у одного провайдера, идут своим контрактом.
- Драйвер объявляет, что умеет (форк, откат файлов, быстрый режим, план, лимиты, побочный
  вопрос). Окно показывает только объявленное.
- Сценарии, задания, цели «до результата», служебные задачи IDE, коннектор от ИИ, статистика и
  телефон работают через драйвер. Где бы ни выбирался провайдер, выбираются и его модель с
  усилием, а где есть режим - и режим. Списки приходят от провайдера (решение владельца).
- Настройки человека у Codex (`~/.codex/config.toml`) и OpenCode IDE не правит, как не правит
  настройки Claude Code: у IDE для них свои папки.
- Коннекторы и у Codex с OpenCode - только через шлюз IDE (ADR 0029): свои MCP-серверы человека
  из их настроек процессам IDE не достаются.
- ADR 0039 частично заменён: движок сценариев говорит с драйвером, а не с потоком stream-json.
- Пересмотреть, если ядро начнёт обрастать развилками по провайдеру: значит, граница ядра
  проведена неверно.

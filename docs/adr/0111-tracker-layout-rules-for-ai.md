# 0111. ИИ раскладывает работу на доске по правилам IDE: шаги - группой, продолжение - проверка после, поток и проект - с согласия

- **Статус:** Принято
- **Дата:** 2026-11-22

## Контекст

ИИ правит доску трекера инструментами `tracker_*` (ADR 0101). Описания говорили только, как
устроена доска: у задачи бывают продолжения - «карточки, которые идут после неё, цепочкой». По
этим словам модель раскладывала план как большую задачу с подзадачами-продолжениями и свободно
заводила потоки и проекты трекера. Владелец работает иначе:

- последовательность задач одной работы - это группа (колонка), задачи в ней по порядку;
- продолжение - не шаг задачи, а то, что делать после того, как она выполнена: например, позже,
  когда появятся новые данные, проверить, что она действительно сработала;
- потоки и проекты трекера он заводит сам заранее. Новый поток ИИ может предложить и заводит
  только после согласия, проект трекера - предлагает лишь по очень весомой причине.

Правило нужно на уровне IDE, а не одного разговора: доску правит любой провайдер (Claude, Codex,
Kimi, открытые модели), в любом проекте.

## Варианты

**Где держать правила.**

- **Инструкции человека к коннектору в проекте** (ADR 0053): владелец сам вписывает правила.
  Плюсы: ничего не менять в коде. Минусы: в каждом проекте заново; занимают его же предел в 1000
  знаков; это правило самой доски, а не одного проекта.
- **Только в описаниях инструментов `tracker_*`.** Плюсы: подробно, видят все провайдеры. Минусы:
  Claude Code показывает описания инструментов MCP только после их поиска, а решение «куда
  положить карточки» и «заведу-ка новый поток» модель принимает раньше.
- **Коротко в пояснении сервера `workstation` и подробно в описаниях (выбрано).** Плюсы:
  пояснение видно сразу, описания договаривают в момент вызова - и у `tracker_save_flow` с
  `tracker_save_project` правило стоит ровно там, где модель создаёт. Минусы: пояснение уже почти
  упиралось в 2048 знаков вместе с описанием человека - пришлось сжать остальные строки.

**Держать ли правило кодом.**

- **Отказ создавать поток или проект без флага «человек согласен».** Минусы: флаг ставит сама
  модель, ничего не держится, а просьба человека «создай поток» получает лишний шаг.
- **Словами модели (выбрано).** Согласие человека код проверить не может, а у человека остаются
  права на инструмент в Connectors, если нужно жёстче.

## Решение

Правила раскладки - в словах IDE для модели: строка трекера в пояснении сервера (`WORKSTATION_GUIDE`)
и описания `tracker_board`, `tracker_save_project`, `tracker_save_flow`, `tracker_save_group`,
`tracker_save_card`, `tracker_add_cards`. Шаги одной работы - задачи одной группы по порядку,
новая последовательность - своя группа без вопросов; продолжение - то, что делать после
выполненной задачи (проверить позже, срок - если он известен); поток - только по просьбе или
после согласия на предложение; проект трекера - предлагать лишь по очень весомой причине.
Справка трекера («?») говорит человеку то же. Главная причина - доску правят все провайдеры, и
правило, которое видит каждая модель в каждом проекте, может дать только сама IDE.

## Факты и замеры

Замера нет: решение о словах для модели. Пояснение с описанием человека предельной длины - 2037
знаков из 2048. Тесты держат правила от тихой потери: `tracker-tools.test.ts` (описания
инструментов) и `connector-view.test.ts` (пояснение и предел) -
`pnpm --filter @agentic-workstation/desktop exec vitest run src/main/connectors`.

## Последствия

- Модель данных ADR 0101 не меняется: продолжения по-прежнему цепочка у задачи, отправка группы
  в очередь идёт «задача, её продолжения». Меняется только смысл, которым продолжения заполняет ИИ.
- Новая строка в пояснении сервера `workstation` - за счёт других: запас до 2048 знаков - 11.
  Следующей области IDE придётся сжимать пояснение или уводить подробности в описания.
- Пересмотреть, если модели будут игнорировать слова и заводить потоки сами (тогда - вопрос
  человеку через права инструмента) или если владелец начнёт вести подзадачи цепочками.

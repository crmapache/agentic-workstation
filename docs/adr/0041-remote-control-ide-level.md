# 0041. Remote Control - на уровне IDE: свой релей, свой протокол v1, провод из архива

- **Статус:** Принято
- **Дата:** 2026-11-10

## Контекст

[ADR 0013](0013-remote-access-ide-level.md) убрал удалённый доступ из панели Claude Code и
оставил открытым вопрос: где он живёт на уровне IDE, что видит телефон и остаётся ли протокол
ACC ([ADR 0011](0011-remote-access-acc-protocol.md)). Владелец ответил (docs/workplan/README.md,
2026-11-10):

- телефону нужна IDE, а не панель одного провайдера: проекты, разговоры каждого провайдера
  (сейчас Claude Code, но провайдер назван везде) и очереди сценариев (ADR 0039);
- свой релей и свой телефонный клиент в этом репозитории, на домене
  `agentic-workstation-relay.mzpizote.com`;
- ACC и его релеи не трогать вообще.

Прошлая панельная версия (ветка `archive/panel-remote-access`) - наш код: провод, шифрование, пара,
переподключение, очередь кадров, проверенные тестами на векторах RFC 5869 и против WebCrypto.

## Варианты

**Протокол ACC байт в байт и релей ACC (как ADR 0011).**

- Плюсы: телефонный клиент ACC работал бы без правок.
- Минусы: модель - одна панель одного провайдера; сценарии на уровне IDE и очередей ACC не знает;
  любое изменение тянет правку ACC, а его трогать нельзя.

**Без релея: телефон звонит прямо в IDE (локальная сеть или туннель вроде Tailscale).**

- Плюсы: нет своего сервера.
- Минусы: вне дома телефон до ноутбука за роутером не достучится; туннель - лишняя установка
  на обоих концах; на iOS у страницы в браузере нет прямых сокетов к машине в сети.

**Свой релей и свой прикладной протокол; провод, шифрование и пара - из архива с новыми метками.**

- Плюсы: модель протокола - IDE (проекты, провайдеры, очереди); провод проверен; телефон ACC и
  эта IDE не поговорят по ошибке даже через один релей; релей маленький и проверяется чтением
  одной папки.
- Минусы: свой сервер на поддержке и свой телефонный клиент (`apps/phone`) - большая работа.

## Решение

Третий вариант. Главная причина - модель: телефону нужны очереди сценариев и провайдеры, а
протокол ACC про одну панель. Устройство:

- **`packages/remote-protocol`** - общий для IDE и телефона, чистый TypeScript (ни Node, ни DOM):
  конверт релея 42 байта (версия, вид SEALED/CONTROL/PUSH, кому, от кого, счётчик u64), метки
  шифрования `aw/v1/...` и доказательство пары `aw-pair-v1` (у ACC - `acc/...`), адрес пары
  `https://<релей>/pair#aw1.<agentId>.<секрет>.<отпечаток>`, сообщения v1 со схемами zod, белый
  список команд с пределами частоты, правила ленты (`applyFeedPatch`).
- **`apps/relay`** - Node 24 и ws, написан заново по образцу релея ACC: адрес → сокет, тела не
  читает; ящик для отсутствующего адреса (2 минуты, 200 кадров, 4 МБ, все ящики вместе - 64 МБ),
  переполнение - одно слово CONTROL «переспроси»; кадр до 256 КБ; соединений с одного адреса -
  32, всего - 2000; источники страниц - свой хост и `RELAY_ALLOWED_ORIGINS`; новое соединение
  адреса вытесняет старое кодом 4009; кадр самому себе возвращается (сердцебиение IDE);
  `/healthz`, `/v1/info`, `/privacy`, статика клиента. Запускается `node src/index.ts` без сборки.
- **`main/remote/`** - из архива `wire/`, `link/`, `store/`, пара и пределы (`agent/`); новый
  `bridge/`: инвентарь, подписки, команды. С IDE мост говорит через узкие порты - публичные методы
  `ClaudeService` и `ScenarioService`, те же, что зовёт окно; врезки - заплатки ленты
  (`observeFeed` в `main/index.ts`) и очереди с прогонами (`ScenarioTaps` в
  `scenarios-setup.ts`).

Правила протокола v1:

- **Пути не уходят.** Проект - ключ `p-` (открыт) или `r-` (недавний) и SHA-256 пути; путь по
  ключу знает только IDE. Из очередей и прогонов убраны папки worktree, проекта и коммит-основа.
- **Лента - элементы ленты IDE**, а не сырые события CLI: снимок последних 120 элементов, сколько
  влезает в кадр, дальше заплатки, сложенные за 150 мс, с номером в журнале разговора (400
  заплаток или 2 МБ) и `epoch` жизни линии. Пропуск номера - подписка заново с `since`; номер
  старше журнала или из прошлой жизни IDE - снимок. Длинные строки режутся с пометкой в тексте.
- **Команды - белый список из 14**: разговор (send, respond, interrupt, new, rename, setModel,
  setEffort) и сценарии (shelves, start, queue без close, control, answer, tell, carryOn).
  «Разрешать всегда» в протоколе не выражается вовсе, план одобряется без смены режима, новый
  разговор - только в режимах default, acceptEdits, plan. Незнакомое - отказ, и отказы считаются
  строгим пределом частоты.
- **Выключено по умолчанию.** Адрес релея - константа (переменная окружения - только для тестов
  и разработки). Ключи - через `safeStorage`; без шифрования - только в памяти, и окно это говорит.

## Факты и замеры

- Тесты 2026-11-10: протокол - 23 (конверт, base64 без Buffer, метки, адрес пары, белый список,
  слова телефона, лента); релей - 18 на настоящих сокетах (маршрут, тело не тронуто, сердцебиение,
  чужое имя, ящик и CONTROL, вытеснение 4009, коды 4001/4002/1009/1008, потолок соединений с
  адреса, чужой источник, `/healthz`, `/v1/info`, `/privacy`, статика) и запуск настоящим Node;
  главный процесс - 49: шифрование против WebCrypto и векторов RFC 5869 (и что метки ACC дают
  другие ключи), окно повторов, очередь и отступ, хранилище, пара, телефон на WebCrypto против
  настоящего агента, мост на подделках сервисов, окно Remote Control - 2.
- Сквозная проверка (`main/remote/remote-e2e.test.ts`, 2 теста): настоящий релей на свободном порту,
  настоящий `RemoteService` со встроенным WebSocket Node, телефон на WebCrypto через свой сокет:
  пара → Approve → инвентарь без путей → подписка → снимок → сообщение доходит до сервиса →
  заплатка доходит до телефона → команда сценарию → запрещённое отказано → отзыв.
- Повторить: `pnpm --filter @agentic-workstation/remote-protocol test`,
  `pnpm --filter @agentic-workstation/relay test`,
  `pnpm --filter @agentic-workstation/desktop exec vitest run src/main/remote`.
- Замера нагрузки нет. Настоящий телефон не участвовал: клиента `apps/phone` ещё нет, релей не
  выложен.

## Последствия

- Канал `remote:*` (вид целиком, событие `remote:state`), окно Remote Control (`features/remote`):
  кнопка в строке состояния и действие поиска везде «Remote Control…».
- Файл `remote.json` в userData - формат `aw-remote/1`; файл прежнего удалённого доступа ACC
  не читается. Адрес IDE на релее и её ключ создаются при первом включении.
- Телефонный клиент берёт протокол из `packages/remote-protocol`, шифрование пишет на WebCrypto
  по образцу `main/remote/__fixtures__/webcrypto-phone.ts`. Пока его нет, релей раздаёт заглушку;
  образ собирает клиент сам, если он появился (`apps/relay/Dockerfile`).
- Push не сделан: кадры PUSH релей отбрасывает, `/v1/info` говорит `push: false`.
- Пересмотреть, если: появится второй провайдер (его лента - тем же видом элементов или своим);
  понадобится push (подписка клиента и служба пушей в релее); телефону понадобится что-то из
  запрещённого.

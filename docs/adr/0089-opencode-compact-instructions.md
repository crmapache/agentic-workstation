# 0089. Модели OpenCode с окном меньше 128K получают только правила проекта

- **Статус:** Принято
- **Дата:** 2026-11-18

## Контекст

После Code Mode (ADR 0088) коннекторы почти ничего не весят, а базовый запрос OpenCode всё ещё
около 23 тысяч токенов. Разбор записанного запроса показал, что собственно OpenCode там мало:
указания и описания инструментов - около 5 тысяч. Остальное OpenCode сам подтягивает из
настроек Claude Code человека: личный `~/.claude/CLAUDE.md` (31 тысяча знаков) и список
скиллов (50 штук, 30 тысяч знаков) - из `~/.claude/skills`, скиллов проекта и
`~/.agents/skills`, куда их кладёт мост Макса для Codex. Локальной модели с окном 64K это
съедает треть окна до первого слова, облачной с окном в сотни тысяч - не мешает.

## Варианты

1. **Как было** - всё, что тянет OpenCode, у всех моделей. Личные предпочтения и скиллы
   везде, но локальная модель начинает с занятой трети окна.
2. **Компактно у всех моделей OpenCode.** Просто и одинаково, но облачные модели с большим
   окном теряют личные предпочтения (язык, тон, формат) и скиллы без нужды.
3. **Убрать только скиллы.** Личный CLAUDE.md остаётся, запрос около 20 тысяч - локальной
   модели всё ещё тесно.
4. **Компактно для окна меньше 128K**, полное - для большого. Выбрал Макс.

Флаги самого OpenCode для этого слишком грубые: `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT` вместе с
личным CLAUDE.md убирает и CLAUDE.md проекта - правила кодовой базы, а
`OPENCODE_DISABLE_CLAUDE_CODE_SKILLS` не трогает `~/.agents/skills`. Поэтому компактный набор
собирается из трёх частей.

## Решение

Вариант 4. При запуске процесса OpenCode (`openCodeLaunch`) IDE берёт окно его модели - у
Ollama то, что держит сервер (ADR 0087). Окно меньше 128K - компактный набор
(`opencode-instructions.ts`): `OPENCODE_DISABLE_CLAUDE_CODE` выключает всё от Claude Code,
CLAUDE.md папки процесса возвращается полем `instructions` (только если рядом нет AGENTS.md -
с ним OpenCode CLAUDE.md и сам не читает), а остальные скиллы закрывает политика
`skill.use: deny`. Модель переключили через границу посреди разговора - процесс поднимается
заново до следующего хода.

## Факты и замеры

MacBook Pro M5 Pro, OpenCode 2.3.2, Ollama 0.40.16, `qwen3.8:latest`. Запрос записывал прокси
между OpenCode и Ollama, размер в токенах - строка `cache miss total=` журнала Ollama.
Временная папка-проект с маленьким CLAUDE.md и одним скиллом проекта, `opencode run`:

| Набор                                                         | Токенов |
| ------------------------------------------------------------- | ------- |
| Всё, что тянет OpenCode                                       | 22 720  |
| `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS`                         | 19 552  |
| `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT` (без CLAUDE.md проекта) | 13 509  |
| `OPENCODE_DISABLE_CLAUDE_CODE`                                | 10 341  |
| то же + CLAUDE.md проекта в `instructions`                    | 10 377  |
| то же + `skill.use: deny` (компактный набор)                  | 5 304   |

Повторить: во временной папке со своими `XDG_*_HOME` - `opencode run "Reply with the single
word: ok"` с `OPENCODE_CONFIG_CONTENT` (подключение Ollama, нужные `instructions` и
`policies`) и переменной из таблицы; размер - `cache miss total=` в
`~/Library/Logs/ollama.log`, состав - телом запроса через прокси перед Ollama.

Ещё замечено: CLAUDE.local.md OpenCode не читает ни в каком наборе; при AGENTS.md в папке
CLAUDE.md проекта не читает; каталог своих инструментов OpenCode (сессии, worktree, около 1.5
тысячи токенов) политикой `tool.use` не убирается - оставлен.

## Последствия

- У модели с маленьким окном в панели, прогонах и разовых вопросах нет личного CLAUDE.md и
  скиллов, правила проекта - есть. Облачные модели с большим окном работают как раньше.
- Процесс OpenCode получает переменные сверх окружения человека (`OpenCodeLaunch.env`), хост
  прогонов знает папку процесса (worktree прогона, пустая папка разового вопроса).
- Пересмотреть, если у OpenCode появится выключатель только личных указаний человека, или если
  локальные окна вырастут настолько, что граница в 128K перестанет их разделять.

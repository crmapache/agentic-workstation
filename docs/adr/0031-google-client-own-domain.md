# 0031. Клиент Google публикуется на домене человека, настройку в браузере делает приложение ИИ

- **Статус:** Принято
- **Дата:** 2026-11-08

## Контекст

Gmail и Calendar входят через свой клиент OAuth (ADR 0028): его создают в Google Cloud
Console руками, API для этого нет. Чтобы не кликать самому, в карточке клиента была кнопка
«Copy prompt for AI» - промпт для ИИ, который сделает шаги в браузере. Промпт просил
опубликовать приложение («In production»): в тестовом режиме Google выкидывает из входа
раз в семь дней.

Владелец отдал промпт ИИ, и тот упёрся в публикацию: Google не даёт нажать «Publish app»,
пока в Branding нет главной страницы и политики конфиденциальности на домене, который
владелец проекта подтвердил в Search Console. Клиент создан, файл скачан, а приложение
осталось в тестовом режиме - и без тестовых пользователей, то есть войти в него было бы
нельзя.

Владелец поставил два требования. Вход в коннекторе должен проходить за любой адрес,
которым человек захочет войти, а не только за заранее вписанные. И скопировать промпт мало:
в IDE нет места, где отдать его ИИ, который умеет работать в браузере, - хочется сразу
открыть его в Claude или Codex.

## Варианты

**Чей клиент и в каком режиме.**

1. Клиент человека в тестовом режиме. Работает у всех и сразу, но войти могут только
   адреса из списка тестовых пользователей, и раз в семь дней Google просит войти снова.
   Требование «любой адрес» не выполняется.
2. Один опубликованный клиент владельца IDE, встроенный в сборку. Человеку ничего не
   настраивать, войти может любой адрес. Но без проверки Google в приложение входят 100
   разных аккаунтов за всё время - на всех людей IDE сразу. Все входы зависят от проекта
   Google владельца, а снять лимит - полная проверка с ежегодным платным аудитом
   безопасности (CASA) для `gmail.modify`.
3. Клиент человека, опубликованный на его домене. Человек кладёт главную страницу и
   политику на свой домен, подтверждает домен в Search Console и публикует приложение -
   ИИ ведёт его по шагам. Любой адрес, лимит в 100 аккаунтов - у каждого свой, от проекта
   владельца IDE ничего не зависит. Нужен свой домен: общие бесплатные адреса (github.io,
   web.app, blogspot.com, Google Sites) Google не принимает.

**Кто делает шаги в браузере.**

1. Только копия промпта (как было). Человек сам ищет ИИ с браузером и вставляет текст.
2. Разговор в панели Claude Code самой IDE с `--chrome`. Всё в IDE, но мост Chrome - это
   MCP Claude Code, а у Claude в IDE MCP только коннекторы (ADR 0029, `--strict-mcp-config`);
   как они уживутся, не проверено. Codex в IDE ещё нет.
3. Ссылка на новый разговор в приложении ИИ: `claude://cowork/new?q=…` (Cowork работает в
   Chrome или своём браузере) и `codex://threads/new?prompt=…`. Обе описаны в документации
   приложений, обе кладут промпт в поле ввода и не отправляют его - отправляет человек. В
   меню - только установленные приложения, копия промпта остаётся для любого другого ИИ.

## Решение

Клиент человека, опубликованный на его домене (вариант 3): так выполняется «любой адрес», и
ни лимит, ни поломка не завязаны на проект владельца IDE. Промпт сначала создаёт клиент
(файл можно выбрать сразу), потом спрашивает про домен: есть - делает две страницы, ведёт
подтверждение домена записью DNS (только добавляет записи, перед этим спрашивает),
заполняет Branding и публикует; нет домена или публикация не прошла - предлагает купить
домен или остаться в тестовом режиме с названными адресами. Выдуманных ссылок ИИ в Branding
не вписывает. Шаги в браузере - через приложение ИИ по ссылке (вариант 3): кнопка «Set up
with AI» с меню «Open in Claude», «Open in Codex», «Copy prompt». Это то, о чём попросил
владелец, и оно не трогает решение про MCP Claude в IDE.

## Факты и замеры

- Публикация: ИИ владельца получил отказ из-за пустых ссылок Branding (2026-11-08). На
  форуме Google с октября 2026 то же у многих приложений «для себя»: «To publish your app,
  you must complete your configuration on the Branding page», ответа Google нет
  (discuss.google.dev, темы 406672, 407270, 408400). Справка Google: ссылки «required for
  all external production apps», главная страница - на подтверждённом домене владельца, а
  не на площадке, где владение не доказать (support.google.com/cloud/answer/15549049,
  13807376); подтверждает домен в Search Console владелец или редактор проекта
  (developers.google.com/identity/protocols/oauth2/production-readiness/policy-compliance).
- Общие адреса: прямого запрета в справке нет, но разработчики пишут, что github.io не
  приняли даже подтверждённым, а запрет общих хостингов (github.io, vercel.app) - в отзывах,
  не в документации. Проверки своим аккаунтом не было.
- Тестовый режим: токен обновления живёт семь дней; войти могут только тестовые
  пользователи. Неопубликованное приложение без проверки - 100 аккаунтов за всё время
  (support.google.com/cloud/answer/13464323). Истекает ли вход раз в неделю у
  опубликованного, но не проверенного приложения, источники расходятся - проверить на деле.
- Секрет клиента Google показывает один раз, в окне создания, с июня 2025 (блог
  developers.googleblog.com, «Usability and safety updates to Google Auth Platform»): файл
  скачивается там же, иначе - новый клиент.
- Ссылки: справка Claude «Open Claude Desktop with a link» (`q`, около 14 000 знаков, не
  отправляется само), справка Codex «Commands» (`prompt`, «doesn't send the prompt
  automatically»). Установлено ли приложение - `app.getApplicationNameForProtocol`. На
  машине владельца: Claude 4.23118.0, Codex 26.1103.41825 (схема `codex` у приложения
  ChatGPT с идентификатором `com.openai.codex`). Промпт - около 4 300 знаков.

## Последствия

- Без своего домена «любой адрес» недостижим: тестовый режим с вписанными адресами и входом
  раз в неделю. Об этом справка «?» карточки и сам ИИ.
- Политика конфиденциальности, которую пишет ИИ, должна говорить правду о том, что IDE
  делает с данными Google: прочитанное ИИ уходит провайдеру разговора. Поменялись
  инструменты Gmail или Calendar - поправить промпт.
- Адрес приложения ИИ собирает главный процесс из своей схемы (`agent-links.ts`), из окна
  приходит только текст промпта: окно не может открыть им чужое приложение или файл.
- Промпт - строка `connectors.google.agentPrompt`: Google поменяет консоль - правится он, а
  не код.
- Пересмотреть, если Google снова разрешит публикацию без ссылок, если IDE пойдёт к людям
  без своих доменов (тогда вариант 2 с проверкой), если у Claude в IDE появится браузер
  (разговор в своей панели) или когда в IDE появится Codex.

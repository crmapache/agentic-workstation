# 0084. Движок панели открытых моделей - OpenCode

- **Статус:** Принято (прогон 2026-11-18)
- **Дата:** 2026-11-18

## Контекст

Третья панель провайдеров (ADR 0083) - открытые модели: локальные на этом маке (Ollama, LM
Studio, любой локальный сервер в формате OpenAI) и облачные (OpenRouter, любой совместимый
адрес). Модель сама по себе агентом не является: инструменты чтения и правки, разрешения,
песочница, сжатие разговора и MCP - это обвязка. Вопрос - чья обвязка работает в этой панели.

## Варианты

**Своя обвязка в IDE: цикл агента поверх API в формате OpenAI.**

- Плюсы: полный контроль, никакого внешнего CLI.
- Минусы: заново писать то, что уже делают Claude Code и Codex: инструменты, песочницу,
  разрешения, сжатие, MCP. Выйдет хуже, и поддержка навсегда на нас.

**Claude Code с подменённым адресом API.**

- Плюсы: драйвер уже есть. Многие открытые модели обучены под обвязку Claude Code. Ollama
  понимает формат Anthropic с версии 0.14, OpenRouter подключается официально.
- Минусы: OpenRouter обещает, что Claude Code работает, только с моделями Anthropic. Локальные
  серверы, которые знают лишь формат OpenAI, не подходят. Вход, лимиты, быстрый режим и
  служебная модель - всё про Anthropic, всё пришлось бы отключать: панель была бы Claude под
  другим именем.

**Codex с подменой источника моделей.**

- Плюсы: драйвер Codex и так пишется. Ollama и LM Studio встроены (`--oss`).
- Минусы: с начала 2026 года Codex понимает только формат Responses, и сервер, который знает
  лишь chat completions, к нему не подключится. Подсказки и инструменты Codex (`apply_patch`)
  заточены под модели OpenAI. Каталог моделей, уровни усилия и лимиты Codex - от OpenAI, их
  всё равно пришлось бы заменять своими.

**OpenCode.**

- Плюсы: сделан под любые модели. Провайдеры идут через AI SDK, каталог моделей models.dev
  даёт контекст, умение вызывать инструменты и цены. Понимает chat completions, а значит, любой
  локальный сервер. Серверный режим `opencode serve` описан OpenAPI, есть типизированный SDK:
  сессии, форк, откат, прерывание, сжатие, ответы на разрешения, поток событий, список
  провайдеров и моделей, MCP.
- Минусы: третий протокол (HTTP и поток событий, а не stdio). Один сервер на много сессий - не
  тот жизненный цикл, что процесс на разговор у Claude и Codex. API второй версии свежий, часть
  путей помечена экспериментальными.

**Один драйвер по ACP (Agent Client Protocol).**

- Плюсы: один драйвер даёт много агентов: Gemini CLI, Qwen Code, OpenCode, Goose и другие.
- Минусы: общий знаменатель. Лимитов, отката файлов и форка в протоколе нет или они слабее, и
  панель открытых моделей не получила бы того, что есть у Claude и Codex.

## Решение

Принято: OpenCode. Главная причина - он единственный из вариантов сделан под любые модели и
понимает все форматы, на которых говорят локальные серверы и облачные шлюзы, а его каталог даёт
то, что нужно меню модели. Живой прогон на этапе 4 подтвердил выбор (замер ниже): на той же локальной модели OpenCode
довёл задачу до конца, Codex с подменой источника - нет.

## Факты и замеры

Прогон 2026-11-18 на этом маке: Ollama 0.40.16 (поставлена для прогона), модель gpt-oss:20b,
OpenCode 2.3.2 со своими папками конфига и данных, Codex 0.163 со своим временным CODEX_HOME.
Задача одна и та же во временном репозитории: в функции суммы корзины две ошибки (сложение
вместо умножения и скидка числом вместо процента), три падающих теста `node --test`; просьба -
найти ошибки, поправить и гонять тесты, пока не пройдут, тесты не трогать.

- **OpenCode** (`opencode run --standalone --auto`, провайдер Ollama в формате chat
  completions): задача решена. Первый прогон - 46 секунд (с загрузкой модели), 6 шагов, 5 вызовов
  инструментов (поиск файлов, чтение, две правки, тесты), ни одного сбоя вызова. Повтор на чистой
  копии - 14 секунд, тоже 5 вызовов, без сбоев. Правка - ровно две строки, тесты не тронуты.
- **Codex с подменой источника** (`codex exec --oss --local-provider ollama`): задача не решена,
  ход упал за 65 секунд. Тесты прогнал один раз, а правку модель шесть раз подряд отправляла
  сломанным вызовом: `apply_patch` через heredoc внутри JSON аргумента команды, Codex не смог
  разобрать вызов (`error parsing tool call ... invalid character`), пять переподключений и
  отказ хода. Ещё одна ошибка роутера инструментов - поле `justification` без
  `sandbox_permissions`. Подсказки и инструменты Codex заточены под модели OpenAI, открытая
  модель с ними не справляется - то, чего и опасались.

Ключа OpenRouter на этой машине нет, облачная часть прогоном не проверялась. Источники на ноябрь
2026:

- Codex оставил только формат Responses, chat completions снят:
  https://github.com/openai/codex/discussions/7782. Флаги `--oss` и
  `--local-provider lmstudio|ollama` есть в установленном Codex 0.163.0 (`codex exec --help`).
- Ollama понимает `/v1/messages` в формате Anthropic с 0.14:
  https://docs.ollama.com/api/anthropic-compatibility
- OpenRouter для Claude Code - адрес `https://openrouter.ai/api`, работа гарантирована только с
  моделями Anthropic: https://openrouter.ai/docs/guides/guides/claude-code-integration
- API сервера OpenCode второй версии: сессии, форк, откат в два шага (подготовить и
  применить), прерывание, сжатие, ответы на разрешения, поток событий, провайдеры и модели,
  состояние MCP: https://opencode.ai/docs/server/

Прогон, который решит вопрос: одна и та же небольшая задача во временном репозитории (найти и
поправить ошибку, прогнать тест) на одной локальной модели через Ollama и, если будет ключ, на
одной модели из OpenRouter - в OpenCode и в Codex с подменой источника. Сравнить, довёл ли
агент задачу до конца, за сколько ходов и были ли сбои вызова инструментов.

## Последствия

- Драйвер OpenCode поднимает `opencode serve` на свободном порту с паролем, со своими конфигом
  и папкой данных. Настройки OpenCode человека IDE не трогает.
- Подключения (Ollama, LM Studio, OpenRouter, свой адрес) хранит IDE, ключи - в зашифрованном
  виде. OpenCode получает их конфигом при запуске.
- Меню модели строится из подключений. Модель, которая не умеет вызывать инструменты, не
  показывается, о маленьком окне контекста меню предупреждает.
- Коннекторы IDE - через шлюз, как у остальных провайдеров.
- Пересмотреть по итогам прогона на этапе 4, а также если API OpenCode начнёт ломаться между
  версиями чаще, чем протокол Codex.

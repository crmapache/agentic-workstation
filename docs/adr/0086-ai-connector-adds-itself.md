# 0086. Готовый коннектор от ИИ без ключа добавляется сам

- **Статус:** Принято
- **Дата:** 2026-11-18

## Контекст

По [ADR 0050](0050-ai-connector-jobs.md) работа ИИ над коннектором кончалась плиткой «Ready» в
разделе Building with AI: ИИ предложил, человек открывает окно работы, проверяет справа и жмёт
Add. Владелец увидел плитку Shotter с «Ready», которая так и висела над «Your connectors», и не
понял, что с ней: готово - значит уже подключено. Просьба: готовое переезжает в «Your
connectors» само.

Не всё готовое можно добавить без человека. ИИ не видит ключей: API и MCP с ключом без ключа
не заработают. Адрес не с сайта документации, которую дал человек, мог подсунуть чужой сайт -
ради этой проверки окно и показывает хост крупно. А браузер для входа открывает только кнопка
человека (`SignInDesk`, правило коннекторов).

## Варианты

1. **Оставить кнопку, переименовать метку.** «Ready» → «Review and add». Понятнее, но лишний
   шаг остаётся и там, где проверять нечего: перенос сервера из Claude Code человек настроил
   сам, ключ переезжает внутри IDE.
2. **Добавлять всё готовое сразу.** Коннектор без ключа встаёт в подключённые сломанным, а
   адрес с чужого сайта получает вход и инструменты во всех проектах без взгляда человека.
3. **Добавлять само то, чему человек не нужен, остальное - с меткой, чего ждёт.** Перенос из
   Claude Code, MCP без ключа (вход в браузере - потом кнопкой на коннекторе) и API без ключа на
   адресе с сайта документации добавляются главным процессом, работа уходит из очереди. С
   ключом - «Needs your key», адрес не с сайта документации - «Check the address».

## Решение

Вариант 3. Что нужно от человека, решает одна функция на оба процесса - `proposalNeed`
(`shared/ai-proposal.ts`): `key`, `host` или ничего. Ничего - `AiConnectorDesk` зовёт
`adopt` сразу после ответа ИИ и после подъёма IDE (`adoptReady`, так доходят работы, готовые до
перезапуска); `ConnectorsService.adoptAiJob` добавляет тем же путём, что кнопка формы (перенос -
`ImportDesk`, остальное - `newConnector` с именем сервиса, без подписи, «один раз»), но без
входа в браузере. Добавилось - работа удаляется, окно получает `connectors:aiJobAdded`, и
открытое окно работы становится окном нового коннектора. Не добавилось - сбой `not-added`:
предложение остаётся, его добавляют руками. Пока добавляется, плитка говорит «Adding».

## Факты и замеры

Замеров нет: решение - про поток окна. Поведение держат тесты `ai-connector-desk.test.ts`
(добавилось - работы нет; не добавилось - `not-added`; с ключом - ждёт; готовое до перезапуска
добавляется после подъёма), `ai-adopt.test.ts` и `ai-proposal.test.ts`.

## Последствия

- Новый вид предложения ИИ - строка в `proposalNeed` и `adoptionOf`: что ему нужно от
  человека и каким запросом его добавить.
- Готовое без ключа больше не ждёт взгляда человека. Адрес проверяется только сравнением с
  сайтом документации: человек её не дал - сравнивать не с чем, и такое предложение добавляется
  само. Пересмотреть, если ИИ начнёт предлагать чужие адреса без документации.
- Имя и «несколько раз» у добавленного само - по умолчанию; поменять их можно в настройках
  своего типа.

# 0090. IDE управляет собой через MCP: встроенный коннектор workstation и вход снаружи по ключу

- **Статус:** Принято
- **Дата:** 2026-11-19

## Контекст

Владелец просит агента в IDE собрать очередь сценариев: «сделай полную очередь всей этой колонки,
поставь её на паузу и запусти завтра». У агента не было способа сделать это, кроме Computer Use:
он открывал окно Run scenario на каждую карточку и печатал ссылку в поле - медленно и хрупко, а
мышь человека всё это время занята (снимок в разговоре 2026-11-18). Просьба: MCP, чтобы
IDE управлялась сама собой, и чтобы ей так же можно было управлять снаружи - агентом в терминале,
Codex, любым клиентом MCP.

Что уже было: шлюз коннекторов (ADR 0028, 0029) - локальный MCP-сервер, через который разговоры
получают коннекторы IDE; встроенный коннектор `notifications` (ADR 0069) - свои инструменты IDE,
заведённые сами; порты моста Remote Control (ADR 0041) - узкие публичные действия сервисов
(сценарии, разговоры панелей, проекты), которыми телефон управляет IDE извне окна.

## Варианты

**Как дать инструменты разговорам IDE.**

- **Как сейчас, мышью по окну (Computer Use, CDP).** Плюсы: ничего нового. Минусы: то, что
  сделал владелец сам, - хрупко, медленно, мышь занята, нет способа «поставить очередь, которая
  ждёт» без кликов по окну часов; снаружи IDE это не работает вовсе.
- **Один инструмент «вызвать любой канал IPC».** Плюсы: вся IDE сразу. Минусы: каналы говорят
  языком окна (id открытой вкладки проекта, состояние целиком), модели их не понять без кода; туда
  же попали бы настройки, аккаунты, git и запись файлов без ступеней доступа - ни выключить
  поштучно, ни разрешить чтение без вопроса.
- **Свой набор инструментов поверх тех же сервисов, встроенным коннектором (выбрано).** Плюсы:
  слова модели (проект путём или именем, время «09:00», отказ - понятным текстом), ступени чтение и
  запись, человек видит коннектор плиткой, выключает его или отдельные инструменты, сужает проекты;
  Codex и открытые модели получают его тем же шлюзом. Минусы: новый инструмент - руками, а не
  даром вместе с каналом.

**Как пустить снаружи.**

- **Тот же шлюз с долгим ключом.** Минусы: порт шлюза - от системы на каждый запуск, адрес в
  чужом клиенте ломался бы с каждым перезапуском IDE.
- **Команда-мост stdio, как native host браузера.** Плюсы: без порта. Минусы: в конфиге клиента -
  путь внутрь бандла и `ELECTRON_RUN_AS_NODE`, свой на маке и Windows, второй исполняемый вход и
  поиск живой IDE по файлам.
- **Второй шлюз только с этим сервером на постоянном порту 127.0.0.1 и ключом (выбрано).** Плюсы:
  Claude Code, Codex и Cursor берут адрес и заголовок `Authorization` как есть, одна строка
  настройки; код шлюза тот же. Минусы: порт может быть занят - тогда так и сказано на виде.

## Решение

Встроенный коннектор `workstation` (тип `workstation`, сервер `workstation`, плитка «Agentic
Workstation»): заводится сам на загрузке реестра (`ensureBuiltIns`), не удаляется, виден во всех
проектах. Имя - не `ide`: так Claude Code зовёт свой сервер связи с редакторами. Инструменты
(`connectors/kinds/workstation/`) поверх портов (`workstation/workstation-link.ts`): проекты,
сценарии и расписание, очереди, прогоны сценариев, задания и поручения, разговоры панелей всех
провайдеров - теми же методами, что у окна и телефона (порты сценариев и панелей - из моста Remote
Control). Новая очередь принимает рабочие часы до первого шага (`ScenarioStartRequest.hours`): так
агент собирает очередь, которая ждёт завтрашнего утра, не запустив первый сценарий. Чтение шлюз
разрешает CLI без вопроса (`--allowedTools mcp__workstation__<чтение>`), запись - по режиму
разрешений разговора, как любое действие. Вход снаружи (`connectors/outside/`) - второй
`ConnectorGateway` на постоянном порту (собранная IDE 4461, dev 4462, переменная
`AGENTIC_WORKSTATION_OUTSIDE_PORT`), выключен, пока человек не включит в окне коннектора; ключ -
в хранилище (`safeStorage`), сравнение хешей за постоянное время, Host - только 127.0.0.1 и
localhost; готовую настройку с ключом главный процесс кладёт в буфер, окно ключа не видит.
Настройка - команды Claude Code (`claude mcp add`) и Antigravity CLI (`agy mcp add`), записи Codex
(`~/.codex/config.toml`) и Kimi Code (`~/.kimi-code/mcp.json`: команды добавить сервер у Kimi Code
2.7.0 нет) и JSON для остальных клиентов.

## Факты и замеры

- Тесты: инструменты на подделках сервисов (18: имена и ступени, IDE поднимается, проекты,
  проект снаружи и по имени, очередь с часами, существующая очередь и пустой ввод, правка очереди,
  вопрос прогона, сообщение свободному, занятому и себе, разговор в закрытом проекте и новый с
  сообщением, задание новое и правка, списки снаружи по всем проектам, часы без дней и воскресенье
  нулём, полка сценария без названной, смена провайдера задания и пустой проект, неоднозначное имя
  проекта, запрет повышать режим, граница проектов); свой вход снаружи в переносе из Claude Code; вход снаружи на настоящем HTTP и клиенте MCP SDK (7: выключен
  по умолчанию, клиент с ключом, отказы 401/403/404 и свой localhost, новый ключ отрезает старый и
  на диске только шифр, память включённого между запусками, занятый порт, без шифрования); правила
  «без вопроса» шлюза; встроенные коннекторы с занятым именем; очередь с часами спит до первого
  сценария на настоящем движке сценариев.
- Живьём 2026-11-19 в копии окна (`/dev`, порт входа снаружи 4472) на временной папке с двумя
  сценариями: плитка «Agentic Workstation» с 24 инструментами, переключатель входа снаружи поднял
  сервер («Listening» и адрес), значок и адрес, кнопки «Copy setup» и «New key» стоят ровно
  (центры совпали до 0,1 px). Команда для Claude Code во временной папке конфига - `claude mcp list`
  2.1.293: «Connected»; запись для Codex 0.163 - `codex mcp get` видит адрес и заголовок с ключом
  (соединение Codex вживую не проверялось). `claude -p` на haiku снаружи собрал очередь как в
  просьбе владельца: две карточки в новой очереди с часами на завтра, вторая - в ту же очередь; вид
  Scenarios → Queues показал её спящей, «Next start: Tomorrow 09:00», обе «Not yet». Разговор
  панели в копии вызвал `list_queues` и `list_conversations` без вопроса разрешения и узнал себя в
  списке разговоров.
- Замера скорости нет: инструмент - вызов сервиса в главном процессе, время - время модели.

## Последствия

- Агент в IDE собирает очереди, заводит задания, пишет соседнему разговору и открывает прошлый
  разговор без Computer Use; пояснение сервера (`WORKSTATION_GUIDE`) говорит ему так и делать.
- Права даёт и повышает только человек. Инструмента «ответить на вопрос разрешения вкладки» нет;
  вопрос разрешения прогона агент может только отклонить (`answer` с `allow: true` - отказ, вопрос
  словами - можно). Новая вкладка от агента открывается в режиме новых вкладок человека. Заданию
  агент ставит только `default` или `readOnly`, сценарию - `default` или `plan` у головы и карточек;
  режим, который в этом задании или сценарии уже поставил человек, правка не трогает. Иначе агент
  завёл бы себе исполнителя без вопросов и запустил бы его (`run_now`, `start_scenario`).
- Сужение коннектора по проектам - граница, а не только видимость: разговор проекта A не видит и
  не трогает проекты, очереди, прогоны, задания и разговоры проекта B, где человек коннектор
  выключил (`workstation/workstation-scope.ts`). Вход снаружи проекта не имеет и видит все: его
  человек включает на всю IDE.
- Перенос серверов из Claude Code не предлагает вход снаружи этой же IDE (адрес на её порту): иначе
  разговоры IDE получили бы её же вход вторым набором, без своего разговора и границы проектов.
- Выход из IDE рвёт открытые ответы шлюзов (`closeAllConnections`): внешний клиент жив и держал
  бы долгий вызов, а выход его не ждёт.
- Новый инструмент - в `kinds/workstation/`, ступень `read` только у того, что ничего не меняет:
  чтение разрешено без вопроса.
- Порт входа снаружи записан в `~/.claude/ports.md`; занят - состояние `port-busy` на виде.
- Пересмотреть, если понадобится управлять видом окна (открыть файл, показать вид середины) -
  это события окну, а не сервисы главного процесса; и если вход снаружи понадобится не только с
  этой машины.

# 0032. Slack app - свой на каждое рабочее пространство, создаётся по готовому описанию

- **Статус:** Принято
- **Дата:** 2026-11-08

## Контекст

Slack MCP не умеет динамическую регистрацию клиентов (ADR 0028): коннектору Slack нужен
свой Slack app человека - Client ID и Client Secret. Окно добавления объясняло это абзацем:
создать приложение, включить MCP, вписать адрес возврата и разрешения, установить,
скопировать ключи. Владелец, только что настроив Google через ИИ (ADR 0031), спросил, как
быть со Slack.

Ограничение Slack: MCP пускает только внутренние приложения (созданные в рабочем
пространстве) и опубликованные в Slack Marketplace, а неопубликованные распространяемые
приложения - нет («unlisted apps are prohibited from using MCP», docs.slack.dev/ai/slack-mcp-server).

## Варианты

1. **Одно распространяемое приложение на все пространства.** Как с Google: один клиент на
   всё. Slack запрещает такому приложению MCP, пока его не опубликуют в Marketplace, а это
   проверка Slack с поддержкой, политиками и сроками. Не подходит.
2. **Приложение на пространство, шаги руками или через ИИ.** Как было, плюс промпт для
   Claude или Codex. ИИ всё равно не впишет ключи в IDE (секрет не должен ходить через
   чат), а ручные шаги длинные: адрес возврата, тридцать разрешений, бот.
3. **Приложение на пространство по готовому описанию.** Slack умеет открывать создание
   приложения по ссылке с описанием (`api.slack.com/apps?new_app=1&manifest_json=…`). IDE
   собирает описание сама: адрес возврата, разрешения, которые объявляет Slack MCP, бот (без
   него Slack не даёт установить приложение). Человеку остаётся выбрать пространство,
   нажать Create, включить переключатель MCP и скопировать два ключа.

## Решение

Третий вариант: кнопка «Create Slack app» в окне добавления, три коротких шага вместо
абзаца, объяснение - в «?». Разрешения главный процесс берёт у Slack в момент нажатия
(`/.well-known/oauth-protected-resource`, запасной список - в коде): вход SDK просит ровно
их, и приложение должно знать каждое. ИИ для Slack не нужен - после кнопки остаётся минута
кликов.

## Факты и замеры

- Ссылка с описанием - документация Slack «Configuring apps with app manifests»:
  `manifest_json` или `manifest_yaml`, значение закодировано в адресе.
- Включить MCP описанием нельзя: поля для него в описании нет, переключатель «Model Context
  Protocol» в Agents & AI Apps, у нового приложения выключен (руководства TrueFoundry и
  adamjones.me, 2026).
- Разрешения Slack MCP на 2026-11-08 - 30 штук (`scopes_supported`); SDK MCP 1.32.2 без
  своего `scope` берёт их все (`client/auth.js`).
- Ссылка с описанием на 30 разрешений - около 2,5 тысяч знаков. Живьём кнопку не нажимали:
  без входа в Slack страница ведёт на вход.

## Последствия

- Новое рабочее пространство - новый Slack app и новый коннектор, это видно в «?».
- Slack объявит новое разрешение - новые приложения получат его сами, у старых вход
  попросит разрешение, которого приложение не знает: тогда добавить его в OAuth &
  Permissions или пересоздать приложение кнопкой.
- Пересмотреть, если Slack разрешит MCP распространяемым приложениям или если IDE пойдёт
  в Marketplace.

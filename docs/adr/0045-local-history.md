# 0045. Локальная история файлов: SQLite в профиле, ключ содержимого - ключ объекта git

- **Статус:** Принято
- **Дата:** 2026-11-11

## Контекст

Владелец попросил локальную историю, как в WebStorm: каждый файл проекта хранит свои версии
30 дней, любую можно посмотреть и вернуть. В IDE файлы правят не только в редакторе: агент
(Claude Code) пишет их своими инструментами, человек - в терминале, git - при смене ветки.
Как раз после правки агента чаще всего и нужно «верни как было». Удаление из дерева уходит в
корзину (ADR 0043), но правку поверх файла корзина не спасает.

Чтобы у первой же правки было «до», история должна знать содержимое файла раньше, чем его
поменяют. WebStorm для этого держит копии всего проекта в своих кэшах.

## Варианты

Где хранить:

1. **Папка копий рядом с проектом** (`.history/`, как у расширения Local History для VS Code).
   Просто, но мусорит в проекте, попадает в поиск, git и в контекст агента.
2. **SQLite в профиле IDE** (этот выбор): события, нынешнее знание о файлах и сжатое
   содержимое в одной базе `local-history/history.db`, как статистика (ADR 0042). Уборка
   устаревшего - одним запросом, место возвращается постепенно (`auto_vacuum INCREMENTAL`).

Что хранить в начале (у файла ещё нет событий):

1. **Ничего, только события с первой правки.** Тогда у первой правки агента нет «до» - ровно
   там, где история нужнее всего.
2. **Копию всего проекта.** Надёжно, но на крупном репозитории - сотни мегабайт на проект и на
   каждую смену ветки.
3. **Ключ содержимого - ключ объекта git** (этот выбор): sha1 от `blob <длина>\0` и байтов.
   Первая сверка читает файлы, считает ключ и спрашивает git (`cat-file --batch-check`), есть
   ли у него такой объект. Закоммиченное и содержимое других веток отдаёт сам git, история
   хранит только то, чего у git нет: новые и изменённые файлы. Минус: версия, которую знает
   только git, пропадёт, если её объект станет недостижимым и git его соберёт (переписанная
   история, удалённая ветка и `git gc` старше двух недель) - раньше 30 дней это почти не
   случается.

Откуда узнавать о правках:

1. **Только запись редактора.** Правки агента, терминала и git прошли бы мимо.
2. **Слежение за диском (то же, что у дерева) и объявления пишущих** (этот выбор). Событие
   диска не говорит, кто писал, поэтому пишущий объявляет себя заранее: редактор - перед
   сохранением, правка ссылок при переименовании - перед записью, возврат версии - перед
   записью, агент - пока идёт его инструмент правки (`Edit`, `Write`, ...) в ленте разговора.
   Изменение файла в это время получает эту причину, иначе - «извне».

## Решение

Главный процесс, `main/history/`:

- `local-history.ts` - сервис: открытые проекты, события слежения, объявления, лента агента,
  список, содержимое, возврат версии, уборка раз в 12 часов (после неё открытая история
  перечитывается).
- `root-history.ts` - история одного проекта и её очередь: полная сверка (при открытии через
  5 с и когда слежение переполнилось - не чаще раза в 3 с), сверка путей, перенос из дерева и
  возврат версии - работами этой очереди, чтобы сверка не увидела их наполовину.
  Незнакомое, что git игнорирует, не читается вовсе, если файл не открыли в редакторе и не
  правил агент: так `.env` попадает в историю, а сборки и `node_modules` - нет.
- `history-plan.ts` - чистый план сверки: изменился, появился, пропал; пропал и появился с тем
  же содержимым - перенос (история едет за файлом и при `git mv` в терминале). Сохранения
  редактора в течение минуты - одна версия.
- Первая сверка копирует к себе только текст, которого нет в git, и не больше 256 МБ на
  проект: папка без git с картинками и документами не переезжает в базу. Двоичное и не
  влезшее история знает по ключу, «до» у его первой правки - нет; дальше правки хранятся
  все. Файлы больше 5 МБ история не хранит; двоичные правки хранит (вернуть можно, показать
  - нет). Имена из индекса git сверяются с диском: после `mv notes.md Notes.md` без `git mv`
    индекс помнит прежний регистр.
- Правка агента: объявление ставится сразу по вызову инструмента в ленте, снимок «до» берётся
  тогда же. CLI с авто-принятием пишет файл раньше, чем IDE успевает прочитать, - тогда «до»
  восстанавливается снятием точного диффа правки из результата CLI (`structuredPatch`, его же
  берёт откат хода): лента держит дифф обрезанным, поэтому правки идут из потока CLI отдельной
  подпиской (`claude/changes/agent-edits-tap.ts`).
- Запись редактора объявляет себя по настоящему файлу (через ссылку - её цель) и сверяет его
  сразу с той же причиной: объявление не истечёт, пока очередь занята.
- «Restore» сначала сверяет файл (непойманная правка становится событием), файл больше 5 МБ
  копирует к себе (до 64 МБ, дальше возврат отказывает, а не затирает), потом пишет версию.
  Уборка не трогает содержимое моложе часа: сверка кладёт его раньше ссылок на него.

Окно: вкладка истории в середине (`features/editor/LocalHistoryView`), одна на проект, как
разница с коммитом. Слева версии по дням, справа разница Monaco - «With Current» (справа сам
файл: правится, кусок версии возвращается стрелкой) или «This Change» (что сделало событие).
«Restore» возвращает версию целиком и удалённый файл. Открывается из меню дерева (файл, папка,
пустое место - весь проект), меню вкладки и редактора и поиском везде.

## Факты и замеры

MacBook на M-серии, первая полная сверка во временную базу (тест на `LocalHistory` с
`listProjectFiles`, база удалена после):

| Проект              | Файлов | Первая сверка | Повторная | Своих копий       | База   |
| ------------------- | ------ | ------------- | --------- | ----------------- | ------ |
| agentic-workstation | 2972   | 2,4 с         | 0,2 с     | 70 файлов, 156 КБ | 636 КБ |
| roas-radar          | 2511   | 2,3 с         | 0,2 с     | 1 файл, 3 КБ      | 316 КБ |

Повторить: временный тест рядом с `main/history/local-history.test.ts` - `LocalHistory.open`
во временную папку, `projectsChanged([корень])`, `idle(корень)`, потом счёт строк `files` и
`blobs` в `history.db`. Остальное содержимое отдаёт git. Повторная сверка - без чтения файлов: размер и время правки
те же.

## Последствия

- Новый инструмент правки у агента (или новый провайдер) - его поле пути в
  `EDIT_TOOL_PATH_FIELD` (`main/claude/changes/changes.constants.ts`) или своё объявление
  через `LocalHistory.expect`.
- Правки агента через `Bash` (`sed -i`, `mv`) видны как «извне»: путь у такой команды не
  известен заранее. «До» такой правки есть, только если файл история уже знала.
- Правка без диффа (большая, `structuredPatch: []`) с проигранной гонкой снимка «до» не
  получает: снять нечего.
- Профиль IDE с базой - на машине человека; в копии окна агента и в `update:e2e` история
  своя и уходит вместе с профилем.

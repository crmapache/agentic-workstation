# 0119. Клик проверяет цель в момент нажатия: ref или expect, ответ называет нажатое

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст

24 ноября 2026 агент в Chrome человека (коннектор Browser) принимал приглашение в Outlook и
нажал «Aceptar» по координатам со скриншота. Пока мышь ехала к точке, Outlook перерисовал панель,
и под точкой оказалась «Rechazar»: организатору ушёл отказ, событие пропало из календаря, а в
веб-Outlook отказ не отменить. Через минуту тот же агент так же целился в папку «Отправленные» и
попал строкой ниже, в «Удалённые».

Причина - в инструменте, а не в одном агенте: клик не проверял, во что попал. Точка считалась
один раз при прицеливании, потом мышь сотни миллисекунд шла к ней путём руки (ADR 0044), и
нажатие уходило туда, что оказалось под ней к этому времени. Ответ клика говорил только адрес
вкладки или «Clicked at (x, y)». У Computer Use (ADR 0057, 0058) то же самое. Правило в
инструкциях («жми по найденному элементу») модель может пропустить, поэтому проверка нужна в
самом инструменте, а правило - в пояснениях серверов IDE, чтобы оно было у любого агента в любом
проекте.

Ограничения:

- Курсор агента в странице - слой поверх всего, стрелка ИИ на Mac - окно в точке нажатия, капсула
  Computer Use - окно внизу экрана. Проверка не должна принимать их за цель.
- Пояснение сервера Claude Code режет на 2048 знаках вместе с описанием человека (держит тест),
  а пояснения Browser и Computer Use уже были почти полные.
- Живого Windows для проверки сейчас нет.

## Варианты

**Когда проверять.**

1. При прицеливании, до движения мыши. Плюсы: одна проверка, рука не ждёт. Минусы: именно этот
   случай она и пропускает - страница меняется, пока мышь едет.
2. Прямо перед каждым нажатием, после пути и паузы руки (выбрано). Плюсы: проверяется то, во что
   уйдёт нажатие; у двойного клика - и второе нажатие. Минусы: несколько миллисекунд на каждое
   нажатие; по ref при неудаче - ещё один подход мыши.

**Как понять, что жать нельзя.**

1. Список «опасных» подписей (Send, Enviar, Отправить, Aceptar, Rechazar, Delete...), для них -
   особая осторожность. Плюсы: остальные клики как раньше. Минусы: список на всех языках и во
   всех интерфейсах не собрать, пропущенное слово - снова отказ организатору.
2. По `x,y` в действующий элемент (кнопка, ссылка, пункт меню, флажок, поле) - только с `expect`,
   подписью того, что модель хочет нажать; по `ref` - только в сам элемент или его потомка
   (выбрано). Плюсы: закрывает все случаи сразу и стоит модели одной строки; холст, текст и
   пустое место по координатам жмутся как раньше. Минусы: модель учится передавать `expect`.

**Как сравнивать `expect` с именем.**

1. Подпись входит в имя (так было в постановке задачи). Плюсы: прощает лишние слова в имени
   («Aceptar invitación»). Минусы: пускает ровно соседнюю кнопку - «Save» входит в «Don't Save»,
   «Reply» - в «Reply all», «Delete» - в «Delete forever», «1» - в «21».
2. Имя целиком, без учёта регистра, лишних пробелов, типографских кавычек и хвостовой пунктуации
   («Save As…» = «Save As») (выбрано). Плюсы: соседняя кнопка не проходит. Минусы: на имени с
   лишними словами модель получает отказ, где это имя названо, и повторяет с ним. Длинное имя,
   скопированное из ответа обрезанным (с «…»), узнаётся по началу от 40 знаков.

**Что под точкой в браузере.** `DOM.getNodeForLocation` в сессии документа под точкой со спуском
во фреймы других процессов, имя и роль - `Accessibility.getPartialAXTree` (ближайший действующий
предок). Другого способа без своего кода в странице нет, расширение менять не нужно.

**Что под точкой на Mac.**

1. Верхнее окно в точке по `CGWindowListCopyWindowInfo` без окон IDE, затем
   `AXUIElementCreateApplication(pid)` и `AXUIElementCopyElementAtPosition` в этом приложении.
   Минусы (замер ниже): поверх всех окон лежит прозрачное окно Dock во весь экран, строка меню
   принадлежит Window Server, и «верхнее окно» - не то, что получит клик. Окна IDE пропускать
   тоже нельзя: агент может жать и по самой IDE.
2. Системный `AXUIElementCopyElementAtPosition` (`AXUIElementCreateSystemWide`) (выбрано). Плюсы:
   бьёт так же, как клик, - мимо окон, сквозь которые проходит мышь (стрелка ИИ, капсула во время
   клика под ней, окно Dock), находит строку меню и Dock. Минусы: синхронный вызов в главном
   потоке IDE, поэтому предел ответа приложения - 0.5 с.

**Chromium и Electron на Mac** (Chrome, Slack). Без особых атрибутов их веб-содержимое для
доступности - пустые `AXScrollArea` и `AXGroup`.

1. Ставить приложению `AXEnhancedUserInterface` или `AXManualAccessibility` перед проверкой.
   Плюсы: видны кнопки страницы. Минусы: чужое приложение строит полное дерево доступности и
   держит его, пока атрибут стоит, - нагрузка на Slack и Chrome человека; дерево появляется не
   сразу (замер ниже), а `AXManualAccessibility` у Electron 44 не сработал вовсе.
2. Не ставить (выбрано): внутри них элемент - «scroll area» без имени. С `expect` - отказ, раз
   проверить нечем, без него - клик с честным ответом. Страницы сайтов и так идут через Browser,
   где проверка полная.

**Windows.** UI Automation (`IUIAutomation::ElementFromPoint`, подъём по `ControlViewWalker`) через
koffi, места методов COM сверены с `include/uiautomationclient.idl` Wine. Окна самой IDE UI
Automation из главного потока не спрашиваем: вызов в свои окна может повиснуть. Любой сбой -
«элемент не определён».

## Решение

Проверка - прямо перед каждым нажатием, в самом инструменте. Browser: по `ref` попадание должно
быть элементом или его потомком (через iframe другого процесса - тоже), не так - один раз
прицелиться заново, снова не так - не нажимать и сказать, что под точкой. Другая кнопка внутри
`ref` под точкой (строка письма и её «Delete») - тоже «закрыт», кроме ссылок внутри поля ввода.
Подпись поля под точкой - попадание в само поле (Chrome прячет такую подпись с причиной
`labelFor`): клик по `ref` флажка, спрятанного под своей подписью, проходит, а текст подписи по
`x,y` - действующий элемент. По `x,y` действующий элемент без `expect` - отказ с подсказкой про
`ref`, с `expect` - имя попадания должно совпасть целиком. Ответ любого клика - `clicked` с ролью
и именем.
Computer Use: тот же контракт по доступности macOS (системный поиск) и UI Automation на Windows;
не определённый элемент без `expect` жмётся с пометкой, с `expect` - отказ; отказ приходит со
свежим снимком. Действующий элемент без имени (кнопка-значок без описания) - как не определённый:
без `expect` жмётся с пометкой «сверить не с чем», с `expect` - отказ; иначе его нельзя было бы
нажать вовсе (у Computer Use нет `ref`). Имя поля на Mac - его подпись рядом
(`AXTitleUIElement`) или подсказка (`AXPlaceholderValue`), а не набранный в нём текст: `AXValue`
читается только у текста, списков и ячеек, чтобы не тянуть весь документ по связи с приложением. Атрибуты доступности Chromium и Electron не ставим. В пояснениях: кнопки, которые
отправляют, принимают, отклоняют, удаляют или платят, - только по `ref`, на компьютере - с
`expect`, ответ сверить с намерением. Главная причина: проверка в момент нажатия - единственная,
которая видит то, что получит нажатие.

## Факты и замеры

MacBook Pro M5 Pro, macOS 27.2, Chrome for Testing 1248, Electron 44.7.2.

Браузер (Chrome for Testing, сквозной тест):

- С `ignorePointerEventsNone: true` (так было в постановке задачи) `DOM.getNodeForLocation` в
  точке нажатия отдаёт слой курсора агента, без него - кнопку. Флаг значит «бить и по
  `pointer-events: none`», настоящая мышь сквозь такие слои проходит. Держит тест «клик сверяет
  попадание».
- `DOM.getNodeForLocation` ждёт координаты документа, а не окна: на странице, прокрученной на
  2500 px, точка окна над кнопкой - «No node found», та же точка плюс прокрутка - кнопка. Поэтому
  к точке прибавляется прокрутка документа (`Page.getLayoutMetrics`) в каждой сессии.
- Во фрейме другого процесса координаты - в его окне: точка страницы минус начало содержимого
  iframe попадает в кнопку фрейма.
- Подпись флажка (обёртка или `for`) в дереве доступности скрыта с причиной `labelFor`, в которой
  назван сам флажок; роль `LabelText` - только у подписи без поля. Под флажком, спрятанным под
  подписью (стиль Bootstrap), точка попадает в `::before` подписи.
- Цепочка предков от кнопки во фрейме своего процесса кончается корнем документа фрейма: iframe
  документа родителя - через `DOM.getFrameOwner`.
- Полоса «Aceptar | Rechazar | Seguir», которая уезжает на ширину кнопки, как только мышь пошла:
  клик по `ref` на «Aceptar» - нажата «Aceptar», у «Rechazar» ноль; `x,y` с `expect: "Aceptar"`
  в старой точке - отказ, ноль нажатий.

Mac (разовый скрипт на koffi из терминала, плюс интеграционный тест):

- `CGWindowListCopyWindowInfo` на экране человека: первым после строки меню (владелец Window
  Server, слой 24) идёт окно Dock во весь экран 1920x1080 на слое 20 - выше всех окон приложений.
  `AXUIElementCopyElementAtPosition` в приложении Dock в точке вне Dock - `kAXErrorNoValue`
  (-25212), в Window Server - `kAXErrorCannotComplete` (-25204).
- Системный поиск в тех же точках: середина экрана - элемент окна под Dock, строка меню - «View»
  переднего приложения, низ экрана - значок Dock. 20-38 мс первый вызов, по приложению -
  0.1-17 мс, кнопки Калькулятора - 0.2-19 мс (`AXButton`, имя - в `AXDescription`: «7», «8»).
- Окно Electron с `setIgnoreMouseEvents(true)` над кнопкой (как стрелка ИИ): системный поиск
  отдаёт кнопку под ним. Окно своего процесса отвечает синхронно за 7.5 мс; тот же вызов через
  `koffi` async из фонового потока роняет Electron (SIGTRAP) - поэтому только синхронно.
- Нативные приложения без всяких атрибутов видны: Finder - список файлов (`AXCell` < `AXRow`
  (`AXOutlineRow`) < `AXOutline`), 2-17 мс; Системные настройки - строка боковой панели `AXCell`
  (подпись - у вложенного `AXStaticText`, точка на слове её находит, точка на поле строки - нет),
  правая часть SwiftUI между элементами - `AXGroup` (`AXHostingView`), 0.4-11 мс.
- Chrome и Slack без атрибутов: попадание - `AXScrollArea`, выше - `AXGroup` без имён до окна.
  Своё окно Electron 44 без поддержки доступности: `AXManualAccessibility = true` - через 2 с
  всё ещё `AXScrollArea`; `AXEnhancedUserInterface = true` (ответ -25208) - через 1-2 с видна
  `AXButton "Aceptar"`.

Живой прогон 2026-11-24: агент Claude Code в отдельной копии IDE (профиль агента, свой Chrome for
Testing с расширением, манифест моста - только в его профиле) по заданию прошёл через коннекторы
Browser и Computer Use. Браузер: клик по `ref` на «Aceptar» во время сдвига полосы -
`clicked: button "Aceptar"`, счётчики Aceptar 1, Rechazar 0; `x,y` с `expect: "Aceptar"` в старой
точке - «Under the pointer is button "Rechazar", not "Aceptar". Nothing was clicked», все нули;
`x,y` в кнопку без `expect` - отказ с подсказкой; холст без `expect` - `clicked: Canvas`; `ref` на
«Seguir» - `clicked: button "Seguir"`. Калькулятор: клавиша «8» с `expect: "7"` - «Under the
pointer is button "8" in Calculator, not "7". Nothing was clicked», дисплей не изменился; «7» с
`expect: "7"` - «Clicked button "7" in Calculator», на дисплее 7; «8» без `expect` - отказ, на
дисплее осталось 7.

Windows: не мерили, живой машины нет. Механика вызова COM по месту в таблице проверена тестом на
поддельной таблице koffi на любой системе.

Повторить:

```
pnpm --filter @agentic-workstation/browser-extension build
AGENTIC_WORKSTATION_BROWSER_E2E=1 pnpm --filter @agentic-workstation/desktop exec vitest run src/main/browser/browser.e2e.test.ts
AGENTIC_WORKSTATION_COMPUTER_E2E=1 pnpm --filter @agentic-workstation/desktop exec vitest run src/main/computer/ax-element.integration.test.ts
```

Второй тест поднимает своё окно Electron с полосой кнопок и прозрачным окном над «Aceptar»;
мышь в нём подставная, настоящих кликов нет.

## Последствия

- Клик Browser - `page-click.ts` (проверка - `page-hit.ts`, правила - `click-check.ts`), у
  Computer Use - `ComputerHand.click` поверх `InputDriver.elementAt`: `ax-element.ts` на Mac,
  `uia-element.ts` и `uia-native.ts` на Windows, разбор и тексты отказов - `screen-element.ts`.
  Сравнение подписи общее - `browser/expect-label.ts`.
- `type` и `fill` по ref жмут тем же кликом и получают проверку сами. `select`, поля даты и
  цвета (`reach`), `hover` и `scroll` ничего не нажимают - вне проверки.
- Отказ Computer Use - код `mismatch`, ответ - ошибка со свежим снимком.
- Модель по координатам больше не нажмёт кнопку без `expect`: в инструкциях и описаниях `click`
  это сказано, а отказ подсказывает, что делать.
- Доступность macOS здесь - только проверка перед нажатием, а не способ работать: модель по-прежнему
  видит снимки экрана (ADR 0057).
- Пересмотреть Chromium и Electron на Mac, если Computer Use начнут часто использовать для Slack и
  других Electron-приложений: тогда `AXEnhancedUserInterface` по требованию, только при `expect`,
  с ожиданием дерева. Windows - после первого прогона на живой машине: места методов COM,
  пределы ответа `IUIAutomation2`, пропуск окон стрелки и капсулы.

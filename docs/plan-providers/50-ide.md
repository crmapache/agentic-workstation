# Этап 5. Вся IDE различает провайдеров

Панели трёх провайдеров готовы (этапы 2-4). Всё, что вне панелей, пока работает только на
Claude Code: сценарии и задания говорят с потоком `claude -p`, служебные задачи - разовые
`claude -p` с моделями в коде, статистика читает только журналы Claude, телефон видит только
Claude. Разведка с путями и строками - в журнале README (2026-11-18).

## Решения

- **Сценарии и задания - через переводчик на границе, движок не меняется.** Порт провайдера
  сценариев (`main/providers/scenario-provider.ts`) так и задуман: движок прогона говорит с
  сессией на потоке stream-json Claude (перенесён из ACC, покрыт тестами), провайдер с другим
  потоком приносит переводчик. Процесс сессии - маленький интерфейс (`SessionProcess`: запись
  сообщения, управляющий запрос, ответ на вопрос, остановка; `SessionWires`: сообщения, вопросы,
  выход). У Codex и OpenCode - свой процесс-переводчик: `codex app-server` и `opencode serve`
  снаружи, сообщения Claude (`system/init`, `assistant` с частями, `user` с `tool_result`,
  `result` с расходом, `control_request can_use_tool`) внутри. Переписать движок на ядро
  панелей значило бы заново проверять всё, что он умеет (заборы головы, почта, переезд при
  лимите, подхват), - риск без выигрыша для человека.
- **Список провайдеров вне панелей - из реестра панелей.** `providers:list` отдаёт все панели,
  которые есть в IDE, с их моделями, уровнями усилия у каждой модели и режимами провайдера
  (`PanelCapabilities.modes`). Одно место правды для сценариев, заданий, коннектора от ИИ и
  телефона.
- **Выбор «провайдер, модель, усилие, режим» - один на всё окно.** Где начинается работа
  (запуск и расписание сценария, задание, коннектор от ИИ), человек выбирает провайдера, и
  списки модели, усилия и режима берутся у него.
- **Служебные задачи - настройкой.** Имена очередей, проверки целей, черновики заданий и
  сценариев, коннектор от ИИ: провайдер и модель - в Settings IDE, по умолчанию как сейчас
  (Claude, те же модели), чтобы ничего не поменялось молча.

## Разведка (2026-11-18, после этапа 4)

- **Окно уже знает провайдера** у элемента очереди, запуска, расписания, прогона и задания,
  но `providers:list` отдаёт только Claude, у `ProviderInfo` нет уровней усилия и режимов, а
  списки усилия и режима вне панелей - постоянные Claude (`EFFORT_LEVELS`, `SCENARIO_MODES`,
  `TASK_MODES`). У головы и карточек сценария провайдера нет.
- **Движок сценариев читает из потока мало:** `system/init` (начало хода), `assistant` с
  текстом по id сообщения, `stream_event` `message_delta` с `end_turn` (концовка),
  `result` (конец хода: текст, расход, токены, ошибка), `rate_limit_event` и
  `assistant.error = rate_limit` (лимит), `control_request can_use_tool` и
  `control_cancel_request` (вопросы). Сам шлёт только сообщение (и посреди хода), `interrupt`
  и ответ на вопрос. Голова отвечает текстом с JSON в концовке. Кроме потока: id сессии
  выдаёт движок (UUID) синхронно; есть ли разговор на диске - `<папка>/<id>.jsonl` из
  `transcriptDirs`; путь к нему уходит голове при перехвате карточки; журнал шага в окне
  читает транскрипт Claude.
- **Задания** идут тем же `ScenarioSession` через `ClaudeSessions`; `task.provider` нигде не
  читается. Проверки целей, черновики заданий и сценариев, имена очередей - разовые
  `claude -p` с моделями в коде. Ответы из уведомлений и `originOf` ищут разговор только у
  Claude: у Codex и OpenCode кнопки ответа отказывают.
- **Коннектор от ИИ** собирается разговором `claude -p` (`connector-chats.ts`), выбора
  провайдера и модели нет.
- **Статистика** читает только `~/.claude/projects`, строки - всегда `claude`, цены только
  Claude (неизвестная модель считается как Opus). Codex пишет журналы
  `$CODEX_HOME/sessions/**/rollout-*.jsonl`, OpenCode IDE - SQLite в своей папке данных.
- **Телефон** видит только Claude: мост, список провайдеров, команды по id разговора, списки
  усилия и режимов в протоколе (без `minimal`, `readOnly`), зов и пуши; вид действия вызова
  мосту не уходит.
- **Звуки, точки и спиннеры на вкладках проектов в окне уже работают** для всех трёх.

## Решения по разведке

- **Переводчик - процесс сессии провайдера.** Codex: `codex app-server` (тот же
  `AppServerProcess`, аккаунт - папка `CODEX_HOME` аккаунта), бриф - `developerInstructions`
  потока, режимы - `policyFor` панели. OpenCode: свой `opencode serve` (тот же
  `OpenCodeServer`, конфиг панели), бриф - первым системным словом сообщения, режимы -
  `rulesFor` панели. Наружу - сообщения Claude, которые читает движок: `system/init` на
  начало хода, `assistant` с текстом на каждое сообщение модели, `end_turn` и `result` с
  токенами на конец хода, лимит - `rate_limit_event` и `assistant.error`. Вопросы: команда -
  `can_use_tool Bash {command}`, правка - `Edit`/`Write {file_path}`, вопрос модели -
  `AskUserQuestion` (ответ переводится обратно), снятый вопрос - `control_cancel_request`.
- **Id сессии движка остаётся UUID.** Переводчик ведёт свой журнал сессии
  `<userData>/run-sessions/<провайдер>/<id>.jsonl`: первая строка - id потока Codex или
  сессии OpenCode, дальше - читаемые строки разговора (сообщения, ответы, вызовы). Это и
  отметка «разговор есть» для движка, и файл, который голова читает при перехвате карточки.
  У OpenCode id сессии задаётся самим IDE (`ses_` и UUID без дефисов).
- **Журнал шага в окне - лентой провайдера:** `StepLogs` спрашивает провайдера прогона, Codex
  отдаёт ленту по журналу потока (`codex-replay`), OpenCode - по журналу сессии
  (`opencode-replay`).
- **Задания идут через того же провайдера**, что сценарии (`ScenarioProvider` по
  `task.provider`); инструменты поручения (`ide-goal`) - через шлюз и у Codex с OpenCode.
- **Служебные задачи - один разовый вопрос провайдеру** (`askOnce`: промпт, схема ответа,
  модель, усилие, папка): Claude - как сейчас (`askStructured`), Codex - эфемерный поток и
  `outputSchema` хода, OpenCode - сессия без инструментов и JSON из ответа. Какой провайдер и
  модель - настройка IDE (раздел Settings «AI»), по умолчанию Claude и прежние модели.
- **Ответ из уведомления** несёт провайдера разговора; поиск разговора и отправка - через
  реестр панелей.

## Шаги

- [x] 5.1 Реестр провайдеров IDE: все панели в `providers:list`, модели с уровнями, режимы
      провайдера, слежение за всеми панелями. Телефон переходит на тот же список в 5.8: его
      протокол пока не знает режимов и уровней Codex и OpenCode.
- [x] 5.2 Переводчик Codex для сценариев и заданий: процесс сессии поверх `codex app-server`,
      id сессии движка ↔ поток Codex (журнал сессии), бриф - `developerInstructions`, режимы,
      модель (чужая - модель Codex по умолчанию), усилие, вопросы, прерывание, расход, лимит
      аккаунта с выручкой, продолжение; журналы шагов - лентой из журнала Codex.
- [x] 5.3 Переводчик OpenCode - то же поверх `opencode serve`: id сессии задаёт IDE, бриф -
      указаниями сессии, режимы - правилами (и у субагентов), субагенты в фоне - фоновые
      помощники движка; живая проверка на Ollama.
- [x] 5.4 Сценарии в окне: у головы сценария - провайдер, модели, усилие и режим головы и
      карточек - его списками; запуск и расписание по умолчанию - на нём; черновик - у
      провайдера служебной работы, «Continue in a chat» - вкладкой панели провайдера прогона.
- [x] 5.5 Задания и цели: выбор провайдера в форме задания, прогон на нём (у прогона свой
      провайдер), открыть прогон и ответить из уведомления - в разговор любой панели;
      проверки целей - провайдером из настройки.
- [x] 5.6 Служебные задачи и коннектор от ИИ: Settings → AI (провайдер и модель служебной
      работы: имена очередей, проверки поручений, черновики заданий и сценариев); при
      создании коннектора - провайдер, модель и усилие, сборка - разговором этого провайдера.
- [x] 5.7 Статистика: журналы Codex и SQLite OpenCode, провайдер у сессии, фильтр по
      провайдеру, цены по провайдеру (OpenAI - по таблице, OpenCode - своя цена, локальные -
      ноль).
- [x] 5.8 Телефон: разговоры всех панелей, модели, усилие и режимы своего провайдера, вид
      действия в ленте; зов и вопросы от всех провайдеров. Мост берёт разговоры у всех панелей
      (`remote/panel-ports.ts`: ядро AgentPanel, у Claude Code своё сверху), команду по id
      разговора ведёт панель, у которой этот id; новый разговор, история и прошлый разговор - у
      панели выбранного провайдера. Провайдер на проводе - моделями (с уровнями у модели),
      уровнями и режимами своей панели и необязательными флагами (вопрос сбоку, быстрый режим,
      остановка задачи, откат и его области): чего провайдер не умеет, телефон прячет, а мост
      отказывает `notSupported`; режим и уровень не своего провайдера - `modeUnavailable` и
      `effortUnavailable`. Протокол знает уровни minimal и ultra, режим readOnly, id сессий и
      сообщений OpenCode (`ses_`, `msg_`). Вызов в ленте и вопрос разрешения несут вид действия без
      диффа по входу, телефон рисует строку по нему (у IDE постарше - по именам Claude Code).
      Состояние, заплатки лент и зов всех панелей идут мосту и пушам (`PanelObservers.call`),
      пуш называет провайдера. Поиск по разговорам - по-прежнему только у Claude Code. Старый
      телефон новую IDE не роняет: он видит разговоры Codex и OpenCode, а новые уровни и readOnly
      либо не показывает, либо отказывает сам; новый рисунок - после выкладки клиента.
- [x] 5.9 Уведомления и звуки: ответы из уведомлений - в разговор любой панели (task-chats),
      Stop капсулы Computer Use - ход разговора любой панели, тексты заданий, сценариев и
      уведомлений - без имени Claude там, где работает любой провайдер. Ревью этапа четырьмя
      ревьюерами: окно (общее правило провайдера, смена провайдера сценария вместе с карточками,
      примитив ChoiceField), регрессии (список провайдеров по всем панелям), граница процессов
      (у Codex в разовом вопросе и разговоре о коннекторе нет командной строки - проверено
      живьём; у OpenCode без субагентов и вопросов), логика (схема ответа словами вместо
      строгой у Codex, отказ на вопрос в разговоре о коннекторе, команда без обёртки оболочки,
      снятие роли прогона в чате, модель Settings → AI везде) - исправлено всё. ADR 0085.
- [x] 5.10 Живая проверка, ревью, коммит. Живьём: переводчики на Codex и на Ollama (бриф, ход,
      вопрос на команду, отказ, имя очереди), разовый вопрос Codex без командной строки, все
      новые выборы в копии окна (Settings → AI, форма задания, голова и запуск сценария,
      коннектор от ИИ, статистика). Ревью - в 5.9. Следом - переименования 2.6 и финал плана.

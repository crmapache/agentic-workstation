# Провайдеры: Codex и открытые модели рядом с Claude Code

Рабочий план агента. Нужен, чтобы после смены чата или сжатия контекста продолжить с того же
места и с теми же решениями, а не придумывать их заново. Галочка ставится, только когда пункт
сделан и проверен, а в журнал внизу пишется, чем проверен.

## Как читать после сброса контекста

1. Этот файл целиком: решения владельца, правила, этапы, журнал внизу.
2. Файл текущего этапа (`20-core.md`, `30-codex.md`, `40-open-models.md`), если он уже заведён.
3. В рабочей копии: `git log --oneline main..HEAD` и `git status` - что сделано и закоммичено.
4. Последние записи журнала - на чём остановился и что было не так.
5. Только потом код. Не переделывать то, что журнал называет готовым и проверенным, без новой
   причины, записанной в журнал.

## Решения владельца (2026-11-18)

Окончательные, заново не обсуждаются.

- **Каждый провайдер - своя иконка и своя панель.** В полосе провайдеров справа, под иконкой
  Claude: Codex, ниже - открытые модели. У каждой панели свои вкладки разговоров, настройки,
  аккаунты и лимиты. Разговоры и настройки провайдеров не смешиваются.
- **Общее - только в коде:** ядро чата плюс драйвер на провайдера. За основу берётся
  выверенное устройство Claude, и оно не копируется: Claude становится первым драйвером.
- **Codex - второй драйвер.** Справочник - `../amazing-codex` (плагин владельца для JetBrains):
  поведение и протокол берём оттуда, код не копируем и сам проект не трогаем, как ACC по
  правилу 6.
- **Открытые модели - третья панель.** Локальные (Ollama, LM Studio, любой локальный сервер в
  формате OpenAI) и облачные (OpenRouter, любой совместимый адрес). Движок - OpenCode
  (предложение агента, подтверждается живым прогоном в этапе 4 и пишется в ADR).
- **Подключения к источникам моделей живут только в третьей панели.** Claude и Codex остаются
  со своими аккаунтами.
- **Выбор провайдера везде полный.** Где бы ни выбирался провайдер (сценарии и элементы
  очереди, задания, цели «до результата», коннектор от ИИ, служебные задачи IDE, телефон),
  выбираются провайдер, модель из его каталога (у открытых моделей - подключение и модель) и
  усилие из уровней этой модели, а где сейчас есть режим - и режим. Как сейчас у Claude, только
  для каждого провайдера. Списки моделей, уровней усилия и режимов приходят от провайдера, а не
  из общего жёсткого списка.
- **Этап 2 вливается в `main` отдельно** (ответ владельца 2026-11-18): когда готов и
  проверен ревьюерами. Одним сжатым коммитом в основной папке (`merge --squash`), там
  предварительно `git status` чистый; после этого ветка `feat/providers` встаёт на свежий
  `main` (`reset --hard main` в рабочей копии, разница пустая) и идёт дальше. Push - нет.
- **Порядок:** ADR → Claude за интерфейсом драйвера без видимых изменений → Codex → открытые
  модели → вся IDE различает провайдеров.

## Правила работы

- Проектные правила в силе целиком: `CLAUDE.md`, `.claude/rules/*`, границы частей, 200 строк
  на `.tsx` и 300 на `.ts`, токены дизайн-системы, i18n, один контракт IPC, ADR на решения.
- Каждый шаг: `pnpm check` зелёный; тронут интерфейс - осмотр окна скиллом `/dev`; логика -
  тесты. Живая проверка CLI - малыми прогонами (haiku, самая дешёвая модель Codex, маленькая
  локальная модель), во временной папке-проекте.
- Перед коммитом этапа - проектные ревьюеры на дифф этапа (`ide-electron-boundaries`,
  `react-architecture`, `react-design-system`, `logic-tracer`, `edge-case-hunter`,
  `regression-hunter`), находки проверяет `finding-verifier`, подтверждённые исправляются.
- Не трогать: dev владельца и его профиль, его `~/.codex/config.toml`, его конфиг OpenCode. У
  IDE для Codex и OpenCode свои отдельные папки.
- Всё запущенное для проверки гасить в том же заходе.

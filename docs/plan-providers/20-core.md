# Этап 2. Общее ядро, Claude - первый драйвер

Решение - ADR 0083. Снаружи ничего не меняется: Claude работает как раньше, второй и третьей
иконки ещё нет. Этап готов, когда панель Claude целиком идёт через ядро и драйвер, а Codex
можно подключить, не трогая ядро.

Карты, по которым составлен дизайн (замер 2026-11-18): главный процесс - `main/claude` 20 410
строк в 18 папках; окно - `features/claude-code` 590 файлов в 84 папках компонентов; IPC - 73
вызова и 6 событий, все вызовы из окна - внутри `features/claude-code`.

## Что общее, а что драйвер

**Ядро (`main/agents/`)** - одно на всех провайдеров:

- сервис панели провайдера: вкладки и их порядок, группы форков, закрытые вкладки, выбранная
  вкладка проекта, сохранение на диск, рассылка состояния окну, открытие из истории, форк как
  вкладка;
- разговор: состояние хода (идёт ход, вопросы ждут, фоновая работа), статус и итог, очередь
  сообщений и её удержания, сон процесса после простоя, перезапуск по смене аккаунта или
  коннекторов, правила имени вкладки (ранги), ошибки «нет CLI / не доверена / пропала папка»;
- лента: хранилище и заплатки (`FeedStore`, синхронизация 33 мс), учёт ходов, часы работы,
  общие элементы (сообщение человека, отметка, команда `!`, конец хода, обрыв);
- правки: движок отката и возврата файла по диффу (`change-revert`, `file-revert`,
  `turn-settle`, `line-diff`, `line-counts`);
- команды `!`, зов человека, индекс поиска, миниатюры картинок.

**Драйвер (`main/claude/` для Claude, потом `main/codex/`, `main/opencode/`)** - своё у
провайдера: поиск CLI и окружение, процесс и протокол, перевод потока в ленту, вопросы
разрешения и ответы на них, модели, усилие, режимы и быстрый режим, имя от модели, откат
разговора и файлов, форк, журналы и страницы истории, картинки из журнала, расход контекста,
аккаунты и лимиты, коннекторы в формате своего CLI, формат исходящего сообщения (картинки,
заметка редактора, вывод команд `!`), свои экраны и их каналы (плагины, `/config`, `/btw`,
моды, продолжения после лимита).

## Интерфейс драйвера (черновик, уточняется в шаге 2.3)

`AgentDriver` - один на провайдера:

- `capabilities` - что умеет: форк, откат разговора, откат файлов, быстрый режим, план,
  побочный вопрос, остановка фоновой задачи, имена от модели, команды `/`, лимиты аккаунта;
- `locate()` - CLI и окружение выбранного аккаунта;
- `open(context, events)` - живая сессия разговора или `null` с причиной;
- `history` - первая страница, страница выше, элементы по id, правки старого хода, есть ли
  журнал; `list(projectPath)` - прошлые разговоры; `forkOrigin`, `renameOffline`, `readImage`;
- `isTrusted` / `trust` - доверие к папке по правилам провайдера;
- модели, режимы и уровни усилия - каталог для окна и для выбора в сценариях и заданиях.

`AgentSession` - один живой процесс разговора: `send(сообщение, посреди хода)`, `interrupt`,
`answer`, `answerInChat`, `dismiss`, `setModel`, `setEffort`, `setMode`, `setFast`, `title`,
`rename`, `rewindConversation`, `previewFiles`, `restoreFiles`, `contextUsage`,
`accountUsage`, `stopTask`, `sideQuestion`, `reconnectMcp`, `stop`, `kill`.

`SessionEvents` - что сессия сообщает ядру: запись в ленту, ход начался, сообщение принято,
ход кончился (итог, цена, длительность, расход), вопрос пришёл и отозван, сменилась сессия
(`/clear`), активная модель, расход контекста, команды, каталог моделей, фоновая работа
изменилась, правка файла инструментом, зов, вход истёк, процесс вышел.

Сообщение для драйвера - общее: id, текст, картинки, заметка редактора, вывод команд `!`,
служебная рамка. Форматирует его драйвер: у Claude это блоки Anthropic, теги `bash-*` и
`system-reminder`.

## Лента: виды действий

У `ToolFeedItem` появляется `action` - что делает вызов, общими словами: `command`, `read`,
`edit`, `write`, `search`, `web`, `mcp`, `agent`, `plan`, `question`, `todo`, `skill`, `other`.
Его ставит драйвер. Окно рисует иконку, подпись, карточку правки, карточку субагента и вопрос
разрешения по `action`, а не по имени инструмента Claude. `name` и `input` остаются для подписи
и подробностей.

## IPC

- Общие операции панели (состояние, лента, вкладки, отправка, очередь, ответы, настройки
  разговора, история, форк, откат, картинки, команды `!`, поиск) - каналы `agent:*`, провайдер
  в каждом запросе. События `agent:state`, `agent:feed`, `agent:call` несут провайдера.
- То, что есть у одного провайдера (аккаунты Claude, плагины, `/config`, `/btw`, продолжения),
  - свои каналы этого провайдера.
- В главном процессе - реестр сервисов панелей по провайдеру; обработчики `agent:*` берут
  сервис из реестра.
- Состояние панели - по ключу `['agent', провайдер, 'state']`, лента - по провайдеру и id.

## Окно

- Одна фича панели провайдера, параметризованная провайдером (вариант A карты): общий
  интерфейс чата в корне фичи, экраны провайдеров - в `providers/<провайдер>/`. Полоса
  провайдеров монтирует её три раза с разным провайдером. Правила границ не меняются.
- Провайдер - из контекста панели. Запросы, кэш, хранилища Zustand (меню, черновики, закрепы,
  потоки, поиск) - по провайдеру: панели не делят черновик новой вкладки и меню.
- Боковое меню: набор экранов - от провайдера (у Claude - история, плагины, аккаунты,
  настройки и подэкраны).
- Режимы, уровни усилия, иконки моделей - из каталога провайдера, а не из констант Claude.
- Лента для сценариев, заданий и коннекторов (`ConversationLog`) получает провайдера.

## Шаги

Каждый шаг - коммит в ветку, `pnpm check` зелёный, поведение Claude то же.

- [x] 2.1 Виды действий в ленте: `action` у вызова, его ставит перевод потока Claude; окно
      (иконки, подписи, вид строки, карточки правки и субагента, вопрос разрешения) читает
      `action`. Тесты на перевод и на окно.
- [x] 2.2 Провайдеры в типах: `ProviderId` - `claude`, `codex`, `opencode`. Какие есть в IDE,
      знает реестр панелей. Мост телефона отдаёт разговоры только провайдеров, которых
      обслуживает (`isServedProvider`, пока Claude), остальным - `providerMissing`.
- [x] 2.3а Общее из `main/claude` переехало без изменения поведения: `main/agents/feed`
      (`feed-store`, `work-clock`), `main/agents/changes` (откат и возврат файла, сверка хода,
      построчный дифф, счёт строк, тип `TurnFile`, свои константы), `main/agents/shell` (запуск
      команды `!` в оболочке человека), `main/agents/calls` (зов и его приоритет),
      `main/agents/images` (миниатюры, уменьшение, расширения картинок), `main/agents/tabs`
      (порядок, имена, фокус панели), `main/process` (группы процессов IDE, окружение login
      shell - это не только про агентов: им пользуется и git). Ядро не импортирует `claude/`.
      Остались в Claude до 2.3б/в: `turn-tracker` (зовёт `turnChanges` по именам
      инструментов), `shell-runs` (пишет в ленту через сборщик Claude), `tab-strip`,
      `closed-tabs`, `new-tab`, `tab-rename` (живут вместе с сервисом и журналами).
- [x] 2.3б Разговор в ядре (`main/agents/conversation`: `ConversationRuntime`, очередь
      `outbox`, интерфейсы `agent-parts.ts`) говорит с сессией драйвера, а не с процессом
      CLI. У Claude: `ClaudeSession` (процесс `claude -p`, ответы на вопросы, остановка,
      исходящее сообщение), `claudeDriver` (лента, подъём сессии, настройки), своё на
      разговор - `ClaudeConversation` через `claudeOf(runtime)` (лента со сборщиком Claude,
      откат хода, рукопожатие, uuid хода, имя, откат разговора). Ядро не импортирует
      `claude/`. Переименования: `prepareSession`, `restartSession`, `sessionEnded`.
- [x] 2.3в Сервис панели в ядре, Claude - драйвер с аккаунтами, лимитами, плагинами,
      настройками, служебным. Тесты разговора и сервиса - на месте и зелёные. Дизайн: - `main/agents/panel/agent-panel.ts` - базовый класс `AgentPanel`: разговоры (Map),
      выбранная вкладка проекта, полоса вкладок (`TabStrip` переезжает в ядро), команды
      проекта (`ProjectCommands`), зов, сохранение на диск и рассылка, лента разговора,
      новая вкладка, открыть из истории, форк вкладкой, доверие, повторный поиск CLI,
      выход. Своё провайдера - через `PanelDriver`: история (список, есть ли журнал, имя
      из журнала), точка форка, умолчания новой вкладки (режим по настройкам провайдера),
      переименование без живой сессии, доверие к папке, поиск CLI. - `main/agents/panel/panel-state.ts` - что о вкладке хранится и как она оживает
      (`StoredConversation`, `freshConversation`, `toStored`, разбор файла) - из
      `claude-state.ts`; проверка режима и усилия - у драйвера. - `ClaudeService extends AgentPanel`: аккаунты, расход, служебное панели, плагины,
      поле ввода, коннекторы, настройки, токены за день. Публичный вид для IPC, сценариев,
      заданий и телефона не меняется (27 мест в `remote-setup.ts`, 21 в
      `claude-handlers.ts` и другие).
- [x] 2.4 IPC `agent:*` с провайдером (`shared/ipc/agent.contract.ts`, 35 каналов и 3
      события), реестр панелей (`main/agents/panel/panel-registry.ts`), обработчики
      (`main/ipc/agent-handlers.ts`). Общие действия разговора - в ядре
      (`main/agents/panel/panel-actions.ts`, своё провайдера - `ConversationOps`). Остались
      каналами Claude: аккаунты, плагины, `/config`, `/btw`, продолжения, токены за день,
      настройки панели, поиск по разговорам, поле ввода (команды, вложения), фокус панели,
      журнал агента флота.
- [x] 2.5 Окно: панель по провайдеру, кэш и хранилища по провайдеру, экраны меню от
      провайдера, режимы и усилие из каталога, полоса готова к трём иконкам.
- [x] 2.5а Данные: провайдер панели из контекста (`state/panel-provider.context.ts`), ключи
      кэша `['agent', провайдер, ...]`, вызовы `agent:*`, события с провайдером.
- [x] 2.5б Полоса: панель Claude отдаёт контексту своего провайдера (`ClaudeCodePanel` →
      `PanelFrame`), виды `claude-code`, `codex`, `open-models` и соответствие
      `PROVIDER_VIEW_OF`; зов и звук проверяют панель своего провайдера. Переход к панели
      из заданий и уведомлений по провайдеру - этап 5 (они пока только Claude).
- [x] 2.5в Хранилища интерфейса панели - по провайдеру: стор панели на провайдера (меню,
      опустевшие проекты, фокус, откат, имя вкладки), свет вкладок - отдельным общим стором,
      черновик проекта без вкладок - с провайдером в ключе, «Send to Chat» - только видимой
      панели. Возможности - `shared/panel-capabilities.ts`, хук `usePanelCapabilities`:
      режимы (меню, Shift+Tab, новая вкладка), усилие по модели, быстрый режим, форк, откат,
      вопрос сбоку, остановка задач, строки меню и настроек, вход, путь к CLI, поиск, токены
      за день, команды `/` (свои CLI и с диска). Лимиты - общим каналом
      `agent:refreshUsage`. Сделано вместе с панелью Codex (шаг 3.5).
- [x] 2.7 Проверка: живой разговор в копии окна (доверие, очередь, ход с инструментами,
      ответ, имя вкладки); ревьюеры - радиус поражения, прослеживание сценариев, граница
      процессов, архитектура окна. Исправлено по ревью: ответы каналов Claude - в кэш Claude
      (`usePutPanelState`, аккаунты - `useClaudeAccounts`), настройки панели - общий канал
      `agent:setPrefs`, свет вкладок гасится только своим провайдером, сценарии отказывают
      незарегистрированному провайдеру сразу, служебные вызовы (BashOutput, KillShell, LS)
      рисуются как раньше, адрес во вопросе разрешения. Этап влит в `main` (решение
      владельца).
- [x] 2.6 Переименования - сделаны в финале плана (после этапа 5), чтобы не плодить
      конфликты с соседними сессиями. Папка панелей в окне - `features/agent-panel`,
      пространство строк - `agentPanel`; общие типы - `shared/conversation.ts`,
      `conversation-feed.ts`, `message-draft.ts`, `panel-extras.ts`, `panel-prefs.ts`,
      `rewind.ts`, `accounts.ts`, `account-usage.ts`, `fast-mode.ts`, состояние панелей -
      `AgentPanelState`; общие файлы фичи - `panel.store`, `panel.queries`, `panel.types`,
      `panel.utils`, `panel.constants`, `conversation-actions.hooks`, вид - `AgentPanelView`.
      Своё у Claude осталось под его именем: модели, настройки `/config`, плагины, поиск по
      разговорам, аккаунты из ACC, `ClaudeCodePanel`, вид `claude-code` в раскладке (он
      записан в сохранённой раскладке окна). Главный процесс (`main/claude`) - драйвер
      Claude, его не трогали.

Сценарии, задания, цели, статистика и телефон в этом этапе продолжают работать на Claude,
только через новые имена. Их перевод на драйверы - этап 5.

## Что держать в голове при переезде

- `list_models` спрашивается раз за запуск IDE (переменная модуля), а не на сессию.
- Цена хода у Claude - разница накопленной цены процесса: `startProcess()` сбрасывает базу.
- `discardStray` и `lastSentUuid` остаются внутри сессии Claude: на них держится откат.
- id сессии у Claude выбираем мы до запуска, и он же имя журнала; у Codex id даёт сервер. В
  ядре id сессии провайдера может быть пустым до первого запуска.
- Форк у Claude ленивый (рождается первым сообщением, точка - uuid строки журнала), у Codex -
  сразу и по номеру хода. В ядре точка форка - id сообщения ленты, драйвер переводит её в своё.
- Черновик новой вкладки сейчас под ключом папки проекта - с тремя панелями он стал бы общим.
- `ViewStack` держит все открытые виды смонтированными: три панели крутят свои хуки
  одновременно.

# Этап 4. Панель открытых моделей (OpenCode)

Третья панель провайдеров (ADR 0083): открытые модели - локальные (Ollama, LM Studio, любой
локальный сервер в формате OpenAI) и облачные (OpenRouter, любой совместимый адрес). Движок -
OpenCode (ADR 0084, принят по живому прогону 2026-11-18). Ядро панели то же, что у Claude и
Codex: вкладки, очередь, лента, ход, вопросы, откат - в `main/agents`, своё OpenCode - драйвером.

## Протокол (замер на OpenCode 2.3.2, 2026-11-18)

Спецификация сервера - `/openapi.json` (копия для работы -
`~/.claude/projects/.../scratch/opencode-openapi.json`), образец потока событий живого хода -
там же, `opencode-events-sample.log`.

- **Запуск.** `opencode serve --stdio`: сервер слушает свободный порт на 127.0.0.1 и печатает
  в stdout одну строку `{"url":"http://127.0.0.1:N"}`; гаснет сам, когда закрывается его stdin
  - сирот не бывает, как у `codex app-server`. Пароль - `OPENCODE_SERVER_PASSWORD` (в режиме
    stdio сервер стирает его из окружения своих дочерних процессов), вход - Basic с именем
    `opencode`. Без пароля - 401 на всё.
- **Свои папки.** `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME` - у IDE
  свои: конфиг и база разговоров человека не трогаются. Конфиг целиком - строкой в
  `OPENCODE_CONFIG_CONTENT`, файла не нужно. `OPENCODE_DISABLE_AUTOUPDATE`,
  `OPENCODE_DISABLE_FREE_MODELS` (бесплатные облачные модели OpenCode Zen - чужой адрес, туда
  код проекта без спроса не уходит). Конфиг проекта (`opencode.json` в папке) и инструкции
  Claude (`CLAUDE.md`, навыки) OpenCode читает сам - это настройки человека, их оставляем.
- **Конфиг второй версии** - ключ `providers` (не `provider`): `{ <id>: { name, package:
"@ai-sdk/openai-compatible", settings: { baseURL, apiKey }, models: { <id>: { name,
capabilities: { tools }, limit: { context, output } } } } }`; модель по умолчанию -
  `model: "<provider>/<model>"`; ещё `mcp`, `permissions`, `share: "disabled"`,
  `update: "disable"`. Пакет провайдера OpenCode ставит в свой кеш сам при первом обращении.
- **Каталог.** `GET /api/model` - модели настроенных провайдеров: `capabilities.tools`,
  `limit.context`, `variants` (уровни рассуждения: `{id, settings: {reasoningEffort}}`), цена.
  Ссылка на модель - `{providerID, id, variant}`.
- **Сессия.** `POST /api/session` с `location.directory` (папка проекта) и `model` - сессия
  (`ses_...`); `POST /api/session/{id}/prompt` `{text, files, delivery: steer|queue}` - сообщение
  (ответ сразу, ход идёт событиями); `interrupt`, `fork`, `compact`, `model`, `agent`,
  `revert/stage` + `revert/commit` (откат разговора и файлов по снимкам OpenCode), `message`
  (журнал страницами), `GET /api/session?directory=` - история проекта.
- **События.** `GET /api/event` - SSE, `data: {id, type, data, location}`. Ход:
  `session.execution.started|succeeded|failed|interrupted`; шаг модели
  `session.step.started|ended|failed` (в `ended` - токены и цена); текст
  `session.text.started|delta|ended`; размышление `session.reasoning.*`; инструмент
  `session.tool.input.started` (имя) → `session.tool.called` (вход) →
  `session.tool.success|failed` (выход), `session.tool.progress`; расход
  `session.usage.updated`; имя `session.renamed`; повтор `session.retry.scheduled`; сжатие
  `session.compaction.*`; очередь `session.inbox.*`. Вопросы: `permission.asked` (действие,
  ресурсы, источник - вызов инструмента) → `POST .../permission/{id}/reply` `once|always|reject`;
  вопрос с вариантами - `form.created` → `.../form/{id}/reply`.
- **Права.** Набор правил `{action, resource, effect: allow|deny|ask}` - у конфига
  (`permissions`) и у сессии при создании. Агенты OpenCode: `build` (работа) и `plan`.

## Как ложится на ядро (ADR 0083)

- **Процесс на разговор**, как у Codex: `opencode serve --stdio` поднимается сессией вкладки и
  гаснет с ней. Один сервер на все разговоры дал бы один ключ шлюза на все проекты - коннекторы
  IDE видны по проекту, поэтому процесс свой у каждого разговора, а база разговоров у всех общая
  (свои папки IDE). Список истории и модели - процессом-каталогом, как у Codex.
- **Подключения хранит IDE** (`open-models.json`, ключи - `safeStorage`): Ollama и LM Studio
  находятся сами на своих портах, OpenRouter и свой адрес - добавляет человек. Из подключений
  IDE собирает конфиг OpenCode (`providers` с моделями) и отдаёт его каждому процессу.
- **Модели.** IDE спрашивает подключение само (Ollama `/api/tags`, `/api/show` и `/api/ps` -
  умение вызывать инструменты и окно, с которым сервер держит модель, а не её предел, ADR
  0087; LM Studio и свой адрес - `/v1/models`; OpenRouter -
  `/api/v1/models` с `supported_parameters` и `context_length`). Модель без инструментов в меню
  не встаёт, окно контекста меньше 32 тысяч - предупреждение у пункта. Значение модели панели -
  `<подключение>/<модель>`. Усилие - варианты модели из каталога OpenCode.
- **Режимы** - агент и правила сессии: «Спрашивать» - правки и команды спрашивают; «Авто» -
  правки в проекте без вопросов, команды спрашивают; «Только чтение» - правки запрещены; план -
  агент `plan`; «Без вопросов» - всё разрешено.
- **Лимиты.** У локальных их нет; у OpenRouter - остаток и расход ключа (`/api/v1/key`).
  Кольцо контекста - из `session.usage.updated` и окна модели.
- **Коннекторы IDE** - через шлюз, ключ в памяти и окружении процесса (как у Codex):
  `mcp: { <имя>: { type: "remote", url, headers: { Authorization: "Bearer {env:...}" } } }`.

# Подпись macOS-сборки

## Зачем сертификат, если Apple приложение не заверяет

Developer ID нет, поэтому сборка подписана самоподписанным сертификатом
`Agentic Workstation Code Signing` - так же, как snakein. Предупреждение Gatekeeper при
первой установке он не убирает (это умеет только Developer ID), поэтому человек один
раз выполняет:

```
xattr -cr "/Applications/Agentic Workstation.app"
```

Сертификат решает другую задачу. macOS узнаёт приложение не по имени и не по пути, а
по правилу подписи (designated requirement). С подписью ad-hoc правило - хеш этой
самой сборки:

```
designated => cdhash H"4b7bccfc3cfb5fdaf8537e6cba09d4586a8c1662"
```

С сертификатом - идентификатор и сертификат, которые от сборки к сборке не меняются:

```
designated => identifier "io.github.crmapache.agenticworkstation" and certificate leaf = H"..."
```

На этом держится самообновление: установленная IDE ставит новую версию, только если
та подходит под её правило, то есть подписана тем же сертификатом
([ADR 0004](adr/0004-self-update.md)). Сборка с подписью ad-hoc обновляться из
приложения не умеет вовсе - уведомление предложит скачать руками.

## Сертификат один на всю жизнь проекта

**Потерять ключ - значит потерять обновления.** Следующая сборка, подписанная другим
сертификатом, не встанет ни у кого из тех, кто уже поставил IDE: только
переустановка руками. Восстановить прежний сертификат нельзя.

Поэтому:

- копия лежит в корне репозитория: `agentic-workstation-code-signing.p12`, пароль
  `agentic-workstation` (секрет - сам файл, а пустой пароль macOS при импорте не принимает).
  Удалять её нельзя;
- в git `.p12` и `.pem` не попадают (`.gitignore`): это приватный ключ, которым
  подписывается то, что запускается у людей;
- у этого проекта свой сертификат, отдельный от snakein и notastream: общий ключ
  связал бы судьбу продуктов без всякой пользы.

Создан 2026-11-10, отпечаток `12E08D08B8E1EC971DEAA83F78FBC8DC6BB1C5B3`. Прежний
`Amazing IDE Code Signing` (2026-10-16, `AC7AA9E35B2E6C086162367A9570C3A34A0A37D1`) заменён
при переименовании до первого релиза ([ADR 0038](adr/0038-rename-agentic-workstation.md)):
он остаётся в связке ключей, его копия `amazing-ide-code-signing.p12` - в корне, но ничего
не подписывает.

## Кто подписывает и почему без доверия

Подписывает не electron-builder, а наш хук `apps/desktop/scripts/sign-app.cjs`
(`afterPack`, до сборки dmg и zip) - прямым вызовом `codesign`. Встроенная подпись
electron-builder ищет сертификат только среди доверенных, а доверие самоподписанному
сертификату macOS выдаёт лишь через системное окно с паролем учётной записи. Самому
`codesign` доверие не нужно, подпись и правило выходят те же. У людей, которые ставят
IDE, доверия к сертификату тоже нет, и проверка обновлений от этого не зависит - это
проверено `update:e2e` с недоверенным сертификатом.

`pnpm dist` подписывает обязательно и падает, если сертификата нет. `pnpm dist:local`
оставляет подпись ad-hoc - для проверки сборки, не для публикации.

## Создать (один раз)

```
bash apps/desktop/scripts/create-signing-cert.sh
```

Ничего не спрашивает. Отказывается работать, если сертификат с таким именем уже есть
или копия уже лежит в корне.

## Перенести на другую машину

Положить копию в корень репозитория и импортировать:

```
security import agentic-workstation-code-signing.p12 -k ~/Library/Keychains/login.keychain-db \
  -P agentic-workstation -T /usr/bin/codesign
```

`-T /usr/bin/codesign` важен: без него каждая подпись при сборке ждёт подтверждения
доступа к ключу в модальном окне.

## Проверить

Сертификат на месте:

```
security find-identity -p codesigning | grep "Agentic Workstation Code Signing"
```

Пометка `CSSMERR_TP_NOT_TRUSTED` в строке - норма: доверие подписи не нужно.

Собранное приложение подписано им, а не ad-hoc:

```
AGENTIC_WORKSTATION_KEEP_UNPACKED=1 pnpm dist
codesign -d -r- "apps/desktop/dist/mac-arm64/Agentic Workstation.app"
```

В ответе должно быть `certificate leaf`. Если там `cdhash` - сборка ушла с ad-hoc
подписью, и публиковать её нельзя: установленные копии её не примут. Хук подписи и
`/build` эту проверку делают сами.

## Windows: ключ подписи обновлений

Сертификата подписи кода для Windows у проекта нет: установщик не подписан, и при первой
установке SmartScreen предупреждает («Подробнее» → «Выполнить в любом случае»). Обновление
держит другая подпись ([ADR 0048](adr/0048-windows.md)): sha512 установщика подписывает закрытый
ключ Ed25519, а установленная IDE пускает установщик, только если подпись сходится с открытым
ключом, вшитым в неё (`WINDOWS_UPDATE_PUBLIC_KEY` в `apps/desktop/src/main/updates/update.constants.ts`).

- Закрытый ключ - `agentic-workstation-update-signing.pem` в корне репозитория (git его не видит,
  права 600), создан 2026-11-11. Подписывает его `scripts/write-update-manifest.mjs` на шаге
  манифеста в `/build`.
- **Потерять ключ - значит потерять обновления на Windows**, так же как с сертификатом мака:
  копии с прежним открытым ключом новый не примут, только переустановка руками. Держи копию
  рядом с копией сертификата мака.
- Новый ключ - только новым ADR и с переустановкой у всех.

## Когда появится Developer ID

Подпись переходит на него: хук `sign-app.cjs` убирается, в
`apps/desktop/electron-builder.yml` вместо `identity: null` вписывается Developer ID,
возвращается `hardenedRuntime: true`, настраивается нотаризация. Правило подписи при
этом сменится, поэтому первую версию на Developer ID установленные копии не примут
автоматически: её ставят руками, дальше обновления снова идут сами.

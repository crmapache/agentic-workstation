# Клик попадает туда, куда задумано: проверка цели в браузере и на Mac

## Зачем

24 ноября 2026 агент в Chrome Макса (коннектор Browser) должен был принять приглашение в Outlook
и нажал «Aceptar» по координатам со скриншота. Между скриншотом и нажатием Outlook перерисовал
панель, и под точкой оказалась «Rechazar»: организатору ушёл отказ, событие пропало из календаря.
В веб-Outlook отказ потом не отменить, пришлось просить организатора прислать приглашение заново.
Через минуту тот же агент тем же способом целился в папку «Отправленные», а попал на строку ниже,
в «Удалённые».

Причина не в одном агенте: инструмент клика сейчас вообще не проверяет, во что попал. Правило
«жми по найденному элементу» в инструкциях помогает, но модель может его пропустить. Нужна
проверка в самом инструменте, а правило - в инструкциях IDE, чтобы оно было у любого агента
(Claude Code, Codex) в любом проекте.

Объём задачи: браузер (коннектор Browser), Mac (коннектор Computer Use), правило в инструкциях
обоих коннекторов, ADR. Windows в Computer Use - по той же схеме, оговорки ниже.

## Как устроено сейчас (по коду)

**Браузер.** Инструмент `click` (`main/connectors/kinds/browser/browser-input-tools.ts`) зовёт
`click` из `main/browser/page-actions.ts`. Там точка считается один раз в начале (`aimOf` из
`page-reveal.ts`: у `ref` - коробка элемента, у `x,y` - сама точка), потом мышь живым путём едет к
ней (`moveTo` в `page-pointer.ts`, сотни миллисекунд), пауза `settleMs`, и только потом
`mousePressed`. За это время страница может сдвинуться, и в момент нажатия под точкой уже другой
элемент. Это касается не только `x,y`: клик по `ref` тоже уязвим, если раскладка поехала во время
движения. Ответ клика (`act`) говорит только вкладку, адрес и `navigated`, но не что нажато.

Расширение (`apps/browser-extension`) пересылает любой метод CDP как есть (`methods.ts`, ветка
`cdp`), поэтому вся логика проверки живёт в `main/browser`, а расширение менять не нужно. Если
всё же понадобится - это новая версия расширения и её доставка людям, учесть.

Курсор агента в странице - слой в закрытом shadow root с `pointer-events: none` поверх всего
(`apps/browser-extension/src/overlay`). Поиск элемента под точкой должен его пропускать.

**Mac.** Инструмент `click` (`main/connectors/kinds/computer/computer-tools.ts`) →
`ComputerAgent.click` (`main/computer/computer-agent.ts`, ответ сейчас `Clicked at (x, y).`) →
`ComputerHand.click` (`main/computer/computer-hand.ts`): `moveTo`, пауза, `mouse('down')`. Ввод -
CoreGraphics через koffi (`cg-events.ts`). Разрешение «Универсальный доступ» IDE уже просит, и
оно же даёт читать дерево доступности чужих приложений (AX API) - нового разрешения не нужно.
Поверх экрана у IDE свои окна: курсор агента (`overlay-window.ts`) и капсула
(`computer-capsule.ts`). Поиск элемента под точкой должен их пропускать.

**Инструкции.** Пояснения серверов - `browser-guide.ts` и `computer-guide.ts`. Claude Code режет
пояснение на 2048 знаках вместе с описанием человека, это держит тест - новые слова должны
влезть, подробности уходят в описание инструмента.

## Что сделать

### 1. Браузер: проверка в момент нажатия

1. **Проверка - прямо перед `mousePressed`**, после движения и паузы, а не при расчёте точки.
   Перед каждым нажатием, у двойного клика тоже.
2. **Что под точкой:** `DOM.getNodeForLocation` с `ignorePointerEventsNone: true` (иначе попадём в
   курсор агента). Если под точкой фрейм другого процесса - спуститься в его сессию со сдвигом
   (в `page-frames.ts` уже есть `frameOffset`). Описание попадания: роль и доступное имя самого
   узла или ближайшего интерактивного предка (button, link, menuitem, checkbox, radio, tab,
   option, textbox, combobox и подобные) через `Accessibility.getPartialAXTree`.
3. **Клик по `ref`:** попадание должно быть самим элементом `ref` или его потомком. Не так - один
   раз пересчитать коробку и довести мышь заново. Снова не так - не нажимать и ответить, что
   элемент сдвинулся или закрыт и что сейчас под точкой; посоветовать новый снимок.
4. **Клик по `x,y` получает необязательное поле `expect`** - ожидаемая подпись. Сравнение по
   имени попадания: без учёта регистра и лишних пробелов, `expect` должен входить в имя. Не
   совпало - не нажимать, ответить, что под точкой на самом деле.
5. **Клик по `x,y` в интерактивный элемент без `expect` - отказ** с подсказкой: «под точкой
   кнопка "Rechazar"; нажми по `ref` из снимка или передай `expect`». Холст, пустое место, текст -
   без `expect` можно, как сейчас. Решение принято сознательно: список «опасных» подписей
   (Send, Enviar, Отправить, Aceptar...) на всех языках не собрать, а требование `expect` для
   любой кнопки по координатам закрывает все случаи сразу и стоит модели одной строки.
6. **Ответ любого клика говорит, что нажато:** поле `clicked` с ролью и именем. Модель сверяет его
   с намерением, человек видит это в логе.
7. `type` по `ref` нажимает через тот же `click` и получает проверку сам. `select` и заполнение
   полей не нажимают по-настоящему (`reach`) - их не трогать. `hover` и `scroll` ничего не
   отправляют - вне объёма.

### 2. Mac: та же проверка в Computer Use

1. **Что под точкой:** AX API через koffi, как уже сделан CoreGraphics. Чтобы не попасть в свои
   окна (курсор, капсула): найти окно под точкой через `CGWindowListCopyWindowInfo` без окон
   своего процесса, взять его pid, `AXUIElementCreateApplication(pid)` и
   `AXUIElementCopyElementAtPosition` внутри этого приложения. Координаты - глобальные точки
   экрана, те же, что у CGEvent (`toScreen` уже переводит пиксели снимка).
2. **Описание попадания:** `AXRole`, `AXSubrole`, имя из `AXTitle`, `AXDescription`, `AXValue`;
   подъём по `AXParent` до ближайшего действующего элемента (`AXButton`, `AXMenuItem`, `AXLink`,
   `AXCheckBox`, `AXRadioButton`, `AXPopUpButton`, `AXTab` и подобные) и имя приложения.
3. **Проверка - после движения мыши, прямо перед `mouse('down')`** в `ComputerHand.click`.
4. **`expect` у `click` Computer Use** с тем же сравнением, что в браузере. Не совпало - не
   нажимать, вернуть свежий снимок и текст, что под точкой.
5. **Действующий элемент без `expect` - отказ**, как в браузере.
6. **Элемент не определился** (игра, холст, приложение без доступности): без `expect` клик идёт
   как сейчас с пометкой «элемент не определён»; с `expect` - отказ, раз проверить нечем.
7. **Ответ клика:** вместо `Clicked at (x, y).` - что нажато: роль, имя, приложение.
8. **Chromium и Electron** (Chrome, Slack, сама IDE) отдают дерево веб-содержимого не сразу: им
   нужен `AXEnhancedUserInterface` или `AXManualAccessibility`, а это нагрузка на чужое
   приложение. Проверить, что видно без этих атрибутов, на Chrome, Slack, Finder и Системных
   настройках; решить, ставить ли атрибут, и записать решение в ADR. Страницы сайтов всё равно
   идут через Browser, так что честное «элемент не определён» внутри Chrome допустимо.

**Windows.** Тот же контракт через UI Automation (`IUIAutomation::ElementFromPoint`) рядом с
`win-native.ts`. Живой Windows-машины для проверки сейчас нет, поэтому поведение при сбое строгое:
не удалось определить элемент - с `expect` отказ, без `expect` клик с пометкой «элемент не
определён». Молча игнорировать `expect` нельзя ни на какой системе.

### 3. Правило в инструкциях IDE

1. **`BROWSER_GUIDE`:** кнопки, которые отправляют, принимают, отклоняют, удаляют или платят, -
   только по `ref` из свежего снимка; после клика сверить `clicked` с намерением.
2. **Описание `click` в браузере:** `ref` - основной способ; `x,y` для интерактивных элементов
   требует `expect`; ответ говорит, что нажато.
3. **`computerGuide` и описание `click` Computer Use:** `expect` для кнопок и пунктов меню,
   сверка ответа с намерением.
4. Всё в пределе 2048 знаков пояснения (тест), английским, коротко.

### 4. ADR

Новый ADR (следующий номер - 0119) через `/adr`: почему проверка в момент нажатия, а не при
прицеливании; почему `expect` обязателен для интерактивных элементов по координатам, а не список
опасных подписей; что делаем с Chromium и Electron на Mac; поведение на Windows. Обновить
`docs/architecture.md`, если там описан путь клика.

## Проверка

Всё на своих тестовых страницах и окнах. Почта, календарь, чаты и приглашения людей - никогда:
ошибка там уходит живым людям.

1. **`pnpm check`** целиком.
2. **Модульные тесты:** сравнение с `expect` (регистр, пробелы, вхождение); что считается
   интерактивным; потомок `ref` или нет; повторное прицеливание и отказ после него; тексты
   отказов; разбор ответа AX и UIA.
3. **Сквозные тесты браузера** (`AGENTIC_WORKSTATION_BROWSER_E2E=1`, Chrome for Testing).
   Тестовая страница повторяет сегодняшний случай: полоса «Aceptar | Rechazar | Seguir», которая
   сдвигается на ширину кнопки, как только мышь начинает движение. У каждой кнопки свой счётчик
   нажатий. Случаи:
   - клик по `ref` на «Aceptar» во время сдвига - нажата «Aceptar», у «Rechazar» ноль;
   - `x,y` с `expect: "Aceptar"`, а под точкой «Rechazar» - отказ, ноль нажатий;
   - `x,y` по кнопке без `expect` - отказ с подсказкой про `ref`;
   - `x,y` по холсту без `expect` - клик проходит, `clicked` называет холст;
   - обычный клик по `ref` - в ответе роль и имя кнопки;
   - кнопка во фрейме другого источника - `ref` и `expect` работают;
   - курсор агента не мешает: попадание определяется по странице под ним.
4. **Mac, интеграционный тест** рядом с `cg-events.integration.test.ts`: своё тестовое окно с
   известными кнопками (Electron-окно с `app.setAccessibilitySupportEnabled(true)` или маленькое
   нативное), поиск элемента в известной точке, `expect` мимо - ноль нажатий, точка на своём окне
   курсора - окно пропущено.
5. **Живой прогон агентом** в отдельной копии IDE (скилл `/dev`, не dev Макса) через коннекторы
   Browser и Computer Use: тестовая страница из пункта 3 и Калькулятор на Mac (`expect: "7"` в
   точке «8» - отказ, в точке «7» - нажата «7»). По итогу короткий отчёт: что проверено, что
   нажалось, где были отказы.
6. Поднятые для проверки процессы - погасить в том же заходе.

## Готово, когда

- В браузере ни один клик не нажимает, если в момент нажатия под точкой не то, что задумано, и
  каждый ответ клика говорит, что нажато.
- На Mac то же для Computer Use; на Windows тот же контракт со строгим поведением при сбое.
- Сегодняшний случай воспроизведён тестом и больше не воспроизводится.
- Правило есть в инструкциях обоих коннекторов, тест длины пояснения зелёный.
- ADR записан, `pnpm check` зелёный, живой прогон из пункта 5 пройден и описан.
